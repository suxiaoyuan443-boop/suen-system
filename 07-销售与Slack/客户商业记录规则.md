# 客户商业记录｜Slack 规则

状态：当前正式规则
最后核对：2026-09-17

## 触发

仅在 Suen 明确要求“生成总结 / 总结”时输出，不在每轮客户消息后自动生成。

## 固定两部分

### 1. 本次沟通结果

必须包含：

- 客户阶段
- 购买意图
- 最终结果
- 下一步

### 2. 可直接发 Slack

使用 `99-模板/Slack商业记录模板.md`。

## 记录原则

- 不复制完整聊天原文。
- 只保留商业复盘需要的数据。
- 状态必须与真实沟通阶段一致。
- 尚未正式报价就写“未报价”，不能因为讨论了价格范围就擅自标成已报价。
- 尚未付款就不能记成交。
- 已读未回属于沟通状态，不自动等于流失。
- 内容兴趣、免费知识咨询与明确购买/服务询盘应区分。

## 有效询盘

判断有效询盘时看对方是否出现了明确的服务/产品需求、问价、执行可能性等购买行为。单纯表达兴趣、问免费资料、讨论学术问题，不自动计入有效询盘。

## 隐私

Slack 可以保存业务需要的客户记录，但 GitHub 不复制客户身份、联系方式、付款资料或完整聊天原文。
