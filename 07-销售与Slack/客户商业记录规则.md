# 客户商业记录｜Slack 规则

状态：当前正式规则
最后核对：2026-09-17

## 触发

**仅在销售私聊专用对话中，Suen 明确要求“生成总结”时输出。**

普通“总结”不触发客户商业记录；商业总控中的“总结”用于每日内容台账流程，二者必须严格区分。

## 目标频道

客户商业记录属于经营事实，目标频道固定为：

**Slack `#商业决策总控`｜Channel ID：`C0C22DAPNUD`**

不得把新的客户询盘、报价、成交推进记录写入 `#内容历史台账`。

“生成总结”默认生成可直接发送 / 复制到该频道的短记录；是否由工具直接写入 Slack，服从 Suen 当次明确指令，不自行假设已经发送。

## 固定两部分

### 1. 本次沟通结果

简短保留：

- 客户阶段
- 购买意图
- 最终结果
- 下一步

### 2. 可直接发 Slack

使用 `99-模板/Slack商业记录模板.md`，默认短记录，不重复完整聊天过程。

## 简短原则

Slack 记录只回答：

- 从哪里来；
- 想买什么；
- 现在到哪一步；
- 报价/成交状态；
- 当前卡点；
- 下一步。

没有实际信息的空字段可以省略，不为了模板完整把记录写成长表。

## 状态判断

- 尚未正式报价就写“未报价”，不能因为讨论了价格范围就擅自标成已报价。
- 尚未付款不能记成交。
- 已读未回属于沟通状态，不自动等于流失。
- 沟通仍在继续时，不提前写“最终失败 / 已结束”。
- 内容兴趣、免费资料咨询、学术问题与明确产品/服务需求要区分。

## 有效询盘

有效询盘通常至少出现一项明确购买行为：

- 问具体服务/产品；
- 问价格；
- 问能否执行；
- 提供与购买决策直接相关的个人需求；
- 继续推进时间、方案、付款等细节。

单纯点赞、表达兴趣、问免费资料或讨论知识，不自动计入有效询盘。

## 隐私

Slack 可以保存业务复盘需要的信息，但 GitHub 不复制客户姓名、微信号、手机号、地址、付款截图、付款账号或完整聊天原文。
