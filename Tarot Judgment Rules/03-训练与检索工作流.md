# 塔罗判断训练｜训练与检索工作流

状态：当前正式规则

## 0｜全量盘点
先索引 328GB，不下载：path、filename、fsid、category、size、content / abstract 状态、修改时间、可能主题。

当前首选本地工具：`tools/baidu_tarot_index.py`。它调用百度网盘官方 `listall` 递归只读接口，Access Token 只从本机环境变量读取，输出 `tarot_master_index.csv`、`tarot_master_index.jsonl` 和摘要 JSON。首次优先把 `--root` 指向塔罗课程总文件夹，而不是无必要地扫整个网盘。

## 1｜已有文字优先
优先：已有字幕 / 音频文稿 → 摘要可定位案例 → PDF / 讲义 → 完全无文字视频。

## 2｜首批高信息案例
优先完整问题、完整牌阵、老师解释原因、现场改判、补牌逻辑、后验。同一张牌在不同问题中的不同处理尤其重要。

第一轮先形成约 50—100 个高质量案例，再做缺口分析，不追求扫完整套课程。

## 3｜缺口分析
检查哪些题型过多、哪些规则只有单例、哪些缺反例、哪些主题缺失、哪些案例信息不足。下一批只补缺口。

## 4｜定向下载 / 转录
只有“无可用字幕 + 高概率含缺口案例 + 其它资料不足”才下载。抽音频、转录、保留时间戳。

## 5｜规则归纳
区分老师明示与多案例归纳，主动搜反例，保留适用范围与冲突。

## 6｜Suen 采用
候选进入 adopted / modified / observe / rejected。只有 adopted / modified 进入高优先运行时。

## 7｜真实牌局反馈
Suen 后续实占产生新反例、后验或失效条件时，回写证据层。

## 新牌局检索顺序
同问题类型 → 同牌位功能 → 同关键牌 → 同组合 → 同现实背景 → 反例 → 后验已知案例。

“牌一样”不能自动排在“问题和牌位一样”前面。
