## 择时体系分流

`05-天象经营/择时系统分流规则.md`

- PGM / PDM → 使用其自身原典与 PGM / PDM 内部择时标准；
- 星符 / Ars Paulina / 水晶显灵 / 古典魔法召唤 → 使用古典魔法择时规则；
- 两套规则不得默认混用。

## 作用

这个当前文件只保存 **已经经过专用择时系统筛选后的经营状态**，供商业总控快速判断近期能卖什么、是否开放预约、商业阶段如何。

完整技术分析不在本仓库展开。

## 星符 / 仪式的经营硬规则

星符和大多数仪式不是 365 天随时执行的普通现货商品。

允许：

- 提前收预约；
- 客户先付款排期；
- 等真正合适的日期统一执行；
- 在已经确认的窗口上开放预约。

### 开放预约与主动商业推广分开

`开放预约` 只表示：这个未来窗口已经可以承接真实预约、付款排期或自然询盘。

它**不等于当天必须主动做商业推广**。主动商业动作可以在窗口临近后再启动，由商业总控结合以下因素判断：

- 距离执行窗口还有多久；
- 当前预约量；
- 承载能力；
- 当天 / 当周商业密度；
- 当前主要内容任务和询盘瓶颈。

除非 Suen 明确指定，不机械写死“提前多少天”开始卖。

当旧窗口日期已经过去时：

- 旧窗口立即停止接受新预约，也不得继续作为当前可宣传窗口；
- 旧窗口是否已经实际执行 / 完成，仍回到技术与实际执行真源确认，不由总控从日期自动推断；
- 如果已经存在下一条未来 `已确认` 窗口，并且 Suen 明确授权开放，总控可以把下一窗口切换为 `开放预约`；
- 下一窗口已经开放预约后，仍可以先只承接自然询盘，等临近执行窗口再进入主动推广阶段。

禁止为了营销：

- 虚构“好天象”；
- 虚构“最佳日期”；
- 虚构“本月唯一窗口”；
- 虚构名额紧张或人为制造稀缺；
- 为了成交降低 Suen 原有择时标准；
- 在日期尚未可靠筛选时公开一个具体执行日期或时分。

只有以下两类日期才可以对外宣传为具体窗口：

1. Suen 已经明确确认的日期；
2. 当前已经由对应择时专用系统可靠筛选、并允许商业宣传的日期。

如果还没有确认日期，公开表达只能使用预约制事实，例如：

- “下一批日期确定后开放预约”；
- “目前采用预约制”；
- “具体执行日期根据实际天象安排”。

不得把“还没确定日期”包装成稀缺营销话术。

## 经营数据与技术真源分开

当前预约池中的窗口用于经营调度，不因为已经登记就意味着技术条件永远不需要复核。

商业总控可以读取并使用：

- 已确认 / 开放预约等经营状态；
- 是否允许商业宣传；
- 适合用途；
- 预约数与承载能力。

### 精确时刻冲突硬规则

如果不同记录中的具体执行时刻存在冲突：

- **不得直接把任何一个冲突时间作为公开宣传时间；**
- **总控不得自行选择“看起来最新”或“更合理”的一个时分；**
- **精确执行时分必须回到对应择时专用对话 / 专用择时系统，以最新可靠复核结果为准。**

在精确时间尚未完成可靠复核时，可以公开经营状态，例如：

> “9 月 17 日木星窗口已开放预约”

但不要擅自宣传具体几点几分。

### 技术真源

完整判断始终以对应择时专用系统为技术真源。PGM / PDM 与星符 / 古典召唤的技术体系必须先按 `择时系统分流规则.md` 分流；不得再默认把 Bonatti、Moon Hard Filter、行星日 / 行星时套到 PGM / PDM recipe 上。
