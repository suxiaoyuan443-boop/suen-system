# 抖音小号｜苏恩

状态：当前正式规则
最后核对：2026-09-18

本文件是小号专属规则，同时继承：

- `00-系统总控/Suen统一文笔总则.md`
- `99-模板/视频类统一交付格式.md`

若两者有细节差异，以本文件更具体的小号内容规则为准；但凡任务属于“口播 / 台词 + 对应图片 / 画面”，最终交付方式统一服从 `99-模板/视频类统一交付格式.md`。

## 定位

小号和大号不是“同一套内容缩短一点”。

大号负责资料、研究、原文、文物、判断逻辑和专业信任；小号更接近 **Suen 的实践人格层**：更轻松、更有人味，但可以同时承载真实实践、个人判断、供奉、器物、工作过程和直接问题型机制解释。

小号优先表现：

- 氛围；
- 反差；
- 互动；
- 情景化；
- 工作日常；
- 真实操作过程；
- 更自然的个人表达；
- 从真实实践 / 供奉 / 评论问题进入的一听就懂的机制解释。

小号可以更生活化，但不能因为“轻松”变成低质 AI 娱乐号；也不能因为“大号负责研究”就把小号限制成只有氛围和边角料。

## 与整体品牌的关系

小号可以更像“人在现场”，但不能变成与大号完全无关的另一个女巫账号。

整个 Suen 品牌对外仍只有一条主线：

> **研究真的存在过、也仍在被实践的神秘学，并把资料、做法和判断讲清楚。**

小号主要负责其中的“做法与人”：

- 今天实际在做什么；
- 材料和器物怎么出现；
- 供奉、祭坛、制作和工作过程；
- 个人经验与现实判断；
- 从现代女巫 / 实践问题进入的一听就懂的解释。

因此现代女巫、生活方式和氛围内容可以明显增加，但每条最好仍能让观众看见至少一项：**真实实践、真实信息、真实判断或真实器物。**

## 内容方向

优先：

- 神秘学工作日常；
- 仪式准备 / 收尾；
- 塔罗桌面、翻牌、整理牌阵；
- 供奉、换供物、整理祭坛等真实片段；
- 材料制作过程；
- 工作前后反差；
- 评论区问题回应；
- 情景化但真实的实践片段；
- 一句话就能听懂的真实知识点；
- 从具体实践问题切入的短机制解释，例如“供品已经献给神了，为什么人还能继续食用”；
- 大号太严肃、不适合完整做成资料讲解的小细节。

### 小号允许完整承担“机制解释”

小号不要求所有知识内容都只剩一句知识点。

如果一个问题：

- 来自真实实践 / 供奉 / 日常观察；
- 普通人一听就懂；
- 不需要做成大号那种完整资料带看；
- 能在较自然的人格表达里把答案讲清楚；

可以直接把“机制解释”作为整条视频的主价值。

大号与小号的差别主要在**表达重心和证据呈现方式**，不是“大号能讲知识、小号不能讲知识”。

## 后台内容类型标签｜用于复盘，不是前台栏目

小号不建立大号式固定栏目，但为了以后比较哪种观看体验最有效，每条已发布内容在 `#内容历史台账` 可以记录一个**主内容类型**。

主内容类型一次只选 1 个：

1. **观点经验**：Suen 对现实问题、选择、个人经历、实践经验的直接看法；
2. **机制解释**：回答“为什么会这样 / 为什么要这样做”，主价值是把某个实践或宗教机制讲清楚；
3. **实践现场**：真实仪式、占卜、操作、准备、收尾、工作过程本身是主角；
4. **神明供奉**：神明、祭坛、供品、祈祷、献供、 devotional / 供奉氛围是主角；
5. **器物制作**：魔碗、护符、香、材料、器物、手作过程或成品本身是主角；
6. **祈愿互动**：短祈愿、宣言、祝福、观众可参与的轻互动或氛围型表达是主角；
7. **商业证明**：客订展示、客户反馈、业务能力、交付成果或社会证明是主角。

### 主题标签与内容类型分开

`内容类型` 看的是**观众实际在看什么体验**，不是学术主题。

主题标签可以另外记录，例如：

`古埃及 / 古希腊 / Bastet / Solomon / Hoodoo / 阿拉姆魔碗 / 天使 / 塔罗 / 财富 / 保护`

同一个主题可以落到不同类型。例如：

- “向 Bastet 献水果与美酒” → 神明供奉；
- “为什么某种供品最后还可以由人食用” → 机制解释；
- “今天实际准备 Bastet 相关仪式” → 实践现场；
- “Bastet 相关器物成品” → 器物制作。

### 内容形式单独记录

为了避免把不同分发机制的数据混在一起，复盘时另外记录：

- **视频**：能取得时记录时长；
- **图文**：能取得时记录图片数。

视频的完播率 / 2 秒跳出率与图文的划走率 / 文案展开率不是同一指标，不能直接横向比较。

### 入口结构单独记录｜用于学习什么开头更有效

`入口结构` 与 `内容类型` 也是两件事。

同一个内容类型可以换不同入口；同一种入口也可以用于不同主题。需要复盘时可记录一个主入口结构：

1. **反直觉问题**：直接抛一个普通人马上能听懂、答案却不直观的问题；
2. **第一人称观点 / 结果**：从 Suen 自己的结果、经验、判断或一句强观点进入；
3. **祈愿参与**：让观众以“见者有份 / 一起祈愿 / 宣言”等方式进入；
4. **视觉对象展示**：先让器物、祭坛、神像、材料或异常画面本身吸引；
5. **现场过程**：从正在做什么、准备什么、操作什么进入；
6. **客订 / 反馈结果**：从客订、反馈、业务结果或社会证明进入。

入口结构主要用于回答：**什么样的第一眼 / 第一问最容易让人进入。**

这不是要求 Suen 每次手填。标题、成片和后台数据足够时，由总控 / 复盘自行判断；判断不稳时标“待确认”。

### 商业角色与内容类型分开

`商业证明` 是一种观看体验，不自动等于 `D｜商业承接`。

同一条客订 / 反馈内容可能是：

- 纯工作记录；
- C｜服务认知；
- D｜商业承接。

是否构成明显商业信号、是否包含 CTA，仍统一执行 `00-系统总控/商业信号与动态状态规则.md`，不能只凭内容类型判断。

### 使用边界

- 这些都是后台分析标签，不要求前台显示；
- 不要求七类机械轮播；
- 不因为某个类型数据高就把其它类型全部停掉；
- 历史内容如果仅凭标题无法可靠判断，先标“待确认”，不强行分类；
- 后续总控比较小号表现时，优先在**相近内容形式 / 相近统计窗口**内比较同一类型，再看不同类型之间的差异；
- 不把发布时间跨度很大的旧内容简单按绝对播放量直接判胜负，需要同时考虑发布时间、形式、时长 / 图片数和统计窗口；
- 复用历史经验时优先复用的是“内容类型 × 入口结构”的组合，不机械重拍旧题。

## 每条至少保留一个真实信息点

即使视频主要是氛围，也至少留一条真实知识，例如：

- 这个材料实际用于什么；
- 某个动作为什么出现；
- 一张牌为什么在这个问题里这样判；
- 供物为什么这样处理；
- 某个仪式准备步骤实际在做什么。

不能整条只剩“女巫氛围 + 神秘音乐”。

## 真实性

不虚构：

- 客户；
- 咨询内容；
- 仪式效果；
- 自己没有经历过的事情；
- 历史来源；
- 到访 / 实拍；
- “刚刚发生”的神秘事件。

如果为了隐私做情景再现，要明确它是情景化表达，不能伪装成真实客户现场。

## AI 内容

低质 AI 短剧不再作为主要方向。

AI 如果使用，只能作为辅助：

- 背景；
- 明确的示意；
- 不承担史实证据的视觉。

不能用 AI：

- 假装真实仪式；
- 假装真实客户；
- 假装本人实拍；
- 假装历史文物 / 手稿；
- 制造虚假的“灵异现场”。

## 文风

- 比大号口语化；
- 可以出现自然第一人称；
- 可以保留真实停顿、动作、表情；
- 不需要每条完整解释历史背景；
- 不堆术语；
- 不用“你有没有想过 / 很多人不知道 / 你绝对想不到”等 AI 钩子；
- 不用营销号式“反转到最后”；
- 不故意一句一段写成短视频模板文案。

## 画面

优先真实桌面、真实手部、真实材料、真实空间和真实工作状态。

不要求像大号一样始终让资料全屏占主体；小号允许人物、动作和空间承担更多画面。

但涉及历史事实时，仍然优先给真实原文 / 文物，而不是用氛围画面替代证据。

## 与大号的关系

同一个主题可以分两种内容：

### 大号

讲：证据、历史、原文、判断。

### 小号

讲：真实工作过程、现场感、个人经验、一个有意思的小细节、评论互动，或从实践入口直接把一个机制问题讲清楚。

不要把大号完整口播换成随意画面直接当小号，也不要把小号轻内容硬塞回大号。

如果小号某个题型表现好，只能说明**这个问题结构 / 观看体验值得继续验证**；大号若要做同类题，重新按大号栏目规则研究、路由和制作，不直接搬运旧视频。

## 商业边界

小号可以更自然地出现产品、仪式准备、塔罗工作等真实商业环境，但不把每条做成广告。

如果当天商业总控已经把唯一商业信号分配给其它平台，小号不重复强推。

## 调度

- 不要求机械日更；
- 是否发布由商业总控结合工作量、平台任务和近期内容频率决定；
- 小号与大号在 `#内容历史台账` 必须分别记录；
- 小号复盘优先保留 `内容类型`，并在有分析价值时记录 `内容形式 / 入口结构 / 主题标签`；
- 不因为小号数据低，就自动把大号资料型内容搬过去救流量。

## 正式交付

有口播 / 台词的视频统一执行：

`99-模板/视频类统一交付格式.md`

小号额外保留两点：

- 如果主要由本人真实操作构成，直接在对应台词后写清真实拍动作，不为了形式硬配网图；
- 成品至少包含：核心情境、真实信息点、完整口播 / 台词、对应真实画面 / 实拍动作、标题与发布文案。

如果使用 AI 辅助画面，必须明确它只是示意，不能冒充真实仪式、客户、本人实拍或历史资料。
