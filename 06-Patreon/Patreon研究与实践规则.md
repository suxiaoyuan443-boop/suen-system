当前核心权益：
1. Full Research Essays

Patreon 主要发布：

2. 原始资料 / 手稿 / 纸草 / 文物专题；
3. 某个具体魔法传统、仪式或做法的来源研究；

“现代女巫”不是 Patreon 的主要身份标签，不为了流量把页面写成现代女巫生活号。

## 三、研究标准

Patreon 研究文章必须优先回到：
- 原始手稿；
- 纸草；
- 原书页；
- 历史版本；
- 博物馆藏品；
- 铭文 / 护符 / 器物；
- 学术论文；
- 学术专著；
- 可靠现代校勘、翻译和研究。

证据优先级：

原始资料 > 可靠校勘 / 学术出版 > 现代学术研究 > 可靠历史资料 > 现代实践者解释

现代实践者、博客、论坛、YouTube、TikTok 等不能承担核心历史事实证明。如果只能找到现代作者的解释，必须明确标注为现代解释，不能反写成古代传统。

## 四、写作方式

Patreon 文章不是论文，也不是营销文。

文风必须：自然、清楚、具体、有研究感、有解释能力、不卖弄术语、不故意神秘化、不讨好读者。

避免：AI 式开头、“你有没有想过”、“很多人不知道”、“本质上”、“说到底”、“真正重要的是”、“这告诉我们”、“值得注意的是”、“底层逻辑”、“建立边界”、“空间结构”、连续使用“不是 / 不能 / 并不 / 不等于”、一句话一段、空泛总结、为了显得专业堆术语。

**段落必须按完整意思自然展开。** 除标题、图注、短引文、清单或确有必要的强调外，不要为了制造节奏把两三句话拆成多个短段。正常正文优先使用完整段落，让一个段落真正完成一件事。

避免频繁在段尾加这类 AI 式判断句：

- “This is important because…”
- “This is a practical passage.”
- “This is difficult to reduce to…”
- “This tells us…”
- “The key point is…”

如果材料本身已经把事实说清楚，就直接推进下一层信息，不额外替读者总结一次。

同样，不要连续用一串独立问题代替正文展开，例如“Where does X go? What is written? Who stands where?”。这些问题可以作为内部研究清单，但正式文章应把答案写成连续、完整的论述。

能说具体动作，就不要先换成抽象概念。

例如不要写：

> 仪式通过建立边界形成神圣空间。

优先写：

> 文本先要求把圆画出来，再规定人站在哪里、被召对象出现在哪里，以及哪些名字要写进圆里。

专业感来自具体资料和解释，不来自抽象术语。

### Patreon 正文段落硬标准

Patreon 正式文章默认使用**正常长文段落**，不是短视频文案排版。

除标题、图注、短引文、表格、资料编号外：

- 正常正文段落原则上至少完成一个完整意思再换段；
- 不允许连续出现“一句话一段 / 两句话一段”的排版；
- 一个来源的动作复原应尽量在 1—3 个完整段落内连续讲清，不拆成十几个短段；
- 内部研究问题（例如“刀在哪里？香在哪里？谁站东边？”）不能原样变成正式正文的连续问句；
- 正式正文优先使用陈述句，把答案直接写出来。

### 否定句密度

Patreon 文章优先写“文本实际要求了什么”，而不是不断写“它不是什么 / 不能怎样理解”。

只有在以下情况才使用明显否定句：

- 修正一个确实存在的现代误读；
- 区分两个容易混淆的版本；
- 证据明确排除某个判断。

同一自然段原则上不要连续使用多个 not / does not / cannot / is not / rather than 等否定结构。能改成正面陈述时直接改成正面陈述。

例如：

不优先写：
> The circle is not simply a protective boundary. It is not an empty space. It does not merely separate the operator from the spirit.

优先写：
> In this manuscript, the circle assigns fixed places to the operator, companions, ritual tools, written names, and the expected site of appearance. Protection is one function within a larger working arrangement.

正式交付前必须做一次“短段落 + 否定句密度”专项 QA。

## 五、涉及仪式时的“具体复原”标准

如果文章主题涉及某个仪式、操作法、咒文、图形、器物或 recipe，**概述“这个文本要求了哪些步骤”是不够的**。

必须尽量把与文章主题直接相关的那一段操作重新写出来，让读者实际知道：

- 文本在什么位置开始这项操作；
- 操作者先做什么；
- 接下来做什么；
- 使用什么工具 / 材料；
- 站在哪里；
- 画在哪里；
- 写什么名字、字符、词或图形；
- 要朝哪个方向；
- 谁进入、谁留在什么位置；
- 如果有需要说出的祈祷、神名、咒语、conjuration 或公式，具体说了什么；
- 哪一步发生在画圆之前、圆画完以后、召唤开始前或显现之后；
- 哪些步骤只是当前主题的背景，可以简述；哪些步骤直接决定当前研究问题，必须详细展开。

### 原文与“念了什么”

当原始资料保留了实际要说出的词、神名、祈祷、conjuration、formula 或 rubric 时：

- 尽量给出可核查的原文 / 转写；
- 紧跟自然英文译文或准确释义；
- 明确这是手稿 / 版本直接保存的文本，还是现代编辑者补标；
- 不用现代译者的一大段版权译文代替原文核查；
- 如果原文太长，只摘取当前动作真正需要的关键句，并把完整位置、folio / page / chapter / line 标清。

如果文本只说“recite the prayer / say the conjuration above”之类指回前文，必须顺着交叉引用找到它实际指向的文本，不能只写“then a prayer is said”。

### 每个主要文本的固定研究单元

凡是作为正文主要比较对象的文本，至少做到：

1. **Source identification**：作品名、手稿 / 版本、年代、shelfmark、folio / page / chapter；
2. **Concrete reconstruction**：按顺序写出与主题直接相关的动作；
3. **Words / inscriptions**：写出实际被念、写、刻或放入图形中的关键文字；
4. **Placement**：人、工具、火、香、圆、三角形、被召对象等实际放在哪里；
5. **What this source actually establishes**：只总结这个文本自己的功能，不先套统一“保护圆”理论；
6. **Comparison**：完成具体复原以后，再和其它文本比较。

**先复原，后比较。不能只比较几个文本“都提到了什么”。**

如果文章只研究“魔法圆”，其它不直接影响圆的完整仪式步骤可以简写；但凡会改变圆怎么画、写什么、谁站哪里、被召对象在哪里出现、画圆时念什么的内容，必须展开。

## 六、第一人称

研究文章默认减少第一人称。允许在解释实践记录、说明为什么开始查某个问题、区分自己的实践选择和历史资料要求、记录一次真实实验或仪式结果时自然出现。

不要整篇反复出现 I think / I believe / In my opinion。研究结论尽量让材料本身承担。

## 七、文章必须真正回答问题

每篇文章必须让读者看完后明确知道：研究对象是什么、原始资料在哪里、原文 / 图像 / 文物具体显示什么、这个东西在当时怎么使用、为什么会这样做、不同版本 / 传统有什么差异、后来发生了什么变化、现代实践最容易混淆什么、哪些结论已有证据、哪些只能暂时保留。

禁止写一大篇以后，读者仍然只得到“这个问题很复杂”“不同传统都有不同理解”“需要结合语境判断”。如果有差异，就把差异具体写出来。

## 八、研究文章常见结构

不机械套固定论文模板，但完整研究文章通常至少包含：一个明确问题或具体对象、历史 / 文本背景、原始资料、对原文 / 图像 / 器物的具体阅读、不同资料之间的比较、实际功能或使用方式、后世变化或现代混淆、Sources / Further Reading。

如果涉及实践，还必须明确区分：1）历史资料明确要求；2）学者解释；3）后世发展；4）Suen 自己的实践选择。

## 九、付费文章标准

付费文章必须真的有完整信息量，不要把普通抖音口播加长一点就收费。

优先提供：视频里放不下的原始资料、完整文献链、更多版本、原文细读、具体步骤、争议、实践意义、Further Reading。

第一批文章宁可少，也要明显让人知道为什么值得 US$5 / month。

Patreon 对外不承诺硬性周更 / 月更数量。内部当前运营目标为：**平均每月约 4 篇付费内容**，允许根据研究难度前后浮动，不为了凑数量降低研究质量。

## 十、公开区与付费区

正式付费文章可以保留约 15%—20% 的公开预览。公开部分要让读者知道这篇到底在研究什么、为什么值得继续读、使用了什么类型的资料。

原始资料展开、完整论证、版本比较、实践分析、Sources / Further Reading 可以放在付费区。

不要用夸张悬念诱导付费。

## 十一、Selected Practice Records

实践记录可以包括：仪式准备、使用的历史资料、为什么这样复原、哪些步骤来自原文、哪些属于 Suen 自己的实践选择、实际执行后的观察、后续修正、失败或不确定结果。

不能为了文章好看虚构神迹、超自然结果、客户反馈、仪式成功、天象或神秘体验。不确定就写不确定。

## 十二、商业边界

Patreon 内容生产对话不擅自决定：Patreon 涨价、新增会员档位、开放咨询、开放仪式、开放星符、新数字产品价格、Patreon 推广节奏、其它平台商业 CTA。

这些由 Suen｜内容商业总控 决定。如果总控没有给商业任务，Patreon 文章本身默认不硬卖其它服务。

## 十三、语言

Patreon 当前默认以英文正式发布。每次正式交付：1）先给完整英文发布稿；2）再给中文完整核对版；3）英文不能写成生硬直译中文；4）术语、人名、书名、手稿编号必须核对拼写；5）必要时保留希腊文、拉丁文、埃及语转写等原文。

## 十四、图片与资料

需要图片时优先：手稿扫描、博物馆藏品、历史版画、原书页、纸草、学术出版中的公开图版。

**正式文章不能只在文末列“这里应该放什么图”。执行对话必须把图片实际找出来，并直接放到正文对应位置。**

交付标准：

- 英文正式稿写到相关手稿、图形、folio、文物或原书页时，紧跟着直接显示该图片；
- 图片下面给简短图注 + 来源页；
- 能确认时写手稿号 / 馆藏号 / folio / page / 日期；
- 如果图片需要看局部，直接给已经定位好的局部图 / 截图，不把整份 PDF 或长网页丢给 Suen 自己找；
- 同一图在中文核对版中也应放在对应位置，方便逐段核对；
- 文末可以额外保留 Images / Figures 清单做来源索引，但**清单不能代替正文内嵌图片**；
- 如果第一次没找到可用图片，继续搜索可靠数字馆藏、图书馆、Internet Archive、Google Books、学术数据库或公共扫描来源；只有经过实际查找仍无法取得时，才明确标记缺图原因。

**Suen 不承担“自己去找图”这一步。**

不能拿 AI 图冒充历史资料，也不能拿相似但错误的手稿 / 图形替代当前对象。

### 图片交付硬门槛

以下情况一律视为**未完成交付**：

- 只写“这里放图 / Figure X / 建议插入某图”；
- 只给来源链接，不显示实际图片；
- 只给一份文末图片清单，让 Suen 自己打开网页找；
- 给整份 PDF / 数字馆藏入口，却没有定位到实际页面 / folio / 局部；
- 用“因为版权 / 页面限制所以暂时不放图”作为默认省略理由，而没有继续尝试可靠可用来源。

执行对话必须做到二选一：

1. **聊天正文可直接显示图片时**：图片直接放在英文正文对应段落后，中文核对版相同逻辑位置再次显示；
2. **当前聊天环境无法稳定内嵌图片时**：自动生成一份已经嵌好图片的 HTML 或 DOCX 作为正式交付，正文里仍保留图注与来源页。

没有实际图片，就不能把文章标记为“最终版 / 可发布版”。

### 原始图像优先与重绘禁替代

Patreon 研究文章中的历史视觉证据，默认优先使用**真实手稿页、原书页、馆藏图像或可靠公开扫描**。

以下内容不能代替原始视觉证据：

- 助手自行绘制的 schematic / editorial reconstruction；
- 根据文字描述重新画出的圆、三角形、手稿布局；
- AI 生成的“类似手稿”；
- 现代二次整理图，却被放在原始 witness 应出现的位置。

如果为了帮助读者理解，确实有必要制作 schematic：

- 只能作为**补充图**；
- 必须明确标注 `Editorial schematic / reconstruction`；
- 必须说明依据哪些具体手稿 / folio / transcription；
- 默认放在真实原始图像之后；
- **Suen 未明确要求时，不用重绘图替代缺失的原始图像。**

### 成稿前图片资产先完成

进入最终长文写作前，执行对话应先在内部完成 Figure manifest。每个主要来源至少确认：

- 计划使用的真实图片是否已经取得；
- witness / shelfmark / folio / page；
- 图片来源页；
- 图片是否可直接显示 / 下载 / 嵌入；
- 图注要证明什么；
- 如果没有可用原图，是否需要明确写“当前未取得可用图像”，而不是临时画一张替代。

**主要图片还没实际取得时，不要先把整篇稿写成“最终版”再回头补图。**

### 图片完整性检查

交付前必须逐图核对，不能只确认“有部分图片显示出来”。

每一张在正文中被提到、编号、引用或作为论证依据的图片，都必须满足：

- 正文对应位置能看到实际图片；
- Figure 编号与图片一一对应；
- 图注、手稿号 / 馆藏号、folio / page 与图片本身匹配；
- 来源页可打开；
- 图片不是空白、黑屏、加载失败或失效预览。

如果同一篇文章中只有部分图片能在聊天里稳定显示，不要继续交付半完整聊天版。应自动改为已完整嵌入全部图片的 HTML 或 DOCX，并确保英文与中文版本图位一致。

正式交付前进行一次 Figure 对账：

正文提到的 Figure 数量 = 实际显示 / 嵌入的图片数量 = 图注数量 = 来源记录数量

四项不相等时，视为未完成。

### 链接与文件可用性验收

图片“有来源链接”不等于来源可用。

正式交付前必须实际检查：

- 来源页能正常打开，不是黑屏、空白页、403、失效预览或只有站点壳；
- 如果一个网页在当前环境只显示黑屏 / 空白，换用更稳定的数字馆藏、Internet Archive、Google Books、大学项目或其它可靠公开来源；
- DOCX / HTML 中的图片必须真实嵌入文件，不依赖外部热链才能显示；
- 生成 DOCX / HTML 后要重新打开成品检查至少一遍，确认所有 Figure 都真实可见、顺序正确、没有空白占位。

如果聊天里显示不稳定但文件版能完整显示，文件版作为正式图文成品；聊天文本只做辅助预览。

## 十五、选题原则

优先选一个具体问题、一个具体动作、一个具体器物、一个具体文本、一个明确的历史变化。

避免“魔法是什么？”“西方神秘学简介”“仪式的本质”“什么是真正的魔法”等过大泛题。

## 十六、正式交付格式

正式交付包括：

【Title】
【Subtitle｜如有必要】
【Public Preview】约全文 15%—20%
【PAYWALL 建议位置】
【Full Paid Article】完整英文付费正文，**图片直接内嵌在真正对应的段落位置**
【Sources & Further Reading】优先原始资料和学术出版
【中文核对版】完整中文对照，**保留相同图片在相同逻辑位置**

如有必要，可在正文后额外附【Images / Figures Source Index】集中列图号、手稿号、来源页，但它只能作为索引，不能代替正文中的直接图片。

正式交付不是“正文 + 一份让 Suen 自己继续找图 / 对图的清单”。

如果文章不需要某一项，可以省略，不机械凑格式。

### 最终发布前失败条件

出现以下任一情况，必须自行返工，不能交给 Suen 做人工修稿：

- 连续多段只有 1—2 句话；
- 正文主要由问题清单组成；
- 同一段连续出现多个否定 / 反驳句；
- 对主要文本只做概述，没有具体动作、文字、站位、图形与相关 formula；
- 图片只有链接 / 占位说明，没有实际嵌入；
- 英文版与中文核对版图位明显不一致；
- 文章读起来像 research summary，而不是完整研究文章。

## 十七、首批内容原则

Patreon 冷启动阶段优先让档案本身先具备订阅价值。

首批内容应尽量覆盖不同价值面，例如：

- 至少 1 篇完整历史 / 原典研究；
- 至少 1 篇与现实实践相关、但能回到历史资料的问题；
- 至少 1 篇 Selected Practice Record。

具体哪一篇先写、当天是否执行、当前做到哪里，属于动态生产状态，记录在 Slack / 当天总控，不固化在长期规则中。

每一篇仍必须独立完成原始资料核查，不能把已有公开视频口播直接翻译或扩写后收费。

## 十八、新对话接管与旧稿隔离

Patreon 长研究任务如果已经连续多轮返工、旧稿和纠错历史明显干扰执行，允许直接新开专用对话继续。

新对话必须先实际读取：

1. `00-系统总控/Suen统一文笔总则.md`
2. `06-Patreon/Patreon研究与实践规则.md`

然后只带入：

- 当前题目；
- 已可靠核查的原始资料 / 书目 / 手稿定位；
- 当前有效的具体修改目标。

**不要把旧对话里失败的成稿全文、反复错误的图位说明和过时临时规则全部复制进新对话。** 目标是保留研究成果，切断错误写作惯性。

如果旧对话已经形成明显“研究摘要腔 / 短段落 / 反驳腔 / 图片占位”惯性，新对话优先从可靠证据重新成稿，而不是继续修补旧文本。

## 十九、与总控关系

本规则只负责 Patreon 内容生产。

如果涉及今天要不要发、Patreon 当前是不是主推平台、是否宣传会员、是否涨价、是否增加档位、是否在抖音 / 小红书 / 公众号引流、Patreon 对整体商业收入承担什么任务，全部回到 Suen｜内容商业总控 决定。

Patreon 内容对话不得自行扩大商业任务。

## 二十、长任务执行与断线保护

Patreon 完整研究文章如果同时包含：

- 多手稿 / 多版本核查；
- 大量网页检索；
- 多张原始图片定位；
- prayer / conjuration 交叉引用；
- 英文正式稿；
- 中文完整核对版；
- DOCX / HTML 成品；

属于长链路任务。

### 推荐执行环境

优先使用 **ChatGPT Work** 在同一 Project 中执行，而不是要求普通 Chat 在单次长回复里完成全部研究、找图、写稿和文件生成。

### 内部分阶段，但不要求 Suen 反复说“继续”

执行对话应自行按以下阶段推进，并在每阶段结束后保存当前成果 / 工作文件，再自动进入下一阶段：

1. **Source Verification**
   - 核对作品、手稿、shelfmark、folio / page、年代、版本关系；
   - 形成可靠 source map。

2. **Figure Manifest**
   - 把所有需要的真实图片先找齐；
   - 核对 witness、folio / page、来源页、可嵌入状态；
   - 不用 schematic 顶替缺失原图。

3. **Text Reconstruction**
   - 追动作、站位、written material、prayer / conjuration / formula；
   - 完成每个主要文本的具体复原与比较。

4. **Final Article**
   - 英文正式稿；
   - 图片直接嵌入；
   - Sources & Further Reading；
   - 中文完整核对版；
   - 最终 QA。

5. **File Validation**
   - 如果生成 DOCX / HTML，重新打开检查；
   - 核对 Figure 数、实际图片数、图注数、来源数一致；
   - 确认没有空白图、黑屏、失效热链或缺页。

### 断线保护

长任务不要把“全部成果只存在最后一次回复里”。

如果当前执行环境支持持久工作文件，应在每阶段结束后保留阶段成果。中断后优先从最近完成阶段继续，不从头重复搜索。

如果普通 Chat 连续两次在长时间执行后中断，**不要第三次用同一超长单次提示词硬跑**。改用 Work，或先完成 Source Verification + Figure Manifest，再进入成稿阶段。

目标是：**不让 Suen 反复说“继续”，同时也不把全部工作押在一次 20—30 分钟的单轮执行上。**
