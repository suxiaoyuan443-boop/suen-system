# 对标数据｜动态数据层

状态：当前正式动态数据区  
建立：2026-09-24

用途：保存 Suen 内容系统核心对标账号的**滚动近 365 天公开发布数据**，供选题与结构复盘直接读取。

长期方法仍在：
`00-系统总控/内容商业对标系统.md`

## 核心原则

- 对标账号尽量收集近 365 天全部公开发布，不只截取爆款；
- 一年基线是主层，最近 90 天 / 最近 3—5 条是趋势层；
- 低频更新账号不因最近 30 天没发内容被判“没有近期样本”；
- 每条记录必须保留抓取日期，因为播放 / 点赞会继续变化；
- 不同账号绝对播放量不直接横比，优先看账号内部中位数、Top 25% / Top 10% 和相对倍数；
- Suen 第一方真实数据始终高于外部对标。

## 年度统计

每个账号至少维护：
- 近一年发布数；
- 中位播放；
- P75；
- P90；
- Top 10 内容；
- 低于中位数的典型内容；
- 高频题材 / 入口；
- 高表现题材 / 入口；
- 是否存在“高播放但低互动”与“低播放但高精准互动”分化；
- 最近 90 天是否发生结构变化。

## 刷新频率

不要求每天重爬全量：
- 新账号首次建立：尽量补齐近 365 天全部公开数据；
- 后续：有新发布时增量补；
- 每周复盘时检查一次是否有遗漏；
- 正式定题时，如年度库已新鲜可直接复用，只补最相关的新发布。

Git commit 保存历史快照，不在当前文件里反复复制旧数据。

### 读取顺序

正式定题时：
1. 先读 Suen 第一方当前状态；
2. 读 `采集状态.md`，知道哪些账号数据够不够；
3. 读与当天候选最相关的 1—3 个账号；
4. 需要跨账号判断时再读 `跨账号结构观察.md`；
5. 不因为某账号年度数据未补齐而假装已经有完整统计结论。


## 数据源纪律

对标年度库允许同时使用：
- 平台公开页；
- 账号官网 / 作者自建归档；
- 可追溯第三方统计页；
- Patreon / 官网只用于补发布时间、主题流或商业桥时的代理数据。

必须区分：
- **平台官方真实数据**；
- **作者自己公布 / 后台截图核对数据**；
- **第三方动态估算**；
- **第三方索引的当前累计值**；
- **仅用于题目结构的代理清单**。

不能把：
- 西瓜数据“预估粉丝”写成微信真实粉丝；
- SponsorRadar估算收入写成实际收入；
- Patreon Early Access日期直接当YouTube正式发布日期；
- 搜狐阅读量当微信阅读量；
- 不同抓取日期的累计播放变化当成两条不同视频；
- 页面没有字段名的互动数字自行映射成点赞 / 收藏 / 分享。

每个账号文件优先保留：
- 数据源；
- 抓取日期；
- 当前缺口；
- 哪些结论可以下；
- 哪些结论还不能下。

年度库的目标是**可追溯、可更新、可比较**，不是表面上把字段填满。
