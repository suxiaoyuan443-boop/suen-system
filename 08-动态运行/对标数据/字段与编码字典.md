# 对标数据｜字段与编码字典

状态：当前正式数据规范  
建立：2026-09-24

用途：保证不同账号、不同平台的数据进入年度库以后，字段和结构编码不会越做越乱。

## 一、基础字段

### 原始数据
- `account`
- `platform`
- `publish_date`
- `title`
- `url`
- `content_format`
- `duration`
- `views`
- `likes`
- `comments`
- `favorites`
- `shares`
- `followers_at_capture`
- `capture_date`
- `source`
- `source_type`

### source_type 只用
- `platform_public`：平台公开页；
- `author_archive`：作者自建归档 / 后台核对；
- `third_party_index`：第三方抓取的当前累计值；
- `third_party_estimate`：第三方模型估算；
- `proxy_topic_stream`：Patreon / 官网等只用于题目流代理；
- `syndicated_feed`：作者同步到播客 / RSS / 联合分发端的精确标题与日期；可用于内容时间线，不自动等于 YouTube 正式发布日期；
- `cross_platform_repost`：其它平台转载 / 分发数据。

不同 source_type 不自动合并成同一口径。

## 二、派生字段

能计算时：
- `age_days_at_capture`
- `like_rate = likes / views`
- `comment_rate = comments / views`
- `favorite_rate = favorites / views`
- `share_rate = shares / views`
- `interaction_rate_visible`
- `relative_to_account_median`
- `performance_band`
- `relative_to_format_median`：相对同账号、同 `content_format` 的中位数；
- `format_performance_band`：按同格式中位数分档。

### performance_band
基于同账号 / 同格式近365天中位数：
- `very_low`：<0.5×
- `below_median`：0.5—1×
- `above_median`：1—2×
- `strong`：2—3×
- `high_outlier`：≥3×

不是跨账号评分。

### 格式内分层

当同一账号同时存在 long-form、interview/livestream、Shorts、News 等明显不同格式时：
- 先保留“全账号混合中位”用于回答一年里整体发布分布；
- 同时计算“同格式中位”；
- 正式判断某条内容强弱时，**优先看同格式相对表现**，避免直播天然低播放把普通研究视频基线拖低，或 Shorts / 特殊形式抬高基线。

## 三、Hook 第一层编码

每条内容允许 1 个主 Hook + 最多 2 个辅助 Hook。

主 Hook 可用：

- `explicit_question`：标题直接问一个问题；
- `strong_mystery`：谜团 / 真相 / 误解 / 最奇怪；
- `real_world_conflict`：偷窃、疾病、关系、工作、选择等现实冲突；
- `familiar_unexpected`：熟悉人物 / 制度 / 时代 + 意外的一面；
- `counterintuitive_action`：一个看起来反常的具体动作；
- `specific_object`：具体文物 / 手稿 / 器物直接做主角；
- `specific_text`：具体书 / 咒文 / 原文做主角；
- `person_story`：人物 + 事件 / 时间线；
- `practice_dispute`：实践者真正会争论的问题；
- `how_to`：教程 / 跟做 / 步骤；
- `process_satisfaction`：制作 / 打包 / ASMR / 开箱；
- `participation`：选牌 / YES-NO / 投票 / 互动参与；
- `product_entry`：商品 / 开箱 / 新品本身做入口；
- `descriptive_topic`：描述型专题，无明显问题 / 冲突。

不要为了让数据好看强行一条多编码。

## 七、代理数据特别规则

### Patreon题目代理
字段：
- `proxy_date`
- `proxy_title`
- `proxy_source=Patreon`
- `youtube_publish_date=N/A`
- `views=N/A`

不能因为题目后来可能上YouTube就填一个推测发布日期。

### 西瓜数据公众号快照
字段：
- `estimated_followers`
- `headline_avg_reads`
- `originality_pct`

必须同时：
- `source_type=third_party_estimate`
- `capture_date`

不能重命名成：
- followers
- actual_reads
- growth

---

## 八、缺失值

统一使用：
`N/A`

不要用：
- 0
- 空字符串
- “大概没有”

除非来源明确显示真实0。

---

## 九、编码升级纪律

第一次编码叫：
- v1

只有：
- 样本足够；
- 定义清楚；
- 对同一批数据复编码；
- 不改变原始字段；

才升级 v2。

历史编码保留 Git commit，不静默改成新的“真相”。
