# 小红书｜前台合集结构

状态：当前正式规则
最后核对：2026-09-18

## 当前前台合集

小红书当前共有 **7 个视频前台合集 + 1 个独立长文合集《长卷》**：

1. `文物`
2. `异录`
3. `辨伪`
4. `残页`
5. `隐理`
6. `世问`
7. `牌记`
8. `长卷`（独立研究型长文）

`口述` 不作为前台合集名，只保留为内部内容形式 / 母类。

## 小红书对外品牌主线

小红书可以比抖音大号更生活化、更收藏型，也可以出现教程、实践、器物和现代女巫搜索词，但账号不能因此分裂成多个方向。

对外仍统一为：

> **Suen 研究真的存在过、也仍在被实践的神秘学，并把资料、做法和判断讲清楚。**

小红书内容可优先落到三种母方向：

1. **资料与真实对象**：文物、原文、历史材料、具体神秘学对象；
2. **做法与现实问题**：现代女巫实践、教程、材料、为什么这样做、怎么判断；
3. **真实实践与人格**：祭坛、制作、工作过程、个人经验、器物与服务认知。

这三类只用于控制账号整体观感，不替代 7 个视频合集、《长卷》或后台历史标签。

现代女巫内容可以增加，但不能变成与原有研究型内容完全分开的第二个账号人格；能和 Suen 的资料能力、实践经验或判断能力接上时才优先做。

## 当前发布基线

小红书当前实际基线是：**每天 1 篇 / 1 条内容。**

通常优先直接同步当天抖音大号同一支完整成片，再针对小红书调整标题、封面文字与发布配文。

这里的“每天1篇”不等于《长卷》每天更新：

- 视频内容可以承担当天小红书更新；
- 《长卷》是独立研究型长文，不机械日更；
- 如果商业总控基于真实数据、平台状态、工作量或当天明确指令决定某天小红书停更，可以例外，但需要有实际理由。

## 历史账号结构必须参与定题

当前 `7 个视频合集 + 长卷` 是**现阶段前台生产结构**，不代表账号历史上只存在这 8 类内容，也不要求把旧内容强行重分类成当前合集。

小红书过去已经发布过：

- 研究知识 / 文物 / 原文核查；
- 实践与祭坛；
- 实操教程；
- 个人观点 / 经验；
- 祈愿参与；
- 器物 / 客订展示等。

因此总控为小红书定新题时，除了最近 7 天，还要读取 `#内容历史台账` 中当前可取得的**整段历史基线**，尤其检查：

- 账号过去已经大量讲过什么；
- 哪些题目结构曾经带来明显浏览、收藏、涨粉或询盘；
- 哪些只是单条强样本，尚未重复验证；
- 当前主页与长期历史共同给观众什么第一印象；
- 新题是在扩展有效结构，还是重复旧题。

### 小红书后台分析维度｜不等于前台合集

为了分析历史内容，不强行给旧内容套当前前台合集；需要时可以在后台使用以下维度：

**历史内容角色**（一次选 1 个主角色）：

1. `研究知识`：文物、原文、历史宗教 / 魔法知识、具体资料核查；
2. `实践与祭坛`：真实仪式、供奉、祭坛、蜡烛、工作过程；
3. `教程方法`：明确告诉读者 / 观众怎么做、怎么判断、怎么区分；
4. `个人观点经验`：Suen 自己的经验、判断、结果或现实看法；
5. `祈愿参与`：祝福、宣言、观众可参与的祈愿 / 氛围；
6. `器物与客订`：成品、材料、客订、器物展示或商业证明。

**内容形式**：

- 视频；
- 图文；
- 长文 / 长卷。

**入口结构**（需要复盘时可选）：

- 视觉异常 / 奇怪对象；
- 反直觉机制问题；
- 原文 / 来源到底写了什么；
- 现实判断 / 大众默认判断；
- 实操教程；
- 第一人称经验 / 结果；
- 祈愿参与；
- 器物 / 客订展示。

这些只是后台分析维度，不要求前台展示，也不要求机械轮播。

### 第一方历史信号怎么使用

统一执行 `00-系统总控/内容商业对标系统.md`：

- 单条明显高表现 → 只记为**强单样本**；
- 多个相近样本在同一目标指标上重复有效 → 才升级为**重复信号**；
- 多个时期 / 多个平台在相同目标指标上持续有效 → 才进入**稳定结构**。

不能把：

- 浏览高直接等同精准涨粉强；
- 点赞高直接等同收藏 / 搜索价值强；
- 某个旧爆款直接当成今天必做题型。

小红书本平台自己的历史数据，优先级高于外部 benchmark。

## 7 个视频合集与抖音大号的关系

七个视频合集与抖音大号使用同一套栏目定位、选题逻辑与事实标准：

- 文物 → `01-抖音大号/文物.md`
- 异录 → `01-抖音大号/异录.md`
- 辨伪 → `01-抖音大号/辨伪.md`
- 残页 → `01-抖音大号/残页.md`
- 隐理 → `01-抖音大号/隐理.md`
- 世问 → `01-抖音大号/世问.md`
- 牌记 → `01-抖音大号/牌记.md`

同时遵守：

- `01-抖音大号/统一交付规则.md`
- `00-系统总控/Suen统一文笔总则.md`
- `00-系统总控/文笔成稿验收协议.md`
- `99-模板/视频类统一交付格式.md`

## 视频交付格式

凡是小红书发布的视频需要输出“口播 / 台词 + 对应图片 / 画面”，统一使用 2026-09-17 最终确认样式：

- 当前界面支持时：**左边完整口播 / 台词，右边直接显示对应图片**；
- 当前界面不支持稳定双栏嵌图时：**一段完整口播 → 紧跟对应图片 → 下一段完整口播 → 紧跟对应图片**；
- 不默认增加时间列；
- 不用素材编号 / 文件名代替图片本身；
- 不把图片统一堆到最后；
- 不要求 Suen 打开 ZIP / TXT 才能完成素材匹配；
- ZIP、原图包、来源表只能是可选附件。

完整执行统一读取 `99-模板/视频类统一交付格式.md`。

## 跨平台发布

- 抖音与小红书可以发布**同一支完整视频**。
- 默认不为了“平台适配”机械重剪、改口播或重新生成第二版。
- 只有当商业总控明确认为标题、封面或文案需要针对小红书搜索 / 推荐做调整时，才调整外围包装；不改动已经验证过的内容主体。
- 当天是否需要改为《长卷》或其它独立内容，由商业总控按实际任务判断。
- **“优先同步”不等于“小红书永远只是抖音镜像”。** 如果小红书自己的第一方历史数据、搜索需求或平台任务明确支持一条独立内容，而且其价值足以覆盖额外制作成本，总控可以安排独立小红书任务；仍需服从 P0 / P1 工作量排序。

## 同一视频的实际执行方式

如果当天商业总控决定“小红书直接同步抖音大号同一支成片”：

**这只算一个制作任务。**

不要再创建第二个“小红书视频制作”提示词，也不要让 Suen 在两个对话里重复做同一条视频。

直接在当天对应的抖音栏目专用对话里，一次完成：

1. 抖音完整成片；
2. 小红书标题候选；
3. 小红书封面文字；
4. 小红书发布配文。

视频主体沿用同一份“完整口播 ↔ 直接图片”主交付，不再另做素材表或逐镜头表。

《长卷》仍然使用自己的独立专用对话，因为它是独立研究型长文产品，不属于视频同步工作流。

## 《长卷》

《长卷》不是上述视频栏目的文字版，也不负责替视频栏目写脚本。

它是小红书独立研究型长文合集，完整规则见 `长卷.md`。研究深度、图文一体、真实资料与事实核查要求独立执行。

## 内容与商业

小红书承担搜索、专业信任、实物 / 服务兴趣与询盘，但具体某一天是否出现商业信号由商业总控决定。被指定为纯内容时，不自行增加预约、购买、私信等 CTA。
