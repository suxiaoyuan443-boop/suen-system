# 小红书｜前台合集结构

状态：当前正式规则
最后核对：2026-09-17

## 当前前台合集

小红书当前共有 **7 个视频前台合集 + 1 个独立长文合集《长卷》**：

1. `文物`
2. `异录`
3. `辨伪`
4. `残页`
5. `隐理`
6. `世问`
7. `牌记`
8. `长卷`（独立研究型长文）

`口述` 不作为前台合集名，只保留为内部内容形式 / 母类。

## 当前发布基线

小红书当前实际基线是：**每天 1 篇 / 1 条内容。**

通常优先直接同步当天抖音大号同一支完整成片，再针对小红书调整标题、封面文字与发布配文。

这里的“每天1篇”不等于《长卷》每天更新：

- 视频内容可以承担当天小红书更新；
- 《长卷》是独立研究型长文，不机械日更；
- 如果商业总控基于真实数据、平台状态、工作量或当天明确指令决定某天小红书停更，可以例外，但需要有实际理由。

## 7 个视频合集与抖音大号的关系

七个视频合集与抖音大号使用同一套栏目定位、选题逻辑与事实标准：

- 文物 → `01-抖音大号/文物.md`
- 异录 → `01-抖音大号/异录.md`
- 辨伪 → `01-抖音大号/辨伪.md`
- 残页 → `01-抖音大号/残页.md`
- 隐理 → `01-抖音大号/隐理.md`
- 世问 → `01-抖音大号/世问.md`
- 牌记 → `01-抖音大号/牌记.md`

同时遵守：

- `01-抖音大号/统一交付规则.md`
- `00-系统总控/Suen统一文笔总则.md`
- `00-系统总控/文笔成稿验收协议.md`
- `99-模板/视频类统一交付格式.md`

## 视频交付格式

凡是小红书发布的视频需要输出“口播 / 台词 + 对应图片 / 画面”，统一使用 2026-09-17 最终确认样式：

- 当前界面支持时：**左边完整口播 / 台词，右边直接显示对应图片**；
- 当前界面不支持稳定双栏嵌图时：**一段完整口播 → 紧跟对应图片 → 下一段完整口播 → 紧跟对应图片**；
- 不默认增加时间列；
- 不用素材编号 / 文件名代替图片本身；
- 不把图片统一堆到最后；
- 不要求 Suen 打开 ZIP / TXT 才能完成素材匹配；
- ZIP、原图包、来源表只能是可选附件。

完整执行统一读取 `99-模板/视频类统一交付格式.md`。

## 跨平台发布

- 抖音与小红书可以发布**同一支完整视频**。
- 默认不为了“平台适配”机械重剪、改口播或重新生成第二版。
- 只有当商业总控明确认为标题、封面或文案需要针对小红书搜索 / 推荐做调整时，才调整外围包装；不改动已经验证过的内容主体。
- 当天是否需要改为《长卷》或其它独立内容，由商业总控按实际任务判断。

## 同一视频的实际执行方式

如果当天商业总控决定“小红书直接同步抖音大号同一支成片”：

**这只算一个制作任务。**

不要再创建第二个“小红书视频制作”提示词，也不要让 Suen 在两个对话里重复做同一条视频。

直接在当天对应的抖音栏目专用对话里，一次完成：

1. 抖音完整成片；
2. 小红书标题候选；
3. 小红书封面文字；
4. 小红书发布配文。

视频主体沿用同一份“完整口播 ↔ 直接图片”主交付，不再另做素材表或逐镜头表。

《长卷》仍然使用自己的独立专用对话，因为它是独立研究型长文产品，不属于视频同步工作流。

## 《长卷》

《长卷》不是上述视频栏目的文字版，也不负责替视频栏目写脚本。

它是小红书独立研究型长文合集，完整规则见 `长卷.md`。研究深度、图文一体、真实资料与事实核查要求独立执行。

## 内容与商业

小红书承担搜索、专业信任、实物 / 服务兴趣与询盘，但具体某一天是否出现商业信号由商业总控决定。被指定为纯内容时，不自行增加预约、购买、私信等 CTA。
