# 阿赫特之门｜公众号

状态：当前正式规则
最后核对：2026-09-23

## 定位

`阿赫特之门` 是研究资料库型公众号。核心是回到原始文本、手稿、文物、版本、咒文与仪式要求，把一个真实对象、真实文本或真实历史问题讲清楚。

专业感来自具体原典、馆藏、手稿、版本、原文、动作和资料链，不来自术语堆砌。

完整语言与成稿规范见：`公众号文笔规则.md`。

---

## 公众号专属对标

当前已经重新建立公众号专属对标体系，完整规则见：`公众号对标体系.md`。

### 一级主对标

- **利维坦**：奇异真实对象、标题入口、陌生读者点击与图文节奏
- **国家人文历史**：历史叙事、人物/事件入口、时间线与大众化解释
- **看理想**：人文标题、编辑感、长内容入口与整体品牌气质
- **轻疯说道**：中文玄学/宗教/神秘事件的现实问题、热点与普通读者问题意识

### 二级辅助对标

- **文化纵横**：只参考深度长文的论证结构、历史语境与学者观点组织，不参考宏观政策评论腔

对标只学具体能力，不复制人格、文风、结论或商业包装。

`穹印之源 / ESOTERICA / Angela Puca / Foolish Fish / Let’s Talk Religion` 仍属于整个商业内容系统的高层对标，见系统总控层规则，不与公众号专属对标混用。

## 2026-09-16 之后的发布结构

旧规则“每次更新固定生成 1 篇 7000+ 长文 + 1 篇贴图”已经覆盖。

现在必须把 **贴图** 与 **长文** 当成两种不同产品分别判断。

### 贴图

承担：

- 陌生流量
- 微信推荐测试
- 新用户第一次认识阿赫特之门
- 轻量专业认知
- 分享与自然关注
- 搜一搜补充入口

### 长文

承担：

- 深度资料资产
- 专业背书
- 搜一搜长期积累
- 可长期回看、引用和沉淀的研究内容
- 未来高意向读者的深入阅读入口

两类内容不能用同一套阅读基线判断，也不能因为贴图有推荐流量就推断长文同样获得分发。

当前阶段更准确的理解是：

**贴图已经进入推荐测试；长文仍未形成稳定自然分发。**

---

## 更新时怎么决定发什么

Suen 自 2026-09-23 起明确要求：**公众号恢复每日更新。**

每日更新指：
- 正常运营日默认至少发布 1 个公众号内容产品；
- 贴图 / 长文仍然分别判断，不恢复旧的“每天固定 1 长 + 1 贴”；
- 当天可以只发贴图、只发长文，或在确有价值时两者都发；
- 只有 Suen 当天明确暂停，或出现真实客观阻塞（核心事实无法核实、关键素材无法合法取得、生产时间被更高优先级真实事件完全占用）时，才允许当天暂缓，并必须写清原因；
- “今天很忙”“昨天刚发过”“没有从现成选题池找到题”本身都不再构成停更理由；总控需要主动寻找合格新题。

商业总控结合最近几天的公众号真实数据、最近发布题材、内容空窗和当天任务，判断当天到底发贴图还是长文。

**没有适合长文的强题时，优先用合格贴图维持日更，不为了日更机械产出 7000 字长文。**

长文如果持续低阅读，先测试：

- 标题
- 封面
- 入口
- 开头理解成本
- 题材结构
- 贴图向长文的自然导流

不能因为短期低阅读立刻把深度长文缩短成普通短内容。

# 未来 14 天自然分发测试

从 2026-09-16 起，贴图与长文分开记录和判断。

## 测试原则

- 未来 14 天不做抽奖等额外刺激，先观察自然分发与自然阅读；
- 长文与贴图分别建立自己的数据基线；
- 不用一类内容的数据证明另一类内容有效；
- 不把抽奖带来的增长、消息或关注当成自然内容表现。

## 阶段复核时间

这是一套**阶段性冷启动测试规则**，不是永久基线。

- 测试起点：2026-09-16
- 第一轮复核点：约 2026-09-30

到第一轮 14 天测试结束后：

- 重新读取这 14 天真实贴图 / 长文数据；
- 重新计算贴图普通水平和较好表现区间；
- 判断长文是否已经从 4—5 阅读进入新的稳定基线；
- 判断长文频率、长度、题材形式和贴图导流是否需要调整；
- 不把下方 100 / 200 / 300 / 500 / 1000 等冷启动分档自动永久沿用。

如果届时还没有完成正式复盘，应把这些数字视为“上一阶段参考”，不能假装仍是最新基线。

## 抽奖数据清洗

抽奖期间产生的：

- 主动消息
- 新增关注
- 活动型互动

必须与自然内容增长分开看。

**抽奖用户主动发消息 ≠ 自然咨询。**

**抽奖期关注增长 ≠ 自然内容转粉。**

以后复盘应尽量区分：

- 抽奖增长
- 自然内容增长

不能用抽奖数据证明公众号已经建立自然转化能力。

# 贴图阶段基线

以下只适用于当前冷启动阶段的**贴图 / 轻内容**，账号增长后需要重新计算。

### 9/25中途校准

9/25后台已补齐5条近期贴图当前累计：61 / 66 / 80 / 85 / 132阅读，中位约80。

因此从9/25到9/30正式复盘前：
- **约60—130阅读**：当前最近一组真实自然区间；
- **约80阅读**：这5条当前中位，只作临时比较；
- 原先“约100阅读为普通水平”降为上一阶段参考，不再单独作为最新判断基准；
- 150+ 仍可视为明显高于这组近期样本，但必须结合推荐来源、搜一搜与发布时间判断；
- 9/30按完整14天数据正式重算，不提前把5条样本固化成长期KPI。

旧阶段分档保留作历史参考：
- 150—200：明显高于旧冷启动普通水平；
- 200—300：旧阶段较好；
- 300+：重点复盘；
- 500+：可能突破现有推荐池；
- 1000+：现阶段真正的小爆款。

这些数字不是永久 KPI，只是当前阶段内部判断标准。

## 阅读来源口径补充｜2026-09-25

“自然流量”不是公众号后台里一个可以直接拿到的单一指标，后续不再把它作为一个总字段要求 Suen 提供。

如果后台能看到阅读来源，按实际渠道分开记录：
- 推荐 / 看一看等算法分发：记为**推荐发现流量**；
- 搜一搜：记为**搜索流量**；
- 好友转发 / 群 / 朋友圈：记为**社交传播流量**；
- 公众号消息 / 会话、历史消息、主页等：记为**已有账号资产 / 粉丝承接流量**；
- 后台只显示“其他”时保留“其他”，不擅自拆成搜一搜或推荐。

这些来源只用于判断文章阅读从哪里来，**不能反推询盘来源**。客户询盘只有在客户本人、聊天上下文或可靠链路明确说明来源时才归因到具体平台 / 内容。

## 贴图每篇记录

优先记录：

- 24 小时阅读
- 推荐阅读 / 推荐来源
- 分享
- 文章页自然关注
- 搜一搜阅读 / 来源

如果平台暂时拿不到某项数据，明确写“未找到 / 不知道”，不估算。

## 贴图选题逻辑

贴图优先寻找：

**真实文物 / 手稿 / 原始材料 + 一个具体且奇怪的对象、行为或现象 + 普通人无需预备知识就能理解的问题。**

贴图的第一问题始终是：

> 陌生人为什么会点开？

# 长文章阶段基线

长文章当前现实起点约为：

**长期 4—5 阅读。**

因此不能和贴图使用同一阅读 KPI。

未来 14 天长文第一目标不是追求 200、300 阅读，而是观察能否逐步进入：

- **10+**
- **20—30 稳定**
- **50+**

如果经过标题、入口、选题结构等前台优化后，长文仍连续维持个位数阅读，必须重新评估：

- 长文发布频率
- 文章长度
- 选题形式
- 是否需要每天发布
- 是否更适合作为非日更深度资产

不能因为旧规则曾经要求“每天一篇 7000 字”就机械继续。

## 长文每篇单独记录

优先记录：

- 24 小时阅读
- 推荐来源是否出现
- 搜一搜阅读 / 来源
- 分享
- 文章页自然关注
- 是否获得贴图导流
- 后续持续阅读 / 后续新增阅读

平台能看到深度阅读或收藏等长期价值指标时，也可补充记录。

## 长文不等于简单缩短

当前不能直接得出：

> “长文章没人看，所以必须缩短。”

未来 14 天先测试：

- 标题
- 封面
- 选题入口
- 开头理解成本
- 题材结构
- 与贴图之间的导流关系

如果前台入口优化后仍持续个位数，再进一步测试：

- 降低发布频率
- 缩短部分文章
- 分层内容长度
- 把部分 7000 字长文改为专题深度内容

# 贴图与长文的关系

当前更适合采用：

**贴图 = 前台入口**  
**长文 = 深度资产**

贴图负责让陌生人第一次认识阿赫特之门。

长文负责让已经产生兴趣的人继续深入。

如果某个贴图题材表现较好，可以判断它是否值得延伸成长文章，但：

- 不机械把每篇贴图都扩成长文；
- 同一天不要让贴图和长文重复讲完全相同的内容；
- 长文必须有“为什么值得继续深入”的明确理由。

## 与抖音 / 小红书的选题分工

从 2026-09-24 起，公众号**默认不消耗抖音大号 / 小红书的高上限短视频题**。

总控在公众号定题前先做一次平台价值判断：

### 优先留给抖音大号 + 小红书
如果一个题同时具备：
- 陌生人一听就懂的现实冲突 / 强反差；
- 第一屏有明显真实对象或异常细节；
- 不需要大量背景知识；
- 有机会承担 A｜流量或 B｜精准涨粉；
- 适合做成同一支短视频跨抖音 + 小红书复用；

默认先进入抖音大号 / 小红书候选或正式定题，不因为公众号需要日更就先把它用掉。

### 更适合公众号
公众号优先吃：
- 原文 / 手稿 / 版本里的具体细节；
- 对冷流量入口不够强、但资料价值高的问题；
- 需要较多上下文才能讲清的研究点；
- 窄题材、档案型、资料库型内容；
- 已经不适合占短视频唯一主发布位、但值得沉淀的研究；
- 同一大研究对象中**与短视频不同价值层**的延伸。

### 同一对象跨平台
原则上当天题材分开。

如果同一研究对象确实值得跨平台：
- 抖音 / 小红书负责最强入口与短视频核心问题；
- 公众号必须提供明显不同的新价值层，例如完整原文、版本差异、长链证据或短视频放不下的细节；
- 不能把同一题换个标题重复发。

**公众号日更不能反过来消耗短视频爆款候选池。**

# 公众号选题判断顺序

无论贴图还是长文，先问：

1. 陌生人能不能立即理解对象是什么；
2. 这个对象有没有具体异常、奇怪行为、视觉特征或明确问题；
3. 是否有可靠原始资料可以支撑；
4. 更适合做贴图还是长文；
5. 如果做长文，为什么值得读者继续深入。

不能从“这份资料很好”直接推导成“它适合公众号发布”。

好资料不自动等于好选题。

# 公众号图片交付硬规则

图片是证据和阅读结构的一部分，不是装饰。

无论贴图还是长文，正式使用的关键图片原则上都要给：

- **HTTPS 图片直链**；
- **来源页**；
- **自然图注**；
- **正文插入位置**；
- 能取得时给名称、编号、年代、馆藏 / 项目。

### 直链技术验证

正式交付前，关键图片直链需要尽量实际核验：

- URL 可以打开；
- 返回的内容确实是图片 MIME，而不是 HTML 页面 / 跳转错误；
- 图片可以正常解码；
- 能取得时核对实际尺寸 / 像素，避免给缩略图冒充高清图；
- 如果微信编辑器中已知无法插入，则不能继续把它当成“可直接使用”的最终图链。

如果拿不到可靠可用的直链：

- 明确写“缺图 / 当前未取得稳定直链”；
- 仍可提供来源页供人工下载；
- 不用无关文物、AI 图或相似图片补位。

### 局部图与整页图

- 局部裁切必须明确说是局部；
- 单个符号、单行文字或局部细节不能标成“整页手稿 / 完整原页”；
- 如果正文讲整页结构，优先先给整页，再给局部放大。

### 已知微信兼容问题

`blogs.reed.edu` 曾有图片在微信编辑器中插入失败。

如果以后继续使用该来源，必须重新实际验证当前直链和微信可用性，不能因为网页浏览器能打开就默认微信一定能插入。

# 贴图内容规则

## 选题

贴图必须围绕一个具体对象或问题，尽快让普通读者知道：

- 这是什么
- 用来做什么
- 最值得看的奇怪/关键细节是什么

优先使用真实文物、手稿、纸草、原始书页、历史图像等有证据主体的题目。

## 篇幅

**标题 + 正文 + 图注 + 必要资料来源，总量控制在 800 字以内。**

优先约 **650—750 字**，给微信编辑器留余量。

## 当前交付形式

贴图内容按 **纯文本稿 + 独立主图/图片素材** 交付。

**贴图不要求一键复制 HTML。**

正式交付至少给：

- 标题
- 正文
- 必要图注
- 必要资料来源
- 主图/配图
- 图片来源页与可打开链接

## 图片

图片必须真实对应正文，不为了“有图”使用相似但无关的文物。

每张关键图继续执行上面的“公众号图片交付硬规则”。

AI 图不能冒充真实文物、手稿或历史现场。

# 深度长文规则

## 篇幅

实际生成完整长文时，默认仍按 **7000 字以上**的深度方向执行，但字数不能替代信息密度。

每一部分都要继续增加新证据、原文、案例、动作或解释，不用重复核心结论凑长度。

## 选题门槛

长文需要有一个可以真正跑通的具体研究对象，例如：

- 一段明确编号和行号的原典
- 一份具体手稿
- 一件文物
- 一个完整 recipe
- 一个版本差异
- 一个能够沿证据链追下去的具体仪式或历史问题

不能只做宽泛“介绍”。

## 内容最低要求

文章要让读者真正看懂一次“这个系统怎么运行”。

涉及仪式时，能取得资料的情况下需要尽量讲清：

- 对象是什么
- 谁使用
- 目的
- 时间
- 材料
- 动作
- 顺序
- 原文依据
- 关键术语
- 因果/仪式逻辑
- 版本问题
- 哪些地方能确定
- 哪些地方仍不确定

不擅自把现代流程补成古代原仪式。

## 原文与资料

能够取得时，尽量具体到：

- 文本 / 手稿 / 纸草 / 文物编号
- 页码 / folio / 行号
- 原文或 transliteration
- working translation
- 中文译文
- 可靠校勘版或学术出版
- 真实扫描或馆藏图

## HTML

**长文继续提供一键复制 HTML 排版。**

复制到公众号后应尽量保持层级与格式；正式使用的图片必须能打开，并继续执行上面的图片技术验证规则。

---

## 最终发布文风

完整规则读取 `公众号文笔规则.md`。

最重要的底线：

- 最终稿完全站在普通读者视角；
- 不出现作者第一人称表演；
- 不出现内部制作/编辑语言；
- 不使用明显 AI 式开头；
- 不连续堆“不是 / 不能 / 并不 / 不等于”等反驳句式；
- 不一句一段；
- 不用空泛升华收尾；
- 每一部分持续增加真实信息；
- 读完必须知道对象实际是什么、怎么用或怎么运作。

## 商业边界

公众号当前阶段暂时不以私信 / 成交作为核心 KPI。

当前优先：

- 贴图：扩大自然推荐和陌生阅读
- 长文：建立高质量深度资产并测试自然分发能力

是否承载商业信号仍由商业总控当天决定。

如果当天被指定为纯内容：

- 不接单
- 不报价
- 不预约
- 不引导购买
- 不强行加微信/私信 CTA

公众号首先是深度信任与资料资产，不为了短期商业转化破坏内容定位。
