# 阿赫特之门｜公众号

状态：当前正式规则
最后核对：2026-10-16

## 定位

`阿赫特之门` 是研究资料库型公众号。核心是回到原始文本、手稿、文物、版本、咒文与仪式要求，把一个真实对象、真实文本或真实历史问题讲清楚。

专业感来自具体原典、馆藏、手稿、版本、原文、动作和资料链，不来自术语堆砌。

完整语言与成稿规范见：`公众号文笔规则.md`。

---

## 公众号专属对标

当前已经重新建立公众号专属对标体系，完整规则见：`公众号对标体系.md`。

### 一级主对标

- **利维坦**：奇异真实对象、标题入口、陌生读者点击与图文节奏
- **国家人文历史**：历史叙事、人物/事件入口、时间线与大众化解释
- **看理想**：人文标题、编辑感、长内容入口与整体品牌气质
- **轻疯说道**：中文玄学/宗教/神秘事件的现实问题、热点与普通读者问题意识

### 二级辅助对标

- **文化纵横**：只参考深度长文的论证结构、历史语境与学者观点组织，不参考宏观政策评论腔

对标只学具体能力，不复制人格、文风、结论或商业包装。

`穹印之源 / ESOTERICA / Angela Puca / Foolish Fish / Let’s Talk Religion` 仍属于整个商业内容系统的高层对标，见系统总控层规则，不与公众号专属对标混用。

## 2026-09-16 之后的发布结构

旧规则“每次更新固定生成 1 篇 7000+ 长文 + 1 篇贴图”已经覆盖。

现在必须把 **贴图** 与 **长文** 当成两种不同产品分别判断。

### 贴图

承担：

- 陌生流量
- 微信推荐测试
- 新用户第一次认识阿赫特之门
- 轻量专业认知
- 分享与自然关注
- 搜一搜补充入口

### 长文

承担：

- 深度资料资产
- 专业背书
- 搜一搜长期积累
- 可长期回看、引用和沉淀的研究内容
- 未来高意向读者的深入阅读入口

两类内容不能用同一套阅读基线判断，也不能因为贴图有推荐流量就推断长文同样获得分发。

具体分发状态读取 `08-动态运行/内容台账/公众号-历史基线.md` 与当前发布数据；历史小样本不自动当作最新结论。

## 更新时怎么决定发什么

### 2026-10-16｜公众号日更偏好

Suen明确“公众号最好也日更”。正常运营默认每天安排1次合格公众号更新；此前总控提出的“一周两次、一轻一深”试排退出当前安排。日更是当前发布偏好，尚无本账号同条件数据证明频率本身提高增长或获客。

### 同日后续确认｜独立题材与深度文章优先

Suen在看到13针人偶配方比较贴图后明确退回：公众号题材应与已发视频不同，公众号应是有含金量的深度内容。本次确认覆盖同日较早“轻图文可承担日常更新”的默认排法。

正常日更默认交付独立选题的深度研究文章，篇幅服从问题和证据；不设固定7000字或以篇幅替代解释。贴图规则保留供Suen明确要求的辅助产品使用，不自动拿800字以内贴图充当当天深度主文，不把日更理解为降低产品深度。确有质量或产能阻塞时如实记待完成与原因，不交一篇摘要作为已完成的替代品。

公众号承担深度解释、可信资料与可回看的资产。可复用已核对的资料、版本或来源路径降低研究成本，文章的核心对象、文本和问题仍须独立于已发或已定视频；不得把视频余料、补充几条差异或更换标题当成独立选题。继续执行下方跨平台去重、原典、文笔和图片交付门。

总控每天给出公众号具体发布落点及稿件状态，纳入实际产能和制作时间；不能以“按需”或“以后补”长期略过。主视频仍先保护一份新剪制作，不因三平台日更强制另剪第二支视频；课程/知识产品、数据库受保护时间与已付款履约保持。

确有现金安全、已付款履约、必要休息、核心事实/图片许可/质量阻塞且无合格替代时，允许当日例外；写明实际缺项与下一动作，不把例外变成默认停更，不产生补更债，不降低内容标准。短期低阅读也不自动成为削掉深度的依据。

需要调整入口时，检查标题、封面、开头理解成本、具体问题及贴图向长文的合理衔接；使用平台自己的数据，不套抖音基线。

# 长文章阶段基线

本节保留9/25历史观察与当时测试思路，不覆盖10/16后续确认的独立题材、深度主文与正常日更安排；频率或产品定位调整需另据新事实和Suen指令判断。

截至9/25，近期5篇可确认长文阅读为 **3 / 3 / 4 / 5 / 22**。

因此当前更准确的起点是：

**多数长文仍在个位数，但已经出现20+的单篇。**

长文不能和贴图使用同一阅读 KPI，也不能继续把“4—5阅读”写成所有长文的固定水平。

当前测试目标继续观察能否逐步进入：

- **10+**
- **20—30 稳定**
- **50+**

如果经过标题、入口、选题结构等前台优化后，长文仍连续维持个位数阅读，必须重新评估：

- 长文发布频率
- 文章长度
- 选题形式
- 是否需要每天发布
- 是否更适合作为非日更深度资产

不能因为旧规则曾经要求“每天一篇 7000 字”就机械继续。

## 长文每篇单独记录

优先记录：

- 24 小时阅读
- 推荐来源是否出现
- 搜一搜阅读 / 来源
- 分享
- 文章页关注 / 关注来源
- 是否获得贴图导流
- 后续持续阅读 / 后续新增阅读

平台能看到深度阅读或收藏等长期价值指标时，也可补充记录。

## 长文不等于简单缩短

当前不能直接得出：

> “长文章没人看，所以必须缩短。”

未来 14 天先测试：

- 标题
- 封面
- 选题入口
- 开头理解成本

- 与贴图之间的导流关系

如果前台入口优化后仍持续个位数，再进一步测试：

- 降低发布频率
- 缩短部分文章
- 分层内容长度
- 把部分 7000 字长文改为专题深度内容

# 贴图与长文的关系

当前更适合采用：

**贴图 = 前台入口**

贴图负责让陌生人第一次认识阿赫特之门。

如果某个贴图题材表现较好，可以判断它是否值得延伸成长文章，但：

- 不机械把每篇贴图都扩成长文；
- 同一天不要让贴图和长文重复讲完全相同的内容；
- 长文必须有“为什么值得继续深入”的明确理由。

## 与抖音 / 小红书的选题分工

从 2026-09-24 起，公众号**默认不消耗抖音大号 / 小红书的高上限短视频题**。

总控在公众号定题前先做一次平台价值判断：

### 优先留给抖音大号 + 小红书
如果一个题同时具备：
- 陌生人一听就懂的现实冲突 / 强反差；
- 第一屏有明显真实对象或异常细节；
- 不需要大量背景知识；
- 有机会承担 A｜流量或 B｜精准涨粉；
- 适合做成同一支短视频跨抖音 + 小红书复用；

适合短视频的强入口先比较主生产单元，不为了填公众号频次先消耗它。

### 更适合公众号
公众号优先吃：
- 原文 / 手稿 / 版本里的具体细节；
- 对冷流量入口不够强、但资料价值高的问题；
- 需要较多上下文才能讲清的研究点；
- 窄题材、档案型、资料库型内容；
- 已经不适合占短视频唯一主发布位、但值得沉淀的研究；
- 同一传统或研究领域中，核心对象、原典和所回答问题独立于视频的研究题。

### 跨平台去重｜2026-10-16 Suen后续确认

公众号定题须同时核对已取得的公众号历史、视频已发布清单及已锁定待生产题；去重不只看当天或最近7天。

- 对照核心文物/人物/历史事件、文本编号/段落、读者问题与文章答案，不能只对照标题。
- 已发或已定视频的同一核心对象、文本段落或问题，默认不再选作公众号主文；“补充细节、换一个角度、比较配方、加长原文”不能自动豁免。若Suen另行明确要求同题深写，才按该次指令处理，不把一次许可变为常态。
- 同属古埃及、同一神明传统或同一类仪式不自动算重复；文章需有独立的具体对象/原典/问题，而不是换成空泛大题。已发对象可作必要的辅助比较，不能继续充当主角和入口。
- 同时核公众号自己的旧稿；历史明细或旧文正文缺失时明确检索范围和缺口，不声称“全账号未发过”。已知重复者直接退回，不以记录缺口放行。
- 内部定题回执须写：本篇主对象/文本/问题、与最近及相关已知视频的区别、与公众号旧文的区别、核心史料与需要深入解释的具体内容。先通过这些门，再定题和写稿。

**公众号独立生产研究文章；新研究抖音与小红书仍可同步同一主视频。跨平台去重不等于三平台都要生产不同视频。**

# 公众号选题判断顺序

无论贴图还是长文，先问：

1. 陌生人能不能立即理解对象是什么；
2. 这个对象有没有具体异常、奇怪行为、视觉特征或明确问题；
3. 是否有可靠原始资料可以支撑；
4. 更适合做贴图还是长文；
5. 如果做长文，为什么值得读者继续深入。

不能从“这份资料很好”直接推导成“它适合公众号发布”。

好资料不自动等于好选题。

# 公众号图片交付硬规则

图片是证据和阅读结构的一部分，不是装饰。

无论贴图还是长文，正式使用的关键图片原则上都要给：

- **HTTPS 图片直链**；
- **来源页**；
- **自然图注**；
- **正文插入位置**；
- 能取得时给名称、编号、年代、馆藏 / 项目。

### 直链技术验证

正式交付前，关键图片直链需要尽量实际核验：

- URL 可以打开；
- 返回的内容确实是图片 MIME，而不是 HTML 页面 / 跳转错误；
- 图片可以正常解码；
- 能取得时核对实际尺寸 / 像素，避免给缩略图冒充高清图；
- 如果微信编辑器中已知无法插入，则不能继续把它当成“可直接使用”的最终图链。

如果拿不到可靠可用的直链：

- 明确写“缺图 / 当前未取得稳定直链”；
- 仍可提供来源页供人工下载；
- 不用无关文物、AI 图或相似图片补位。

### 局部图与整页图

- 局部裁切必须明确说是局部；
- 单个符号、单行文字或局部细节不能标成“整页手稿 / 完整原页”；
- 如果正文讲整页结构，优先先给整页，再给局部放大。

### 已知微信兼容问题

`blogs.reed.edu` 曾有图片在微信编辑器中插入失败。

如果以后继续使用该来源，必须重新实际验证当前直链和微信可用性，不能因为网页浏览器能打开就默认微信一定能插入。

# 贴图内容规则

## 选题

贴图必须围绕一个具体对象或问题，尽快让普通读者知道：

- 这是什么
- 用来做什么
- 最值得看的奇怪/关键细节是什么

优先使用真实文物、手稿、纸草、原始书页、历史图像等有证据主体的题目。

## 篇幅

**标题 + 正文 + 图注 + 必要资料来源，总量控制在 800 字以内。**

优先约 **650—750 字**，给微信编辑器留余量。

## 当前交付形式

贴图内容按 **纯文本稿 + 独立主图/图片素材** 交付。

**贴图不要求一键复制 HTML。**

正式交付至少给：

- 标题
- 正文
- 必要图注
- 必要资料来源
- 主图/配图
- 图片来源页与可打开链接

## 图片

图片必须真实对应正文，不为了“有图”使用相似但无关的文物。

每张关键图继续执行上面的“公众号图片交付硬规则”。

AI 图不能冒充真实文物、手稿或历史现场。

# 深度长文规则

## 篇幅

篇幅按问题和证据所需决定，不设默认 7000 字下限。需要完整长链解释时可以写长；资料讲清后结束，不能拉长背景或重复结论凑字数。

每一部分都要继续增加新证据、原文、案例、动作或解释，不用重复核心结论凑长度。

## 选题门槛

长文需要有一个可以真正跑通的具体研究对象，例如：

- 一段明确编号和行号的原典
- 一份具体手稿
- 一件文物
- 一个完整 recipe
- 一个版本差异
- 一个能够沿证据链追下去的具体仪式或历史问题

不能只做宽泛“介绍”。

## 内容最低要求

文章要让读者真正看懂一次“这个系统怎么运行”。

涉及仪式时，能取得资料的情况下需要尽量讲清：

- 对象是什么
- 谁使用
- 目的
- 时间
- 材料
- 动作
- 顺序
- 原文依据
- 关键术语
- 因果/仪式逻辑
- 版本问题
- 哪些地方能确定
- 哪些地方仍不确定

不擅自把现代流程补成古代原仪式。

## 原文与资料

能够取得时，尽量具体到：

- 文本 / 手稿 / 纸草 / 文物编号
- 页码 / folio / 行号
- 原文或 transliteration
- working translation
- 中文译文
- 可靠校勘版或学术出版
- 真实扫描或馆藏图

## HTML

**长文继续提供一键复制 HTML 排版。**

复制到公众号后应尽量保持层级与格式；正式使用的图片必须能打开，并继续执行上面的图片技术验证规则。

## 最终发布文风

完整规则读取 `公众号文笔规则.md`。

最重要的底线：

- 最终稿完全站在普通读者视角；
- 不出现作者第一人称表演；
- 不出现内部制作/编辑语言；
- 不使用明显 AI 式开头；
- 不连续堆“不是 / 不能 / 并不 / 不等于”等反驳句式；
