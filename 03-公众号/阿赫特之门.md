# 阿赫特之门｜公众号

状态：当前正式规则
最后核对：2026-09-17

## 定位

研究资料库型公众号。核心是回到原始文本、手稿、文物、版本、咒文与仪式要求核查。

## 当前发布结构

旧的“每次更新固定 1 篇长文 + 1 篇贴图”不再作为硬规则。

现在由商业总控分别判断：

- **贴图内容**：更偏前端推荐、陌生人触达和轻量进入；
- **长文**：更偏深度资料资产、专业背书与长期沉淀。

同一天可以只安排贴图、只安排长文、两者都安排，或暂缓其中一种。长文不机械日更；如果连续阅读明显偏低，可以降低频率，把长文继续作为深度资产而不是为了日更硬发。

## 长文

实际生成长文时，默认仍以 **7000 字以上**作为完整深度稿方向，但字数不能代替信息密度。

长文必须回到具体文本、手稿、文物、版本或历史问题，保留原始资料并用自然中文重新组织，不把文章写成制作报告或检索日志。

## 贴图

最终发布稿的 **标题 + 正文 + 图注 + 资料来源**整体控制在 800 字以内，优先约 650—750 字，为公众号复制后留余量。

贴图要让读者迅速知道对象是什么、用来做什么、最值得看的细节是什么；不把贴图写成被截断的论文。

## 最终成稿文风

- 完全站在普通读者视角。
- 拒绝明显 AI 味。
- 正文不出现内部制作、编辑、复核、流程或任务语言。
- 禁止“本文将 / 这篇只做一件事 / 本篇后面采用 / 参数钉死 / 完整实例重写版 / 原页阅读训练 / 方便以后核查 / 图片对应正文插入位置”等内部措辞。
- 图片在文章中自然承担证据和阅读功能，不写“图 1 负责解释什么”这类制作说明。
- 避免连续反驳模板、空泛升华和术语堆砌。

## 术语与原文

专业内容优先按具体对象逐层展开。需要呈现外文术语时，可使用：

中文名 → 原文/希腊文等 → 拉丁转写 → 基本解释 → 对应词 → 中文说明

但不为了格式整齐机械堆术语。

## 图片硬规则

每张正式使用的图应提供并核验：

- HTTPS 可访问图片直链
- 来源页面
- 图注
- 正文自然插入位置
- MIME / 文件格式可正常解码
- 尺寸满足公众号使用

缺图要明确说明。不得把单个符号误标成整页文献，不得用 AI 画面冒充真实手稿、文物或历史现场。

## 一键复制 HTML

实际生成的长文和贴图都应同时提供可直接复制到公众号的 HTML 排版版本。复制后应尽量保持层级与排版，图片链接必须实际可打开。

## 商业边界

是否承载商业信号由商业总控当天决定。纯内容日可以完全不接单、不报价、不预约、不引导购买。不要为了转化破坏研究资料库定位。
