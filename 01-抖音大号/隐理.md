# 隐理｜神秘学里没人讲清楚的问题

状态：当前正式规则  
最后核对：2026-09-27

共同文笔、成稿 QA 与完整执行统一读取：`00-系统总控/Suen统一文笔总则.md`。

正式视频交付统一读取：`99-模板/视频类统一交付格式.md`。

本文件只补充本栏目的专属定位、结构、语气与证据要求，不覆盖共同文笔真源。

## 一、核心定位

《隐理》解释：

> **神秘学实践里大家已经默认会做的一步，为什么存在？它实际起什么作用？**

主角是**机制**，不是某件文物、某一段原文、某个人物或某个现实咨询问题。

栏目路由读取：

`栏目选题边界与路由.md`

## 二、两个入选条件

### 1. 去掉具体案例，问题仍然成立

例如：

- 为什么名字在仪式里重要 → 可以成立；
- 为什么很多仪式要先画圈 / 规定位置 → 可以成立；
- 为什么某批具体守护像被埋在某扇门下 → 更像《文物》。

### 2. “为什么”真的有证据答案

标题问“为什么 X”，最终必须能回答：

`因为 Y`

而且 Y 有可靠材料支持。

如果只能证明“这个现象存在”，却解释不了原因，就改题或换栏目。

尤其不要为了回答：

- 偏偏为什么是某个数字；
- 某个材料为什么一定如此；
- 某一步为什么具有某个万能象征

而用现代猜测、泛能量理论或无证据联想补洞。

## 三、优先题型

适合：

- 名字；
- 重复；
- 圆 / 门槛 / 方向；
- 时间；
- 材料；
- 接触、书写、佩戴；
- 供品；
- 临在 / 启用 / 奉献；
- 埋、烧、沉水等处理动作。

不适合：

- 纯现实咨询 / 个人服务原则，没有可证实机制主角 → 不强塞大号，优先小号、朋友圈或适合的小红书内容；
- 稳定对 / 错 → 辨伪；
- 主角是一段原文 → 残页；
- 主角是一件具体对象 → 文物；
- 主角是人物 / 事件时间线 → 异录。

## 四、内容结构

答案尽早出现。

优先顺序：

1. 先给一句核心答案；
2. 说清实际发生了什么；
3. 当时文本 / 实践者怎样理解；
4. 这个动作在该系统里起什么作用；
5. 如果跨时期 / 传统，分别讲清差异；
6. 后世解释有没有变化；
7. 最后只补现代常见混淆，不重新总结整条视频。

每个案例都必须增加新信息。没有新增功能、时期差异、动作或证据的案例删除。

### 四点一、机制深挖硬规则｜2026-09-27

《隐理》不能停在“文本要求这样做 / 实践者会这样做”这一层。标题既然问“为什么”，正文要继续往下追到**该传统自己如何理解这一步为什么会起作用**，直到证据允许的最深一层。

执行时固定检查：

- **操作要求不是机制答案。** 例如“星符还要择时”，不能只回答“因为原典规定要看行星日、行星时和位置”。这些属于操作条件。
- 要继续回答：在该文本的理论里，**天体为什么会和人工物发生关系，材料为什么重要，图形为什么重要，制作发生的那一刻为什么会进入这段关系。**
- 如果证据支持，可以沿着“天体作用 → 下层物质 / 材料的接受 → 图形或形状的对应 → 人工物成形的时刻 → 具体制作动作”往下讲；哪一层没有证据就停在哪一层，不用现代“能量”说法补洞。
- **择时是机制落到操作上的结果，不是整条视频的全部答案。**
- 行星日、行星时、上升位置、相位、目标行星状态等细节，只选真正能证明机制的例子。不要连续多段反复说“什么时候 / 哪个小时 / 在哪里 / 什么位置”。
- 同一种关系讲清一次即可。后面的材料必须增加新的因果层、文本差异或实际动作。
- 原典出现的顺序不等于口播顺序。不要按“第29章 → 第34章 → 第35章”机械讲书；先把机制讲清，再把不同原典放到真正能支撑它的位置。
- 不把每一段都写成“资料一句 + 所以一句总结”。允许证据连续推进，让答案自然长出来，最后再落一次结论。

正式成稿前额外问一句：
> **观众看完以后，得到的是“具体什么时候做”，还是终于明白“为什么这一步会被认为有作用”？**

如果主要记住的是条件清单，说明还写浅了。

## 四点五、开头

《隐理》的前2—5秒优先同时出现两件事：
1. 大家实践里真的会做的那个动作；
2. 这个动作为什么值得问。

例如不要先讲传统背景，再到十几秒以后才说“原来要画圆 / 贴身 / 等时辰”。

可以直接从：
- “为什么仪式开始前要先画一个圆？”
- “护符为什么经常要贴着身体？”
- “图已经刻好了，为什么星符还要等时间？”——**只有在“时间为什么构成这类实践的操作条件”本身有独立、足够范围的机制证据时才成立；如果实际只能围绕 Agrippa 某章 / 某一 recipe 展开，就不能因为题面像机制题而强归《隐理》。**

进入。

如果核心答案本身一句话就能说清，可以在开头很早给出答案方向，不为了留人故意拖到最后。

强度来自**反常实践动作本身**，不额外套“很多人都不知道 / 这背后没那么简单 / 真相其实是”等模板。

### 开头补充｜2026-09-27

- 当正式标题本身已经是一句自然、清楚的问句，**第一句可以直接说标题问句**，然后马上进入答案。
- 默认不要从“我最近在查…… / 我最近在研究…… / 最近做东西的时候……”开始。
- 《隐理》正式口播默认减少第一人称；当天题目如果并不需要 Suen 的个人经历，就不要为了“真人感”硬加研究过程。
- 真人感来自思路自然、词简单、动作具体，不来自模拟“我最近……”的开场口头禅。

## 四点六、栏目漂移红旗｜专用对话必须退件

出现以下任一情况时，停止继续写完整稿，先返回“栏目漂移”：

- 正文主要靠一个作者 / 一本书 / 一段 recipe 的章节顺序推进；
- 为了回答“为什么”，大部分篇幅变成定位原文、翻译句子、解释术语；
- 核心机制不能在不说作者名 / 文本名的情况下先用一句中文讲清；
- 标题范围比证据范围大，例如标题说“行星星符为什么……”，证据实际只够支持 Agrippa 某类 astrological image；
- 去掉当前那一页 / 那一章以后，整条视频就基本无法成立。

处理顺序：
1. 先缩题目范围；
2. 仍然是原文本身最有价值 → 改《残页》；
3. 能建立独立机制、原文只做证据 → 才继续《隐理》。

专用对话不能因为总控已经给了“隐理”标签就机械完成；栏目资格比完成任务更高。

## 四点七、六栏目共用退件原则

《隐理》执行上同时服从六栏目统一规则：总控给出的栏目标签不是不可推翻指令。

如果实际生产后发现主角已经变成具体文物、人物事件、明确真假、具体原文或具体牌局，专用对话必须先退件 / 重路由，不能为了“把任务做完”继续润色。

最终验收仍以：
**删掉任何单一案例以后，机制问题是否仍成立；观众看完最该记住的是否真的是“为什么这一步存在、起什么作用”。**

## 五、跨文化

跨文化比较不等于寻找一个“所有魔法都这样”的共同原理。

古埃及、希腊—埃及、犹太、中世纪、近代仪式魔法、民间实践、现代重构需要按真实材料分别处理。

只有存在传播、翻译、文本借用、人员交流或接受史证据时，才讨论直接影响。

## 六、证据

优先：

- 原始文本；
- 神庙日课；
- 手稿；
- 文物；
- 仪式 recipe；
- 学术研究；
- 有上下文的历史案例。

只有现代 occult 作者解释时，明确写现代解释，不反写成古代通则。

## 七、时长

《隐理》**没有几十秒硬上限**。

已存在 4分44秒成片先例。

常见可落在约 **3—5分钟**，但不是硬卡秒：

- 2分钟讲清就结束；
- 4—5分钟才讲清就保留；
- 优先删重复、背景铺垫和不推进答案的案例，不删核心机制。

前 5—10 秒尽快进入问题和答案方向。

## 八、文笔与执行

共同文笔、正面陈述、具体动作优先、语义去重、中文观众端、不得中途停下来等统一读取：

`00-系统总控/Suen统一文笔总则.md`

本栏目额外要求：

- 正式口播默认不使用第一人称；
- 一个意思只讲一次；
- 每段必须推进新事实 / 动作 / 证据 / 判断；
- **口播优先用普通中文和日常词。** 难懂术语、长外文、章节编号、精确原句优先放图片 / 字幕 / 来源，嘴里只说观众当场能听懂的意思；
- **正式口播优先使用正面陈述。** 除标题本身已经锁定的自然问句、必要原文引用或事实确实需要外，正文不要依赖“不是 / 不能 / 没有 / 并不 / 不等于”推进；
- 不用“边界、空间结构、底层逻辑”等抽象词替代本来能直接说清的动作；
- 不连续使用“所以 / 也就是说 / 这就说明”等总结词给每段收尾；
- 不把每一段都整理成“完整知识点 + 总结句”。以前已经说清的意思，后面直接往下走；
- 跨传统案例用来显示真实差异，不强行统一。

### 真人感与旧稿参照｜2026-09-27

正式生产《隐理》时，如果仓库 / 项目中存在 Suen 已经认可、已经发布或明确认为文笔合格的旧《隐理》成稿，**在写新稿前优先读 1—2 条作为节奏参照**。

参考的是：
- 问题怎样进入；
- 句子有多长；
- 一段怎样自然接下一段；
- 原典怎样插进来；
- 什么时候停，不强行总结。

不机械复制旧题内容，也不让旧稿覆盖当前正式规则。规则负责边界，旧稿负责帮助对齐 Suen 已经认可的真实语感。

### 整稿级返工判断｜2026-09-28

Suen对《隐理》的“很AI”反馈要区分局部和系统性：

- 如果只是个别句子、单段重复、术语难懂 → 局部修；
- 如果整篇句式、组织、重复、抽象总结和推进方式都呈现AI感 → **整篇重写**；
- 如果稿子只停在“文本规定要这样做 / 要择时 / 看行星日、行星时、位置”等操作层，没有继续追到该传统自己的作用机制 → **整篇重写**。

不得用“事实都对，所以只润色”保留一个机制浅或整篇AI的结构。

每次整稿重写必须真正吸收上一轮明确反馈：
- 已指出“机制太浅”，下一版必须改变解释层级；
- 已指出“整篇AI”，下一版必须改变整篇组织与口语节奏，不只是替换词语；
- 已确认合格的事实和证据继续保留，避免无关内容一起漂移。

连续出现多版时，先检查问题为什么反复发生；**不设置机械的整稿重写次数上限**。

### 任务提示词不得替代机制研究｜2026-09-28

总控提示词里的“答案方向、证据分工、开头方向”只算任务线索，不能直接当成成稿结论。

正式写稿前，《隐理》必须先在内部完成机制预演：
- 用一句普通中文回答：这个传统为什么认为这一步会起作用；
- 展开成3—5个连续因果环节；
- 每一环都标出可靠原典或研究依据；
- 区分操作条件、机制解释、后世解释；
- 中间有证据断点就缩小结论，不能用总控提示词里的现成句子补洞。

尤其不能把“文本要求择时”“要看行星日、行星时、位置”“时间是制作条件的一部分”直接当作《隐理》的最终答案。这些最多说明发生了什么。

《隐理》还要继续回答：为什么这个体系认为这些时间条件会参与、改变或赋予这件人工制作物相应的性质或作用。只有机制预演成立后，才进入完整口播。

总控不能用过长任务词替代专用对话自己的研究，也不能预设作者顺序来替代成片结构。

## 九、画面与交付

统一视频格式读取：

`99-模板/视频类统一交付格式.md`

《隐理》额外要求：

- 画面必须跟机制走，不只放氛围图；
- **当前固定采用“一段口播 → 一张对应图片”**。该图片紧跟在这段口播下面；除 Suen 当次明确要求外，不把一段口播再拆成图片组，也不让一张图承担几段口播的匹配任务；
- 原文说到哪一行，就给能直接看清那一行的截图；
- 文物 / 图形 / 手稿细节直接给图片本体；
- **正式图片默认不要画红框 / 红色矩形高亮。** 需要定位时优先用自然裁切、放大、上下文位置和简短图注；只有 Suen 当次明确要求时才加彩色框；
- 不把长网页、PDF入口、馆藏浏览器丢给 Suen 自己找；
- 每个关键判断都能回到相应资料。

正式交付至少让 Suen 直接看到：

- 最早出现的核心答案；
- 需要区分的传统 / 时期；
- 各自的资料依据；
- 现代常见混淆点；
- 每段口播对应的剪辑即用图片；
- **一个明确结尾**：最后落到“所以这一步实际接下来怎么做 / 为什么到这里才算接上完整制作”，不要用模糊升华、抽象总结或重新复述标题结束。

### 去重专项 QA｜2026-09-27

交付前再做一次只针对重复的检查：

- 连续两段是否都在换词说同一个结论；
- 是否三段以上都围着“什么时候 / 哪里 / 什么位置 / 哪个小时”打转；
- 是否每看一份原典都重新说一遍“所以时间很重要”；
- 是否开头已经给过的答案，在中段和结尾又完整复述；
- 是否为了凑时长，把同一套条件拆成多段。

出现以上情况时，直接合并或删除。宁可段落更少，也不要让观众听同一个意思三遍。


## 九点五、标题定稿｜本栏目专属校准

最终标题必须在机制预演已经成立、核心“因为Y”有证据以后再定，并先执行 `00-系统总控/内容商业对标系统.md` 的 benchmark title pass。

《隐理》的标题优先抓**实践里真实存在的一个动作 / 条件 / 处理方式**：
- 标题先让人看到“为什么这一步值得问”，不要先出现抽象理论名词；
- 不强制所有标题都写成“为什么X？”；如果短陈述更像真人说话，就用陈述句；
- 不使用“底层逻辑 / 真正原理 / 背后的机制 / 本质上”等抽象词充当题眼；
- 不把总控内部的机制答案直接改写成标题；
- 如果去掉传统名、作者名以后问题仍然更清楚，优先用普通中文表达，再让原典进正文证明。

本栏目标题优先参考 Angela Puca 的 practice_dispute / explicit_question、穹印之源把复杂机制翻译成普通问题的方式，以及 Suen 自己“画圆”等反直觉实践强样本。

## 十、商业边界

《隐理》主要承担精准涨粉和专业信任。

当题目本身确实有可证实的实践机制时，《隐理》可以承担 C｜服务认知，让观众在理解机制的同时知道 Suen 实际会怎么判断 / 处理。但 C 是任务标签，不改变《隐理》“机制为主角”的栏目标准。

除非商业总控当天明确指定，不自行加入接单、价格、预约或购买 CTA。

## 视频口播可说性硬规则｜2026-09-26

本栏目所有视频口播同时执行 `00-系统总控/Suen统一文笔总则.md` 与 `99-模板/视频类统一交付格式.md` 的“视频口播可说性硬规则”。

额外确认：
- 口播按真实讲话写，不把馆藏说明、论文摘要直接搬进嘴里；
- 难读英文 / 外文优先换成自然中文解释，原词放字幕、图片或来源；
- 馆藏号、墓号、长串编号默认不念；
- 年代、尺寸只保留真正影响理解的数字，不在一句话里连续塞多组数字；
- 交付前按正常语速读一遍，凡是容易卡、需要提前练、像在念资料卡的句子都继续改。



## HTML主交付｜2026-09-27

《隐理》正式视频固定以**单一 HTML 文件**作为主交付。

要求：
- 完整口播段落直接写在 HTML 中；
- 每段口播下面直接显示该段剪辑实际使用的真实图片 / 原页；
- 所有正式素材图必须实际嵌入 HTML，本地离线可见；
- 正式图片使用 `data:image/...;base64`，不能只把远程 HTTPS 地址写进 `<img src>`；
- 来源链接只用于核查，不等于图片交付；
