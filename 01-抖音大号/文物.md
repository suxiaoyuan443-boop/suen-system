# 文物｜原版资料讲解型

状态：当前正式规则
最后核对：2026-09-21

共同文笔、成稿 QA 与完整执行统一读取：`00-系统总控/Suen统一文笔总则.md`。

正式视频交付统一读取：`99-模板/视频类统一交付格式.md`。

本文件只补充本栏目的专属定位、结构、语气与证据要求，不覆盖共同文笔真源。

## 核心定位

《文物》是“带观众一起看真实资料”的栏目。

资料本身始终是主角：文物、博物馆页面、原始书页、纸草、手稿、历史图像、馆藏记录。Suen 的人物画面只负责带看和解释，不抢资料主体。

这个栏目不是“讲一个神秘学知识点然后随便配几张古埃及图”，而是从一件真实对象出发，让观众知道：

- 眼前这件东西是什么；
- 它来自哪里、什么年代；
- 哪些细节值得看；
- 这些细节和它的实际用途有什么关系；
- 现存证据能支持到什么程度。

完整栏目路由统一读取：`栏目选题边界与路由.md`。

## 选题边界硬判断

《文物》的主角是**具体真实对象本身**。

判断时优先问：

> **把这件具体对象拿掉以后，这个问题还成立吗？**

如果基本不成立，通常就是《文物》。

因此《文物》不仅能讲“这是什么”，也可以讲：

- 为什么这件东西长这样；
- 为什么有这个结构 / 图像 / 铭文；
- 为什么会被放在这个位置；
- 为什么会这样使用；
- 某个具体细节说明了什么；
- 一个具体对象的奇怪用途、异常位置与历史做法。

例如：

- “为什么新亚述人把这些守护小像埋在门下面？” → 《文物》
- “为什么这个护符上有两个孔？” → 《文物》
- “为什么这尊像底部刻了这句话？”如果核心仍是对象结构与用途 → 《文物》

即使内容里包含仪式机制，只要观众的入口、画面主体和最终记忆仍然围绕**这一件 / 这一类具体对象**，就优先归《文物》，不要因为题目里出现“为什么”就改塞《隐理》。

## 与《残页》《隐理》的区别

### 文物

重点是**对象整体**：一件文物、一页馆藏记录、一件护符、一块石碑、一幅历史图像。

讲清它是什么、怎么用、哪些视觉细节能说明用途。

### 残页

重点是**具体文本和句子**：逐行、逐段拆原文、译文、关键词、版本和争议。

如果一条内容需要连续逐句翻译和解释，优先归《残页》；如果重点是带观众观察一件对象，归《文物》。

### 隐理

重点是**去掉具体对象以后仍然成立的底层机制**。

例如“为什么名字在仪式里重要”可以跨多个具体案例继续成立，属于《隐理》。

如果问题只围绕某一件对象“为什么这样放 / 这样刻 / 这样用”，优先《文物》。

## 选题优先级

优先：

- 有清晰馆藏信息的真实文物；
- 视觉上有可观察细节的对象；
- 用途明确但普通观众不容易一眼看出的器物；
- 一件东西能带出具体仪式、信仰或历史实践；
- **真实文物 + 一个神秘用途 / 异常行为 + 原始证据**；
- 网上常被错误使用、错误配图或错误解释的真实对象；
- 课程之外仍然有独立研究价值的材料。

当前前台优先寻找：

**具体真实对象 + 奇怪 / 神秘现象 + 普通人马上能理解的问题。**

中段再进入馆藏、原典、历史语境和仪式机制。不要把《文物》做成普通考古冷知识，也不要为了“更神秘”虚构灵异故事。

不优先：

- 只有一个宽泛知识点、找不到具体对象；
- 只能靠无来源网图支撑；
- 和最近内容只是换一件相似文物重复同一结论；
- 必须完整泄露课程核心教学链才能讲清的选题。

## 开头

开头直接进入对象或细节。

允许：

- “先看这里。”
- “这件东西最值得看的是胸口这一处。”
- “先别看整件，先看右下角这个小人。”
- “这一行馆藏说明里有一个很关键的词。”

不使用：

- “今天我来讲……”
- “我最近看到……”
- “我查到……”
- “你有没有想过……”
- “很多人不知道……”
- “你绝对想不到……”

当当天任务属于流量入口时，开头优先让陌生人先明白“这件东西哪里奇怪 / 为什么值得看”，不要把第一屏浪费在术语教学上。

## 口播

- 正式口播默认不使用作者第一人称。
- 语气是“带着观众一起看”，不是课堂宣讲。
- 可以反复使用指向性语言：这里、这一行、这个位置、再看另一面。
- 每出现一个术语就解释到普通观众能跟上。
- 资料越硬，导航越简单：原文、希腊文、拉丁文、字符、铭文等必须告诉观众“看哪里 / 这一处是什么意思 / 为什么重要”。
- 不连续使用“不是 / 不能 / 并不 / 不等于”等反驳模板。
- 不靠“神秘、古老、强大、神圣”等形容词撑内容。
- 不因为总控要求流量优化就改成普通营销号文案；运营层可以压时长、减案例、调整顺序，但 Suen 文笔规则继续有效。

## 信息最低要求

只要资料允许，一条《文物》至少讲清：

1. 名称；
2. 年代；
3. 馆藏 / 来源；
4. 编号；
5. 最值得看的具体细节；
6. 实际用途或历史情境；
7. 这个细节为什么和用途有关；
8. 哪些解释可以确定，哪些仍有争议。

当天如果承担 A 类流量任务，不要求把所有可查信息一次塞完。优先“一件文物解决一个奇怪问题”，删除不影响核心答案的重复信息，把可独立成题的材料留进后续选题池。

## 画面结构

推荐顺序：

1. 全屏文物 / 馆藏页；
2. 局部放大；
3. 箭头 / 圈选 / 下划线等轻标注；
4. 必要时切另一面、细节照、同类对象或原始说明页；
5. 回到整体对象收束。

### 绿幕

可以使用 Suen 左下角小绿幕头像，但：

- 尺寸偏小；
- 不遮挡关键资料；
- 资料画面始终占主体；
- 不需要端坐正面讲课式构图。

## 图片与来源

优先：

- 博物馆官方馆藏页；
- 大学 / 研究项目；
- 数字手稿项目；
- 原始出版扫描；
- 可靠历史档案。

关键图片必须与口播对象实际对应。

不得：

- 用“看起来像”的文物替代当前对象；
- 把现代复原图当成原物；
- 用 AI 生成假文物或假历史现场；
- 把 Pinterest / 无来源转载图当最终证据。

## 固定可剪辑交付格式｜HTML 主交付

从 2026-09-21 起，《文物》**固定以单一 HTML 文件作为主交付**。

原因：
- 聊天界面内直接把真实图片稳定插在每段口播下面，容易出现错图、重复图、链接错位和多轮返工；
- Suen 真正需要的仍然是“从上往下直接剪”，不是改成素材编号表或另做镜头管理表；
- HTML 可以稳定保留口播、真实图片、来源页和剪辑说明的直接对应关系。

### HTML 内部固定阅读顺序

HTML 内继续执行 Suen 已确认的原始剪辑逻辑：

**完整口播段落 → 这段真正对应的实际图片 / 图片组直接显示 → 下一段完整口播 → 下一组实际图片。**

不是：
- 完整口播全部放前面、素材全部放最后；
- 口播 + 素材编号；
- 时间 / 口播 / 素材三列表；
- 另开 ZIP 才能看素材；
- 只给来源链接而不展示实际图片。

### 口播

- 一块是一整段自然、完整、可直接录制的口播；
- 不为了配图机械一句一段；
- 不加时间列；
- 不在口播正文里插素材编号；
- 原文 / 馆藏 / 文物细节出现时，口播自然告诉观众看哪里。

### 图片

每个口播块下面直接放这一段真正要剪进去的真实图片。

要求：
- 图片本身优先直接显示在 HTML 中；
- 多张图按真实剪辑顺序从上到下排列；
- 图片必须与当前口播对象真实对应；
- 不用“看起来像”的文物替代；
- 不用 AI 图冒充真实文物 / 历史现场；
- 局部图明确是局部；
- 需要整件 → 局部时，先整件，再放大细节；
- 需要箭头 / 圈选 / 下划线时，可在 HTML 中直接使用已处理图，或在图下写一句极简剪辑说明。

### 来源

每张关键图在 HTML 中同时保留：

- 图片；
- 来源页；
- 能稳定取得时的图片直链；
- 必要时名称 / 馆藏号 / 年代；
- 极简图注或截取说明。

来源信息不能抢主视觉。Suen 第一眼仍然看到：

**口播 → 图片。**

### HTML 技术要求

正式交付前必须尽量检查：

- HTML 本身可以正常打开；
- 中文不乱码；
- 图片能够正常加载；
- 图片不是失效缩略图、HTML 跳转页或错误 MIME；
- 外部来源页可以打开；
- 图片宽度适合直接浏览，不需要横向滚动；
- 手机 / iPad 上从上往下阅读时，口播和对应图片不会明显错位；
- 不依赖本地绝对路径；
- 如果远程图片不适合稳定嵌入，优先把已取得的合法可用图片放入 HTML 可稳定读取的方式，而不是把问题转给 Suen。

### 标题与标签

完整视频主体结束后，HTML 内直接追加：

**标题：** 最终可发布标题  
**标签：** 最终可发布标签

不等 Suen 再追问。

如果当天明确同步小红书，同一个 HTML 末尾继续追加：

- 小红书标题；
- 封面文字；
- 发布配文；
- 必要标签。

不重新制作第二支视频主体。

### 禁止

- 不再把聊天消息里的逐段嵌图作为正式主交付；
- 不把“完整口播 + 原句锚点素材区”作为正式主交付；
- 不用时间列；
- 不让 Suen 靠素材编号二次匹配；
- 不把所有素材堆到 HTML 最后；
- 不要求打开 ZIP / TXT 才知道怎么剪；
- 不用文件名代替图片；
- 不把来源页链接冒充已交付图片；
- 不因为 HTML 制作麻烦就退回旧的聊天内拼接格式。

### 聊天中的交付

聊天正文只需要简短说明：

- HTML 已完成；
- 有真实缺图 / 链接限制时说明具体哪一处；
- 提供 HTML 文件本身。

**正式内容以 HTML 为主，不在聊天里再复制一整套口播和素材，避免产生两个版本。**

最终目标：

> Suen 打开一个 HTML，就可以从上往下按“完整口播 → 直接图片 → 下一段口播 → 下一组图片”完成录制和剪辑，不需要第二次匹配素材。

## 商业与课程边界

《文物》首先承担流量、精准涨粉和专业信任。没有总控明确任务时，不自行增加购买 / 预约 CTA。

古埃及题材可以继续大量做，但不完整公开付费课程核心教学链。具体边界读取 `内容与课程区隔.md`。

## 正式交付

在 `统一交付规则.md` 与 `99-模板/视频类统一交付格式.md` 基础上，本栏目还必须给：

- **单一 HTML 主交付文件**；
- 文物 / 对象准确名称；
- 馆藏号或稳定编号；
- 年代与馆藏；
- 原始来源页；
- 完整、连续、可直接录制的最终口播；
- 每个完整口播块下面直接显示该段真正对应的实际文物图 / 原页 / X-ray / 局部图；
- 必要的中文标注位置；
- 如存在解释争议，明确写出证据边界；
- 主体结束后直接有标题与标签；
- 当天同步小红书时，同一 HTML 末尾补小红书标题 / 封面 / 配文。

《文物》的交付正确性以 **打开 HTML 后能否直接按“口播 → 图片”顺序剪辑** 为准。
