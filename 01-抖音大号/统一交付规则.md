# 抖音大号｜统一交付规则

状态：当前正式补充规则  
最后核对：2026-10-08

本文件只保存**抖音大号 6 个合集共同、但视频统一格式没有覆盖的补充要求**。

完整视频主交付统一读取：

`99-模板/视频类统一交付格式.md`

共同文笔与执行读取：

`00-系统总控/Suen统一文笔总则.md`

## 一、观众端默认中文

正式口播、标题、封面、解释字幕和发布文案默认中文。

原始文本是证据时保留原文，但必须同步给中文定位 / 译文 / 解释。

## 二、素材优先级

优先使用：

- 博物馆馆藏；
- 大学 / 数字人文项目；
- 手稿、纸草、原书扫描；
- 原始文献；
- 学术出版中的可靠图版；
- 历史档案 / 照片 / 地图。

如果只有来源页、没有稳定图片直链，明确写：

`当前未取得稳定图片直链`

不能拿相似但错误的图或 AI 图补位。

## 三、本人实拍

本人实拍只在：

- 题目天然需要 Suen 的真实操作 / 实物；
- Suen 已明确有素材或愿意拍

时使用。

找不到历史素材不是让 Suen 补拍的理由。

## 四、信息与事实

- 标题 / Hook 不能比正文答案更强；
- 正文必须有真实信息推进；
- 区分文本直接记载、学术解释、传说、后世发展和现代重构；
- 证据只支持局部结论时，只写局部结论。

## 五、小红书同步

如果当天小红书同步同一支成片：

- 不重新做第二支视频；
- 主体只交一份；
- 末尾补小红书标题、封面文字、发布配文和必要标签。

具体栏目时长、开头、结构、素材特殊要求全部服从栏目文件。


## 抖音大号六栏目 HTML 主交付

抖音大号六个正式视频栏目（文物 / 异录 / 辨伪 / 残页 / 隐理 / 牌记）当前统一固定以 HTML 作为主交付。

HTML 内必须保留：
- 完整自然口播；
- 每个口播块下面直接显示该段实际使用图片 / 图片组；
- 可靠来源；
- 必要剪辑说明；
- 最终标题与标签；
- 同步小红书时的标题 / 封面 / 配文。

聊天中不再复制第二套完整稿，也不把聊天内图片当正式交付，避免 HTML 与聊天正文产生版本分叉。

### 六栏目 HTML 图片技术验收

- 正式素材图不得依赖远程 URL 在线加载；
- HTML 源码中的正式素材图应为 `data:image/...;base64`；
- 来源页仍使用可点击 HTTPS 链接；
- 网页可打开但 HTML 图片不显示时，先走 Google Doc → DOCX → `word/media` → Base64 中转流程；
- 不得在未尝试该中转流程前把下载问题转给 Suen；
- 交付前由 ChatGPT 自行打开并检查 HTML、图片显示、顺序、中文、移动端宽度与来源链接。

六栏目全部服从 `99-模板/视频类统一交付格式.md` 的统一 HTML 主交付方式；各栏目文件只补充栏目专属结构和证据要求。

## 六栏目正式HTML生成前置门｜2026-10-07

HTML 是正式主交付格式，但**HTML生成本身不代表内容合格**。

生成正式HTML之前，专用对话必须内部完成：
- 栏目主角复核；
- 正文是否真正持续推进；
- 真人口播可说性；
- 当栏目专属核心门：
  - 文物：对象本身是否始终是主角；
  - 异录：是否真是一则完整奇妙小故事，而不是历史事件摘要；
  - 残页：原页 / 原句是否不可替代；
  - 隐理：是否已经追到有证据支撑的底层机制；
  - 辨伪：是否能稳定判定明确范围内的对 / 错；
  - 牌记：判断是否由具体问题与牌面条件共同生成。

任何一项未通过：**先在内部重写正文，不进入Base64素材包装。**

如果用户对上一版正文已经明确给出负反馈，新版HTML生成前必须先针对该负反馈重新完成对应核心门；不能沿用旧稿结构只换词。

技术QA只证明：
- 文件能打开；
- 图片能显示；
- 来源能核；
- 排版能用。

它不能证明：
- 文笔自然；
- 机制够深；
- 故事好听；
- 选题不无聊。

## 视频口播可说性硬规则｜2026-09-26

本栏目所有视频口播同时执行 `00-系统总控/Suen统一文笔总则.md` 与 `99-模板/视频类统一交付格式.md` 的“视频口播可说性硬规则”。

额外确认：
- 口播按真实讲话写，不把馆藏说明、论文摘要直接搬进嘴里；
- 难读英文 / 外文优先换成自然中文解释，原词放字幕、图片或来源；
- 馆藏号、墓号、长串编号默认不念；
- 年代、尺寸只保留真正影响理解的数字，不在一句话里连续塞多组数字；
- 交付前按正常语速读一遍，凡是容易卡、需要提前练、像在念资料卡的句子都继续改。
