完整视频主交付统一读取：

## 一、观众端默认中文

正式口播、标题、封面、解释字幕和发布文案默认中文。

原始文本是证据时保留原文，但必须同步给中文定位 / 译文 / 解释。

## 二、素材优先级

优先使用：

- 博物馆馆藏；
- 大学 / 数字人文项目；
- 手稿、纸草、原书扫描；
- 原始文献；
- 学术出版中的可靠图版；
- 历史档案 / 照片 / 地图。

如果只有来源页、没有稳定图片直链，明确写：

`当前未取得稳定图片直链`

不能拿相似但错误的图或 AI 图补位。

## 二-A、素材门不是“找到图”｜2026-10-08

六栏目所说的“素材通过”，从现在起统一指：

> **有足够的真实视觉材料支撑完整口播推进，而不是只找到一两张能用的图。**

正式进入 HTML 包装前，必须先完成成片级素材验收：

- 口播的主要信息推进点，都有对应真实视觉；
- 标准 45—90 秒视频原则上应能形成 **至少 6 个有效视觉单元**；更长内容按实际推进继续增加，不拿最低数当上限；
- “有效视觉单元”必须提供新信息或新观看位置，例如：完整对象、不同角度、同组物、原页整页、具体行 / 词局部、历史图版、地图、相关档案、不同版本对照；
- 同一张完整图片原样重复原则上不超过 2 次；再次出现必须换到真正不同的局部、细节或比较关系；
- 原始图、有效证据焦点、HTML实际显示三层分开记录，验收方法统一执行 `99-模板/视频类统一交付格式.md` 的“三层记录与实际展示”；
- 同一来源页可以产生多个有效视觉单元，但每个裁切必须已经落实、可辨且对应不同信息；相同整页反复内嵌或只有“推近”说明不算完成。
- 自制大段文字卡、现代说明页、聊天文字、翻译整页 **不能用来补足素材数量**；
- 原始手稿、原书、纸草、铭文等“文字本身就是证据”的画面可以使用，但必须具体带观众看整页、行、词、版本或位置，不能整条视频只反复放同一页文字；
- 找不到足够真实素材时，先换来源、找局部、同组物、版本、档案或可靠图版；仍不足则返回“素材覆盖不足”，不靠文字卡、AI图或重复图强行完成。

栏目附加要求：
- **文物**：完整对象之外，至少继续取得关键局部 / 不同角度 / 同组物 / 历史图版中的若干种；只有一张馆藏正面图时，默认不能直接判成片素材通过。
- **异录**：不能只靠人物肖像 + 一页原书；人物、事件地点 / 对象、原始记录、后续留下的作品 / 档案应形成不同视觉层。
- **残页**：原页是主角，但必须能做“整页 → 行 / 段 → 词 / 细节 → 必要版本 / 手稿信息”的视觉推进；不拿现代翻译大字卡替代原页局部。
- **隐理**：不同机制环节要有对应证据图；不能让一个文物 / 原页从头撑到尾。
- **辨伪**：错误说法与原始证据 / 版本 / 对照对象需要视觉上可比较。
- **牌记**：具体牌阵、牌位、关键牌和相互关系必须可见，不用纯文字复述牌面。

素材 QA 与技术 QA 分开：
- **素材 QA**：够不够剪、有没有推进、是否重复、是否拿文字凑数；
- **技术 QA**：图片能否显示、Base64 是否正常、来源链接是否可打开。

画面路径未通过不进入正式包装；生成后仍核实际展示。用户指出实际只有一张重复图时，按交付失败处理，不能用内部数量推翻用户观感。不同词句的真实局部可以继续使用，不为凑数增添无关资料。

## 三、本人实拍

本人实拍只在：

- 题目天然需要 Suen 的真实操作 / 实物；
- Suen 已明确有素材或愿意拍

时使用。

找不到历史素材不是让 Suen 补拍的理由。

## 四、信息与事实

- 标题 / Hook 不能比正文答案更强；
- 正文必须有真实信息推进；
- 区分文本直接记载、学术解释、传说、后世发展和现代重构；
- 证据只支持局部结论时，只写局部结论。

## 五、小红书同步

如果当天小红书同步同一支成片：

- 不重新做第二支视频；
- 主体只交一份；
- 末尾补小红书标题、封面文字、发布配文和必要标签。

具体栏目时长、开头、结构、素材特殊要求全部服从栏目文件。


## 抖音大号六栏目 HTML 主交付

抖音大号六个正式视频栏目（文物 / 异录 / 辨伪 / 残页 / 隐理 / 牌记）当前统一固定以 HTML 作为主交付。

HTML 内必须保留：
- 完整自然口播；
- 每个口播块下面直接显示该段实际使用图片 / 图片组；
- 可靠来源；
- 必要剪辑说明；
- 最终标题与标签；
- 同步小红书时的标题 / 封面 / 配文。

聊天中不再复制第二套完整稿，也不把聊天内图片当正式交付，避免 HTML 与聊天正文产生版本分叉。

### 六栏目相册导入包｜2026-10-09

Suen 在 iPhone / iPad 上剪辑，不能再要求从 HTML 逐张截图或手动保存图片。

每次六栏目含图片正式生产，在不改变 **HTML主交付：口播段落 → 实际图片紧贴** 的前提下，**必须额外生成一份“相册导入包.zip”**：
- 包内为 HTML 实际使用的 JPG / PNG 剪辑画面，按真实剪辑顺序编号；实际需要的原页局部 / 文物细节必须给独立清晰图；
- 只包含可直接存入系统相册的图片，不夹杂 HTML / PDF / TXT / 来源卡；资料来源与使用限制继续在 HTML 记录；
- 正式交付时同时提供 HTML 与相册导入包的真实下载链接；
- 不能用重复复制、低清缩略图或无关现代大字卡凑包；包内内容与 HTML 实际展示一致；
- 没有成功创建 / 验证 ZIP 时，不得宣称可批量存相册，必须明确缺口，并优先自行修复。

iPad / iPhone 用户只需在“文件”App 解压 ZIP、选择全部图片并经共享菜单存储图像即可批量进入“照片”图库；首次可能需要系统授权。ChatGPT 不能未经用户设备授权直接将图片写进相册。

具体执行及 QA 唯一真源：`99-模板/视频类统一交付格式.md` 的“三-B、iPhone / iPad 相册导入包”。

### 六栏目 HTML 图片技术验收

- 正式素材图不得依赖远程 URL 在线加载；
- HTML 源码中的正式素材图应为 `data:image/...;base64`；
- 来源页仍使用可点击 HTTPS 链接；
- 网页可打开但 HTML 图片不显示时，先走 Google Doc → DOCX → `word/media` → Base64 中转流程；
- 不得在未尝试该中转流程前把下载问题转给 Suen；
- 交付前由 ChatGPT 自行打开并检查 HTML、图片显示、顺序、中文、移动端宽度与来源链接。

六栏目全部服从 `99-模板/视频类统一交付格式.md` 的统一 HTML 主交付方式；各栏目文件只补充栏目专属结构和证据要求。

## 六栏目正式HTML生成前置门｜2026-10-07

HTML 是正式主交付格式，但**HTML生成本身不代表内容合格**。

生成正式HTML之前，专用对话必须内部完成：
- 栏目主角复核；
- 正文是否真正持续推进；
- 真人口播可说性；
- 当栏目专属核心门：
  - 文物：对象本身是否始终是主角；
  - 异录：是否真是一则完整奇妙小故事，而不是历史事件摘要；
  - 残页：原页 / 原句是否不可替代；
  - 隐理：是否已经追到有证据支撑的底层机制；
  - 辨伪：是否能稳定判定明确范围内的对 / 错；
  - 牌记：判断是否由具体问题与牌面条件共同生成。

任何一项未通过：**先在内部重写正文，不进入Base64素材包装。**

如果用户对上一版正文已经明确给出负反馈，新版HTML生成前必须先针对该负反馈重新完成对应核心门；不能沿用旧稿结构只换词。

技术QA只证明：
- 文件能打开；
- 图片能显示；
- 来源能核；
- 排版能用。

它不能证明：
- 文笔自然；
- 机制够深；
- 故事好听；
- 选题不无聊。

## 视频口播可说性硬规则｜2026-09-26

本栏目所有视频口播同时执行 `00-系统总控/Suen统一文笔总则.md` 与 `99-模板/视频类统一交付格式.md` 的“视频口播可说性硬规则”。

额外确认：
- 口播按真实讲话写，不把馆藏说明、论文摘要直接搬进嘴里；
- 难读英文 / 外文优先换成自然中文解释，原词放字幕、图片或来源；
- 馆藏号、墓号、长串编号默认不念；
- 年代、尺寸只保留真正影响理解的数字，不在一句话里连续塞多组数字；
- 交付前按正常语速读一遍，凡是容易卡、需要提前练、像在念资料卡的句子都继续改。
