# 抖音大号｜统一交付规则

状态：当前正式规则
最后核对：2026-09-17

本文件适用于文物、异录、辨伪、残页、隐理、世问、牌记。栏目专用文件可以增加栏目自己的研究、画面与结构要求，但不得降低真实性与来源标准，也不得覆盖统一视频主交付格式。

共同文笔底线读取：

- `00-系统总控/Suen统一文笔总则.md`
- `00-系统总控/文笔成稿验收协议.md`

**所有视频类正式成品统一继承：`99-模板/视频类统一交付格式.md`。**

## 一、正式成品的主交付

2026-09-17 已最终确认：

**主交付只围绕“完整口播 / 台词 ↔ 直接对应图片”展开。**

优先形式：

| 完整口播 / 台词 | 对应图片 |
|---|---|
| 一整段自然、连续、可以直接录制的完整口播 | 这一段真正要使用的图片直接显示 |
| 下一段完整口播 | 下一组真正要使用的图片直接显示 |

如果当前聊天 UI 不能稳定在表格里直接显示图片，自动切换成：

**一段完整口播 → 紧跟对应图片 → 下一段完整口播 → 紧跟对应图片。**

不得因此退回素材编号表、ZIP 对照表或“完整口播在前 / 素材统一堆在后面”的旧流程。

## 二、主交付默认不要出现的东西

默认不增加：

- 时间列；
- 预计时间码；
- `01 / 02 / 03` 素材编号作为理解主交付的依据；
- 文件名作为图片替代；
- 独立镜头表；
- 独立剪辑顺序表；
- 需要 Suen 打开 ZIP 才能知道该配哪张图的流程。

时间码只有 Suen 当次明确要求，或已经存在真实录音 / 成片需要精确对齐时才增加。

ZIP、原图包、来源表、TXT 只能作为**可选补充附件**，放在主交付之后。Suen 不打开附件，也必须能直接录和剪。

## 三、每条正式成品至少包含

1. 完整中文口播 / 台词；
2. 每个自然口播块紧邻的真实对应图片 / 画面；
3. 必要时一句极简使用说明，例如 `整页 → 放大第3行`；
4. 外部资料的可靠来源页；
5. 封面标题；
6. 发布文案。

默认只生成当前实际运营需要的中文版本。除非 Suen 当次明确要求，不额外制造英文 / TikTok 等版本工作量。

## 四、中文平台观众端语言

中文平台的视频正式成品，观众实际会听到或直接看到的内容默认全部用中文表达，包括：

- 口播；
- 标题；
- 封面；
- 后加字幕与画面标注；
- 发布文案。

外文书名、论文名、术语、影视名等进入正式口播时，优先使用清楚稳定的中文译名；没有稳定中文译名时，用中文音译或说明性译法。

后台来源备注可以保留英文原名、原文、链接、馆藏编号和学术引用。

原始资料本身如果是英文、拉丁文、希腊文、埃及语等，不为了“全中文”抹掉原文证据。尤其《残页》必须保留原文，但需要用中文框注、中文译文或中文解释主动带看。

## 五、图片与素材

优先使用：

- 博物馆公开馆藏；
- 大学项目；
- 数字手稿 / 纸草 / 原书扫描；
- 原始文献；
- 论文与学术出版物；
- 历史地图、历史照片、档案页面。

右侧 / 紧跟图片区域第一视觉优先是**图片本身 / 图片预览**，来源与说明只做辅助。

图片下面最多保留必要信息：

- `来源：……`
- `使用：整页 → 放大第4行`
- `馆藏：……`（确有必要时）

如果当前只有来源页、没有稳定图片直链，明确写：`当前未取得稳定图片直链`，然后给可靠来源页。不得拿不相关的氛围图补位。

## 六、本人实拍

“本人实拍”不是找不到外部素材时的默认补洞方式。

只有题目本身需要 Suen 的真实操作 / 桌面 / 现有实物，或 Suen 已明确有该素材 / 愿意拍时，才安排本人实拍。

本人实拍时，口播旁边直接写清拍什么、怎么拍，不为了凑图片链接硬配无关网图。

## 七、AI 画面

默认不使用 AI 画面代替真实资料。确需使用复原或示意时必须明确标注，不得冒充真实文物、真实历史现场或原始手稿。

## 八、信息结构

- 正文承担至少约 80% 的实际信息量；
- 不允许标题很猛、正文只有口水；
- 优先选择有真实对象、原始资料、具体动作或可验证判断的内容；
- 如果当天题目有观众现实里经常刷到、见过、用过或容易立刻想象的具体画面，可以直接从这个画面开头，再自然问当天具体问题；
- 栏目自己的固定开头优先级更高，例如《辨伪》的判断题结构继续有效。

具体时长、开头秒数等以各栏目更具体规则为准。统一规则不得反向覆盖《隐理》等栏目已确认的时长形态。

## 九、文风

- 正经但自然，信息密度高；
- 避免空泛流水线开头；
- 避免连续“不是 / 不能 / 并不 / 不等于 / 不是……而是……”的反驳段落；
- 不用一句一段的碎句堆节奏；
- 不靠“本质上 / 真正重要的是 / 说到底”等空泛总结制造深度；
- 术语出现时必须解释；
- 口播优先使用具体对象、具体动作和具体位置；
- 抽象概括只在具体内容已经讲清、且确实有解释需要时少量使用；
- 运营层可以优化题目、信息顺序、案例数量和第一屏，但不能把 Suen 的口播改成普通营销号 / AI 短视频文风。

## 十、事实边界

需要主动区分：

- 史料直接记载；
- 文物 / 文本能证明到什么程度；
- 学术解释；
- 当事人声称；
- 民间传说；
- 后世接受史；
- 现代重构或现代实践。

如果证据只支持局部结论，就只写局部结论。

## 十一、小红书同步

如果当天小红书直接同步同一支抖音成片：

- 视频主体只交这一份“完整口播 ↔ 直接图片”成片稿；
- 不重新制作第二份视频稿或素材表；
- 同一成片稿末尾追加小红书标题、封面文字、发布配文即可。

## 十二、交付前检查

正式发给 Suen 前确认：

- 主交付没有默认时间列；
- 没有靠素材编号才能理解的地方；
- 每段完整口播旁边 / 紧跟位置就是对应图片；
- 图片顺序就是剪辑顺序；
- 不打开 ZIP / TXT 也能直接剪；
- 没有把本可以由执行对话解决的素材匹配工作交给 Suen。

详细执行统一以 `99-模板/视频类统一交付格式.md` 为准。
