# 抖音大号｜统一交付规则

状态：当前正式补充规则  
最后核对：2026-09-21

本文件只保存**抖音大号 7 个合集共同、但视频统一格式没有覆盖的补充要求**。

完整视频主交付统一读取：

`99-模板/视频类统一交付格式.md`

共同文笔与执行读取：

`00-系统总控/Suen统一文笔总则.md`

## 一、观众端默认中文

正式口播、标题、封面、解释字幕和发布文案默认中文。

原始文本是证据时保留原文，但必须同步给中文定位 / 译文 / 解释。

## 二、素材优先级

优先使用：

- 博物馆馆藏；
- 大学 / 数字人文项目；
- 手稿、纸草、原书扫描；
- 原始文献；
- 学术出版中的可靠图版；
- 历史档案 / 照片 / 地图。

如果只有来源页、没有稳定图片直链，明确写：

`当前未取得稳定图片直链`

不能拿相似但错误的图或 AI 图补位。

## 三、本人实拍

本人实拍只在：

- 题目天然需要 Suen 的真实操作 / 实物；
- Suen 已明确有素材或愿意拍

时使用。

找不到历史素材不是让 Suen 补拍的理由。

## 四、信息与事实

- 标题 / Hook 不能比正文答案更强；
- 正文必须有真实信息推进；
- 区分文本直接记载、学术解释、传说、后世发展和现代重构；
- 证据只支持局部结论时，只写局部结论。

## 五、小红书同步

如果当天小红书同步同一支成片：

- 不重新做第二支视频；
- 主体只交一份；
- 末尾补小红书标题、封面文字、发布配文和必要标签。

具体栏目时长、开头、结构、素材特殊要求全部服从栏目文件。


## 《文物》HTML 主交付例外

《文物》当前固定以 HTML 作为主交付。

HTML 内必须保留：
- 完整自然口播；
- 每个口播块下面直接显示该段实际使用图片 / 图片组；
- 可靠来源；
- 必要剪辑说明；
- 最终标题与标签；
- 同步小红书时的标题 / 封面 / 配文。

聊天中不再复制第二套完整稿，避免 HTML 与聊天正文产生版本分叉。

### 《文物》HTML 图片技术验收

- 正式素材图不得依赖远程 URL 在线加载；
- HTML 源码中的正式素材图应为 `data:image/...;base64`；
- 来源页仍使用可点击 HTTPS 链接；
- 网页可打开但 HTML 图片不显示时，先走 Google Doc → DOCX → `word/media` → Base64 中转流程；
- 不得在未尝试该中转流程前把下载问题转给 Suen；
- 交付前由 ChatGPT 自行打开并检查 HTML、图片显示、顺序、中文、移动端宽度与来源链接。

其它栏目继续服从 `99-模板/视频类统一交付格式.md` 的当前默认方式，除非各自栏目文件另有明确专属格式。
