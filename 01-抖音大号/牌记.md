最后核对：2026-10-08

正式视频交付统一读取：`99-模板/视频类统一交付格式.md`。

## 核心定位

《牌记》不做词典式牌义教学。

### 2026-09-23｜牌记主形态与塔罗内容分工

《牌记》的主形态固定为：**真实问题 / 匿名真实案例 / 明确标注的演示牌局中的现场判断。**

它主要承担：
- 判断能力展示；
- C｜服务认知；
- 让观众理解“同一张牌为什么在不同问题里会判得不一样”；
- 让潜在咨询者看到 Suen 如何把牌面、牌位、周围牌和现实背景放在一起判断。

新手向塔罗内容仍然可以做，但它的主要任务通常是：
- 拉新；
- 收藏；
- 搜索；
- 基础兴趣建立。

例如开牌、提问方式、基础牌阵、洗牌等内容如果没有“具体问题 + 具体牌阵 + 具体判断”，不因为数据好就自动归入《牌记》。应按内容价值中心路由到更合适的平台 / 栏目。

当前测试思路：
- 优先连续测试案例型《牌记》，观察真实判断内容能否补足服务认知；
- 新手实用型内容作为前端流量结构单独观察；
- 判断误区型内容可作为两者之间的桥，例如“抽到恋人就一定复合吗”。

《牌记》的复盘不能只看播放。除播放 / 留存外，优先观察：
- 是否出现观众主动讲自己的现实问题；
- 主页访问；
- 精准关注；
- 私信 / 加微信；
- 有效询盘；
- 是否出现“想让 Suen 帮忙判断”的明确服务认知。

没有询盘不等于内容失败；必须结合该条的主任务判断。新手教学内容如果带来收藏 / 关注但没有咨询，仍可能完成其前端流量任务。案例型《牌记》如果播放普通但明显带来现实问题评论、主页访问或有效询盘，则具有更高的服务认知价值。

核心问题始终是：

**“为什么在这个具体问题里，这张牌要这样判？”**

专业感来自判断过程，而不是背关键词。

完整栏目路由统一读取：`栏目选题边界与路由.md`。只有当**具体问题 + 具体牌阵 + 具体牌面条件**本身是内容主角时，才优先进入《牌记》。如果拿掉这副具体牌以后，问题依然成立，就不要为了服务认知硬塞进《牌记》；有可证实机制时回《隐理》，纯现实判断 / 服务原则优先放小号、朋友圈或适合的小红书内容。

## 开头

《牌记》开头先让观众知道：
**问的是什么 + 这副牌哪里让直觉判断出问题。**

优先从真实问题和牌直接进入，不先讲牌义背景。

例如：
- “问工作要不要辞，抽到死神，答案不一定就是辞。”
- “问复合出了恋人牌，这组牌还要结合它的位置和旁边的牌判断。”

第二句马上告诉观众哪张周围牌、哪个牌位或哪个现实条件改变了判断。

不要使用：
- “今天教大家怎么看……”
- “很多人抽到这张都会……”
- “这张牌其实没有你想得那么简单……”
- 为了钩子故意把真实牌局结论说反。

强度来自**具体问题 + 观众熟悉的关键词判断被真实牌局修正**，不是靠营销话术。

## 固定判断逻辑

**问题 → 现实背景 → 牌位 / 功能 → 牌面与正逆位 → 周围牌 / 组合 → 关键反证 → 最终判断**

这是后台判断顺序，前台口播不机械展示步骤。任何一张牌都不能脱离问题直接下结论。

## 核心规则

- 必须先明确提问是什么；
- 必须知道牌在牌阵中的位置或功能；
- 正逆位只作为判断条件之一，不替代整体牌阵；
- 必须看周围牌如何修改、强化或限制这张牌；
- 必须结合现实背景；
- 最终判断要能解释“为什么”，不能只给结论。

不做：

- “抽到恋人 = 一定复合”；
- “抽到死神 = 一定分手”；
- “圣杯二 = 他一定爱你”；
- “恶魔 = 一定有第三者”；
- 单张牌关键词套现实。

## 适合选题

优先选大众很容易套关键词、但实际需要重新判断的场景：

- 恋人牌出现在复合问题里为什么不一定是复合；
- 死神在关系问题里什么时候才真的指向结束；
- 圣杯二为什么不等于稳定关系；
- 星币十在感情问题里为什么可能更多指现实结构；
- 高塔出现在工作问题里到底看什么；
- 宫廷牌什么时候代表人物，什么时候更像状态；
- 同一张牌在“他怎么想”和“关系会怎么发展”里为什么会判得不一样；
- 正位看起来很好，但周围牌为什么会把结果拉下来；
- 逆位什么时候是阻滞、内部化、减弱或另一种表现，而不是简单“反义词”。

## 不适合做成《牌记》的内容

- 单纯“XX 牌是什么意思”；
- 一张牌十个关键词；
- 没有真实问题背景的牌义百科；
- 为了流量编造客户案例；
- 把一次私人客户占卜原封不动公开；
- 拿掉具体牌阵以后依然只是“现实中该怎么办”的问题。

## 一条内容怎么讲

推荐顺序：

1. 先说具体问题；
2. 展示牌阵 / 当前牌位；
3. 说明普通人最容易怎么套关键词；
4. 回到这张牌在这个问题里的实际功能；
5. 看正逆位；
6. 看旁边的牌；
7. 加入现实背景；
8. 给最终判断；
9. 解释如果某个条件改变，结论为什么也可能变。

不需要每次显式念出 9 步，但判断不能跳步骤。

## 文风

《牌记》围绕一副真实牌局形成判断，重点让观众明白哪个问题、牌位、正逆位或周围牌改变了解读。句子完整自然，判断过程可以随着牌面推进，不必先定义所有关键词。

正文默认不使用作者“我 / 我们”。可以直接说明“恋人牌在这里对应的是选择，旁边的牌进一步限制了关系发展的判断”，并把依据落到当前牌面。资料中没有实际改判过程时，不模拟惊讶、停顿或“刚才看错了”来制造现场感。

后台核对问题、牌位、正逆位、周围牌和现实背景；前台不机械列教学步骤。不同牌面条件必须提供新增信息，不能把一个结论换几种说法。判断不确定时说明缺少什么信息，不为了成片强给结果。

Suen 明确要求现场个人经验表达时，允许采用其真实经验和自然口语；不得虚构客户反馈、亲历或实时反应。

### 口播自检

按正常语速读完整稿，核对：

- 是否清楚指向当前牌、位置和判断依据；
- 资料、判断过程与后续现实反馈是否分层；
- 是否把自然解释写成术语、碎句或反复纠错；
- 读者能否复述这组牌为何在这个问题里得到这个判断。

看牌语气继续自然，作者隐身不能使中文变成生硬被动句。

## 训练案例与外部老师材料

老师课程 / 案例可以作为**私有训练来源**，但不能直接把单个老师的一次判断升级为 Suen 的固定规则。

正式《牌记》使用训练所得规律时：

- 优先使用 `Tarot Judgment Rules/` 中已经通过 Suen 采用层的规则；
- 尚未采用的老师规则只作为内部参考，不自动覆盖 Suen 自己的判断；
- 不把版权课程的大段原话、完整案例讲解或可替代原课程的内容搬到前台；
- 如果某个规则只来自单个案例，前台不能包装成普遍定律；
- 老师案例用于提高判断质量，不要求在视频里表演“引用老师”。

## 真实案例与隐私

使用真实看牌经验时：

- 不泄露客户身份；
- 不公开能识别个人的信息；
- 必要时把具体背景抽象成不可识别的案例；
- 不为了内容效果编造客户反馈或最终结果。

## 拍摄规则

继续使用 Suen 本人的真实塔罗牌、真实桌面和真实手部操作。

重点增加“正在判断”的过程：

- 现场翻牌；
- 手部操作；
- 牌阵逐步展开；
- 指牌；
- 停顿；
- 移动或重新排列牌；
- 对比两张牌；
- 补牌（只有实际判断需要时）；
- 重新判断或补充结论。

减少：

- 全程固定俯拍；
- 牌早就摆得整整齐齐再照稿讲；
- 字幕像知识卡模板；
- 为了“高级感”加入与判断无关的 AI 画面。

## 画面和口播关系

口播说到哪张牌，镜头就让观众明确看到哪张牌。

涉及：

- 正逆位；
- 牌阵位置；
- 周围牌；
- 两张牌之间的关系

时，要用手势、局部放大或简单标注帮助观众跟上。

## 与其它内容的边界

《牌记》只在**具体问题 + 具体牌阵 + 具体牌面条件**共同产生判断时成立。

如果没有具体牌局：

- 可证实的占卜 / 仪式实践机制 → 优先《隐理》；
- 个人服务原则、现实建议、是否接某类需求 → 优先小号、朋友圈或适合的小红书内容；
- 不为了“服务认知”虚构牌阵或补一副无必要的牌。

C｜服务认知可以成为《牌记》的当天任务，但服务认知必须从真实看牌过程自然产生，不能覆盖栏目本身。

## 栏目漂移红旗｜专用对话必须退件

出现以下任一情况时，不继续按《牌记》交付：

- 具体牌阵只是配图，正文主要在讲一张牌的通用牌义；
- 换一副牌 / 换一个问题，原来的判断逻辑仍几乎完全成立；
- 没有牌位、正逆位、周围牌或现实背景也能直接得出同样结论；
- 内容主要在讲“咨询时应该怎么做 / 我为什么这样服务”，而不是这副牌为什么这样判；
- 为了做内容临时补牌、虚构牌阵或补一个没有实际判断必要的案例。

处理：
- 通用占卜 / 实践机制 → 《隐理》；
- 服务原则 / 现实建议 → 小号、朋友圈或小红书；
- 没有具体牌局 → 不做《牌记》。

《牌记》的不可替代性必须来自这副具体牌本身，不能用“出现了塔罗牌”代替栏目资格。


## 标题定稿｜本栏目专属校准

最终标题必须在具体问题、牌位、正逆位、周围牌和现实背景已经形成完整判断后再定，并先执行 `00-系统总控/内容商业对标系统.md` 的 benchmark title pass。

《牌记》的标题优先像**一个真实人在问问题，或者真实看牌时出现的那个判断冲突**：
- 现实问题优先于牌义术语；
- 如果某张牌的出现让直觉判断失效，可以直接抓这个反差；
- 不写“XX牌是什么意思 / XX牌正逆位解析 / 塔罗告诉你……”；
- 不使用“关系能量 / 宇宙指引 / 灵魂课题”等抽象词替代真实问题；
- 标题可以口语化，但不能为了戏剧性编造客户背景、结论或结果。

本栏目优先参考 Suen 自己的真实案例与已采用判断规则；外部只参考魔女小玉塔罗等中文塔罗账号“问题如何直接前台化”，不迁移其结论、人格或玄学措辞。

## 商业边界

《牌记》可以自然建立塔罗服务认知，但不要求每条结尾都写：

- 可以找我占；
- 私信预约；
- 多少钱。

只有商业总控当天明确分配塔罗商业信号时，才加入一个高度相关的承接。

## 正式交付

生成正式《牌记》成品至少包含：

- 具体问题；
- 牌阵 / 牌位；
- 牌面；
- 正逆位；
- 周围牌；
- 现实背景；
- 完整判断过程；
- 最终结论；
- 完整口播；
- 每个自然口播块直接对应的真实牌面、实拍画面或动作；
- 标题与发布文案。

《牌记》以真实牌面和真实操作为主，不需要为每张牌寻找历史资料配图；通用文风与交付读取 `统一交付规则.md` 与 `99-模板/视频类统一交付格式.md`。

### 最终交付样式

如果已经有牌面照片、已上传素材或可直接显示的真实牌面：

- 当前界面支持时：左边完整口播，右边直接显示对应牌面 / 局部图；
- 当前界面不支持稳定双栏时：一段完整口播 → 紧跟对应牌面图片 → 下一段完整口播 → 紧跟下一组。

如果这一段主要依赖现场翻牌 / 指牌 / 移动牌面：

- 该段完整口播后立刻紧跟具体动作说明；
- 例如 `本人实拍｜翻开第三张后停 2 秒，手指点恋人牌，再把镜头推近周围两张牌`；
- 如果已有对应实拍素材，优先直接显示 / 引用，而不是只写文件名。

默认不增加时间列或预计时间码，不用素材编号 / 文件名代替真实牌面或动作，不要求 Suen 打开 ZIP / TXT 才完成口播与画面的匹配。

最终标准：**口播说到哪张牌，Suen 在同一位置就能立刻看到 / 知道这一段要展示哪张牌和怎么拍。**

## 视频口播可说性硬规则｜2026-09-26

本栏目所有视频口播同时执行 `00-系统总控/Suen统一文笔总则.md` 与 `99-模板/视频类统一交付格式.md` 的“视频口播可说性硬规则”。

额外确认：
- 口播按真实讲话写，不把馆藏说明、论文摘要直接搬进嘴里；
- 难读英文 / 外文优先换成自然中文解释，原词放字幕、图片或来源；
- 馆藏号、墓号、长串编号默认不念；
- 年代、尺寸只保留真正影响理解的数字，不在一句话里连续塞多组数字；
- 交付前按正常语速读一遍，凡是容易卡、需要提前练、像在念资料卡的句子都继续改。
