# 客户商业记录模板

状态：当前正式模板
最后核对：2026-09-25

**仅在销售私聊专用对话中，Suen 明确说“生成总结”时使用。**

普通“总结”用于商业总控的每日内容台账流程，不触发本模板。

目标位置：
- 当月商业事实：`08-动态运行/商业/YYYY-MM.md`
- 当前经营状态：`08-动态运行/商业/当前商业状态.md`（仅在当前状态改变时同步）

不得把新的客户询盘、报价、成交推进记录写入内容台账。

目标：**短、能复盘、可直接写入 GitHub 商业运行记录。**

## 输出

```text
【本次沟通结果】
阶段：
意图：
结果：
下一步：

【可直接写入商业运行记录】
【客户商业记录】
日期：
来源平台：
对应内容：（能确认时）
需求：
阶段：
报价/成交：
成交金额：（已成交且已知时）
预计毛利：（已知时）
客户关系：新客 / 复购 / 转介绍（能确认时）
主要异议/成交断点：
购买质量信号：（聊天中有明确证据时，可选）
下一步：
```

## 归因规则

- 能确认询盘来自具体内容时，写“来源平台 + 对应内容”。
- 只能确认平台、不能确认具体内容时，只写平台，不猜最近一条内容就是来源。
- 转介绍、老客户复购等来源能确认时直接写，不混成普通平台自然询盘。

## 金额规则

- 尚未报价时写“报价：未报价”。
- 已报价未付款不能写成交。
- 已成交时保留实际成交金额；如果实际成交金额和原报价不同，以真实成交金额为准。
- 预计毛利只有在材料成本 / 执行成本足够明确时才写；不知道就省略，不为了算利润随便估。
- 转介绍、复购能确认时保留，便于后续判断真实商业质量。

## 省略规则

- 没有实际意义的空字段直接省略，不为了模板完整保留一排“无 / 未知”。
- 尚未报价时可写“报价：未报价”，不需要再单列“是否报价 + 报价金额”两个字段。
- 未成交且能从真实聊天判断时，保留“主要异议/成交断点”；无法确认主因时可写“尚无法确定”，不要为了模板完整强行归因。
- 不复制客户完整原话。
- 不记录客户姓名、联系方式、付款资料等隐私到 GitHub。

## 示例逻辑

一条记录只保留商业复盘真正需要的信息：

**从哪里来 → 哪条内容带来（能确认时）→ 想买什么 → 现在到哪一步 → 钱有没有谈清楚 → 实际成交价值 / 毛利 → 是否复购或转介绍 → 下一步做什么。**
