# Suen｜每日总控模板

状态：当前正式模板  
最后核对：2026-10-12

本文件只规定**最终输出形状**，不重复保存选题、实验、商业密度等详细规则。

正式执行先按 `总控启动索引.md` 路由读取相关真源。

## 一、唯一输出入口

执行 `00-系统总控/每日总结与更新工作流.md` 第十二节，不保留另一套默认短版。

```text
今日判断：瓶颈｜改变判断的事实
P0：客户履约 / Revenue P0 / 经营建设 / 内容或长期产品
动作与完成条件：
实际安排：只列今天执行、观察或发生变化的事项
发布时间 / 必要执行时段：
对应专用任务词：紧跟任务，独立代码块
执行顺序：
```

后台覆盖必要事项，前台可以合并无独立任务的平台；简洁不能漏已付款履约。

## 二、写入 GitHub 商业运行记录

保留最少必要信息：

```text
【今日判断】
主要瓶颈：
判断依据：

【P0】
类型与具体动作：
完成条件：

【P1 / P2】
只列实际任务

【主要验证】
有才写；没有写“无新增实验｜执行稳定结构”

【今日主要商业信号】
承载平台：
方向：

【今日明确不推】
```

新的流量 / 精准关注 / 研究前台候选，在后台按 `内容商业对标系统.md` 二-A保留来源依据。最终短输出可在“今日判断”下合并一句：

`选题依据：自有作品 / 指标 / 日期＋具体对标作品 / 指标 / 日期 → 本条新增问题或知识`

缺可比字段时明确待补；通知或已确定的商业动作不硬套。C/D候选按对标系统二-B留存真实疑问、可展示依据与业务关系；短输出只概括本次要帮助谁理解什么，不复制四项清单。不是另一套评分表，也不写入口播正文。

如果当天刷新近期对标，可增加一行：

`近期对标：已刷新｜主任务｜账号`

不要把完整搜索结果、100 分细项、SHA 清单写入当前商业动态文件。

## 三、专用对话短交接

```text
执行今天正式更新。

前台合集 / 内容产品：
题目：
主任务：A / B / C / D
今日重点：
选题依据：A/B/研究新题引用已核作品与新增知识；C/D引用本次具体问题/事实范围与可展示依据，长期细则由专用对话读真源
商业边界：纯内容 / 唯一允许的商业方向

按当前 GitHub 本栏目 / 平台规则完整执行。
没有真实阻塞时，自行完成研究、成稿、素材和 QA，一次性交付。
```

小红书同步时追加：

`小红书同步同一成片，并补标题 / 封面文字 / 发布配文。`

## 四、原则

- P0 优先于 P1，P1 优先于 P2。
- P0 类型和保护顺序按每日工作流；有内容任务时优先一份主生产单元，不默认双倍剪辑。
- 公众号贴图 / 长文独立判断。
- 小号、朋友圈、Patreon 不机械日更。
- 一天原则上只有一个主要商业信号。
- 不发的平台不生成无用提示词。
- 详细判断全部回对应真源，不在模板重复。
