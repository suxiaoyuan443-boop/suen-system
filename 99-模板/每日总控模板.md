# Suen｜每日总控模板

状态：当前正式模板
最后核对：2026-09-18

用于“更新”完成诊断后的最终简洁输出。

正式执行前仍必须内部完成：

- `00-系统总控/选题定稿硬门槛.md`
- `00-系统总控/商业信号与动态状态规则.md`
- `00-系统总控/总控简化与生产保护规则.md`

内部检查继续完整执行，但正常稳定日不把五个对标逐项、100 分明细、SHA 清单和所有数据分析默认展示给 Suen。

只有出现未通过、冲突、读取故障、Suen 明确要求或需要定位执行问题时，再展开详细检查。

## 一、内部硬检查｜默认不展示

定题以前内部确认：

- 最新 Slack 三个核心频道已读取；
- 当前主要瓶颈已判断；
- 栏目路由正确；
- 五个对标方法已检查；
- Suen 100 分模型已检查；
- 最近 7 天重复度已检查；
- 核心答案证据可答；
- 真实素材可以取得；
- 商业密度与当天任务一致。

如果当天存在商业动作，再确认：

- 今日经营决定是上海当天最新状态；
- 当前产品 / 服务真实可售或可预约；
- 价格 / 排期 / 容量 / 交付方式仍有效；
- 天象窗口仍有效且允许宣传；
- 跨平台商业触点数没有超出当天安排。

任何硬门槛未通过：只能保留为 `候选题｜待筛选`，不能进入正式执行。

正常通过后，对 Suen 只显示：

`选题状态：已通过硬门槛`

## 四、执行提示词

只给当天真正需要执行的专用对话。

默认使用 `99-模板/专用对话执行提示词模板.md` 的**短交接格式**，只传：

- 前台合集 / 内容产品；
- 题目；
- A / B / C / D 主任务；
- 今天唯一需要特别优化的变量；
- 商业边界；
- 小红书是否同步同一成片。

不要把栏目长期规则、文笔总则、规则读取协议、视频交付格式全文重新复制进每日提示词。

这些由专用对话实际读取 GitHub 当前真源。

## 五、使用原则

- P0 优先于 P1，P1 优先于 P2；P0 未完成时，不用非阻塞性系统维护挤占主生产。
- 抖音大号和小红书当前仍有日更基线；偏离时写明真实例外理由。
- 小红书同步同一支成片只算一个制作任务，但商业触点按实际发布平台计算。
- 公众号贴图与长文继续独立判断，不恢复固定每日两篇。
- 朋友圈与抖音小号不机械日更。
- 一天原则上只有一个主要商业信号，确有需要时最多两个明显商业触点。
- 纯内容日明确写“无”，不偷偷加 CTA。
- 不发的平台不生成无用执行提示词。
- 选题进入生产保护状态后，总控不再中途追加新理论或擅自改栏目长期时长；只有核心事实 / 证据 / 路由 / 商业或天象硬边界真正阻塞时才退回重新定题。
