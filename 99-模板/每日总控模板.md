# Suen｜每日总控模板

状态：当前正式模板
最后核对：2026-09-18

用于“更新”完成诊断后的最终简洁输出。

正式执行前仍必须内部完成：

- `00-系统总控/选题定稿硬门槛.md`
- `00-系统总控/商业信号与动态状态规则.md`
- `00-系统总控/总控简化与生产保护规则.md`
- `00-系统总控/内容商业对标系统.md`
- `00-系统总控/内容实验与验证规则.md`

内部检查继续完整执行，但正常稳定日不把五个对标逐项、100 分明细、SHA 清单和所有数据分析默认展示给 Suen。

只有出现未通过、冲突、读取故障、Suen 明确要求或需要定位执行问题时，再展开详细检查。

---

## 一、内部硬检查｜默认不展示

定题以前内部确认：

- 最新 Slack 三个核心频道已读取；
- 当前主要瓶颈已判断；
- **Suen 自己相关的历史有效内容 / 题目结构已经先检查，外部 benchmark 不覆盖第一方真实数据；**
- **第一方样本已区分“单样本信号 / 重复信号 / 稳定结构”，没有把一条高播放直接写成永久公式；**
- **当前账号已有内容 / 主页结构已检查；如果账号样本很少，已查看当前全部已发布内容而不是只看近 7 天；**
- **如果低样本账号被单一栏目 / 观看体验明显占据，已经做过至少 1 个跨内容体验合格候选比较，或明确记录其它类型没有合格候选；**
- 栏目路由正确；
- 五个长期 benchmark 方法已参与判断；
- 当天第一次定前台题时，最相关 2—3 个对标账号近期真实创作已实际刷新；如果无法可靠取得，已经明确记录；
- Suen 100 分模型已检查；
- 最近 7 天重复度已检查；
- 核心答案证据可答；
- 真实素材可以取得；
- 商业密度与当天任务一致；
- P0 工作量可行；
- **如果是新的正式前台内容，已在看到结果以前写好 1 个“主要验证假设”，并且它只对应一个主要变量 / 组合假设；**
- **主要观察指标与当天 A / B / C / D 主任务一致；没有拿点赞替代涨粉、拿播放替代成交；**
- **存在可靠可比样本时已写对照基线；没有可靠可比样本时明确写“无可靠可比样本”，不硬找旧内容。**

如果当天属于时效通知、已确认商业动作或纯稳定结构复用，可以写：

`主要验证：无新增实验｜执行已验证稳定结构`

不为了形式强行制造实验。

如果当天存在商业动作，再确认：

- 今日经营决定是上海当天最新状态；
- 当前产品 / 服务真实可售或可预约；
- 价格 / 排期 / 容量 / 交付方式仍有效；
- 天象窗口仍有效且允许宣传；
- 跨平台商业触点数没有超出当天安排。

任何硬门槛未通过：只能保留为 `候选题｜待筛选`，不能进入正式执行。

正常通过后，对 Suen 只显示：

`选题状态：已通过硬门槛`

## 二、近期对标采样状态

为了避免同一天换一个对话后又把同一批 benchmark 重搜一遍，完成近期真实创作采样后，在当天 Slack 总控里保留一行短状态：

`近期对标：已刷新｜主任务 A/B/C/D｜账号：X、Y（必要时 Z）`

如果无法可靠取得：

`近期对标：样本未可靠取得｜已按长期 benchmark 方法降级判断`

这行只记录**是否刷新、为什么看这些账号、看了谁**，不把每天抓到的完整题目列表、链接和分析长期堆进 Slack。

同一 Asia/Shanghai 运营日里，如果这行已经存在、主任务和选题需求没有发生实质变化，可以复用当日样本。

跨日重新定新前台题时，再按 `内容商业对标系统.md` 刷新。

## 三、主要验证假设｜内部记录，Slack 保留短句

新的正式前台内容原则上只设 1 个主要验证假设。

最小格式：

```text
主要验证：
主任务：A / B / C / D
主要观察指标：
对照基线：最近最可比样本 / 无可靠可比样本
```

完整规则读取：`00-系统总控/内容实验与验证规则.md`。

假设必须在发布前写，数据出来以后不能倒推“其实这条是在验证 XX”。

假设用于发布后学习，不得为了实验纯度增加 Suen 的制作负担，也不得打断生产保护。

## 六、复盘时的验证结果短格式

取得合理数据窗口后，由总控回看当天发布前已经写好的假设。

写入 `#商业决策总控`：

```text
【验证结果】
对应内容：
结果：支持 / 不支持 / 无法判断
依据：一句话
信号状态：单样本 / 重复信号 / 稳定结构 / 不升级
```

结果只按原来确定的主要任务和主要观察指标判断。

不能因为其它指标漂亮，就事后更换实验目标。

## 七、执行提示词

只给当天真正需要执行的专用对话。

默认使用 `99-模板/专用对话执行提示词模板.md` 的**短交接格式**，只传：

- 前台合集 / 内容产品；
- 题目；
- A / B / C / D 主任务；
- 今天唯一需要特别优化的变量；
- 商业边界；
- 小红书是否同步同一成片。

主要验证假设通常留在总控，不要求专用对话为了实验额外改变正常制作；只有它与“今日唯一需要特别优化的变量”直接相关时才传。

不要把栏目长期规则、文笔总则、规则读取协议、视频交付格式全文重新复制进每日提示词。

这些由专用对话实际读取 GitHub 当前真源。

## 八、使用原则

- P0 优先于 P1，P1 优先于 P2；P0 未完成时，不用非阻塞性系统维护挤占主生产。
- 抖音大号和小红书当前仍有日更基线；偏离时写明真实例外理由。
- **定题先看 Suen 自己已经验证过的内容结构与真实数据，再用外部 benchmark 扩视野，不反过来。**
- **第一方数据按“单样本信号 → 重复信号 → 稳定结构”使用；单条爆款只提供验证假设，不直接升级成稳定公式。**
- **每条新的正式前台内容原则上只设 1 个主要验证假设，而且必须在看到结果以前写；复盘只判断支持 / 不支持 / 无法判断。**
- **主要验证假设与 A/B/C/D 主任务绑定，不能用无关指标宣布实验成功。**
- **跨账号迁移只迁移题目结构 / 入口假设，不把小号跑通直接当成大号已经验证。**
- **选题不只检查最近 7 天，还必须检查当前账号主页已有内容结构；账号样本少时，优先查看全部已发布内容。**
- **账号结构检查不是机械轮播：强题仍可连续同栏目，但如果同栏目已占当前主页绝大多数，继续重复必须先和至少 1 个其它内容体验的合格候选比较。**
- 小红书同步同一支成片只算一个制作任务，但商业触点按实际发布平台计算。
- 公众号贴图与长文继续独立判断，不恢复固定每日两篇。
- 朋友圈与抖音小号不机械日更。
- **抖音小号如果已经有真实素材、制作成本低，并且能验证一个明确的第一方内容假设，可以在 P0 完成后进入 P1；普通更新仍留在 P2。**
- 小号测试不能重新发展成一个重研究项目，也不能挤占大号 P0。
- 一天原则上只有一个主要商业信号，确有需要时最多两个明显商业触点。
- 纯内容日明确写“无”，不偷偷加 CTA。
- 不发的平台不生成无用执行提示词。
- 对标采用“双层”：五个长期 benchmark 方法一直参与判断；每天第一次定新前台题时，实际刷新最相关 2—3 个账号的近期创作，不机械刷五个最新内容。
- 当日近期样本已经刷新且任务未发生实质变化时，允许根据 Slack 中的“近期对标”状态复用，避免同日重复劳动。
- 选题进入生产保护状态后，总控不再中途追加新理论或擅自改栏目长期时长；只有核心事实 / 证据 / 路由 / 商业或天象硬边界，或 Suen 新补充的真实账号内容结构使原判断失效时，才退回重新定题。
