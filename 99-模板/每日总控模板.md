# Suen｜每日总控模板

状态：当前正式模板
最后核对：2026-09-18

用于“更新”完成诊断后的最终简洁输出，并区分：

1. 写入 Slack `#商业决策总控` 的“今日更新总表”；
2. 在 ChatGPT 对话里交给 Suen 的实际执行提示词。

正式定题以前必须先读取并执行：

`00-系统总控/选题定稿硬门槛.md`

商业信号、跨平台重复销售、旧价格 / 旧预约状态和跨日总控有效期统一读取：

`00-系统总控/商业信号与动态状态规则.md`

**没有完成栏目路由 + 五个对标账号方法 + 100 分模型 + 近 7 天重复度 + 证据可答性检查时，只能保留为候选题，不得使用本模板写成“最终题目”。**

## 零、定题前内部硬检查

在生成下面的 Slack 总表以前，先内部确认：

```text
【选题硬门槛】
栏目价值中心：通过 / 不通过
穹印之源｜中文入口：通过 / 不通过 + 原因
ESOTERICA｜证据与学术组织：通过 / 不通过 + 原因
Angela Puca｜source-based品牌：通过 / 不通过 + 原因
Foolish Fish｜商业连接：通过 / 不通过 + 原因
Let's Talk Religion｜复杂问题大众化：通过 / 不通过 + 原因
Suen 100分模型：已检查 / 未检查
最近7天重复度：已检查 / 未检查
核心答案证据可答性：通过 / 不通过
结论：可定稿 / 仅候选
```

如果结论不是“可定稿”，停止生成正式执行提示词，先改题或继续筛选。

如果当天存在商业动作，再额外内部确认：

```text
【商业状态硬检查】
今日经营决定是否为上海当天最新：是 / 否
产品当前可售 / 可预约：已确认 / 未确认
价格 / 排期 / 容量 / 交付方式：已确认 / 不适用 / 未确认
天象窗口日期是否仍有效：是 / 不适用 / 已过期待确认
今日商业触点数：
是否存在跨平台重复销售：无 / 有 + 原因
```

动态状态未确认时，不把旧价格、旧预约或旧“开放预约”直接写进今日任务。

## 使用原则

- 抖音大号与小红书有当前日更基线；如果当天偏离，写清例外原因，不把停更当默认。
- 公众号已经进入贴图 / 长文独立判断阶段，不套用旧的每日两篇机械频率。
- 朋友圈与抖音小号不要求机械日更。
- 先给结论，再给必要依据，不展开成长篇运营报告。
- 如果小红书直接同步抖音同一支完整成片，不再生成第二个“小红书视频制作”任务；在对应抖音栏目专用对话里一次完成小红书标题、封面与配文。
- 同一支视频只算一个制作任务，但如果视频本身含商业 CTA，发布到两个平台会形成两个真实平台商业触点；商业密度不能按“制作任务数”计算。
- 公众号贴图与长文必须分开判断，不能只写“公众号正常更新”。
- 一天原则上只有一个主要商业信号，确有需要时最多两个明显商业触点。
- 纯内容日明确写“无”，不要偷偷加 CTA。
- 不发的平台不生成提示词。
- **对标检查不是备注项；漏掉任何一次，对应题目自动降级为候选，不能继续执行。**
