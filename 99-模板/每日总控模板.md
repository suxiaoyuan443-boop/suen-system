# Suen｜每日总控模板

状态：当前正式模板  
最后核对：2026-10-14

本文件只规定**最终输出形状**，不重复保存选题、实验、商业密度等详细规则。

正式执行先按 `总控启动索引.md` 路由读取相关真源。

## 一、唯一输出入口

执行 `00-系统总控/每日总结与更新工作流.md` 第十二节，不保留另一套默认短版。

```text
今日判断：瓶颈｜改变判断的事实
P0：客户履约 / Revenue P0 / 可售阻塞 / 现有服务验证 / 有限知识产品 / 内容 / 数据库研究
动作与完成条件：
实际安排：只列今天执行、观察或发生变化的事项
发布时间 / 必要执行时段：
执行与交付：默认当前对话衔接；需要新素材或参数时只列真实缺项
执行顺序：
```

后台覆盖必要事项，前台可以合并无独立任务的平台；简洁不能漏已付款履约。

## 二、写入 GitHub 商业运行记录

保留最少必要信息：

```text
【今日判断】
主要瓶颈：
判断依据：

【P0】
类型与具体动作：
完成条件：

【P1 / P2】
只列实际任务

【主要验证】
有才写；没有写“无新增实验｜执行稳定结构”

【今日主要商业信号】
承载平台：
方向：

【今日明确不推】
```

新的流量 / 精准关注 / 研究前台候选，在后台按 `内容商业对标系统.md` 二-A保留来源依据。最终短输出可在“今日判断”下合并一句：

`选题依据：自有作品 / 指标 / 日期＋具体对标作品 / 指标 / 日期 → 本条新增问题或知识`

缺可比字段时明确待补；通知或已确定的商业动作不硬套。C/D候选按对标系统二-B留存真实疑问、可展示依据与业务关系；短输出只概括本次要帮助谁理解什么，不复制四项清单。不是另一套评分表，也不写入口播正文。

如果当天刷新近期对标，可增加一行：

`近期对标：已刷新｜主任务｜账号`

不要把完整搜索结果、100 分细项、SHA 清单写入当前商业动态文件。

## 三、直接执行与例外交接

视频默认由当前总控对话直接完成，读取每日工作流第十二节第4项。有限知识单元回 `07-销售与运行/有限知识产品验证规则v1.md`，课程/数据库内容回各自专用真源。内部准备、用户采用、技术交付、实际发布与付款分别记。

只有Suen明确要求其它对话/委派时，才生成最小交接变量；普通“更新”不再附专用任务词。

## 四、原则

- P0 优先于 P1，P1 优先于 P2。
- P0 类型和保护顺序按每日工作流；有内容任务时优先一份主生产单元，不默认双倍剪辑。
- 公众号贴图 / 长文独立判断。
- 小号、朋友圈、Patreon 不机械日更。
- 一天原则上只有一个主要商业信号。
- 不发的平台不生成无用提示词。
- 详细判断全部回对应真源，不在模板重复。
