# Suen｜每日总控模板

状态：当前正式模板  
最后核对：2026-09-23

本文件只规定**最终输出形状**，不重复保存选题、实验、商业密度等详细规则。

正式执行先按 `总控启动索引.md` 路由读取相关真源。

## 一、给 Suen 的默认短版

```text
【今日总控】

当前瓶颈：
判断依据：

【P0｜今天必须先完成】
抖音大号：栏目｜题目｜A/B/C/D｜建议发布时间
小红书：同步同一成片 / 独立任务 / 例外停更｜建议发布时间

【P1｜P0 后值得做】
只列今天真的需要做的公众号 / Patreon / 朋友圈 / 小号轻量任务

【P2｜有余力再做】
没有则省略

【商业信号】
无 / 承载平台 + 唯一商业方向

【今日明确不推】

【执行对话】
只给真正需要复制的短执行令
```

可选字段：

- 选题状态：已通过硬门槛 / 候选待筛
- 主要验证：只有今天确实有实验价值时显示
- Patreon：当前动态状态要求介入时才显示；暂停期默认不展示，也不写任何篇数进度目标

没有实际任务的块直接省略。

## 二、写入 GitHub 商业运行记录

保留最少必要信息：

```text
【今日判断】
主要瓶颈：
判断依据：

【P0】
大号：
小红书：

【P1 / P2】
只列实际任务

【主要验证】
有才写；没有写“无新增实验｜执行稳定结构”

【今日主要商业信号】
承载平台：
方向：

【今日明确不推】
```

如果当天刷新近期对标，可增加一行：

`近期对标：已刷新｜主任务｜账号`

不要把完整搜索结果、100 分细项、SHA 清单写入当前商业动态文件。

## 三、专用对话短交接

```text
执行今天正式更新。

前台合集 / 内容产品：
题目：
主任务：A / B / C / D
今日重点：
商业边界：纯内容 / 唯一允许的商业方向

按当前 GitHub 本栏目 / 平台规则完整执行。
没有真实阻塞时，自行完成研究、成稿、素材和 QA，一次性交付。
```

小红书同步时追加：

`小红书同步同一成片，并补标题 / 封面文字 / 发布配文。`

## 四、原则

- P0 优先于 P1，P1 优先于 P2。
- 当前通常先保护“大号 1 条 + 小红书同步同一成片”。
- 公众号贴图 / 长文独立判断。
- 小号、朋友圈、Patreon 不机械日更。
- 一天原则上只有一个主要商业信号。
- 不发的平台不生成无用提示词。
- 详细判断全部回对应真源，不在模板重复。
