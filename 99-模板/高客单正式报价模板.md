# Suen｜高客单正式报价模板

状态：当前正式模板  
建立：2026-09-27

用途：只在客户已经进入“方案适配确认”且当前真实价格已知时使用。

本模板是后台结构，不要求逐字发送给客户。前台表达继续服从 `07-销售与运行/销售私聊规则.md` 的自然微信语气。

---

## 使用前检查

报价前确认：

- 客户问题已经足够具体；
- 必要信息已经取得；
- 当前方案确实适配；
- 当前价格、执行条件、排期 / 天象资格真实有效；
- 没有虚构案例、效果、时间、名额或稀缺；
- 客户不需要自己从复杂技术菜单里选项目；
- 付款前条款已经经 Suen 确认，且本次平台 / 交易入口核查通过；
- 草案、内部情景价格与最终报价区分。

任一关键事实未知时，先补事实，不生成假报价。

---

## 后台报价结构

### 1. 客户当前问题

用一句话内部确认：

`客户希望推动：__________`

不要在前台复述过多隐私。

### 2. 当前专业判断

`当前建议：__________`

`主要原因：__________`

如果不建议做，直接停在专业判断，不为了成交硬给替代高价项目。

### 3. 当前方案包含

按 `07-销售与运行/完整定制仪式产品定义v1.md` 已确认范围，落实本单提供内容：

- 前期判断 / 定制方案；
- 材料与准备；
- 择时（适用时）；
- 实际执行；
- 执行时间信息及现场制作 / 仪式视频；
- 完成通知与完成后的效果占卜；
- 一次与本单有关的回访；
- 有实物时寄送，并附使用方法与注意事项手写信。

本单主要目标和视频 / 占卜 / 回访节点须说清；有实物包邮，快递费含报价。寄送地域和寄出时间另按本单确认。效果占卜按解读记录，客户实际变化单独跟踪；没有实物的方案不因此新增实物。

未提供的内容不为了显得高价而补写。

### 4. 当前执行条件

根据项目真实情况写：

- 可立即安排 / 需要等待；
- 日期 / 时间窗口（仅在已可靠确认时）；
- 材料 / 采购前提；
- 其它会改变执行的条件。

### 5. 正式价格

`具体项目 / 个别方案：__________`

`本单实际价格：¥__________`

每个仪式 / 物品分别核价；沿用该项目已确认现价或获得本项目改价确认。不得把历史 ¥1580 / ¥1680 情景自动填为所有项目统一价。常规现金成本≤¥30的口述估计只在具体适用项目中核对，不能全局减30报利润。

如果存在明确、真实的分阶段付款方式，由 Suen 当次确认后写。没有确认不得自动创造分期、定金或退款规则。

### 6. 付款后下一步

客户应该清楚：

- 付款后 Suen 会先做什么；
- 什么时候进入准备 / 排期 / 执行；
- 什么节点会收到通知、视频、效果占卜与回访；
- 有实物时如何寄送及收到使用说明；说明包邮及确认范围内的寄出时间、地域。

### 7. 结果与时间说明

付款前简洁、主动说明会影响购买决定的结果与时间边界，不等待客户追问：

- 不做百分百结果保证；
- 不承诺固定天数；
- 可以明确的是方案、准备、执行、状态通知和约定回访流程。

不要每次报价都机械附一大段免责声明。

---

## 前台发送原则

实际微信消息优先做到：

**判断清楚 + 方案清楚 + 价格清楚 + 下一步清楚。**

不要写成销售页，不需要一次发送所有后台字段。

一个自然报价通常只需要：

1. 先说当前更建议哪个方案；
2. 一两句说明为什么；
3. 说清本次价格；
4. 说付款 / 确认后下一步。

效果、案例等进一步疑问按真实资料回答；服务范围、价款、履行条件、回访 / 实体、改期和取消处理必须在付款前主动说清，可分消息或书面说明自然提供，不以客户没问为由省略。

---

## 报价后后台记录

正式报价发生后，在客户商业记录中更新：

- 机会阶段：正式报价；
- 报价金额；
- 报价方案；
- 客户主要顾虑；
- 是否给出决策时间；
- 下一步；
- 后续真实结果。

如果客户进入考虑期，按 `高客单机会漏斗.md` 处理，不把沉默自动写成失败。
