# Suen｜专用对话执行提示词模板

状态：当前正式模板
最后核对：2026-09-18

用于商业总控完成当天判断以后，把任务交给具体栏目 / 平台专用对话。

核心原则：

**总控只传当天变量；长期规则由专用对话自己实际读取 GitHub 当前真源。**

总控不再每天把栏目规则、文笔总则、规则读取协议、视频交付规则和 QA 条目重新复制进提示词。

完整生产优先级与保护规则读取：

`00-系统总控/总控简化与生产保护规则.md`

---

## 一、默认短交接格式

```text
执行今天正式更新。

前台合集 / 内容产品：
题目：
主任务：A｜流量 / B｜精准涨粉 / C｜服务认知 / D｜商业承接
今日重点：只写今天唯一真正需要优化的变量
商业边界：纯内容 / 唯一允许的商业方向

按当前 GitHub 本栏目 / 平台规则及统一验收规则完整执行。
没有真实阻塞时，自行完成研究、成稿、文笔 QA、素材 QA 和最终交付，不停下来等“继续”。
```

如果小红书同步抖音同一支成片，再追加：

`小红书同步同一成片，并补小红书标题 / 封面文字 / 发布配文，不重新制作第二支视频。`

这就是日常默认提示词。

---

## 二、专用对话收到短交接后必须自己做什么

专用对话正式生成以前，按当前仓库实际读取：

- 本平台 / 本栏目当前正式规则；
- `00-系统总控/规则读取验收协议.md`；
- `00-系统总控/专用对话执行验收协议.md`；
- `00-系统总控/Suen统一文笔总则.md`；
- `00-系统总控/文笔成稿验收协议.md`；
- 本任务对应的统一交付规则；
- 视频任务再读 `99-模板/视频类统一交付格式.md`。

抖音大号需要判断栏目边界时，同时读取：

`01-抖音大号/栏目选题边界与路由.md`

不能拿总控的短提示词代替栏目真源，也不能用旧对话记忆代替本轮必要读取。

---

## 三、读取回执什么时候展示

正常稳定日不要求把一大串 SHA 挡在成品前面。

只有以下情况显示简短【GitHub读取回执】：

- Suen 明确要求；
- 仓库刚修改过与本任务直接相关的规则；
- 当天已经发生过规则误读 / 冲突；
- 旧对话记忆与仓库可能冲突；
- 读取失败或需要定位执行故障。

需要显示时，按 `规则读取验收协议.md` 执行。

读取动作本身仍然必须真实发生；“不展示回执”不等于“可以不读”。

---

## 四、生产保护

当天题目已经通过硬门槛并进入生产后，专用对话按既定任务完成，不因为新的临时灵感反复推翻方向。

只有以下真实阻塞可以退回总控：

- 核心事实 / 证据不成立；
- 核心问题实际答不出来；
- 栏目路由明显错误；
- 商业 / 天象 / 法律或平台硬边界冲突；
- Suen 明确改变任务。

文笔、素材、图片链接、排版和交付格式问题优先由专用对话自行修好，不自动退回重新选题。

---

## 五、视频任务

视频正式交付统一读取：

`99-模板/视频类统一交付格式.md`

最终使用体验固定为：

**看到一段完整口播时，旁边或紧跟位置立即看到这一段真正要用的图片 / 画面。**

不默认增加：

- 时间列；
- 素材编号匹配表；
- 文件名第三列；
- 需要打开 ZIP / TXT 才能理解的素材流程。

聊天界面无法严格双栏时，自动使用：

**完整口播 → 紧跟对应图片 → 下一段完整口播 → 紧跟对应图片。**

不要回复“这种交付不了”然后停止。

完整视频主体结束后，必须直接跟上该平台可发布的最终标题与标签；如果同一成片同步多个平台，按平台分别给标题 / 标签，并在同一次完整交付中完成。

---

## 六、小红书同步

小红书当天直接同步抖音同一支完整成片时：

- 只算一个制作任务；
- 不重新剪第二支视频；
- 在同一份成片稿后补小红书标题、封面文字和发布配文；
- 商业边界保持当天总控一致。

---

## 七、公众号

公众号提示词只需明确：

- 贴图 / 长文 / 两者；
- 题目 / 方向；
- A / B / C / D 主任务；
- 商业边界。

公众号自己读取：

- `03-公众号/阿赫特之门.md`
- `03-公众号/公众号文笔规则.md`
- 对应对标 / 交付规则。

不恢复旧的固定“1长+1贴”。

---

## 八、朋友圈

朋友圈只有总控明确安排时才生成。

专用对话自己读取 `04-朋友圈/朋友圈规则.md`。

总控只需要传：

- 今天为什么发；
- 是工作记录、提醒还是商业承接；
- 唯一允许的商业方向（如有）。

---

## 九、最终目标

这套模板的目的不是让每日提示词越来越完整，而是让它越来越短。

**仓库负责长期规则，总控负责当天变量，专用对话负责把任务完整做完。**
