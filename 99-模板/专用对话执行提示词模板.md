# Suen｜专用对话执行提示词模板

状态：当前正式模板
最后核对：2026-09-18

用于商业总控完成当天判断以后，把任务交给具体栏目 / 平台专用对话。

核心原则：

**总控只传递“今天为什么做、做什么、承担什么任务、哪些边界不能碰”；专用对话继续负责按自己的长期规则生成完整成品。**

不要在总控里重新复制整套栏目长期规则，也不要因为流量优化替栏目改掉 Suen 文笔。

---

## 一、前台栏目名 ≠ ChatGPT 对话名

GitHub 记录的是当前正式前台结构和执行规则，不保证用户的 ChatGPT 专用对话标题已经同步改名。

例如：

- `隐理 / 世问` 是当前前台合集名；
- `口述` 只保留为内部内容母类；
- 旧专用对话仍保留历史标题，不代表前台继续使用旧合集名。

因此总控交接时必须明确今天前台发布属于哪个合集。

如果不知道某个新合集是否已有独立专用对话，不虚构对话名 / 对话 ID。

---

## 二、规则真源与读取验收

GitHub 当前正式规则是专用对话生成正式成品前的配置真源。

必须执行：

- `00-系统总控/规则读取验收协议.md`
- `00-系统总控/专用对话执行验收协议.md`
- `00-系统总控/Suen统一文笔总则.md`
- `00-系统总控/文笔成稿验收协议.md`
- 本平台 / 本栏目的当前正式规则
- 本任务对应的统一交付规则
- 视频任务再读 `99-模板/视频类统一交付格式.md`

不能用旧对话记忆、项目摘要、“之前读过”或总控提示词对规则的二次概括代替本轮必要读取。

当 Suen 明确要求“先读仓库 / 按最新 GitHub 执行”，或当天已经发生规则读取错误 / 冲突时，正式成品前先输出简短【GitHub读取回执】：

- 实际读取文件路径；
- 当前 SHA；
- 本次直接影响成稿的硬规则；
- 冲突检查。

GitHub 可访问但关键文件读取失败时，不得继续生成正式最终成品。

当前对话根本无法访问 GitHub 时，明确写：

`当前对话无法实际访问 GitHub，因此不能声称已读取仓库。`

然后使用本专用对话内最新、最明确规则 + 当天总控交接；商业方向无法确认时默认纯内容。

---

## 三、通用交接模板

```text
执行今天的正式更新。

【GitHub读取是强制前置步骤】
先实际读取：
1. 本平台 / 本栏目的当前正式规则；
2. `00-系统总控/Suen统一文笔总则.md`；
3. `00-系统总控/文笔成稿验收协议.md`；
4. `00-系统总控/专用对话执行验收协议.md`；
5. 本任务对应的统一交付规则；
6. 视频任务：`99-模板/视频类统一交付格式.md`；
7. 本提示词另外点名的其它规则文件。

同时执行：
`00-系统总控/规则读取验收协议.md`

禁止用旧对话记忆、项目摘要、之前读过或本提示词对规则的概括代替本轮实际读取。

读取完成以后，先输出【GitHub读取回执】：
- 文件路径｜SHA
- 本次直接影响成稿的硬规则
- 冲突检查：无 / 有

GitHub 可访问但关键文件读取失败：停止生成正式成品。
无法访问 GitHub：明确说明，禁止声称已读取。

【今日总控任务】
平台：
前台合集 / 内容产品：
题目 / 选题方向：
主任务：A｜流量 / B｜精准涨粉 / C｜服务认知 / D｜商业承接
辅助目标：（没有则省略）

【为什么今天做这个】
用1—3条写清当前瓶颈和这条内容要解决什么。

【今天需要特别优化】
只写今天真的需要调的项目，例如第一屏、信息顺序、案例数量、素材节奏。
不要用总控临时要求覆盖栏目自己的长期时长 / 文风 / 研究规则。

【执行】
严格执行 `专用对话执行验收协议.md`：
- 先内部确认核心答案和证据是否成立，再展开长稿；
- 同日研究同日交付是允许的，不擅自新增多日准备期；
- 任务目标明确且没有真实阻塞时，不做到一半停下来等“继续”；
- 能自行解决的问题先自行解决，不把搜图、裁图、匹配、排版和明显 QA 转给 Suen；
- 如果成品出现问题，先检查规则读取 / 执行偏差，不先重新发明栏目理论。

【文笔】
严格执行本栏目正式规则 + `Suen统一文笔总则.md`。
正式成稿发出前执行 `文笔成稿验收协议.md`。
发现同义复述、连续否定、抽象词替代具体对象、擅自拔高理论、不可自然口播等问题，先自行重写，不交给 Suen 做人工质检。

【商业边界】
今天：纯内容 / 允许的唯一商业方向

纯内容：禁止接单、报价、预约、购买、私信引导或其它商业 CTA。
允许商业信息：只能使用总控明确指定的唯一方向，不自行扩展第二个产品 / 服务广告。

【交付】
按本栏目当前正式交付格式生成最终可执行成品。
未完成规则读取、冲突检查、执行验收与文笔验收，不得标记“最终版 / 可录制版 / 可发布版”。
视频任务严格执行 `99-模板/视频类统一交付格式.md`。

视频主交付必须做到：
- 口播与真实图片直接相邻；
- 当前界面支持时，左边完整口播，右边直接显示图片；
- 不支持严格双栏时，一段完整口播后立刻直接显示对应图片；
- 默认不增加时间码、素材编号、文件名第三列；
- ZIP / TXT / 素材包只能作为可选补充，不能成为理解对应关系的必要步骤；
- Suen 不打开任何补充附件，也必须能直接知道每段该用哪张图。

不要先写长篇修改思路。
```

## 四、A / B / C / D 说明

- `A｜流量`：陌生人点击、停留和进入。
- `B｜精准涨粉`：让真正相关的长期受众识别并关注 Suen。
- `C｜服务认知`：让观众理解 Suen 会判断 / 处理什么以及工作边界。
- `D｜商业承接`：把已经存在的需求承接到询盘、报价、预约、购买或成交。

同一条内容只指定一个主任务；专业信任、收藏、搜索等可以作为辅助目标。

---

## 五、所有视频任务｜视觉交付

统一执行：

`99-模板/视频类统一交付格式.md`

核心标准不是“有没有做素材包”，而是：

**Suen 看到某段口播时，旁边或紧跟位置立刻就是这一段真正要用的图。**

优先级：

1. 当前界面支持：真正双栏，左边完整口播，右边直接显示对应图片；
2. 当前界面不支持表格内直接显示图片：自动切换成“一段完整口播 → 紧跟对应图片预览 → 下一段口播 → 紧跟下一组图片”；
3. 当前聊天显示受限但具备文件生成能力：可以生成单个 HTML / DOCX 可视化成品，内部真正左口播右图片；
4. ZIP 只允许作为可选的批量下载补充，必须放在主交付之后；
5. 默认不做 `时间｜口播｜素材编号` 三列表；
6. 默认不增加预计时间码；
7. 不得因为严格双栏渲染受限，就回复“这种交付不了”然后停止；
8. 不得退回“素材编号 + 另一份素材表 / 素材包让 Suen 自己匹配”的旧流程。

交付前必须自己检查：

- 不打开 ZIP，是否已经能直接剪；
- 不记 01 / 02 / 03 编号，是否仍能知道每段用什么图；
- 图片是否真正显示在对应口播附近；
- 有没有为了显得专业加入不必要的时间、文件名、素材管理信息。

任一项不通过，先自行重排。

---

## 六、小红书同步

当天小红书直接使用抖音同一支完整成片时：

- 不重新剪辑、不另做第二版视频；
- 在同一成片稿之后额外给小红书标题候选、封面文字候选、发布配文；
- 视频主体与商业边界保持一致。

---

## 七、公众号

公众号提示词分别写清今天是贴图、长文或两者都有，以及各自承担的任务。

不得恢复旧的“固定1长+1贴”逻辑。

贴图 + 长文同日发布时，最多只有其中 1 篇允许出现轻商业信息；另一篇保持纯内容。

公众号最终语言服从 `03-公众号/公众号文笔规则.md`。

---

## 八、朋友圈

只有总控明确安排朋友圈时才给提示词。

继续服从：

- 像本人临时说话；
- 默认无标点；
- 不用运营文案腔；
- 天象只写可靠核查事实；
- 不虚构稀缺；
- 精确时分有冲突时不公开具体时间。

---

## 九、不执行的平台

当天明确“不发”的平台：

- 不生成成品；
- 不生成无用提示词；
- 不因为“顺便”增加第二份工作。

目标是让每天总控实际减少 Suen 的工作量，而不是把一个决策拆成更多任务。
