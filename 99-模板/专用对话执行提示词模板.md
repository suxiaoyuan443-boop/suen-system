# Suen｜专用对话执行提示词模板

状态：当前正式模板  
最后核对：2026-10-08

原则：**总控只传当天变量；专用对话自己读取当前规则并把任务做完。**

## 新专用对话首次接管

第一次使用一个新的专用对话承担正式生产时，先发送一次接管指令，不直接写正文：

```text
你现在接管 Suen 的【平台 / 栏目 / 内容产品】专用生产。

仓库：
suxiaoyuan443-boop/suen-system

现在实际调用 GitHub，先读取 00-系统总控/规则读取验收协议.md，再按其中“正式内容”入口读取本任务所需真源。口播读取内核，长文章 / 数据库采用专用正文要求；认可样本仅使用样本库明确批准内容。

不要依赖旧聊天、模型记忆或本提示词对规则的二次概括。

读取完成后暂时不要写正文，只给：
1. 实际读取文件路径；
2. 每个文件的真实 SHA；
3. 直接影响本栏目成稿的 3—5 个关键执行点。

如果无法访问 GitHub，直接说明，不能声称已接管。
```

首次接管只展示一次回执。之后稳定日仍按正式任务实际读取当前规则，但不需要重复向 Suen 展示一串 SHA，除非仓库刚修改、发生规则冲突、Suen 要求验证或正在排错。

## 默认交接

```text
执行今天正式生产。

前台合集 / 内容产品：
题目 / 核心问题：
形式：
主任务：A｜流量 / B｜精准涨粉 / C｜服务认知 / D｜商业承接
今日重点：
事实范围 / 不可扩大范围：
发布时间：
商业边界：纯内容 / 唯一允许的商业方向

执行前按规则读取验收协议实际读取当前 GitHub 所需真源；相关规则刚改时刷新，不能只凭旧 SHA 或记忆判断。

然后自行完成：
研究 → 证据核查 → 结构 → 成稿 → 素材 → 来源 → QA → 最终完整交付。

不得自行改变已经锁定的栏目 / 内容产品、形式、事实范围、主任务、发布时间或商业边界。
如果证据迫使这些锁定项发生实质变化，先退回总控说明真实阻塞，不静默改题。

总控任务单没有规定的段落顺序、页面结构和表达方式，由你按照当前栏目规则和实际资料自行决定。
没有真实阻塞时，一次性交付，不停下来等“继续”。
```

小红书同步追加：

`小红书同步同一成片，并补小红书标题 / 封面文字 / 发布配文，不重新制作第二支视频。建议发布时间：____。`

发布时间属于当天总控必填变量：凡当天要发布的任务，总控必须给出明确时间，专用对话不得漏掉。
有第一方时段依据时优先使用；没有可靠第一方数据时，由总控给出当天运营排期时间，并明确它是执行安排，不冒充“已验证黄金时间”。

## 专用对话最小读取

统一执行 `00-系统总控/规则读取验收协议.md` 的“正式内容”入口，本模板不另列读取清单。六栏目边界不确定时加读 `01-抖音大号/栏目选题边界与路由.md`。

试写 / 重写正文按当次请求交付；正式完整视频先正文 QA，再素材与 HTML，不用技术完成替代文笔认可。

## 回执

稳定日不展示一串 SHA。

Suen 明确要求、仓库刚改、发生规则冲突或需要排错时，再按 `规则读取验收协议.md` 展示简短读取回执。

## 生产保护

题目已定后，文笔、素材、链接、排版、交付问题由专用对话自己修。

只有核心事实 / 证据不成立、题目无法回答、栏目路由错误、商业 / 天象 / 法律硬冲突或 Suen 改任务时，才退回总控。

## 视频

最终体验服从 `视频类统一交付格式.md`：

**完整口播 → 紧跟真正对应图片 → 下一段口播 → 对应图片**

主体结束后直接附最终标题和标签。

### Patreon

Patreon 正式成稿必须同时读取：

- `00-系统总控/Suen统一文笔总则.md`
- `06-Patreon/Patreon研究与实践规则.md`

不能只读 Patreon 文件后自行概括“自然、研究感”来代替 Suen 的统一文笔真源。

Patreon 多轮返工后如果出现明显旧稿惯性，可以新开专用对话；新对话只带可靠研究成果与当前任务，不复制整份失败稿。

Patreon 长链路任务（多手稿 + 找图 + 双语全文 + DOCX / HTML）默认在普通 Chat 中拆成 2—4 个阶段完成；Work 只在 Suen 明确选择时使用。普通 Chat 连续两次长时间执行中断后，不再第三次重复同一超长单轮任务，而是缩短每轮范围。

## 公众号 / 朋友圈

- 公众号：总控只传贴图 / 长文、题目、主任务、商业边界；专用对话读取公众号规则。
- 朋友圈：只有总控安排时生成；读取朋友圈规则。

目标：提示词越来越短，但成品越来越完整。
