# 天象检索与预约简版模板

状态：当前正式模板
最后核对：2026-09-23

用于把完整技术择时分析压缩为 GitHub `08-动态运行/天象/` 的经营记录。完整技术推导保留在专用择时系统，不复制到动态运行区。

```text
【天象窗口】
项目：
目的：
地点：
日期：
时间窗口：
评级：B / A / S / SS
状态：候选 / 待复核 / 已确认 / 开放预约 / 准备中 / 执行中 / 已完成 / 已淘汰 / 已取消
适合用途：
核心优点：
1.
2.
需要注意：
1.
2.
是否允许商业宣传：
当前预约数：
承载能力：
商业阶段：
```

原则：

- 正式记录尽量控制在约 20 行以内。
- 经营简版只保留结论层和经营层信息。
- 行星、月亮、应用/分离、orb、VOC、接纳、Bonatti 检查、原典长文等完整推导留在专用择时系统。
- 未完成复核时不得把候选窗口写成“已确认”。
- 只有 Suen 明确确认后才能标记“已确认”。
- `候选 / 待复核` 默认只是内部经营状态，不能因为填进模板就自动变成对外宣传的“好日期”。
- `是否允许商业宣传：是` 必须来自当前已确认 / 可靠筛选的经营状态，不能为了成交自行填写。
- 没有确认具体日期时，对外只能使用预约制事实，例如“下一批日期确定后开放预约 / 目前采用预约制 / 具体执行日期根据实际天象安排”。
- 不虚构“最佳日期 / 本月唯一窗口 / 名额紧张”等营销稀缺。
- 如果精确执行时刻在不同记录之间存在冲突，`时间窗口` 不得自行挑一个填写成最终公开时刻；应写“待复核 / 以专用择时系统最新可靠复核为准”，或保留当前内部记录并明确冲突状态。
- 经营层可以先记录“开放预约 / 是否允许商业宣传”等状态，但对外公开具体时分前必须以专用择时系统最新可靠复核结果为准。

完整经营边界读取：`05-天象经营/天象预约池规则.md`。
