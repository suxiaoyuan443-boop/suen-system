# Suen｜视频类统一交付格式

状态：当前正式模板  
最后核对：2026-09-19

适用于抖音大号、小号及同步小红书的视频。

目标只有一个：

> **Suen 从上往下看，就能直接完成“读口播 → 看对应图片 → 剪这一段 → 继续下一段”。**

## 一、主交付

优先：

| 完整口播 / 台词 | 直接图片 |
|---|---|
| 自然、连续、可直接录制的一整段 | 这一段真正要使用的图片 / 图片组 |

如果聊天 UI 不适合表格内嵌图，自动改成：

**完整口播 → 紧跟对应图片 → 下一段口播 → 紧跟对应图片**

不能改成“口播 + 素材编号”或“正文结束后统一列素材”。

## 二、默认不要出现

除非 Suen 当次明确要求，不增加：

- 时间列 / 预计时间码；
- 素材编号作为理解依据；
- 文件名代替图片；
- 独立镜头表；
- 必须打开 ZIP / TXT 才能理解的流程。

ZIP 只能是可选补充，不能成为主交付。

## 三、图片

- 第一视觉必须是图片 / 预览本身；
- 多张图按真实剪辑顺序直接展示；
- 外部资料保留可靠来源页；
- 使用说明只需极简，如 `整页 → 放大第4行`；
- 真实文物、手稿、纸草、原书页优先；
- 不用 AI 图冒充真实资料；
- 没有稳定直链时明确写 `当前未取得稳定图片直链`，不伪装已交付。

不要因为暂时缺素材就把搜图、匹配、裁切工作转给 Suen。

## 四、口播

- 一块是一整段自然口播，不为了配图机械一句一块；
- 文笔服从 `Suen统一文笔总则.md` 和栏目规则；
- 原文 / 手稿 / 文物出现时主动告诉观众看哪里、什么意思、为什么重要。

## 五、标题与标签

完整主体结束后必须直接追加：

**标题：** 最终可发布标题  
**标签：** #相关标签

不等 Suen 再追问。

如果小红书同步同一成片，再直接追加：

- 小红书标题
- 封面文字
- 发布配文
- 必要标签

不重新生成第二份视频主体。

## 六、无法直接显示图片时

如果当前环境不能直接显示，但可以生成单一可视化文件，可用一个 HTML / DOCX 作为主交付，仍保持“口播 ↔ 图片”直接对应。

如果两种方式都做不到，明确说明界面限制并使用最接近的紧贴模式；不能只说“交付不了”。

## 七、最终检查

交付前只检查：

1. 每段口播旁边 / 后面是否直接看到对应图；
2. 是否需要靠编号、ZIP、文件名二次匹配；
3. 是否有无必要时间码；
4. 图片是否真实、正确、顺序可剪；
5. 主体结束后是否已经有最终标题和标签；
6. 同步小红书时是否已补标题、封面、配文。

任一项不通过，先自行修复。
