# Suen｜视频类统一交付格式

状态：当前正式模板  
最后核对：2026-10-12

适用于抖音大号、小号及同步小红书的视频。

## 零、最终视频画幅｜2026-10-12

Suen 已明确：**所有最终视频成品统一采用宽∶高＝4∶3的横向画幅。** 本条适用于Suen各平台视频，包括大号、小号及跨平台同步；下文各栏目交付方式仍按原有范围执行。

- 制作与导出均采用4∶3画布，不因抖音或小红书的常见版式自动改为9∶16、16∶9或3∶4。Suen当次另有明确要求时以当次指令为准。
- 1440×1080、1920×1440等均为4∶3尺寸示例，不另设强制分辨率；依实际素材清晰度与剪辑条件选择，不能将尺寸放大等同于画质提高。
- **成片画幅与资料图片比例分别处理。** 原始图片、原书页及相册导入包继续保留真实比例和来源画质；放入4∶3画布时等比缩放、安排留白或简单底色，不能拉伸人物、器物或文字，也不能为了填满画面强裁关键证据、题刻、页边或上下文。
- 整页、竖图或窄局部的展示继续执行“三-A、裁切与连续观看门”；需要推近时保留可追踪的位置关系，不用生成式扩图或修复填补4∶3画布。
- 字幕、标题及本人出镜位置在4∶3实际预览中检查，避免遮挡关键证据、文字溢出和边缘截断。HTML或PDF的阅读页面可正常滚动，不要求整份阅读文件采用4∶3纸张或将每张来源图改成4∶3。
- 交付最终视频文件时，核导出宽高、显示比例及实际画面，确认4∶3且无拉伸、误裁和遮挡。只交HTML、图片、ZIP或PDF时，只能记录“按4∶3剪辑准备”；没有实际成片，不写成“成片比例已验收”。

## 栏目专属格式优先级

如果某个栏目已经明确存在更稳定的专属交付格式，以该栏目当前规则为准。

当前已确认：
- **《文物》固定使用 HTML 主交付**；
- HTML 内继续执行 Suen 已确认的“完整口播段落 → 对应实际图片直接显示 → 下一段口播 → 下一组图片”；
- 《文物》不以聊天消息内嵌图作为正式主交付；
- 《文物》不使用“完整口播 + 原句锚点素材区”作为正式主交付；
- 具体读取 `01-抖音大号/文物.md`。

不要用本模板把《文物》改回聊天内拼接、素材编号表或独立素材清单。

目标只有一个：

> **Suen 从上往下看，就能直接完成“读口播 → 看对应图片 → 剪这一段 → 继续下一段”。**

## 正文生成与HTML切块顺序｜2026-10-07

“完整口播段落 → 对应图片”是**最终交付排版**，不是正文生成模板。

正式生产时必须：
1. 先完成一份连续自然口播；
2. 先做栏目核心 / 深度 / 故事 / 真人文笔QA；
3. 通过后再根据实际换图点切成HTML口播块；
4. 不因为切成多个beat，就给每个beat补“解释—总结—收束”。

禁止从一开始就按：
`口播1观点 → 图1 → 口播2观点 → 图2 → 口播3总结`
来生成正文。

这种写法会把素材编排结构反向污染成稿文风，形成模块化AI整理稿。

## 一、主交付

优先：

| 完整口播 / 台词 | 直接图片 |
|---|---|
| 自然、连续、可直接录制的一整段 | 这一段真正要使用的图片 / 图片组 |

大号正式视频不再根据聊天 UI 在“聊天内图文”和 HTML 之间切换。

**固定生成单一 HTML 主交付：完整口播 → 紧跟对应图片 / 图片组 → 下一段口播 → 下一组图片。**

不能改成“口播 + 素材编号”、聊天内单独发图或“正文结束后统一列素材”。

## 二、默认不要出现

除非 Suen 当次明确要求，不增加：

- 时间列 / 预计时间码；
- 素材编号作为理解依据；
- 文件名代替图片；
- 独立镜头表；
- 必须打开 ZIP / TXT 才能理解的流程。

ZIP 不得替代 HTML 口播与图片主交付，也不得要求 Suen 打开 ZIP 才能理解正文或找到对应图片。**但在六栏目含图片正式交付中，“相册导入包.zip”属于默认附加交付，不再是可省略的素材附件。** 下文“iPad 相册导入包”规定其范围与验收。

## 三、图片

- 第一视觉必须是图片 / 预览本身；
- 多张图按真实剪辑顺序直接展示；
- 外部资料保留可靠来源页；
- 使用说明只需极简，如 `整页 → 放大第4行`；
- 真实文物、手稿、纸草、原书页优先；
- 不用 AI 图冒充真实资料；
- **正式资料图默认不加红框 / 红色矩形高亮。** 需要观众看局部时，按下文“裁切与连续观看门”采用保留上下文的放大 / 裁切或简短图注定位；只有 Suen 当次明确要求时才使用彩色框；
- 没有稳定直链时明确写 `当前未取得稳定图片直链`，不伪装已交付。

不要因为暂时缺素材就把搜图、匹配、裁切工作转给 Suen。

## 三-A、画面脚本与素材覆盖硬门｜2026-10-08

口播通过以后、HTML 生成以前，必须先在内部做一次**画面脚本 / 素材覆盖检查**。不要求把独立镜头表交给 Suen，但系统内部必须能回答每一段“实际用什么图”。

### 0. 三层记录与实际展示

在内部把以下三层分开：原始来源图有几张、可辨证据 / 焦点有几个、交付HTML实际显示了哪些不同画面。单元数必须能对应到已交付的图片 / 局部、原文位置和该段新增信息；只写一条剪辑动作不算已经落实。

同一原页可以带读不同具体词句，前提是实际显示位置可辨、每次解决新问题。若需要独立裁切，应在交付中真正给出相应局部；不能把相同整页重复内嵌后自报多个新单元，也不能因为一次失败就禁止所有同页带读。

### 1. 视觉数量与推进

对常规 45—90 秒视频：
- 原则上至少形成 **6 个有效视觉单元**；
- 60—90 秒、信息点较多时优先做到约 8—12 个视觉变化；
- 数量仅为前置覆盖检查，不证明实际展示已合格；仍保留现有原则性下限，不要求机械每几秒换图，也不为了凑数压碎完整句子或加入无关图。
- 超过90秒的口播按真实时长与知识推进匹配，不把45—90秒的数字当所有长稿的完成标准。

每个视觉单元必须至少满足一项：
- 展示新的对象 / 角度 / 同组物；
- 展示新的原页 / 版本 / 档案；
- 展示同一原页上新的具体行、词或位置；
- 展示能改变理解的局部；
- 建立有意义的对照。

### 2. 重复限制

- 同一张完整图原样重复原则上不超过 2 次；
- 如果再次使用同一来源，必须改变观看任务：例如整件 → 针刺部位局部 → 铅片同组物，而不是简单放大 / 缩小；
- 连续两个口播块不应默认使用完全相同的画面；
- 只有当口播确实重新指向同一证据位置时才允许回到同图。

### 2-A. 裁切与连续观看门｜2026-10-10

局部图用于带读证据，必须同时保持可辨位置、上下文和连续观看的观感。**有独立词句、有新增信息或已满视觉数量，均不能豁免这一门。**

- 先提供实际取得的整页 / 较完整对象或较大局部，建立位置关系；馆方只公开局部时如实标注“官方公开局部”，不称为整页。不可为补边缘、文字或缺失内容使用生成式修复。
- 裁切保留足够相邻行、页边、红字 / 栏目等实际参照。单行或少数行被截成极窄横向字条、截断关键文字或失去定位参照时，默认退回重新选择范围；特殊细节确实需要窄图时，只作有上下文衔接的辅助，不直接撑满主画面。
- HTML 与目标剪辑画面分别检查。图片保持比例，结合容器、留白和展示尺度避免字条、竖图与整页之间突兀跳变；不拉伸、过度放大，也不为统一画幅强裁所有图片。
- 同页连续推近 / 带读可以使用；须在实际图或可检查预览中明确当前段、行、词的位置。若仅有母图和一句“推近”，只记剪辑路径，不能报独立局部 / 成片已完成。需要独立剪辑图时实际导出带上下文的清晰局部，保留母图；不要求每个词都另存一张窄图。
- 辅助图必须对应当前口播的明确观看任务。正文没有对应任务的同卷页、插图或背景图移到资料附录，不为凑数加入主剪辑流程，也不为保图追加无必要口播。
- 交付前实际查看移动端显示和相邻画面，核文字可读、位置可追踪、边缘无误裁、尺寸过渡自然。未查看实际显示时写“观感待核”；明确负反馈未修复时写“返工版｜待验收”。仅修视觉时保留现有口播，发现核心事实 / 正文问题另行说明；不得顺手压短口播或从零重写。

本门适用于原页、铭文与器物局部等证据图。允许合理裁切，不恢复重复整图凑单元，也不将图片数量作为质量通过证明。

### 3. 文字不能充当缺图补丁

以下内容**不计入有效视觉单元**：
- ChatGPT / Suen 自制的大段说明文字；
- 现代中文翻译整页；
- 把口播重新排成图片；
- 来源卡、参考文献列表；
- 为了“有画面”临时做的标题卡。

例外：
- 原始手稿、原书、纸草、铭文、档案等，文字本身就是研究对象；
- 即使如此，也要通过整页、局部、行、词、版本差异等方式形成真实视觉推进，不能一页文字从头重复到尾。

### 4. 缺图时的处理顺序

素材不足时依次尝试：
1. 同一对象的其它官方 / 公版角度；
2. 对象局部裁切；
3. 同组出土物 / 同一卷册相关页；
4. 原始版本、早期版画、地图、历史照片或馆藏档案；
5. 可靠学术出版中的必要图版；
6. 仍不足则退回“素材覆盖不足”。

**禁止用 AI 假史料、相似但错误的图、重复图或现代文字卡把素材门硬凑过去。**

### 5. HTML 生成许可

只有以下三项同时成立才进入 Base64 / HTML：
- 正文 QA 通过；
- 栏目 QA 通过；
- **素材覆盖 QA 通过。**

进入包装前先落实画面路径，包装完成后再看交付文件实际渲染的图。内部核对每个信息推进点是否真的显示对应焦点、关键字是否可读、相邻块是否只重复同一整图。检查落到实际文件和具体位置，不用一句“12个单元 / Base64正常”替代。

若只能确认链接 / Base64 / 清单而未看实际展示，回执应写技术或清单检查完成、实际展示待核，不标素材成品通过。Suen已否决的版本即退件；无新的修复与验收事实，不恢复旧通过状态。

## 三-B、iPhone / iPad 相册导入包｜2026-10-09

Suen 使用 iPhone / iPad 进行视频剪辑。此前 HTML 图片虽以 Base64 内嵌，却需要逐张打开或截图才能进系统相册，显著增加人工操作。**从本规则起，大号六栏目有图的正式交付默认同时提供两个成果：**

1. **HTML 主交付**：完整口播与实际图片紧贴，仍是唯一阅读 / 剪辑对照主文件。
2. **相册导入包.zip**：另外提供真实 JPG / PNG 图片文件，供 iPhone / iPad 从“文件”App 一次性多选存入“照片”App。不能只给 HTML、一个图片链接列表或声称 HTML 已内嵌就视作图片可导入。

### 相册导入包内容

- ZIP 根目录优先直接放可导入的 JPG / PNG 图片；不要夹入 HTML、PDF、TXT、说明卡、隐藏的图片缩略图或无关文件，确保 iPad 解压后可直接全选图片。
- 图片按实际剪辑使用顺序命名：`01-主题-画面用途.jpg`、`02-主题-局部.png` 等。文件名自然中文、简短；不要只用不明数字作为语义索引。
- **必须是 HTML 中实际展示、且剪辑真正要使用的画面**：整件图、对应局部裁切、不同角度、同组物、明确标注的辅助历史图像；确需独立剪辑的局部通过上文“裁切与连续观看门”后交独立图片，保留母图；连续带读以实际母图 / 预览交付，不强制将每个词拆成窄图，不能要求 Suen 自行截图取得缺失素材。
- 如果同一图片在 HTML 被重复使用，ZIP 可只放一次文件；ZIP 的序号服务第一次出现的剪辑顺序，HTML 继续显示实际每次的对应图。
- 不能用同一张图复制出多个文件来凑数量；不能放低分辨率网页缩略图冒充已有清晰原图。
- 逐图保留真实来源与许可 / 归属信息在 HTML 的对应图片说明或来源区；**不得因为打包而移除必要署名、扩大版权使用权限**。若某图不可合法下载 / 打包 / 传播，不能强行收入 ZIP；应换合规来源、退回缺图，或清楚说明限制。
- 图像默认保留原来源的像素尺寸和画质；需要局部剪辑时另存足够清晰的实际裁切版本，不要通过截图得到图。
- 除非 Suen 当次要求，**不**在照片本身叠加大段中文翻译、标题或来源说明；本应在视频字幕解决的文字不做成图像主体。
- 可选另有“原始高清资料包”，但不与相册导入包混合；默认相册导入包只包含实际剪辑用图。

### 生产步骤与验收

1. 完成已有口播 / 栏目 / 素材质量 QA；
2. 正式取得每张可用图片，落实需要的局部及母图，按“裁切与连续观看门”检查；HTML 与 ZIP 使用相同的实际视觉资产，资料附录图不混入主剪辑包；
3. 验证 ZIP 真实存在、可解压，内部均是可被系统相册识别的 JPG / PNG，且尺寸 / 数量 / 对应画面无遗漏；
4. 正式交付在 HTML 链接旁，**再提供直接可下载的相册导入包 ZIP 链接**；不能只写 ZIP 文件名或把一串来源网页当下载包；
5. 如果技术上未成功生成 ZIP，明确说明“相册导入包未完成”，不能写“已交付可批量存相册”；可在当前可用环境内自行尝试导出、解码 Base64 并重新打包，不能把截图 / 整理工作转给 Suen。

### iPad 用户端路径

下载相册导入包.zip → iPad“文件”App 点开解压 → 打开所得文件夹 → 选择 / 全选图片 → 共享 → 存储图像（或系统相应保存到照片选项）。照片进入图库后即可在剪辑 App 选取。

说明：**HTML / ZIP / ChatGPT 本身无法不经用户授权直接写入 iOS“照片”图库**。如果 Suen 另外建立 iOS“快捷指令”，可以把“解压并存储到相簿”合并为更少操作，但默认交付不以安装或配置快捷指令为前置条件。

## 四、口播

- 一块是一整段自然口播，不为了配图机械一句一块；
- 文笔服从 `Suen统一文笔总则.md` 和栏目规则；
- 原文 / 手稿 / 文物出现时主动告诉观众看哪里、什么意思、为什么重要。

## 四点五、标题与前2—5秒验收

正式视频交付前，标题和开头必须单独过一遍，不因为正文研究很完整就放宽。

### 标题
必须同时满足：
- **有吸引力**：一眼就知道最怪 / 最反常 / 最值得点开的点是什么；
- **像真人**：删掉运营腔以后仍然成立；
- **一条只放一个主钩子**：不堆“冲突 + 反转 + 价值判断”三层；
- **事实不超证据**：不为了点击扩大原文、文物、案例或功效结论。


### 标题 benchmark 强制校准

六个抖音大号栏目在生成最终标题前，必须读取并执行：
`00-系统总控/内容商业对标系统.md` 中的
**“八点七｜六栏目最终标题必须走 benchmark title pass”**。

也就是说：
- 标题不能只由模型根据正文自行概括；
- 必须先看当前相关 benchmark 年度库 / 题目流；
- 现有库不足时再定向搜索真实标题；
- 只迁移入口与表达方法，不复制具体标题；
- 最终仍以 Suen 自己的自然标题语感和事实范围为最后一关。

未完成这一轮 benchmark title pass，不得把标题标成“最终可发布标题”。

### 前2—5秒
必须让陌生人尽快知道：
**这条到底怪在哪里 / 问题在哪里 / 为什么值得继续看。**

不是每个栏目都用同一种开头：
- 文物：怪对象 / 怪用途 / 怪细节先出现；
- 异录：最怪的事件或转折先出现；
- 辨伪：直接进入“判断题：……对还是错？”；
- 残页：原文里真正奇怪、会改变意思的句子 / 词先出现；
- 隐理：大家会做的反常动作 + 为什么存在；
- 牌记：具体问题 + 这副牌里真正改变判断的地方。

### 自检
交付前问：
1. 把“你绝对想不到 / 很多人不知道 / 其实 / 居然”等词删掉，标题还吸引人吗？
2. 第一两句话是否已经出现真正的题眼，而不是背景铺垫？
3. 标题和开头是否在重复同一句废话？
4. 如果入口不够强，是不是应该换题眼，而不是再加运营词？

如果不通过，先自行重写，不把弱标题 / 弱开头交给 Suen 再返工。

## 四点六、成片栏目复核｜专用对话有退件义务

正式交付前必须独立于总控标签，再做一次栏目复核。

检查：
- 文物：最终成片是否仍由具体对象推进；
- 异录：是否仍由人物 + 事件 + 时间线推进；
- 辨伪：是否真的给出了稳定、范围明确的对 / 错；
- 残页：是否仍由具体原文 / 词句 / 版本问题推进；
- 隐理：是否仍由机制答案推进，具体材料只是证据；
- 牌记：是否仍由具体牌局、牌位、正逆位、周围牌与现实问题产生判断。

如果成片实际已经更像另一栏目：
1. 不继续润色假装符合；
2. 明确返回“栏目漂移”；
3. 指出当前更像哪个栏目、为什么；
4. 能低成本重路由则重路由；
5. 不能则退回总控重新定题。

**总控给出的栏目标签不是不可推翻指令。栏目成片一致性优先于按时交稿。**

## 五、标题与标签

完整主体结束后必须直接追加：

**标题：** 最终可发布标题  
**标签：** #相关标签

不等 Suen 再追问。

如果小红书同步同一成片，再直接追加：

- 小红书标题
- 封面文字
- 发布配文
- 必要标签

不重新生成第二份视频主体。

## 六、HTML 主交付

抖音大号六栏目正式视频固定生成一个 HTML 文件作为主交付，不以聊天界面是否能显示图片为判断条件。

HTML 必须保持“口播 ↔ 图片”直接对应，且 Suen 打开单一文件即可从上往下录制 / 剪辑。

栏目文件如果规定更严格的图片对应方式，按栏目规则执行。当前《隐理》固定为**一段自然口播 → 紧跟一张实际使用图片**；除 Suen 当次明确要求外，不改成一段多图、先口播后素材区或靠素材编号匹配。

如果两种方式都做不到，明确说明界面限制并使用最接近的紧贴模式；不能只说“交付不了”。

## 七、最终检查

交付前只检查：

1. 每段口播旁边 / 后面是否直接看到对应图；
2. 是否需要靠编号、ZIP、文件名二次匹配；
3. 是否有无必要时间码；
4. 图片是否真实、正确、顺序可剪；
5. 是否具备足够的有效视觉单元支撑完整口播，且没有用2—3张图反复硬撑；
6. 是否存在同一张图连续 / 多次原样重复，或用现代文字卡补缺图；局部是否通过“裁切与连续观看门”，实际相邻画面是否已经目视检查；
7. 主体结束后是否已经有最终标题和标签；
8. 同步小红书时是否已补标题、封面、配文；
9. 最终标题是否“强吸引 + 非AI”，前2—5秒是否已经进入真正题眼；
10. 成片实际主角是否仍符合所标栏目；如已漂移，是否已退件 / 重路由。
11. 是否额外交付可实际下载 / 解压、包含真实按序 JPG / PNG 剪辑图的相册导入包 ZIP；是否与 HTML 实际视觉一致且未侵犯图像使用限制。

12. 是否已按“零、最终视频画幅”准备4∶3画布；有最终视频时是否核实际导出比例、字幕 / 出镜位置、等比缩放与证据完整性；没有成片时是否保留待核状态。

任一项不通过，先自行修复。


## HTML 图片内嵌统一规则

凡当前栏目采用“图片 + 口播”的 HTML 主交付：

- 正式素材图片不能只依赖远程 `https://...` 写入 `<img src>`；
- 必须尽量实际取得 JPG / PNG 二进制文件；
- 取得后验证 MIME、解码、尺寸和内容身份；
- 正式 HTML 中将素材图片转换为 `data:image/...;base64` 内嵌；
- 来源页链接仍可保留 HTTPS；
- **来源链接 ≠ 已交付图片**。

如果网页图片可打开但普通下载失败：
- 优先使用已验证的 Google Doc 中转方案；
- 导出 DOCX；
- 从 `word/media/` 提取图片；
- 再 Base64 内嵌。

“网页能打开但 HTML 不显示”不属于真正阻塞。
只有来源不可取得、权限不允许、对象身份无法确认或所有合法来源均无法访问时，才算真实阻塞。

抖音大号六个正式视频栏目现在统一强制执行此流程。

## 视频口播可说性硬规则｜2026-09-26

所有视频口播首先按“人实际要说出口”来写，不按资料卡、论文摘要或馆藏记录的写法直接搬进嘴里。

### 英文 / 外文
- 有自然中文名称时，口播优先说中文。
- 英文馆名、术语、拉丁文、希腊文、埃及语转写、英文类别名如果读起来会卡，不要求口播逐字念。
- 原词对证据重要时：**口播先说中文意思，原词放字幕 / 图片 / 来源里。**
- 馆藏页上的英文标题、考古地点代码、墓号、英文材料名不因为“资料完整”就强塞进口播。
- 不自行发明中文译名；没有稳定译名时，用普通中文解释它是什么，原词留在画面。

### 数字
- 馆藏号、登录号、长串编号默认留在图注 / 来源，不要求口播念。
- 年代优先说成自然中文，如“新王国时期”“大约三千多年前”“公元前十六世纪左右”；只有具体年份直接影响结论时才精确念。
- 尺寸只在“大小本身值得看”时进入口播，且一次只保留真正有用的数字。
- 一句话里不要连续塞“馆藏号 + 年代范围 + 尺寸 + 墓号”等多组数字。
- 数字书面上可以完整保留，口播允许改成更自然的近似范围，只要不改变事实结论。

### 实际讲话验收
正式交付前必须把口播按正常语速完整读一遍，并额外检查：
- 哪个英文词真实拍摄时容易卡；
- 哪串数字需要低头确认才能念；
- 哪句话像在念馆藏说明或论文摘要；
- 哪些信息观众看字幕就够了，不需要嘴里再念一遍。

出现上述情况，优先改口播，把精确信息留给画面、图注和来源。

**判断标准：如果 Suen 拿起手机直接录，这句话需要先练两遍才能顺下来，就还不是最终口播。**
