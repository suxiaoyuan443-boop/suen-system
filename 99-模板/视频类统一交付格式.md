# Suen｜视频类统一交付格式

状态：当前正式模板
最后核对：2026-09-17

本文件规定 `suen-system` 内所有正式视频成品的统一交付格式。

适用范围包括：

- 抖音大号 7 个前台合集：文物、异录、辨伪、残页、隐理、世问、牌记；
- 抖音小号；
- 当天小红书直接同步的抖音同一支视频；
- 以后纳入本仓库、且属于“需要口播/台词 + 画面/素材”的其它视频内容。

不适用于公众号、小红书《长卷》、朋友圈文字、商业总控记录、非视频型文章或数据库内容。

---

## 一、真正目标：口播旁边立刻看到对应图片

正式交付的目标不是强迫某一种 Markdown 排版，而是让 Suen 不需要二次匹配素材。

核心体验固定为：

**看到一段口播时，紧挨着就能看到这一段真正要用的图片。**

因此：

- 不得先给完整口播，再在后面另列素材表；
- 不得只给素材编号，再要求 Suen 去另一处找图；
- 不得把右侧 / 图片区写成一篇素材研究报告；
- 不得因为当前聊天 UI 不支持“表格单元格内直接显示图片”，就停止交付或退回复杂素材清单。

“表格内嵌图做不到”不等于“视觉一一对应做不到”。

---

## 二、交付模式 A｜当前界面确实支持双栏直接图片时

如果当前输出环境能够在双栏 / 表格中稳定直接显示图片，则优先使用：

| 完整口播 / 台词 | 直接图片 |
|---|---|
| 一整段自然、可直接录制的口播 | 这一段真正要用的图片直接显示 |
| 下一段完整口播 | 下一组真正要用的图片直接显示 |

要求：

- 左边是一整段自然、连续、可直接录制的口播；
- 右边第一视觉是图片本身，不是编号或 URL；
- 图片下面只补极简来源与使用动作；
- 一段需要多张图时，按实际剪辑顺序直接展示。

---

## 三、交付模式 B｜聊天 UI 不支持表格内直接图片时

这是正式允许的默认兜底，而且**不算降级成交付失败**。

每一段固定按下面顺序交付：

### 口播 01
完整、连续、可直接录制的一整段口播。

### 对应图片
这里立刻直接显示这一段真正要用的图片 / 图片组。

来源：只保留必要来源页。
使用：例如 `整页 → 放大第3行`。

然后紧接：

### 口播 02
下一段完整口播。

### 对应图片
下一段真正要用的图片 / 图片组。

也就是说，虽然视觉上不是严格“左 / 右”，但使用逻辑完全相同：

**一段口播 → 紧跟直接图片 → 下一段口播 → 紧跟直接图片。**

禁止在模式 B 中退回：

- 01 / 02 / 03 素材编号 + 另一份素材包让 Suen 自己查；
- 只给链接、不显示图片；
- 口播和图片分别放在两个很远的区域；
- 完整口播结束后再统一列所有图片。

---

## 四、如果 Suen 明确要求“真正左边口播 / 右边图片”

如果聊天 UI 本身不支持表格内嵌图，但当前对话具备文件 / 文档生成能力：

- 可以额外生成单个 HTML / DOCX 等可视化交付文件；
- 文件内使用真正双栏布局：左侧完整口播，右侧嵌入对应图片；
- 仍需在聊天中给出可直接使用的简化版本；
- 不要求 Suen 为此切换到其它模式，除非当前环境确实只有该模式才具备文件能力，而且 Suen主动同意。

如果当前环境既不能表格内嵌图，也不能生成可视化文件：

- 明确说明这是当前界面的显示限制；
- 立即使用“模式 B”；
- 不得只回复“这种我交付不了”然后停止。

---

## 五、左侧 / 口播部分

- 必须是一整段自然、连续、可以直接照着录的口播；
- 一块可以有连续数句话，只要它们自然属于同一组画面；
- 不为了配图机械一句一块；
- 口播服从 `00-系统总控/Suen统一文笔总则.md`、`00-系统总控/文笔成稿验收协议.md` 与栏目专属规则；
- 如果是现场对话 / 情景 / 无旁白动作，则写完整现场台词、字幕或动作说明。

---

## 六、图片部分

图片部分第一视觉优先是**图片本身 / 图片预览**。

涉及外部真实资料时：

- 优先给真实文物、手稿、原书页、纸草、历史图像；
- 优先使用可直接显示 / 打开的 HTTPS 图片；
- 同时保留可靠来源页用于核查；
- 图片下面只保留简短的使用说明；
- 不用相似但错误的对象补位；
- 不用 AI 图冒充真实文物、历史现场、手稿或原页。

如果当前工具只能取得来源页，暂时没有稳定图片直链：

明确写：`当前未取得稳定图片直链`。

但这属于真实缺图状态，不得伪装成已经交付图片。

---

## 七、不要为了缺素材把工作转给 Suen

“本人实拍”不是默认补洞方案。

只有以下情况可以安排本人实拍：

- 题目本身就需要 Suen 的真实操作 / 桌面 / 现有实物；
- Suen 已明确说有该素材或愿意拍；
- 该画面天然应该由本人出镜完成。

如果只是执行对话暂时没找到历史图片、手稿页或文物图，应先自行继续寻找可靠真实素材。

---

## 八、原文 / 手稿 / 文物类画面

资料越硬，导航越简单。

图片出现后只需要一句简短说明，例如：

- `先整页 → 放大第4行`
- `圈右上角符号`
- `先整件 → 再切胸口局部`

不额外制作复杂镜头表。

如果一张图可以覆盖连续多句话，保持一个完整口播块，不机械切碎。

---

## 九、小红书同步

如果小红书当天直接同步抖音同一成片：

- 视频主体只交这一份“口播 ↔ 直接图片”成片稿；
- 不重新制作第二份素材表或逐镜头稿；
- 成片稿后追加小红书标题、封面文字、发布配文即可。

---

## 十、禁止的交付方式

禁止：

- 因为表格里不能直接显示图，就说“交付不了”；
- 左边口播，右边只有一串素材编号；
- 图片区先写长篇说明，再把真正图片藏在链接里；
- 完整口播和素材完全分离；
- 先给一篇口播，最后再给十几个链接让 Suen 自己匹配；
- 明明当前界面能直接展示图片，却只给来源页；
- 一句话拆成一格 / 一块导致口播支离破碎；
- 为了补素材擅自让 Suen 重新拍摄；
- 为了填满图片区使用无关文物、AI 假史料或错误对象。

---

## 十一、最终检查

正式交付前确认：

- 从上到下是一份自然完整的口播；
- 每段口播旁边或紧跟位置都直接出现真正要用的图；
- 图片顺序就是剪辑顺序；
- 必要来源保留，但不干扰剪辑阅读；
- 没有把本可以由执行对话解决的素材工作转给 Suen；
- Suen 不需要再做“口播 ↔ 图片”二次匹配；
- 当前 UI 不支持严格左右双栏时，已经自动切换到模式 B，而不是停止。

最终目标只有一句：

**能左口播右图片就直接这样交；做不到严格左右排版时，也必须做到“一段口播紧跟对应图片”，绝不把素材匹配工作重新丢给 Suen。**
