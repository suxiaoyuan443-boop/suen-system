# Suen｜视频类统一交付格式

状态：当前正式模板  
最后核对：2026-09-27

适用于抖音大号、小号及同步小红书的视频。

## 栏目专属格式优先级

如果某个栏目已经明确存在更稳定的专属交付格式，以该栏目当前规则为准。

当前已确认：
- **《文物》固定使用 HTML 主交付**；
- HTML 内继续执行 Suen 已确认的“完整口播段落 → 对应实际图片直接显示 → 下一段口播 → 下一组图片”；
- 《文物》不以聊天消息内嵌图作为正式主交付；
- 《文物》不使用“完整口播 + 原句锚点素材区”作为正式主交付；
- 具体读取 `01-抖音大号/文物.md`。

不要用本模板把《文物》改回聊天内拼接、素材编号表或独立素材清单。

目标只有一个：

> **Suen 从上往下看，就能直接完成“读口播 → 看对应图片 → 剪这一段 → 继续下一段”。**

## 一、主交付

优先：

| 完整口播 / 台词 | 直接图片 |
|---|---|
| 自然、连续、可直接录制的一整段 | 这一段真正要使用的图片 / 图片组 |

大号正式视频不再根据聊天 UI 在“聊天内图文”和 HTML 之间切换。

**固定生成单一 HTML 主交付：完整口播 → 紧跟对应图片 / 图片组 → 下一段口播 → 下一组图片。**

不能改成“口播 + 素材编号”、聊天内单独发图或“正文结束后统一列素材”。

## 二、默认不要出现

除非 Suen 当次明确要求，不增加：

- 时间列 / 预计时间码；
- 素材编号作为理解依据；
- 文件名代替图片；
- 独立镜头表；
- 必须打开 ZIP / TXT 才能理解的流程。

ZIP 只能是可选补充，不能成为主交付。

## 三、图片

- 第一视觉必须是图片 / 预览本身；
- 多张图按真实剪辑顺序直接展示；
- 外部资料保留可靠来源页；
- 使用说明只需极简，如 `整页 → 放大第4行`；
- 真实文物、手稿、纸草、原书页优先；
- 不用 AI 图冒充真实资料；
- **正式资料图默认不加红框 / 红色矩形高亮。** 需要观众看局部时，优先直接裁切、放大或用简短图注定位；只有 Suen 当次明确要求时才使用彩色框；
- 没有稳定直链时明确写 `当前未取得稳定图片直链`，不伪装已交付。

不要因为暂时缺素材就把搜图、匹配、裁切工作转给 Suen。

## 四、口播

- 一块是一整段自然口播，不为了配图机械一句一块；
- 文笔服从 `Suen统一文笔总则.md` 和栏目规则；
- 原文 / 手稿 / 文物出现时主动告诉观众看哪里、什么意思、为什么重要。

## 四点五、标题与前2—5秒验收

正式视频交付前，标题和开头必须单独过一遍，不因为正文研究很完整就放宽。

### 标题
必须同时满足：
- **有吸引力**：一眼就知道最怪 / 最反常 / 最值得点开的点是什么；
- **像真人**：删掉运营腔以后仍然成立；
- **一条只放一个主钩子**：不堆“冲突 + 反转 + 价值判断”三层；
- **事实不超证据**：不为了点击扩大原文、文物、案例或功效结论。

### 前2—5秒
必须让陌生人尽快知道：
**这条到底怪在哪里 / 问题在哪里 / 为什么值得继续看。**

不是每个栏目都用同一种开头：
- 文物：怪对象 / 怪用途 / 怪细节先出现；
- 异录：最怪的事件或转折先出现；
- 辨伪：直接进入“判断题：……对还是错？”；
- 残页：原文里真正奇怪、会改变意思的句子 / 词先出现；
- 隐理：大家会做的反常动作 + 为什么存在；
- 牌记：具体问题 + 这副牌里真正改变判断的地方。

### 自检
交付前问：
1. 把“你绝对想不到 / 很多人不知道 / 其实 / 居然”等词删掉，标题还吸引人吗？
2. 第一两句话是否已经出现真正的题眼，而不是背景铺垫？
3. 标题和开头是否在重复同一句废话？
4. 如果入口不够强，是不是应该换题眼，而不是再加运营词？

如果不通过，先自行重写，不把弱标题 / 弱开头交给 Suen 再返工。

## 四点六、成片栏目复核｜专用对话有退件义务

正式交付前必须独立于总控标签，再做一次栏目复核。

检查：
- 文物：最终成片是否仍由具体对象推进；
- 异录：是否仍由人物 + 事件 + 时间线推进；
- 辨伪：是否真的给出了稳定、范围明确的对 / 错；
- 残页：是否仍由具体原文 / 词句 / 版本问题推进；
- 隐理：是否仍由机制答案推进，具体材料只是证据；
- 牌记：是否仍由具体牌局、牌位、正逆位、周围牌与现实问题产生判断。

如果成片实际已经更像另一栏目：
1. 不继续润色假装符合；
2. 明确返回“栏目漂移”；
3. 指出当前更像哪个栏目、为什么；
4. 能低成本重路由则重路由；
5. 不能则退回总控重新定题。

**总控给出的栏目标签不是不可推翻指令。栏目成片一致性优先于按时交稿。**

## 五、标题与标签

完整主体结束后必须直接追加：

**标题：** 最终可发布标题  
**标签：** #相关标签

不等 Suen 再追问。

如果小红书同步同一成片，再直接追加：

- 小红书标题
- 封面文字
- 发布配文
- 必要标签

不重新生成第二份视频主体。

## 六、HTML 主交付

抖音大号六栏目正式视频固定生成一个 HTML 文件作为主交付，不以聊天界面是否能显示图片为判断条件。

HTML 必须保持“口播 ↔ 图片”直接对应，且 Suen 打开单一文件即可从上往下录制 / 剪辑。

栏目文件如果规定更严格的图片对应方式，按栏目规则执行。当前《隐理》固定为**一段自然口播 → 紧跟一张实际使用图片**；除 Suen 当次明确要求外，不改成一段多图、先口播后素材区或靠素材编号匹配。

如果两种方式都做不到，明确说明界面限制并使用最接近的紧贴模式；不能只说“交付不了”。

## 七、最终检查

交付前只检查：

1. 每段口播旁边 / 后面是否直接看到对应图；
2. 是否需要靠编号、ZIP、文件名二次匹配；
3. 是否有无必要时间码；
4. 图片是否真实、正确、顺序可剪；
5. 主体结束后是否已经有最终标题和标签；
6. 同步小红书时是否已补标题、封面、配文；
7. 最终标题是否“强吸引 + 非AI”，前2—5秒是否已经进入真正题眼；
8. 成片实际主角是否仍符合所标栏目；如已漂移，是否已退件 / 重路由。

任一项不通过，先自行修复。


## HTML 图片内嵌统一规则

凡当前栏目采用“图片 + 口播”的 HTML 主交付：

- 正式素材图片不能只依赖远程 `https://...` 写入 `<img src>`；
- 必须尽量实际取得 JPG / PNG 二进制文件；
- 取得后验证 MIME、解码、尺寸和内容身份；
- 正式 HTML 中将素材图片转换为 `data:image/...;base64` 内嵌；
- 来源页链接仍可保留 HTTPS；
- **来源链接 ≠ 已交付图片**。

如果网页图片可打开但普通下载失败：
- 优先使用已验证的 Google Doc 中转方案；
- 导出 DOCX；
- 从 `word/media/` 提取图片；
- 再 Base64 内嵌。

“网页能打开但 HTML 不显示”不属于真正阻塞。
只有来源不可取得、权限不允许、对象身份无法确认或所有合法来源均无法访问时，才算真实阻塞。

抖音大号六个正式视频栏目现在统一强制执行此流程。

## 视频口播可说性硬规则｜2026-09-26

所有视频口播首先按“人实际要说出口”来写，不按资料卡、论文摘要或馆藏记录的写法直接搬进嘴里。

### 英文 / 外文
- 有自然中文名称时，口播优先说中文。
- 英文馆名、术语、拉丁文、希腊文、埃及语转写、英文类别名如果读起来会卡，不要求口播逐字念。
- 原词对证据重要时：**口播先说中文意思，原词放字幕 / 图片 / 来源里。**
- 馆藏页上的英文标题、考古地点代码、墓号、英文材料名不因为“资料完整”就强塞进口播。
- 不自行发明中文译名；没有稳定译名时，用普通中文解释它是什么，原词留在画面。

### 数字
- 馆藏号、登录号、长串编号默认留在图注 / 来源，不要求口播念。
- 年代优先说成自然中文，如“新王国时期”“大约三千多年前”“公元前十六世纪左右”；只有具体年份直接影响结论时才精确念。
- 尺寸只在“大小本身值得看”时进入口播，且一次只保留真正有用的数字。
- 一句话里不要连续塞“馆藏号 + 年代范围 + 尺寸 + 墓号”等多组数字。
- 数字书面上可以完整保留，口播允许改成更自然的近似范围，只要不改变事实结论。

### 实际讲话验收
正式交付前必须把口播按正常语速完整读一遍，并额外检查：
- 哪个英文词真实拍摄时容易卡；
- 哪串数字需要低头确认才能念；
- 哪句话像在念馆藏说明或论文摘要；
- 哪些信息观众看字幕就够了，不需要嘴里再念一遍。

出现上述情况，优先改口播，把精确信息留给画面、图注和来源。

**判断标准：如果 Suen 拿起手机直接录，这句话需要先练两遍才能顺下来，就还不是最终口播。**
