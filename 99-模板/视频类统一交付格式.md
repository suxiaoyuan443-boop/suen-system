# Suen｜视频类统一交付格式

状态：当前正式模板  
最后核对：2026-09-21

适用于抖音大号、小号及同步小红书的视频。

## 栏目专属格式优先级

如果某个栏目已经明确存在更稳定的专属交付格式，以该栏目当前规则为准。

当前已确认：
- **《文物》固定使用 HTML 主交付**；
- HTML 内继续执行 Suen 已确认的“完整口播段落 → 对应实际图片直接显示 → 下一段口播 → 下一组图片”；
- 《文物》不以聊天消息内嵌图作为正式主交付；
- 《文物》不使用“完整口播 + 原句锚点素材区”作为正式主交付；
- 具体读取 `01-抖音大号/文物.md`。

不要用本模板把《文物》改回聊天内拼接、素材编号表或独立素材清单。

目标只有一个：

> **Suen 从上往下看，就能直接完成“读口播 → 看对应图片 → 剪这一段 → 继续下一段”。**

## 一、主交付

优先：

| 完整口播 / 台词 | 直接图片 |
|---|---|
| 自然、连续、可直接录制的一整段 | 这一段真正要使用的图片 / 图片组 |

如果聊天 UI 不适合表格内嵌图，自动改成：

**完整口播 → 紧跟对应图片 → 下一段口播 → 紧跟对应图片**

不能改成“口播 + 素材编号”或“正文结束后统一列素材”。

## 二、默认不要出现

除非 Suen 当次明确要求，不增加：

- 时间列 / 预计时间码；
- 素材编号作为理解依据；
- 文件名代替图片；
- 独立镜头表；
- 必须打开 ZIP / TXT 才能理解的流程。

ZIP 只能是可选补充，不能成为主交付。

## 三、图片

- 第一视觉必须是图片 / 预览本身；
- 多张图按真实剪辑顺序直接展示；
- 外部资料保留可靠来源页；
- 使用说明只需极简，如 `整页 → 放大第4行`；
- 真实文物、手稿、纸草、原书页优先；
- 不用 AI 图冒充真实资料；
- 没有稳定直链时明确写 `当前未取得稳定图片直链`，不伪装已交付。

不要因为暂时缺素材就把搜图、匹配、裁切工作转给 Suen。

## 四、口播

- 一块是一整段自然口播，不为了配图机械一句一块；
- 文笔服从 `Suen统一文笔总则.md` 和栏目规则；
- 原文 / 手稿 / 文物出现时主动告诉观众看哪里、什么意思、为什么重要。

## 四点五、标题与前2—5秒验收

正式视频交付前，标题和开头必须单独过一遍，不因为正文研究很完整就放宽。

### 标题
必须同时满足：
- **有吸引力**：一眼就知道最怪 / 最反常 / 最值得点开的点是什么；
- **像真人**：删掉运营腔以后仍然成立；
- **一条只放一个主钩子**：不堆“冲突 + 反转 + 价值判断”三层；
- **事实不超证据**：不为了点击扩大原文、文物、案例或功效结论。

### 前2—5秒
必须让陌生人尽快知道：
**这条到底怪在哪里 / 问题在哪里 / 为什么值得继续看。**

不是每个栏目都用同一种开头：
- 文物：怪对象 / 怪用途 / 怪细节先出现；
- 异录：最怪的事件或转折先出现；
- 辨伪：直接进入“判断题：……对还是错？”；
- 残页：原文里真正奇怪、会改变意思的句子 / 词先出现；
- 隐理：大家会做的反常动作 + 为什么存在；
- 牌记：具体问题 + 这副牌里真正改变判断的地方。

### 自检
交付前问：
1. 把“你绝对想不到 / 很多人不知道 / 其实 / 居然”等词删掉，标题还吸引人吗？
2. 第一两句话是否已经出现真正的题眼，而不是背景铺垫？
3. 标题和开头是否在重复同一句废话？
4. 如果入口不够强，是不是应该换题眼，而不是再加运营词？

如果不通过，先自行重写，不把弱标题 / 弱开头交给 Suen 再返工。

## 五、标题与标签

完整主体结束后必须直接追加：

**标题：** 最终可发布标题  
**标签：** #相关标签

不等 Suen 再追问。

如果小红书同步同一成片，再直接追加：

- 小红书标题
- 封面文字
- 发布配文
- 必要标签

不重新生成第二份视频主体。

## 六、无法直接显示图片时

如果当前环境不能直接显示，但可以生成单一可视化文件，可用一个 HTML / DOCX 作为主交付，仍保持“口播 ↔ 图片”直接对应。

如果两种方式都做不到，明确说明界面限制并使用最接近的紧贴模式；不能只说“交付不了”。

## 七、最终检查

交付前只检查：

1. 每段口播旁边 / 后面是否直接看到对应图；
2. 是否需要靠编号、ZIP、文件名二次匹配；
3. 是否有无必要时间码；
4. 图片是否真实、正确、顺序可剪；
5. 主体结束后是否已经有最终标题和标签；
6. 同步小红书时是否已补标题、封面、配文；
7. 最终标题是否“强吸引 + 非AI”，前2—5秒是否已经进入真正题眼。

任一项不通过，先自行修复。


## HTML 图片内嵌统一规则

凡当前栏目采用“图片 + 口播”的 HTML 主交付：

- 正式素材图片不能只依赖远程 `https://...` 写入 `<img src>`；
- 必须尽量实际取得 JPG / PNG 二进制文件；
- 取得后验证 MIME、解码、尺寸和内容身份；
- 正式 HTML 中将素材图片转换为 `data:image/...;base64` 内嵌；
- 来源页链接仍可保留 HTTPS；
- **来源链接 ≠ 已交付图片**。

如果网页图片可打开但普通下载失败：
- 优先使用已验证的 Google Doc 中转方案；
- 导出 DOCX；
- 从 `word/media/` 提取图片；
- 再 Base64 内嵌。

“网页能打开但 HTML 不显示”不属于真正阻塞。
只有来源不可取得、权限不允许、对象身份无法确认或所有合法来源均无法访问时，才算真实阻塞。

当前《文物》已经正式验证并强制执行此流程；其它以后采用同类 HTML 图片+口播交付的栏目也按同一技术原则执行。
