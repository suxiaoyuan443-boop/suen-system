# Suen｜视频类统一交付格式

状态：当前正式模板
最后核对：2026-09-17

本文件规定 `suen-system` 内所有正式视频成品的统一交付格式。

适用范围包括：

- 抖音大号 7 个前台合集：文物、异录、辨伪、残页、隐理、世问、牌记；
- 抖音小号；
- 当天小红书直接同步的抖音同一支视频；
- 以后纳入本仓库、且属于“需要口播/台词 + 画面/素材”的其它视频内容。

不适用于公众号、小红书《长卷》、朋友圈文字、商业总控记录、非视频型文章或数据库内容。

---

## 一、最终目标只有一个

**Suen 看到一段口播时，旁边或紧跟位置就直接看到这一段真正要用的图片。**

最终交付首先服务“马上录、马上剪”，不是服务素材管理。

判断是否合格只看一件事：

> Suen 是否可以在同一份交付里，从上往下直接完成“读口播 → 看图片 → 剪这一段 → 继续下一段”，而不需要再打开另一份素材表、记素材编号、翻 ZIP、对照文件名或重新判断哪张图对应哪段。

如果还需要二次匹配，就不算完成交付。

---

## 二、首选形式｜真正双栏

当前环境如果可以稳定实现，正式主体固定为两栏：

| 完整口播 / 台词 | 直接图片 |
|---|---|
| 一整段自然、可直接录制的口播 | 这一段真正要用的图片直接显示在这里 |
| 下一段完整口播 | 下一组真正要用的图片直接显示在这里 |

硬规则：

- 只保留两列；
- 默认不增加“时间”“素材编号”“镜头表”“文件名”等第三列；
- 右侧第一视觉必须是图片本身 / 图片预览；
- 图片下方最多保留极简来源与一句使用动作；
- 一段需要多张图时，按实际剪辑顺序直接展示多张图；
- 同一张图后面再次使用时，可以再次直接展示，不要求 Suen 记住“04号素材”。

### 时间码

时间码不是默认交付字段。

只有 Suen 当次明确要求时间码，或已经有真实录音 / 成片需要精确对齐时，才增加时间信息。

不得为了显得“像剪辑脚本”自行生成预计时间段，增加阅读负担。

---

## 三、聊天 UI 不支持表格内嵌图时

不要退回“时间 + 口播 + 素材编号 / 文件名”的表格。

自动使用紧贴模式：

### 口播 01
完整、连续、可直接录制的一整段口播。

### 对应图片
直接显示这一段真正要用的图片 / 图片组。

来源：必要来源页
使用：例如 `整页 → 放大第3行`

然后立刻进入：

### 口播 02
下一段完整口播。

### 对应图片
下一段真正要用的图片 / 图片组。

核心仍然是：

**一段口播 → 直接图片 → 下一段口播 → 直接图片。**

不能变成：

- 一段口播 → “01号素材”；
- 一段口播 → 文件名；
- 一段口播 → “去 ZIP 里找 04”；
- 完整口播结束后 → 再统一列素材。

---

## 四、如果聊天里确实无法稳定直接展示图片

如果当前对话具备文件 / 文档生成能力，优先生成一个**单一可视化交付文件**作为主交付，例如 HTML 或 DOCX：

- 左侧完整口播；
- 右侧直接嵌入对应图片；
- 图片按实际剪辑顺序出现；
- 来源只做极简小字；
- 不要求 Suen 再打开第二份素材表进行匹配。

聊天正文仍给简化版口播与对应关系，但真正“左口播 / 右图片”的体验由这个单一可视化文件保证。

如果当前环境既不能在聊天里直接显示，又不能生成可视化文件，才明确说明界面限制，并给最接近的紧贴模式。

不能只回复“这种交付不了”。

---

## 五、ZIP / 素材包只能是可选补充

ZIP 不是主交付。

如果为了批量下载方便额外生成 ZIP：

- 必须放在主交付之后；
- 明确标记 `可选｜批量下载素材包`；
- Suen 不打开 ZIP，也必须完全看懂每段口播该配哪张图；
- ZIP 内文件名可以编号，但编号只用于下载整理，不参与理解主交付；
- 不得写“直接下载这个就够了”来替代真正的口播 ↔ 图片视觉交付。

同理，`剪辑顺序.txt`、`资料来源.txt` 等都只能是补充附件，不得成为理解成品的必要步骤。

---

## 六、口播部分

- 每块是一整段自然、连续、可以直接照着录的口播；
- 一块可以有连续数句话，只要自然属于同一组画面；
- 不为了配图机械一句一块；
- 口播服从 `00-系统总控/Suen统一文笔总则.md`、`00-系统总控/文笔成稿验收协议.md` 与栏目专属规则；
- 如果是现场对话 / 情景 / 无旁白动作，则写完整现场台词、字幕或动作说明。

---

## 七、图片部分

图片部分第一视觉必须优先是**图片本身 / 图片预览**。

涉及外部真实资料时：

- 优先给真实文物、手稿、原书页、纸草、历史图像；
- 优先使用可直接显示 / 打开的 HTTPS 图片；
- 同时保留可靠来源页用于核查；
- 图片下面只保留非常短的使用说明；
- 不用相似但错误的对象补位；
- 不用 AI 图冒充真实文物、历史现场、手稿或原页。

如果当前工具只能取得来源页，暂时没有稳定图片直链：

明确写：`当前未取得稳定图片直链`。

这属于真实缺图状态，不得伪装成已经交付图片。

---

## 八、不要把缺素材转给 Suen

“本人实拍”不是默认补洞方案。

只有以下情况可以安排本人实拍：

- 题目本身就需要 Suen 的真实操作 / 桌面 / 现有实物；
- Suen 已明确说有该素材或愿意拍；
- 该画面天然应该由本人出镜完成。

如果只是执行对话暂时没找到历史图片、手稿页或文物图，应先自行继续寻找可靠真实素材。

---

## 九、原文 / 手稿 / 文物类画面

资料越硬，导航越简单。

图片出现后只保留一句简短动作，例如：

- `先整页 → 放大第4行`
- `圈右上角符号`
- `先整件 → 再切胸口局部`

不额外制作复杂镜头表。

如果一张图可以覆盖连续多句话，保持一个完整口播块，不机械切碎。

---

## 十、小红书同步

如果小红书当天直接同步抖音同一成片：

- 视频主体只交这一份“口播 ↔ 直接图片”成片稿；
- 不重新制作第二份素材表或逐镜头稿；
- 成片稿后追加小红书标题、封面文字、发布配文即可。

---

## 十一、禁止的交付方式

禁止：

- `时间｜口播｜素材编号 / 文件名` 作为默认主表；
- 左边口播，右边只有 `01 / 02 / 03` 素材编号；
- 右边只有文件名，没有直接图片；
- 先让 Suen 下载 ZIP，再靠文件名判断对应关系；
- 主交付结束后才统一列图片；
- 完整口播和素材完全分离；
- 图片区先写长篇说明，再把真正图片藏在链接里；
- 明明当前界面能直接展示图片，却只给来源页；
- 一句话拆成一格 / 一块导致口播支离破碎；
- 为了补素材擅自让 Suen 重新拍摄；
- 为了填满图片区使用无关文物、AI 假史料或错误对象；
- 把 ZIP、TXT、素材编号系统做得比主交付本身还复杂。

---

## 十二、交付前硬验收

正式发给 Suen 前，执行对话必须自己检查：

1. 主交付是不是只有最必要的信息；
2. 每段口播旁边 / 紧跟位置是不是直接看到真实图片；
3. 有没有必须靠素材编号才能理解的地方；
4. 有没有必须打开 ZIP 才知道用什么图的地方；
5. 有没有无必要的时间码；
6. 有没有把来源、馆藏、镜头说明写得比图片本身还抢眼；
7. Suen 能不能只看这一份主交付直接开始录和剪。

任一项不通过，先自行重排，再交付。

最终标准：

**主交付不是“剪辑计划表”，也不是“素材管理表”。它就是：左边 / 上面是要说的话，右边 / 紧跟位置是马上要用的图。**
