# Slack｜内容复盘台账模板

状态：当前正式模板
最后核对：2026-09-18

用于商业总控每天中午“总结”阶段。只整理实际已经发布的内容与复盘事实，不在这里做选题或商业决策。

使用时只保留平台实际能看到、当天确实有意义的字段；未知写“不知道 / 未找到”，不估算。

默认运营时区：**Asia/Shanghai（UTC+8）**。

除非 Suen 当次明确指定其它时区，复盘日期、发布时间和发布后时长都先按上海时间判断，不跟随设备 / VPN 推测位置自动变化。

## 实际发布前置检查

正式生成某条内容的复盘块以前，先确认它**真的已经发布**。

以下都不等于已发布：

- 计划发布时间；
- 已经生成成品；
- 已经排好稿；
- 准备今天发；
- 历史记录里只写“计划发布”。

如果只能确认计划、不能确认真实发布，先单独写：

```text
【平台】
发布状态：待确认
计划发布时间：（如已知）
```

等 Suen 确认真正发布后，再生成正式复盘块。不要把计划日期直接填成实际发布时间。

## 输出块原则

- 每个平台使用**独立短复制块**；
- 抖音大号与抖音小号绝不合并；
- 公众号贴图与长文绝不合并；
- 不把所有平台塞进一个超长代码块，避免复制时还要手动拆。

## 制作耗时｜可选，首次复盘记录一次

从 2026-09-18 起，如果 Suen 知道大概制作时间，可在一条新内容第一次进入台账时补：

```text
制作耗时档位：30分钟以内 / 30—60分钟 / 1—2小时 / 2—4小时 / 4小时以上
```

规则：

- 不知道就省略，不追问到影响复盘；
- 不要求精确到分钟；
- 后续 41—42 小时或更晚复盘不重复询问；
- 历史旧内容不要求回忆补录；
- 抖音大号 + 小红书同步同一支完整成片时，只记录一次主制作耗时；
- 小红书仅改标题 / 封面 / 短配文时，不重复算一份完整制作成本；
- 独立《长卷》、独立图文、明显重剪 / 重新研究才单独记录。

完整口径读取 `00-系统总控/生产投入产出规则.md`。

## 复盘日期头格式

每个实际发布内容的复盘块，第一行优先使用：

```text
【YYYY-MM-DD｜约X小时早期数据】
发布时间：YYYY-MM-DD
```

例如：

```text
【2026-09-16｜约17—18小时早期数据】
发布时间：2026-09-15
```

这里第一行日期是**复盘日期**，不是发布时间。

同一内容隔日再次复盘时：

- 发布时间保持原发布日期不变；
- 第一行改成新的复盘日期；
- 更新对应发布后时长；
- 已经明显超过早期阶段时，可把“早期数据”改为“后续数据 / X天后数据”；
- 不覆盖或篡改之前的复盘事实。

如果内容涉及星符 / 仪式等项目，可以额外写：

```text
涉及项目执行日期：YYYY-MM-DD
```

它只是主题日期，不是发布时间。

## 抖音小号

```text

发布时间：

内容形式：视频 / 图文
时长 / 图片数：（能取得时）
入口结构：（可选｜反直觉问题 / 第一人称观点或结果 / 祈愿参与 / 视觉对象展示 / 现场过程 / 客订或反馈结果）
主题标签：（可选）
题目 / 内容：
制作耗时档位：（首次复盘且已知时）

播放：
点赞：
评论：
收藏：
分享：
新增粉丝：
主页访问：
封面点击率 / 进入率：（后台有时）

视频指标：（按后台真实字段保留）
2秒跳出率：
平均播放时长 / 平均播放占比：
完播率：

图文指标：（按后台真实字段保留）
划走率：
文案展开率：
平均浏览图片数：

私信：（确认由本条带来时）
有效询盘：（确认由本条带来时）
成交：（确认由本条带来时）

```

使用时只保留对应形式有意义的指标，不要求视频块同时填图文指标，也不要求图文块填视频指标。

`内容类型` 是后台观看体验标签，不是前台栏目；`入口结构` 用来学习什么第一眼 / 第一问有效；文化、神明、传统、器物等放 `主题标签`。具体定义读取 `01B-抖音小号/小号规则.md`。

若没发，直接单独写：

```text
【抖音小号】
发布状态：未发布
```

不要为了模板完整填一排空数字。

## 公众号｜贴图

贴图与长文必须分开记录。

```text
【YYYY-MM-DD｜约X小时早期数据】
【公众号｜贴图】
发布时间：
题目：
制作耗时档位：（首次复盘且已知时）

阅读（当前）：
推荐阅读 / 推荐来源：
搜一搜阅读 / 来源：
分享：
文章页自然关注：

是否受抽奖/活动干扰：否 / 是（说明）
评论 / 留言信号：
```

如果统计时已经达到约24小时，可以把字段明确写成：

```text
24h阅读：
```

**未满24小时不得把当前阅读误标成“24h阅读”。** 当前阶段虽然重点比较24小时数据，但17—18小时、41—42小时等复盘仍按实际统计时点记录。

有后续持续增长时可以再次复盘。

如果后台另有“总新增关注”等不同口径，不要把它直接替代“文章页自然关注”；需要时另列真实字段名。

## 询盘 / 成交怎么放进内容块

只有能可靠确认某个私信、有效询盘或成交由**当前这条内容**带来时，才放进该内容块。

如果只能确认来自某个平台，但不能确认具体哪条内容：

- 不为了给内容“记功”而硬塞进最近一条；
- 在销售 / 商业记录里保留真实平台来源；
- 等有更明确归因证据再补具体内容。

**同一天发生 ≠ 同一条内容带来。**

---

## 评论信号怎么写

只记录会影响以后判断的反馈，例如：

- 观众主动想看什么；
- 哪一步没看懂；
- 对“真实资料 / 不乱讲”的品牌认可；
- 长期兴趣受众暴露出来的偏好；
- 圈内实践者 / 深度爱好者识别；
- 现实问题、服务认知或潜在购买需求。

普通表情、单纯“好看 / 支持”如果没有额外判断价值，只计入评论数量；但如果结合公开账号身份能明确判断为神秘学实践者 / 从业者的识别反馈，可以作为评论信号记录，仍不自动算潜在客户。

## 写入 Slack 前检查

1. 日期是否按 Asia/Shanghai 判断？
2. 这条内容是否已经确认实际发布，而不是只有计划发布时间？
3. 第一行日期是不是这次复盘日期？
4. `发布时间` 是不是内容真正发出的日期？
5. 仪式/星符执行日期有没有被错当成发布时间？
6. 大号、小号有没有拆成独立复制块？
7. 抖音小号已发布时，是否记录了一个可解释的 `内容类型`；仅凭标题无法判断时是否保留“待确认”而没有强行分类？
8. 小号视频 / 图文是否使用了各自真实指标，没有把完播率和划走率混着比较？
9. 公众号贴图、长文有没有拆开？
10. 公众号未满24小时的数据有没有被错误标成“24h阅读”？
11. 未发布 / 待确认的平台有没有明确标记？
12. 未知数据有没有被估算？
13. 私信 / 询盘 / 成交是否真的能归因到当前这条内容？
14. 有价值评论有没有单列评论信号？
15. 抽奖/活动带来的增长有没有和自然内容增长分开？
16. 公众号字段是否使用后台真实口径，没有把“总新增关注”混成“文章页自然关注”？
17. 制作耗时是否只在已知时记录，没有自行估算？
18. 同一支抖音 + 小红书同步成片是否避免重复计算制作耗时？
