# Suen｜高客单机会漏斗

状态：当前正式规则  
建立：2026-09-27  
适用：定制仪式、星符 / 特定古典魔法项目，以及商业总控明确指定的其它高价值定制服务。

本文件只管理**真实销售机会从询盘到付款、执行、复购 / 转介绍的推进状态**。  
不替代内容漏斗，不把所有私信都升级成高客单机会，也不要求 Suen 使用复杂 CRM。

---

## 一、为什么单独建立这一层

现有内容漏斗继续保留：

`触达 / 停留 → 精准兴趣 → 主页 / 服务理解 → 有效询盘`

从“有效询盘”开始，高客单使用独立机会漏斗：

`有效询盘 → 合格机会 → 需求信息完整 → 方案适配确认 → 正式报价 → 决策中 → 付款 → 执行 → 结果跟踪 → 案例 / 复购 / 转介绍`

目的不是增加表格，而是能回答：

- 客户究竟卡在需求澄清、方案、报价还是付款；
- 某类内容带来的到底是随口问价，还是可成交机会；
- 某个报价没有成交时，真实断点是什么；
- 高客单到底能不能形成可重复付款，而不是只看“有人来问”。

---

## 二、机会阶段

### 0. 有效询盘

客户已经出现真实购买需求，例如询问：

- 自己的情况能否处理；
- 适合什么方案；
- 流程、时间、价格、预约或执行条件；
- 某个真实现实目标是否适配 Suen 当前服务。

只问泛知识、闲聊、同行交流、单纯夸赞不算有效询盘。

### 1. 合格机会｜Qualified Opportunity

满足以下核心条件后进入：

- 有相对具体的现实问题；
- 愿意提供判断所需的基本信息；
- 目标基本能够说清；
- 与 Suen 当前真实可提供的服务存在潜在适配；
- 已经进入“我的情况适合怎么处理”而不只是随口问价格。

以下情况不强行升级：

- 只要求百分百保证、固定结果或无法真实承诺的条件；
- 需求明显不适配当前服务；
- 对方拒绝提供任何必要信息；
- 只是问完价格立即离开，尚未形成可判断需求。

### 2. 需求信息完整

完成当前方案判断所需要的关键信息已经取得。

不同项目需要的信息不同，不设一套机械问卷。  
只收真正影响适配、方案、执行条件和报价的信息，不为了显得专业增加无意义问题。

### 3. 方案适配确认

Suen 已能明确判断：

- 是否建议做；
- 如果做，推荐哪一类方案；
- 为什么当前方案适配；
- 是否需要等待日期 / 材料 / 其它条件；
- 是否存在需要先处理的现实前提。

客户不需要自己从复杂魔法菜单中选择技术。

### 4. 正式报价

必须已经给出当前真实可执行方案的明确价格或明确计价方式。

“会贵一点”“大概几百到几千”不算正式报价。

价格、容量、排期、天象资格等动态事实必须读取当前状态或由 Suen 当次明确，不从旧聊天自动沿用。

### 5. 决策中

客户已经收到方案与正式报价，但尚未付款，也未明确拒绝。

此阶段必须保留：
- 主要顾虑；
- 客户是否给出决策时间；
- 下一步是什么。

不把沉默自动写成“流失”。

### 6. 已付款

只有真实付款 / 交易事实发生后进入。

报价接受、口头说“可以”、说“之后转”都不能提前计成交。

### 7. 执行中 / 已执行

按项目真实状态记录。

“已付款”与“已执行”分开，不能为了成交统计把未执行订单写成完成案例。

### 8. 结果跟踪

只在适合跟踪、客户同意正常回访的项目中使用。

记录：
- 执行前状态；
- 客户目标；
- 执行日期；
- 后续真实变化及时间点；
- 客户自己报告的结果；
- 没有变化 / 部分变化时同样保留；
- 是否出现追加购买、复购或转介绍。

### 9. 案例可用 / 复购 / 转介绍

只有真实材料足够并符合隐私、公开授权与真实性规则时，才进入案例资产。

## 三、Revenue P0｜收入级优先任务

商业总控每天先检查是否存在 Revenue P0，再安排内容 P0。

以下情况可以成为 Revenue P0：

- 合格机会已经具备报价条件，但 Suen 还没有完成方案 / 报价；
- 已报价客户正在当天做明确决策，且有真实需要回应的信息；
- 客户已确认付款节点 / 执行节点，需要当天完成关键承接；
- 已付款订单存在当天必须完成的交付、采购、择时或执行动作；
- 已约定的结果回访可能形成真实案例、复购或转介绍；
- 已存在的高价值机会因为 Suen 未回复 / 未报价而面临人为流失。

以下不自动成为 Revenue P0：

- 普通私信；
- 泛知识问题；
- 单纯问价但没有具体需求；
- 无明确下一步的闲聊；
- 为了“追单”制造虚假紧迫感。

当 Revenue P0 与主视频生产冲突时，原则上先完成真实客户承接 / 交付，再决定当天内容是否降级、改低成本形式或顺延。  
这不等于有人私信就暂停内容，而是高价值真实机会不再永远排在内容生产之后。

## 四、机会推进动作

### 有效询盘 → 合格机会
目标：确认真实问题与购买意图。

### 合格机会 → 信息完整
目标：取得会改变方案判断的必要信息。

### 信息完整 → 方案适配
目标：给出明确专业判断，不用复杂技术菜单让客户自己选。

### 方案适配 → 正式报价
目标：把方案、执行范围、关键条件和真实价格说清。

### 正式报价 → 决策
目标：回答真实顾虑，不无限补充销售话术。

### 决策 → 付款
允许客户正常考虑。禁止虚构稀缺、恐吓、效果保证或“今天不买就没有”的压力。

---

## 五、跟进规则｜先作为 v1 验证

1. 客户明确说“某天 / 发工资后 / 某件事确认后再决定”时，按客户给出的节点跟进，不提前追问。
2. 已正式报价、客户没有给明确时间且对话自然停住时，可以在约 **48—72 小时**后做一次简短、自然的跟进。
3. 一次跟进后仍无回复，不连续追单；转为“待客户主动 / 暂停”，后续只有出现与其需求高度相关的真实新信息时再自然触达。
4. 未正式报价的询盘，不用统一“48小时追单”规则；先判断是否其实缺方案推进。
5. 本规则是早期验证基线，后续用真实成交数据修正。

## 六、未成交原因

只有聊天中有真实证据时才记录。优先使用：

- 价格；
- 结果可信度；
- 起效时间 / 时间不确定；
- 案例 / 反馈不足；
- 需要百分百保证；
- 方案不适配；
- 当前时机不合适；
- 现实条件变化；
- 正在比较其它服务；
- 未形成明确需求；
- 尚无法判断。

禁止为了复盘完整感强行归因。

---

## 七、核心高客单指标

高客单不再用“全部询盘总成交率”代表。

优先观察：

- 高客单有效询盘数；
- 合格机会数；
- 方案适配确认数；
- 正式报价数；
- 付款数；
- 报价成交率；
- 实际平均成交客单；
- 贡献利润（数据足够时）；
- 执行 / 交付耗时粗档；
- 后续购买 / 复购；
- 转介绍；
- 可用案例数。

样本很小时只描述，不设虚假稳定率。

---

## 八、前台与后台分工

客户前台不显示“Qualified Opportunity / Pipeline / Revenue P0”等术语。

对外仍使用 Suen 自然微信表达。

后台商业总控负责：
- 判断机会阶段；
- 发现卡点；
- 提醒下一步；
- 统计真实转化；
- 判断今天是否存在 Revenue P0。

Suen 本人把时间优先放在真正的需求判断、方案、客户沟通和执行上。
