# Suen｜高客单 Offer 与报价规则

状态：当前正式规则  
建立：2026-09-27

本文件负责把“定制仪式 / 星符 / 特定古典魔法项目”从技术类别整理成客户能够理解、能够购买、能够比较价值的服务结构。

不在这里虚构价格、结果、案例、容量或执行日期。动态事实仍以 Suen 最新明确指令和 `08-动态运行/` 为准。

---

## 一、核心原则｜客户带问题，Suen 选工具

高客单前台不以复杂魔法菜单作为主要购买入口。

客户首先表达：
- 自己遇到什么现实问题；
- 想推动什么结果；
- 当前已经发生到哪一步。

Suen 再判断：
- 是否适合接；
- 是否需要先做判断 / 占卜 / 其它低风险步骤；
- 是否适合定制仪式、星符或其它项目；
- 是否需要等待真实天象 / 材料 / 执行条件。

PGM、行星星符、古埃及体系、不同 grimoire、材料与择时属于后台专业工具库，不要求陌生客户先理解完整技术分类。

---

## 二、购买体验标准化，执行方案继续定制

高客单不需要把仪式本身做成流水线。

需要标准化的是客户经历的购买过程：

`现实问题 → 必要信息 → 专业判断 → 定制方案 → 报价 → 付款 → 执行 → 完成通知 → 结果跟踪（适用时）`

不同客户最终使用不同工具、材料、时间和执行方式仍然正常。

---

## 三、每个高客单 Offer 必须说清 6 件事

### 1. 谁适合

按购买状态 / 问题状态描述，不用年龄、城市、职业等人口统计画像硬套。

### 2. 开始前需要什么

例如：
- 需要客户提供哪些真实信息；
- 是否需要先判断；
- 是否要等待时间窗口；
- 是否存在不接 / 不建议执行的条件。

### 3. 为什么推荐当前方案

必须能解释：
- 为什么这个问题与该方案适配；
- 哪些现实条件影响判断；
- 哪些技术选择是因为材料、原典、择时或执行条件。

专业价值优先体现在“会判断怎么做”，不只体现在“会做某个项目”。

### 4. 客户实际购买到什么

根据项目真实情况说明，例如：
- 前期判断；
- 定制方案；
- 材料与准备；
- 择时（适用时）；
- 实际执行；
- 必要的执行记录 / 完成通知；
- 约定范围内的后续回访。

不能把未提供的内容为了显得高价而写进去。

### 5. 哪些事情可以确定

高客单降低风险不能只靠解释“结果不能保证”。

在真实可控范围内，应尽量让客户明确：
- 服务包含什么；
- 当前方案是什么；
- 什么时候进入下一步；
- 是否等待窗口；
- 付款后会发生什么；
- 完成后会得到什么通知；
- 是否存在后续回访。

**结果存在不确定性，过程应尽量清晰。**

### 6. 哪些事情不能承诺

继续明确：
- 不保证百分百结果；
- 不保证固定天数见效；
- 不把客户期望写成已经发生的事实；
- 不虚构历史依据、天象、稀缺和客户反馈。

---

## 四、报价必须与具体方案绑定

高客单正式报价前至少确认：

- 客户需求已经达到可判断程度；
- 当前方案真实可提供；
- 执行条件 / 时间窗口没有被虚构；
- 价格是当前真实价格；
- 是否存在额外材料、采购、定制或其它会显著改变成本 / 工作量的因素。

“仪式会贵一点”“大概一千左右”只算价格预告，不算正式报价。

正式报价应让客户知道：
- 当前建议做什么；
- 为什么；
- 价格；
- 付款后下一步；
- 关键限制 / 时间条件。

不要求写成长销售文案。

---

## 五、内部定价底线模型

在价格尚未充分验证阶段，先保证经济模型可成立。

内部至少考虑：

`直接材料 / 外采成本 + 研究与准备时间 + 实际执行时间 + 客户沟通与后续时间 + 有限执行容量 = 最低经济可行成本基础`

然后再结合：
- 真实市场接受度；
- Suen 的专业差异化；
- 项目复杂度；
- 已有案例与信任资产；
- 客户需求强度；
- 品牌阶段。

当前未明确的参数不得擅自估：
- Suen 的目标小时价值；
- 不同项目真实平均工时；
- 不同高客单项目正式价格带；
- 每周 / 每月最大可承接量。

这些参数后续由 Suen 提供真实数据后进入动态经营状态。

---

## 六、高售价 ≠ 高客单商业模型

复盘不能只看成交金额。

一个高价项目如果占用大量研究、采购、沟通和执行时间，可能仍然是低效率业务。

数据足够时，增加观察：

**贡献利润 / 实际交付小时**

不要求每日精确计时。  
可使用：
- 1小时以内
- 1—3小时
- 3—6小时
- 6—10小时
- 10小时以上
- 不知道

只用于产品经济性判断，不把 Suen 变成工时打卡。

---

## 七、低价入口不是必经路径

当前同时允许两种真实购买路径：

### Path A｜直接高客单

`内容 / 转介绍 → 具体高价值问题 → 合格机会 → 定制方案 → 报价 → 付款`

### Path B｜先低风险购买

`内容 → 具体问题判断 / 塔罗 / 咨询等 → 第一次真实付款 → 后续出现适配需求 → 高客单`

不预设哪条一定更好。

后续用真实数据比较：
- 直接高客单占比；
- 从低价升级占比；
- 升级周期；
- 平均客单；
- 复购 / 转介绍；
- 对价格敏感度。

低客单服务继续可以承担现金流和首次付款，但不把所有高客单客户强制先导入低价。

---

## 八、折扣与风险逆转

高客单默认不依赖持续打折成交。

优先降低购买风险的方式：
- 流程清楚；
- 方案理由清楚；
- 真实执行证据；
- 真实案例；
- 明确的服务范围；
- 正常回访；
- 不夸大结果。

如确实测试优惠，必须有明确产品、人群、时间和真实经营理由，不使用虚假稀缺。

---

## 九、常驻服务入口

正式结构模板读取：`99-模板/常驻服务入口模板.md`.

高客单系统需要一个长期存在的被动购买入口，而不是靠每条内容硬 CTA。

常驻服务入口至少应让陌生人快速知道：

1. Suen 可以处理 / 判断哪些类型的现实问题；
2. 开始时先描述自己的情况，不需要先选复杂魔法项目；
3. Suen 会先判断是否适配与使用什么方案；
4. 怎么发起咨询 / 进入下一步。

课程、Database 等未正式可售产品不提前塞入当前服务入口。

平台具体合规表达仍服从各平台当前规则。

---

## 十、案例证据三层

### A｜判断案例
证明 Suen 如何判断“该不该做 / 应该做什么”。

### B｜执行案例
证明方案、材料、择时、流程和真实工作如何发生。

### C｜结果案例
记录执行前状态、真实后续变化、时间点、最终结果、无变化 / 部分变化、复购与转介绍。

当前 C 不足时，继续积累 A + B，不用话术伪造 C。

---

## 十一、报价与产品验证

在真实高客单成交样本不足时：

- 不把当前价格写成“市场已验证最优价格”；
- 不因一个客户嫌贵就全面降价；
- 不因一个客户接受就立即全面涨价；
- 不用少量样本建立复杂价格弹性模型。

优先完成真实第 1、2、3 个高客单成交，并记录：
- 来源；
- 需求；
- 是否直接高客单；
- 方案；
- 报价；
- 付款原因；
- 未成交时的真实断点；
- 执行时间；
- 后续结果；
- 复购 / 转介绍。


## 十二、价格展示与锚点分层

当前公开价目表包含大量 ¥20—¥688 的低 / 中客单项目。未来四位数定制服务不能默认直接加入同一张全品类价格表。

### 原则

1. **标准化 / 低风险项目可以继续明码标价。**
   例如已稳定存在的塔罗、查事、现有护符、固定规格实物等，是否继续展示由 Suen 决定。

2. **高客单定制另建入口。**
   前台先让客户描述现实问题，再由 Suen 判断是否适合进入定制方案。

3. **未确认正式价格时不伪装成“¥X起”。**
   当前可使用“需要先判断具体情况与方案后报价”作为真实状态，不提前写不存在的起售价。

4. **高客单和低价项目避免同屏形成直接横向比价。**
   这不是隐藏价格，而是区分不同购买逻辑：
   - 低 / 中客单：客户已知道自己买什么；
   - 高客单：客户先进入问题诊断和方案判断。

5. **以后如果正式确认高客单起价，可以公开。**
   是否写“¥XXXX起”必须由真实价格与成交验证决定，不为了筛客擅自设置。

### 当前现行价格表的角色

当前价格表继续视为“现有标准服务 / 产品价目表”，不是未来全部业务的唯一总菜单。

未来新增：
**定制项目 / 高价值执行入口**

只承担：
- 现实问题；
- 适配判断；
- 定制方案；
- 正式报价；
- 执行与后续。


## 十三、标准仪式与完整定制必须分层

当前已有固定感情 / 复合仪式 ¥688。它与未来四位数定制仪式不是同一产品逻辑。

### 标准仪式

特征：
- 核心流程已经固定；
- 客户主要是在一个既有项目中购买执行；
- 允许存在必要的个体信息与正常准备，但不从零重新设计整套方案。

### 完整定制

特征：
- 从客户现实问题进入；
- 需要重新判断适配；
- 可能重新选择技术体系、材料、择时与执行结构；
- 前期判断 / 准备 / 执行占用更高；
- 不要求客户自己选术式。

因此以后高客单定制不能只用“同样也是感情问题”与 ¥688 固定仪式直接比较。报价前必须让客户理解：
**一个是固定项目，一个是根据具体问题重新做方案。**

### 高时耗专业服务

Ars Paulina 与水晶召灵当前单次约2—3小时、公开价均为¥528。它们暂时单列为“高时耗专业服务”，不自动归入未来四位数定制，也不继续默认等同普通标准项目。

后续优先验证：
- 是否存在固定流程；
- 是否有直接材料 / 前期准备；
- 客户购买目的；
- 市场接受度；
- 是否需要调整价格或减少主推频率。
