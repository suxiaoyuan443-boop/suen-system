# Suen｜有限知识产品验证规则 v1

状态：当前正式内部验证方法
建立：2026-10-14

本文件负责把已有研究资产转成一份范围有限、可独立交付的知识产品，并验证需求与交付负担。具体主题、进度、价格、入口和结果只写入 `08-动态运行/商业/当前商业状态.md` 与真实工作资产。它不定义完整课程或数据库的售卖模式。

## 一、首轮只推进一个单元

优先核对《古埃及魔法实践》课程中已真实完成的单元，选择能独立回答一个具体问题、有完整来源和可用展示材料的部分。没有合格现成资产时，先补最接近完成的一个单元，不另开大型新专题。

既有“约40%”只是带日期的口述进度，不证明具体单元已经完成。主题与交付形式须实际核对资产，不能从账号点赞或栏目名称直接定成商品。总控先形成具体可审阅方案，再请Suen确认尚未定案的价格、发售和访问参数。

## 二、内部准备必须交付什么

首轮内部准备至少形成以下可检查结果，不以新增规则文件算产品完成：

- 一页范围说明：面向谁，解决什么学习/资料问题，读者完成后能复述或掌握什么，包含与不包含什么；
- 一份真实示范：从现有资产选择一个可读片段，来源、译文/解释与图像权利清楚，能够体现交付质量；
- 交付清单：实际形式、完整性、使用方式与适用限制；是否有答疑、修订与维护，分别说明；
- 经济性核对：初次整理/制作投入、每位购买者新增支持时间、平台与支付成本、授权及维护成本，缺项明确列出；
- 交易条件草案：拟用平台/类目及许可核查、价格待确认、交付节点、取消退款与访问条件待确认。

教学产品交付真实知识和方法，不把受限仪式服务换名成“研究”。正式文章/讲稿、版权、证据和数据库内容继续执行各自真源；完整资产留在Library/Drive/Obsidian，GitHub只保存范围和状态。

## 三、验证顺序

`资产核对 → 范围与示范 → 目标受众对具体交付的理解/需求 → 可售条件与参数确认 → 正常价付款 → 实际交付与支持负担 → 是否值得继续`

资料兴趣、点赞收藏、意向与付款分别记录。没有向适合受众展示过明确交付，就不能写成需求失败；没有正常价真实付款，也不能写成商业已验证。已完成产品的正常价首轮销售与未完成产品预售分开，当前授权不自动开启预售或公开发售。

每个阶段只解决眼前会改变决策的缺口；内部草案充分后再请求必要定案，不反复让Suen挑抽象想法。不增加每日私信、问卷或销售配额，不为验证未经授权主动联系他人。

## 四、继续、调整与停止

- **继续**：受众理解具体价值并出现真实购买，交付完整且支持/维护投入可承受；随后观察新的独立购买样本，单笔只记单样本。
- **调整**：已真实展示后反复出现具体范围、理解或交付顾虑，或每次购买仍需重新完成大规模研究；先改范围、示范或交付，价格改变仍需Suen确认。
- **停止追加投入/暂缓**：证据或版权无法解决，平台条件不成立，或支持负担与目标明显冲突。保留研究资产，不以沉没成本扩大成全课或数据库。
- **无法判断**：缺资产、缺展示、样本或付款证据。指出下一项必要核查，不把未知写成无人购买。

首轮结论同时说明生活资金贡献与亲自交付依赖；可复制不自动等于被动收入。扩展课时、题目或数据库访问只在明确证据与Suen决定后推进。
