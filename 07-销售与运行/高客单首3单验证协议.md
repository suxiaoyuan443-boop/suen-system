# Suen｜高客单首3单验证协议

状态：当前正式规则  
建立：2026-09-27

适用：
- 未来完整定制仪式；
- 商业总控明确指定的其它四位数高价值定制服务。

纯银金属行星星符是当前下一项明确的四位数高客单产品方向。正式样品、完整工时 / 总成本、规格与正式售价确认前，先走产品开发验证；达到可售状态后，实际支付 ≥¥1000 的真实正常订单可以进入高客单首3单验证，并单独标记为“高价值实物型”样本，不与定制仪式强行混成同一种产品。

目标：
**用真实第1、2、3笔正常付款，验证高客单是否具有可重复商业基础。**

不是为了快速做出漂亮成功率，也不是为了三单后立刻宣布模型跑通。

---

## 零-A、什么订单计入“高客单首3单”｜2026-10-08

本协议中的“高客单”按验证目的定义为：

- 一笔真实正常付款；
- 对应一个明确高价值项目 / 个别方案；
- **实际支付达到四位数（≥¥1000）**；
- 不是私人熟人配合测试；
- 不是免费 / 极低价换反馈；
- 服务范围、价格与付款前条款均已明确。

¥688 固定感情 / 复合仪式、¥528 Ars Paulina / 水晶召灵、标准蜂蜜罐 / 护符等继续按各自产品统计，不因为服务复杂就混入“高客单首3单”。

≥¥1000 是内部验证样本分类线，**不是公开统一起价，也不代表所有仪式都必须卖到四位数。**

## 一、首3单必须是真实正常购买

允许来源：
- 陌生内容流量；
- 老客户的新需求；
- 过去真实询盘再次回来；
- 朋友 / 老客户转介绍。

不要求三单都来自陌生流量。

禁止：
- 免费换反馈；
- 极低价换好评；
- 要求客户必须给正面反馈；
- 为了凑案例主动给无需求的人推项目；
- 把熟人配合测试冒充市场成交。

如果某一单存在友情价 / 特殊优惠，必须真实记录，不能和正常价格样本混写。

---

## 二、每一单成交前记录

### 1. 来源
- 平台；
- 具体内容（能确认时）；
- 老客 / 转介绍 / 陌生；
- 是否此前有过真实付款。

### 2. 需求
- 客户现实问题；
- 想推动什么结果；
- 当前状态是否清楚。

### 3. 机会阶段
按 `高客单机会漏斗.md` 记录：
- 有效询盘；
- 合格机会；
- 信息完整；
- 方案适配；
- 正式报价；
- 决策中；
- 付款。

### 4. 报价
记录：
- 正式报价金额；
- 是否为正常价 / 特殊价；
- 客户主要顾虑；
- 报价到付款所需时间。

不因为客户付款就事后改写他的真实顾虑。

---

## 三、每一单执行中记录

至少记录：

- 实际择时工时；
- 前期准备工时；
- 采购 / 材料准备；
- 实际执行工时；
- 客户沟通与后续工时；
- 直接材料 / 外采成本；
- 是否发生原来没有预计的额外工作；
- 项目总历时（例如跨1天 / 2天）与真实工作小时分开。

不要求分钟级计时，可用合理粗估。

---

## 四、每一单执行后记录

### 交付体验

记录：
- 是否按原约定完成；
- 客户是否清楚当前执行状态；
- 是否出现流程理解问题；
- 是否发生超范围追加需求；
- Suen 自己做完后的负担感：轻 / 正常 / 偏累 / 明显不值得。

### 结果跟踪

在客户同意正常回访时记录：
- 执行前现实状态；
- 执行日期；
- 后续发生的具体变化；
- 变化时间点；
- 未变化 / 部分变化同样记录；
- 客户主观反馈与可观察现实事实尽量分开；
- 是否追加购买 / 复购 / 转介绍。

---

## 五、每完成1单只做局部判断

### 第1单

只回答：
- 有人是否愿意真实支付四位数；
- 从哪里来；
- 为什么愿意付；
- 实际交付比预想重还是轻；
- 是否出现明显流程问题。

**禁止因为第1单成功就立即涨价。**

同样：
**禁止因为第1单未成交就立即降价。**

### 第2单

开始比较：
- 两个客户来源是否相同；
- 需求是否相同；
- 顾虑是否重复；
- 报价是否仍能接受；
- 实际工时是否接近；
- 是否出现可重复流程。

仍不宣布稳定模型。

### 第3单

做第一次阶段性判断：

- 三单是否都来自同一个特殊关系渠道；
- 是否至少有两单表现出相似购买逻辑；
- 当前价格对成交是否形成明显重复阻力；
- 实际完整工时是否符合当前口述3—4或4—5小时的区间，并区分额外工作；
- 贡献利润是否值得；
- 客户是否理解“完整定制”与 ¥688 固定仪式的差异；
- 是否出现可用结果证据；
- 是否有复购 / 转介绍信号。

三单后只决定：
**下一阶段继续原价验证 / 调整报价 / 优化Offer / 优化入口 / 调整适配客户。**

不因为3单就声称已经获得稳定成功率或长期市场份额。

---

## 六、首3单核心商业问题

必须最终回答：

1. **谁愿意付？**
2. **为什么愿意付？**
3. **他们从哪里知道 Suen？**
4. **是直接高客单，还是低价购买后升级？**
5. **报价真正卡在哪里？**
6. **当前完整交付3—5小时口述区间与实际耗时是否一致？**
7. **四单 / 月的舒适承载假设成立吗？**
8. **结果证据是否开始形成？**
9. **有没有复购 / 转介绍？**
10. **这项服务是否比现有标准产品更值得占用 Suen 的时间？**

---

## 七、价格纪律

在首3单验证期：

- 不因一人嫌贵就全面降价；
- 不因一人秒付就立刻涨价；
- 不为了成交临场创造未确认的套餐；
- 不把固定 ¥688 仪式包装成“便宜版定制”；
- 不用“仅剩几位”制造虚假压力；
- 特殊价格必须标记原因。

每个仪式 / 物品 / 个别方案分别定价；既有项目用现价，新价由 Suen 在真实报价前确认。旧内部情景不是统一测试价，首3单中的不同项目要分别标明项目、范围、工时和成本，不混算成单一产品的价格验证。  
内部建议、区间讨论不能自动升级为公开售价。

---

## 八、成功不只看“3单都成交”

阶段成功可能表现为：

- 真实四位数付款成立；
- 客户理解定制价值；
- 实际工时可控；
- 贡献利润合理；
- 不需要强推或虚假承诺；
- 案例与复购开始积累。

如果只有高价格付款，但：
- 工时严重超标；
- 客户期待管理失控；
- 售后负担过大；
- 必须大量折扣才成交；

仍不能视为健康模型。

---

## 九、总控执行

当首3单验证期出现真实机会：

- Revenue P0 优先推进；
- 每一单结束后写入商业月度事实；
- 只有当前状态真正改变时更新当前商业状态；
- 第3单完成后执行一次专项高客单复盘。

在没有真实机会时：
**不为了完成“首3单目标”增加硬销售频率。**
