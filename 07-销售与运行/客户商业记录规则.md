# 客户商业记录｜GitHub 运行规则

状态：当前正式规则
最后核对：2026-09-25

## 触发

**仅在销售私聊专用对话中，Suen 明确要求“生成总结”时输出。**

普通“总结”不触发客户商业记录；商业总控中的“总结”用于每日内容台账流程，二者必须严格区分。

## 目标位置

客户商业记录属于经营事实，默认写入：

- 当月事实：`08-动态运行/商业/YYYY-MM.md`
- 如该记录改变当前漏斗、成交累计、产品状态或下一步，再同步更新 `08-动态运行/商业/当前商业状态.md`

不得把客户询盘、报价、成交推进写入内容台账。

Suen 在销售私聊专用对话中明确说“生成总结”时，先生成短记录；若当前具备 GitHub 写入能力，直接写入上述经营文件，不再要求复制到 Slack。

## 固定两部分

### 1. 本次沟通结果

简短保留：

- 客户阶段
- 购买意图
- 最终结果
- 下一步

### 2. 可直接写入商业记录

使用 `99-模板/商业记录模板.md`，默认短记录，不重复完整聊天过程。

## 简短原则

商业记录优先回答：

- 从哪里来；
- 能否确认对应哪条内容；
- 想买什么；
- 现在到哪一步；
- 报价/成交状态；
- 实际成交金额与预计毛利（能确认时）；
- 是否属于复购 / 转介绍（能确认时）；
- 主要异议 / 成交断点；
- 下一步。

没有实际信息的空字段可以省略，不为了模板完整把记录写成长表。

## 来源归因

客户来源尽量区分：

- 抖音
- 小红书
- 微信 / 朋友圈
- 公众号
- 转介绍
- 老客户复购
- 其它真实来源

如果能从客户原话、私信入口、店铺来源、评论跳转等可靠信息确认对应具体内容，应补上“对应内容”。

如果只能确认平台，不能确认是哪条内容带来的：

- 只写平台；
- 不因为某条内容发布时间最近就自动归因给它。

## 新联系时的来源登记｜2026-10-18

新联系的人如果自然进入对话且适合询问，**只问一次**：

> 你是怎么找到我的？还记得看过哪条内容吗？

允许对方回答“不记得”或不答；不以回答作为提供正常帮助的条件。不要求手机号、真实姓名、社交账号或聊天截图。不根据最近发布作品自行补出对应内容。

仅在Suen实际确认沟通事实、并触发当次商业更新或客户“生成总结”时，向 `08-动态运行/商业/当前商业状态.md`／当月商业记录写**去标识聚合字段**：来源平台、可核实的内容或「不清楚」、新联系/有效询盘/付款阶段、一次需求去重状态。当前未有新接触时不新增假记录，不把同人多次接触重复累计。客户原话可以用不含可识别信息的简短需求类别替代；公开仓库不存联系方式、独特身份、完整对话、付款凭证。

## 状态判断

- 尚未正式报价就写“未报价”，不能因为讨论了价格范围就擅自标成已报价。
- 尚未付款不能记成交。
- 已读未回属于沟通状态，不自动等于流失。
- 沟通仍在继续时，不提前写“最终失败 / 已结束”。
- 内容兴趣、免费资料咨询、学术问题与明确产品/服务需求要区分。

## 主要异议 / 成交断点

未成交记录如果聊天里存在明确证据，尽量保留一个轻量字段：

`主要异议 / 成交断点`

可用描述包括：
- 价格 / 预算；
- 效果预期；
- 起效时间；
- 缺少真实反馈 / 社会证明；
- 不清楚服务流程；
- 不知道该选什么；
- 产品匹配不清；
- 信任不足；
- 只比较价格；
- 沟通中断；
- 购买意愿弱；
- 其它真实出现的原因。

只根据真实聊天判断。多个因素同时存在时可以并列；无法确认主因时写：

`尚无法确定`

“未成交”本身不能反推客户一定是嫌贵、没信任或预算不足。

## 购买质量信号｜高客单验证

为了验证高客单目标客户，不新增数值评分。

当聊天里有明确证据时，可保留一个轻量字段：

`购买质量信号`

可记录：
- 有明确现实目标；
- 已有同类消费经验；
- 主动提供具体情况；
- 重视适配 / 方案 / 材料 / 择时 / 原典 / 执行；
- 正在比较不同方案或服务商；
- 主要只比较最低价格；
- 要求百分百保证；
- 在了解限制后仍愿意继续进入具体方案；
- 其它真实出现的购买行为。

不知道就省略，不能凭感觉给客户贴“高净值 / 优质 / 低质”标签。

这个字段只用于回答：
**什么样的人最终更容易进入报价、成交、复购和转介绍。**

### 结果证明 / 风险异议

当仪式类客户明确询问以下内容时，可在“主要异议 / 成交断点”中保留：
- 效果是否可信；
- 起效时间；
- 百分百保证；
- 缺少同类真实反馈；
- 自己的情况是否太难；
- 正在与其它服务比较；
- 对失败风险 / 花钱无变化的担心。

只有真实聊天出现才记录，不因为客户未成交就自动归因。

## 客户问题资产｜从真实询盘反哺内容与产品

每次真实有效询盘在不增加客户隐私的前提下，除了交易阶段，还应尽量提炼可复用的**问题资产**。只有聊天中真实出现才记录，不补写、不脑补。

可选字段：
- **客户原始问题表达**：保留其问题结构和常用措辞，但去除可识别个人信息；
- **想得到的现实结果**：客户真正希望发生什么；
- **已尝试 / 已购买过什么**：只有客户明确说过才记；
- **主要顾虑 / 追问**：价格、适配、效果、时间、案例、流程、风险等；
- **继续推进的触发点**：什么信息让客户愿意继续说明情况、进入方案或报价；
- **停止推进的已知原因**：仅有证据时记录，未知就写尚无法确定。

这些字段的用途是发现重复问题、购买语言和真实成交阻力，不建立“客户心理画像”，不保存完整聊天原文。

### 进入内容系统的条件

同类问题在多个独立询盘中重复出现，或单个问题本身具有明确代表性时，可以进入商业总控的候选输入，但仍必须重新通过：
- 真实性与隐私；
- 平台 / 栏目适配；
- 证据可答性；
- 商业距离与当天主任务；
- 选题定稿硬门槛。

客户问过不等于一定值得公开；销售私聊也不能原样搬成公开内容。

### 进入产品优化的条件

如果多个独立客户在同一环节反复卡住，可以把它作为产品 / 销售流程的待验证问题，例如：服务流程不清、不会选择、案例不足、价格理解困难。仍需真实样本验证，不能因为一位客户的异议就全局改价或改产品。

## 金额与利润

已成交时，能确认就保留：

- 实际成交金额；
- 已知直接材料 / 执行成本；
- 预计毛利。

预计毛利只在成本足够明确时记录。不知道成本时不凭感觉估算。

报价金额和最终成交金额不同，以真实成交金额作为成交事实，必要时可以保留原报价用于复盘。

## 复购与转介绍

如果能确认客户属于：

- 老客户复购；
- 现有客户追加购买；
- 老客户 / 朋友转介绍；

应单独保留。它们属于重要商业质量信号，不能全部混进“自然平台询盘”。

## 有效询盘

有效询盘通常至少出现一项明确购买行为：

- 问具体服务/产品；
- 问价格；
- 问能否执行；
- 提供与购买决策直接相关的个人需求；
- 继续推进时间、方案、付款等细节。

单纯点赞、表达兴趣、问免费资料或讨论知识，不自动计入有效询盘。

## 隐私

GitHub 只保存业务复盘需要的信息。即使仓库为 private，也默认不记录客户姓名、微信号、手机号、地址、付款截图、付款账号或完整聊天原文。


## 高客单机会记录扩展｜2026-09-27

当该需求属于高客单验证范围时，除原字段外尽量记录：
- 机会阶段：有效询盘 / 合格机会 / 信息完整 / 方案适配 / 正式报价 / 决策中 / 已付款 / 执行 / 结果跟踪；
- 推荐方案：能去身份化且已真实形成时；
- 是否直接高客单，或来自此前低风险真实付款；
- 客户当前主要顾虑；
- 下一步与客户给出的时间节点；
- 未成交原因：只有真实证据时；
- 已成交后的交付耗时粗档、直接成本（已知时）；
- 是否形成复购 / 转介绍 / 可用案例。

不要为了填 Pipeline 把历史旧询盘强行补成不存在的阶段。新规则生效后，从新发生或仍在真实推进的机会开始记录；历史仅在有可靠聊天事实时补录。
