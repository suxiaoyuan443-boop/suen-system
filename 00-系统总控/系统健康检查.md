# Suen System｜系统健康检查

状态：维护清单
建立：2026-09-20
最后核对：2026-09-25

用途：只在周复盘、重大迁移、规则大改、发现冲突时使用。普通日常任务不加载。

## 1. 真源一致性

检查：
- 正式规则是否仍只有一个当前真源；
- `08-动态运行/` 是否仍是唯一当前动态真源；
- 历史归档 / CHANGELOG / 旧规则残留是否被误写成当前执行要求；
- 是否出现已经删除路径的引用。

通过标准：
当前规则、当前状态、历史三层没有互相覆盖。

## 2. 当前总览同步

核对：
- `08-动态运行/00-当前总览.md`
- 内容当前状态
- 轻量灵感库存（仅检查是否误被当成定题真源）
- 商业当前状态
- 天象当前预约池

只检查会影响总控判断的摘要字段，不要求复制全部细节。

## 3. 月度滚动

进入新月后检查：
- 内容 `YYYY-MM.md` 是否建立；
- 商业 `YYYY-MM.md` 是否建立；
- 天象 `YYYY-MM.md` 是否按需要建立；
- 上月文件是否停止新增非补录事实；
- 补录旧事实是否仍按真实发生月份归档。

## 4. 内容数据完整性

检查：
- 新发布内容是否进入当月台账；
- 重要数据变化是否更新当前状态；
- 抖音大号 / 小号 / 小红书历史基线是否只在需要重新总结规律时更新；
- 不同统计窗口是否仍明确区分；
- 删除 / 重发 / 异常上传是否没有被误算为正式样本。

## 5. 商业数据完整性

检查：
- 有效询盘是否按独立需求去重；
- 成交是否有真实付款 / 交易事实；
- 同一订单补款是否没有重复算成交；
- GMV / 预计毛利 / 净利润是否仍严格区分；
- 客户隐私是否没有进入仓库。

## 6. 定题机制健康

检查：
- 是否又开始维护跨日高优先候选、冷却、P0 等“隐形选题池”；
- 是否先看当天第一方数据、最近发布、制作条件和商业状态，再生成当天少量候选；
- 是否因为旧题已经投入研究时间而产生救题倾向；
- 灵感库存是否仍只保存轻量线索，没有膨胀成第二套候选管理系统。

## 7. 天象经营状态

检查：
- 日期已经过去的窗口是否仍错误显示“开放预约”；
- 当前预约窗口是否仍经过专用择时真源确认；
- 经营层是否没有擅自改技术时刻或评级。

## 8. 仓库体积与文件边界

检查：
- 不把视频、高清图片、ZIP、PDF等大文件长期塞进本运营仓库；
- 大文件继续放 Drive / Library / 原始来源；
- 当前状态文件没有重新膨胀成历史堆积；
- 单条内容的一次性素材包没有被固化成长期系统文件。

## 9. 迁移 / 大改后的最低验收

任何重大迁移结束后至少确认：

1. 新真源能读；
2. 新真源能写；
3. 被新真源完全覆盖、没有兼容价值的旧正式路径已经删除；需要追溯时使用 Git history / CHANGELOG；
4. 启动索引已更新；
5. README / AGENTS 已更新；
6. CHANGELOG 已记录；
7. 当前总览与细分状态没有冲突；
8. 至少实际跑一次正常接管流程。

全部通过后才算迁移完成。
