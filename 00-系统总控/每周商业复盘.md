# Suen｜每周商业复盘

状态：当前正式规则
最后核对：2026-09-18

本文件补齐商业总控的“每周复盘”职责。

**不设置固定星期几。**只有 Suen 明确说“周复盘 / 每周总结 / 复盘这周”，或商业总控在当前工作中明确需要做周级判断时执行。

不得自行创建新的周 KPI；目标仍以 `商业目标与产品优先级.md` 为准。

商业触点、跨平台重复销售与动态状态有效期同时读取 `商业信号与动态状态规则.md`。

---

## 一、读取范围

执行周复盘时，至少读取：

1. Slack `#内容历史台账` 最近 7 天实际发布与复盘；
2. Slack `#商业决策总控` 最近 7 天询盘、报价、成交与产品推进；
3. Slack `#天象检索与预约` 当前仍有效的经营状态；
4. `商业目标与产品优先级.md`；
5. `商业指标口径.md`；
6. `商业信号与动态状态规则.md`；
7. 当周用户最新明确指令。

如果核心 Slack 数据读取失败，明确数据覆盖缺口，不拿旧记忆假装完整周报。

---

## 二、周复盘必须回答什么

### 1. 目标进度

至少看：

- 有效询盘：本周新增、当前周期累计；
- 成交：本周新增、当前周期累计；
- 已知成交额；
- 预计毛利 / 已知利润贡献；
- 净利润数据是否足够完整。

严格执行 `商业指标口径.md` 的去重和利润口径。

### 2. 商业漏斗卡在哪里

按实际数据判断：

`内容触达 → 精准关注 → 服务认知 → 有效询盘 → 报价 → 成交 → 复购 / 转介绍`

周复盘只确定当前最主要的 1 个瓶颈，必要时补 1 个次级瓶颈，不把所有问题同时列成同等优先级。

### 3. 哪些内容真正产生价值

分开看：

- A｜流量内容；
- B｜精准涨粉；
- C｜服务认知；
- D｜商业承接。

同时复盘：

- 哪类入口带来更好的陌生流量；
- 哪类内容带来精准关注；
- 哪些内容出现真实服务需求 / 问价；
- 哪些内容能可靠归因到有效询盘 / 成交；
- 最近是否出现内容体验过度重复。

不能只用最高播放量决定下周全部内容。

### 4. 产品经营状态

至少检查：

- 哪些产品 / 服务当前真实可售；
- 哪些处于准备中 / 未完成；
- 哪些依赖天象窗口；
- 哪些已经出现真实需求；
- 哪些已经被内容反复曝光但没有询盘；
- 哪些询盘多但报价 / 成交弱；
- 哪些旧价格、旧排期、旧预约状态已经不应继续沿用；
- 是否存在日期已经过去、但 Slack 状态仍停留在“开放预约”的天象窗口。

产品长期价值高，不等于下周必须主推。

### 5. 商业密度与触点质量

回看最近 7 天所有明显商业触点，而不是只看“卖了几个不同产品”。

至少检查：

- 哪些平台出现过价格 / 预约 / 购买 / 私信 CTA；
- 是否连续多天处于销售状态；
- 是否同一天抖音、小红书、公众号、朋友圈重复同一个销售动作；
- 同一支同步视频是否在正文和配文里重复强化 CTA；
- 哪些商业触点带来真实有效询盘 / 报价 / 成交；
- 哪些触点只增加销售感但没有商业结果；
- 下周是否应该降低、维持或提高商业承接密度。

80 / 20 只作为长期内容结构方向，不为了凑比例机械安排销售。

### 6. 工作量

复盘这一周实际制作负担：

- 哪类内容返工最多；
- 哪些任务占用了过多时间却没有明显商业 / 品牌收益；
- 是否存在本可由系统自行完成、却转给 Suen 人工 QA 的工作；
- 下周哪些流程应该减少而不是继续增加。

---

## 三、下周结论

周复盘最后只定以下经营方向：

- 下周最主要瓶颈；
- 下周主要内容任务倾向（A / B / C / D）；
- 需要继续测试的 1—3 个变量；
- 当前最值得承接的产品 / 服务（如有）；
- 下周商业触点密度方向；
- 下周明确不推什么；
- 是否需要调整内容频率、栏目体验或商业密度；
- 是否存在需要 Suen 单独定案的商业参数。

不在周复盘里提前把未来 7 天每一天选题全部写死。

每天的真实选题仍由当天“更新”读取最新数据后决定。
