# Suen｜每周商业复盘

状态：当前正式规则
最后核对：2026-09-25

本文件补齐商业总控的“每周复盘”职责。

**不设置固定星期几。**只有 Suen 明确说“周复盘 / 每周总结 / 复盘这周”，或商业总控在当前工作中明确需要做周级判断时执行。

不得自行创建新的周 KPI；目标仍以 `商业目标与产品优先级.md` 为准。

商业触点、跨平台重复销售与动态状态有效期同时读取 `商业信号与动态状态规则.md`。

制作耗时、同一生产单元和投入产出判断读取 `生产投入产出规则.md`。

内容实验、主要验证假设与信号升级读取 `内容实验与验证规则.md`。

---

## 一、读取范围

执行周复盘时，至少读取：

1. `08-动态运行/内容台账/当前状态.md` + 覆盖最近7天的月度内容台账；
2. `08-动态运行/选题池/当前选题池.md` 当前候选、冷却、淘汰与观看体验分布；
3. `08-动态运行/商业/当前商业状态.md` + 覆盖最近7天的月度商业记录；
4. `08-动态运行/天象/当前预约池.md` 当前仍有效的经营状态；
5. `商业目标与产品优先级.md`；
6. `商业指标口径.md`；
7. `商业信号与动态状态规则.md`；
8. `生产投入产出规则.md`；
9. `内容实验与验证规则.md`；
10. 当周用户最新明确指令。

如果核心 GitHub 动态文件或覆盖周窗口的月度记录读取失败，明确数据覆盖缺口，不拿旧记忆假装完整周报。

## 二、周复盘必须回答什么

### 1. 目标进度

至少看：

- 有效询盘：本周新增、当前周期累计；
- 成交：本周新增、当前周期累计；
- 实际总回款；
- 外部市场商业回款；
- 预计毛利 / 已知利润贡献；
- 净利润数据是否足够完整。

熟人本人真实付款计入实际总回款，但不用于证明外部市场验证；具体口径读取 `商业指标口径.md`。

严格执行 `商业指标口径.md` 的去重和利润口径。

### 2. 商业漏斗卡在哪里

按实际数据判断：

`内容触达 → 精准关注 → 服务认知 → 有效询盘 → 报价 → 成交 → 复购 / 转介绍`

周复盘只确定当前最主要的 1 个瓶颈，必要时补 1 个次级瓶颈，不把所有问题同时列成同等优先级。

### 3. 哪些内容真正产生价值

分开看：

- A｜流量内容；
- B｜精准涨粉；
- C｜服务认知；
- D｜商业承接。

同时复盘：

- 哪类入口带来更好的陌生流量；
- 哪类内容带来精准关注；
- 哪些内容出现真实服务需求 / 问价；
- 哪些内容能可靠归因到有效询盘 / 成交；
- 最近是否出现内容体验过度重复；
- 当前选题池是否过度集中在单一栏目 / 单一视觉 / 单一传统，是否需要补不同观看体验。

不能只用最高播放量决定下周全部内容。

### 4. 产品经营状态

至少检查：

- 哪些产品 / 服务当前真实可售；
- 哪些处于准备中 / 未完成；
- 哪些依赖天象窗口；
- 哪些已经出现真实需求；
- 哪些已经被内容反复曝光但没有询盘；
- 哪些询盘多但报价 / 成交弱；
- 哪些旧价格、旧排期、旧预约状态已经不应继续沿用；
- 是否存在日期已经过去、但当前预约池仍停留在“开放预约”的天象窗口。

产品长期价值高，不等于下周必须主推。

### 5. 商业密度与触点质量

回看最近 7 天所有明显商业触点，而不是只看“卖了几个不同产品”。

至少检查：

- 哪些平台出现过价格 / 预约 / 购买 / 私信 CTA；
- 是否连续多天处于销售状态；
- 是否同一天抖音、小红书、公众号、朋友圈重复同一个销售动作；
- 同一支同步视频是否在正文和配文里重复强化 CTA；
- 哪些商业触点带来真实有效询盘 / 报价 / 成交；
- 哪些触点只增加销售感但没有商业结果；
- 下周是否应该降低、维持或提高商业承接密度。

80 / 20 只作为长期内容结构方向，不为了凑比例机械安排销售。

### 6. 工作量与生产效率

复盘这一周实际制作负担。有制作耗时档位的样本时，优先结合真实耗时判断，而不是凭印象。

至少看：

- 哪类内容返工最多；
- 哪些任务占用了过多时间却没有明显商业 / 品牌收益；
- 哪些低成本内容在对应主任务上反而取得较好结果；
- 哪些高成本内容虽然短期数据一般，但有明显精准受众 / 搜索 / 长期资产价值；
- 同一支抖音 + 小红书同步成片是否被正确视为一个生产单元，没有重复算成本；
- 是否存在本可由系统自行完成、却转给 Suen 人工 QA 的工作；
- 下周哪些流程应该减少、降频或改成轻量形式。

不计算伪精确的“每小时播放价值”。

周级投入产出重点是判断：

- **高投入高回报**：值得保留，但需要控制频率；
- **低投入高回报**：优先继续验证；
- **高投入普通回报**：优先优化制作方式、降频或换题型；
- **低投入普通回报**：如果承担账号人格 / 稳定更新作用，可保留为轻量内容。

如果当周制作耗时数据很少，只写“样本不足”，不强行下结论。

### 7. 本周实验到底学到了什么

读取当周发布前已经写入商业运行记录的主要验证假设，再看后续真实结果。

至少回答：

- 哪些假设得到支持；
- 哪些不支持；
- 哪些因为数据太少 / 多变量同时变化 / 平台异常而无法判断；
- 哪些结构只是第一次支持，仍停留在单样本；
- 哪些已经出现第 2 个、第 3 个相近样本，可以升级为重复信号；
- 是否有原本以为成立的结构，在新样本里开始变弱，需要降级或重新验证。

禁止周末看见结果以后，给没有预先写假设的内容补造“实验目的”。

如果当周多数内容没有新增实验，也可以正常写：

`本周主要执行稳定结构，新增验证样本较少。`

周复盘不追求“每周必须证明三个规律”。

---

### 8. Patreon

只有 Patreon 当前动态状态为“已恢复主动运营”时，周复盘才检查 Patreon；暂停期默认只记录“暂停，无需复盘篇数”。

恢复后可检查：
- 公开帖与付费帖是否形成可理解的档案结构；
- 当前付费会员数；
- 本周新增 / 取消（平台能取得时）；
- 实际订阅收入 / 到账口径（能可靠取得时）；
- 哪篇文章或哪个外部入口带来会员（能可靠归因时）；
- Full Research Essays 与 Selected Practice Records 哪类更值得继续投入。

不设内部“约4篇”节奏，也不因为某周没有发布就机械补稿。

## 三、下周结论

周复盘最后只定以下经营方向：

- 下周最主要瓶颈；
- 下周主要内容任务倾向（A / B / C / D）；
- **需要继续验证的 1—3 个主要假设 / 变量；**
- 当前最值得承接的产品 / 服务（如有）；
- 下周商业触点密度方向；
- 下周明确不推什么；
- 是否需要调整内容频率、栏目体验或商业密度；
- **哪些重内容继续保留，哪些生产方式应该降频 / 轻量化；**
- 是否存在需要 Suen 单独定案的商业参数。

不在周复盘里提前把未来 7 天每一天选题全部写死。

每天的真实选题仍由当天“更新”读取最新数据后决定。

下周测试变量只定方向，不强迫每天都做实验，也不为了凑验证次数牺牲强题。
