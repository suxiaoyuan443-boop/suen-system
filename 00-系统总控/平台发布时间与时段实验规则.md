# Suen｜平台发布时间与时段实验规则

状态：当前正式规则
最后核对：2026-09-18

本文件用于控制“什么时候发”，目标不是寻找一个永久黄金分钟，而是逐步用 Suen 自己的第一方数据建立各平台发布时间基线。

运营时区统一使用：**Asia/Shanghai（UTC+8）**

## 一、优先级

发布时间判断按以下优先级：
1. Suen 自己平台后台的小时级粉丝活跃数据；
2. Suen 自己历史内容的实际发布时间 + 同窗口表现；
3. 当前受众画像与内容消费场景；
4. 外部平台通用活跃时段，只作为缺少第一方数据时的初始先验。

不得把外部“黄金时间”文章覆盖第一方真实数据。如果平台没有小时级活跃曲线，不能声称已经知道精确最佳小时。

## 二、发布时间不是主要内容质量的替代品

时段只能解释一部分分发结果。复盘时必须同时看：内容类型 / 前台合集、入口结构、内容形式、时长、标题与封面、统计窗口、平台异常与实际发布时间。

不能因为一条爆款发在 18:30，就直接得出“18:30一定最好”。

### 4. 公众号

当前没有足够第一方发布时间样本建立“最佳时段”。临时运营默认：贴图 / 轻内容 12:30；长文 20:30—21:00。只作为测试起点。

### 5. 朋友圈

朋友圈不按公域推荐流量理解。普通工作记录 / 轻内容优先 12:00—13:00 或 18:00—19:00；预约 / 商业提醒优先 20:00—21:00。真正优先级仍是有没有真实事件和商业需要。

## 五、总控每天怎么用

正常“更新”时，如果当天有正式发布任务，总控应给出：平台、建议发布时间，以及该时间属于历史基线 / 挑战点 / 临时测试 / 已有稳定时段。

默认不精确到某个神奇分钟。例如：抖音大号｜建议20:30｜峰值前测试；或 抖音大号｜建议21:15｜峰值内测试；需要对照时才安排18:45历史基线。

## 六、什么时候算“时段有信号”

发布时间属于实验变量之一，统一服从内容实验与验证规则。先比较同平台，尽量比较相近内容形式与题材，并使用相同或接近统计窗口。

不把一个爆款当成发布时间证明。多个独立样本在同一方向重复以后，才从“挑战点”升级成“优先窗口”。其它变量差异太大时，结果写：无法判断发布时间影响。

## 七、台账要求

以后所有新发布内容，只要后台能看到，就记录实际发布时间（Asia/Shanghai），格式：实际发布时间：2026-09-18 18:47。

旧内容不要求大规模补录；已经通过截图可靠取得的可以补。发布时间进入分析时，必须与内容类型、内容形式、统计阶段、主要任务 A/B/C/D 一起看。

## 八、什么时候重新改默认时间

出现以下任一情况时重新评估：平台后台出现可靠小时级粉丝活跃曲线；同一时段积累了多个可比样本；当前默认时段连续多个可比样本明显走弱；账号受众结构发生明显变化；Suen 明确调整作息或发布时间限制。

没有新证据时，不因为一两天数据波动频繁换时间。

最终目标：用稳定发布时间减少变量，再用真实第一方数据逐步找到各平台自己的优先窗口。
