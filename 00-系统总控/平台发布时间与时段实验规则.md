# Suen｜平台发布时间与时段实验规则

状态：当前正式规则  
最后核对：2026-09-24  
运营时区：**Asia/Shanghai（UTC+8）**

本文件只控制“什么时候发”。目标不是寻找永久黄金分钟，而是用 Suen 自己的第一方数据建立各平台可更新的发布时间基线。

## 一、证据优先级

发布时间判断按以下顺序：

1. Suen 当前明确的长期发布时间偏好 / 现实时间限制；
2. 该平台最新的第一方粉丝活跃数据；
3. Suen 自己历史内容的实际发布时间 + 可比窗口表现；
4. 当前受众画像与内容消费场景；
5. 外部平台通用时段，只在缺少第一方数据时作初始参考。

旧截图、旧活跃排名和单条爆款不得覆盖更新后的第一方数据。

## 二、当前统一执行锚点

截至 2026-09-24，商业总控与内容当前状态统一使用：

**默认发布锚点：20:30。**

含义：
- 某平台没有更强第一方证据时，当天正式发布优先 20:30；
- 这不是“黄金分钟”，只是当前稳定执行锚点，用来减少变量；
- 单条在 20:30 附近表现差，不能单独推翻时段；先检查题材、Hook、留存、长度、分发与其它变量；
- 只有新的一组可比第一方数据形成更强反证，才为某个平台单独覆盖 20:30。

## 三、抖音大号

### 当前最新粉丝活跃顺序
最新已确认第一方数据：

1. **22:00—23:00 第一**
2. **21:00—22:00 第二**
3. **23:00—24:00 第三**

因此当前仍优先 **20:30 左右发布**，让首轮分发进入随后 21:00—23:00 的主要活跃段。

旧的 2026-09-18 活跃排名（21—22第一、22—23第二、20—21第三）属于历史截图，不再作为当前排序。

### 历史发布时间样本怎么用
18:00—19:00、20:30 左右以及其它已发布时点仍可作为历史样本比较，但：
- 不再维护“18:45历史基线 / 21:15峰值内测试”这类固定测试点；
- 新内容先稳定使用 20:30；
- 只有为了验证一个明确时段假设，才临时设置对照时点；
- 时段实验必须尽量比较相近题材、形式与统计窗口。

## 四、小红书

当前没有可靠的小时级粉丝在线曲线。

已知历史样本显示 18:00—20:45 都曾出现有效内容，但这些样本题材差异很大，不能证明某个小时稳定更优。

当前执行：
- 默认随大号同步时：**20:30 左右**；
- 独立小红书内容：没有更强第一方证据时仍用 20:30；
- 不再按“强视觉18:30、解释型20:30”机械分流，除非未来真实数据反复支持这种差异。

## 五、抖音小号

当前粉丝基数较小，缺少稳定的小时级粉丝活跃画像。

执行原则：
- 有真实素材再发，不机械日更；
- 发布时间不是当前小号主要瓶颈；
- 没有更强证据时使用 20:30 左右，或服从当天真实工作 / 实践发生时间；
- 不因为历史上某一条午间或晚间高播放，就固定新的黄金时段。

## 六、公众号

当前没有足够第一方发布时间样本建立独立最佳时段。

执行：
- 每日更新基线服从 `03-公众号/阿赫特之门.md`；
- 没有更强平台证据时，正式发布时间优先 20:30；
- 如贴图 / 长文后续积累了足够可比样本，再分别建立自己的时段基线。

不再把“贴图12:30、长文20:30—21:00”当固定默认。

## 七、朋友圈

朋友圈不按公域推荐算法理解。

发布时间优先服从：
- 真实事件发生时间；
- 当天商业密度；
- 内容是否需要时效；
- Suen 当天作息。

没有时效需要时，不为了所谓黄金时段强行卡点。

## 八、什么时候可以改当前锚点

满足以下之一再重新评估：

- 平台出现新的可靠小时级粉丝活跃数据；
- 同一时段积累多个相近内容 / 相近窗口样本；
- 当前锚点连续多个可比样本明显走弱，并排除了题材与留存等主要变量；
- 账号受众结构明显变化；
- Suen 明确调整长期发布时间偏好或现实作息。

一个爆款或一条低表现都不够。

## 九、台账要求

新发布内容能取得时记录：
- 实际发布时间；
- 平台；
- 内容形式 / 栏目；
- 主任务 A / B / C / D；
- 复盘统计窗口。

发布时间只作为解释变量之一，不能替代内容结构判断。

最终目标：

**用一个稳定锚点减少无意义变动，再用第一方数据决定是否真的值得改时间。**
