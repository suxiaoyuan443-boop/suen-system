# Suen｜平台发布时间与时段实验规则

状态：当前正式规则  
最后核对：2026-09-24  
运营时区：Asia/Shanghai（UTC+8）

本文件只负责“什么时候发”。发布时间是辅助变量，不能替代题材、Hook、留存、内容结构与平台分发判断。

## 一、判断优先级

发布时间按以下优先级决定：

1. Suen 自己平台后台的**最新小时级粉丝活跃数据**；
2. Suen 自己可比内容的**实际发布时间 + 同统计窗口表现**；
3. Suen 已确认的长期作息 / 发布偏好；
4. 只有前三项不足时，才参考外部平台通用时段。

旧截图、旧实验结论一旦被更新的第一方数据覆盖，就只保留为历史对照，不继续作为“当前最佳时段”。

## 二、当前统一执行锚点

在没有更强平台级第一方反证时：

**默认发布时间锚点：20:30（Asia/Shanghai）。**

理由：
- Suen 当前明确偏好 20:30 左右；
- 抖音大号最新小时级活跃高峰集中在 21:00 之后，20:30 可让首轮分发进入后续活跃段；
- 小红书、公众号、抖音小号目前都缺少足够稳定的小时级曲线，不值得为了“错峰”随意改成一堆未经验证的分钟。

单条内容在 20:30 附近表现差，不能单独推翻该锚点。先检查题材、首屏、2秒 / 5秒留存、时长、分发与统计窗口。

## 三、抖音大号

### 当前最新粉丝活跃时段
以最近已确认后台数据为准：

1. **22:00—23:00｜第一**
2. **21:00—22:00｜第二**
3. **23:00—24:00｜第三**

因此当前默认：
- **20:30：首选发布锚点**
- 让首轮分发进入 21:00—23:00 主活跃区间。

### 历史对照
18:30—19:00 曾是早期连续发布窗口，只作为历史比较基线，不再自动作为默认首选。

若后续要做时段实验，必须尽量控制题材、形式与统计窗口；不能拿一个爆款证明某个分钟永久最好。

## 四、小红书

当前没有可靠小时级粉丝在线曲线。

已确认历史上 18:00—20:45 都出现过有效样本，因此：
- 当前默认仍使用 **20:30**；
- 18:00—20:45 只视为“历史可用宽窗口”，不是多个固定黄金点；
- 不再长期固化“强视觉必须18:30、解释型必须20:30”这类场景分配，除非新数据重复支持。

如果后续取得小时级活跃数据，再由第一方数据覆盖当前默认。

## 五、抖音小号

当前粉丝量仍不足以形成稳定小时级活跃画像。

因此：
- 默认发布锚点：**20:30**；
- 真实实践 / 工作现场有明显时效性时，可以按事件本身安排，不为了时段规则拖延真实内容；
- 早期 12:20、17:15、18:43、19:36、20:14、20:47 等样本只作为历史对照，不形成“某内容类型必须某小时”的硬规则。

## 六、公众号

当前没有足够第一方发布时间数据证明“贴图12:30、长文20:30”等固定分流长期有效。

因此：
- 默认发布锚点：**20:30**；
- 若当天有明确阅读场景、平台后台数据或运营现实需要，可调整；
- 贴图 / 长文的内容产品选择，与发布时间判断分开，不因为形式不同自动套不同小时。

公众号是否当天发布，服从 `03-公众号/阿赫特之门.md` 当前“每日更新”规则。

## 七、朋友圈

朋友圈不按公域推荐算法理解。

优先级：
1. 真实事件发生时点；
2. 业务 / 预约信息的现实需要；
3. Suen 当天生活与工作节奏。

没有必要为了“最佳发布时间”推迟一条本来应当及时出现的真实工作记录。

## 八、什么时候允许改默认时段

只有出现以下之一才重新评估：

- 平台后台出现新的可靠小时级粉丝活跃曲线；
- 同一时段积累多个相对可比样本并重复呈现同方向；
- 当前默认时段在多个相对可比样本中连续明显走弱；
- 账号受众结构发生明显变化；
- Suen 明确调整作息或发布限制。

改动后必须同步：
- 本文件；
- `08-动态运行/内容台账/当前状态.md` 中的时段摘要；
- 涉及“更新”执行的工作流 / 模板（如确有变化）。

## 九、复盘纪律

发布时间只能作为解释变量之一。

复盘时至少同时看：
- 内容类型 / 栏目；
- 题目入口；
- 首屏 / Hook；
- 时长；
- 2秒 / 5秒留存；
- 平均观看；
- 互动 / 涨粉；
- 实际发布时间；
- 统计窗口；
- 是否存在平台异常分发。

最终目标是**减少不必要变量**，不是寻找一个神奇分钟。
