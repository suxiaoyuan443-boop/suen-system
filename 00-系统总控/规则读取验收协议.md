# Suen｜规则读取验收协议

状态：当前正式规则
最后核对：2026-09-19

本文件解决一个执行稳定性问题：**“提示词里写了去读 GitHub”不等于实际已经读取 GitHub 当前规则。**

只要某个 ChatGPT / Agent / 专用对话声称自己“已读取仓库 / 已按最新仓库规则执行”，就必须满足本协议。

---

## 一、什么时候必须实际读取

出现以下任一情况时，必须先实际调用 GitHub 连接器读取相关文件，再生成正式成品：

1. Suen 明确要求“先读仓库 / 读取 GitHub / 按最新规则执行”；
2. 商业总控把当天任务交给某个平台 / 栏目专用对话；
3. 当前任务第一次进入某个尚未在本会话实际加载过的平台 / 栏目；
4. Suen 明确说仓库规则刚修改过；
5. 当前对话记忆、旧提示词、旧成稿与 GitHub 当前规则可能冲突；
6. 当前任务依赖时长、文风、素材、交付格式、栏目边界等长期规则。

不能用以下内容替代本轮实际读取：

- 旧对话记忆；
- 项目摘要；
- 历史 commit 印象；
- “之前读过”；
- 总控提示词里对规则的二次概括。

---

## 二、最低读取集

### 具体栏目 / 平台任务

至少实际读取：

1. 该栏目 / 平台当前正式规则；
2. `00-系统总控/Suen统一文笔总则.md`；
3. `00-系统总控/文笔成稿验收协议.md`；
4. `00-系统总控/专用对话执行验收协议.md`；
5. 该任务对应的统一交付规则；
6. 如果是视频：`99-模板/视频类统一交付格式.md`；
7. 如果总控提示词明确列出其它文件，一并读取。

抖音大号选题还应按需要读取：

- `01-抖音大号/栏目选题边界与路由.md`；
- 相关总控当日交接。

### 商业总控运行时

固定先读取：

1. `00-系统总控/总控启动索引.md`；
2. `00-系统总控/商业目标与产品优先级.md`；
3. Slack 三个动态频道。

随后只按启动索引读取当前任务需要的规则。

不得把“读取越多”误认为“执行越可靠”。

涉及商业目标累计、周复盘或漏斗统计时再读取：

- `00-系统总控/商业指标口径.md`；
- 需要周级判断时再读取 `00-系统总控/每周商业复盘.md`。

### 隔离 Rule Vault

`Suenakhet Database Rules/` 不属于商业总控启动集。只有数据库专用任务或 Suen 明确要求时才读取。

---

## 三、什么叫“实际读取成功”

必须满足以下条件：

- 实际调用 GitHub 读取动作，而不是只在文字里说“我会读取”；
- 返回的是当前仓库默认分支或当次明确指定分支的文件内容；
- 能确认文件路径；
- 能确认当前 blob SHA；
- 正文生成前已经读取完成。

如果工具没有返回 SHA，但能可靠确认当前文件内容与版本来源，可以明确说明“当前工具未返回 SHA”；不得编造 SHA。

---

## 四、读取回执

当 Suen 明确要求“先读仓库”，或今天曾发生规则读取错误 / 规则冲突时，正式生成前必须先给一份简短【读取回执】。

固定格式：

```text
【GitHub读取回执】
已实际读取：
- 文件路径｜SHA
- 文件路径｜SHA
- 文件路径｜SHA

本次直接影响成稿的硬规则：
1.
2.
3.
4.
5.

冲突检查：无 / 有
如有：写明“旧要求 A ↔ 当前仓库规则 B”，先等待 Suen 或按明确优先级处理。
```

读取回执的目的不是增加形式工作，而是让 Suen 能一眼确认：

**这次到底真的读了什么，以及成稿将依据什么。**

如果是日常稳定执行、Suen 没有要求显示回执、且当前会话刚刚已经实际读取同一版本文件，可以不重复展示完整回执；但内部仍不得跳过必要读取。

---

## 五、冲突校验

读取完成后、正式生成前，必须主动比较：

1. Suen 本轮最新明确指令；
2. 当天总控交接；
3. GitHub 当前正式栏目 / 平台规则；
4. 旧对话记忆 / 旧成稿要求。

默认优先级：

**Suen 最新明确指令 > 当前仍有效的 Slack 当日经营决定 / 状态 > GitHub 当前正式运营规则 > 历史记录 / 旧提示词 / 旧成稿。**

如果旧提示词与 GitHub 冲突：

- 不继续机械执行旧提示词；
- 明确指出冲突；
- 使用优先级更高的当前规则；
- 如果无法判断谁更新，先停在冲突说明，不自行猜。

---

## 六、读取失败协议

### GitHub 连接器可用，但读取失败

如果关键文件读取失败：

- 不得输出“已按仓库最新规则执行”；
- 不得继续生成正式最终成品；
- 明确写：`GitHub 当前未成功读取：<文件路径>`；
- 可以说明缺的是哪一层规则；
- 修复 / 重试成功后再继续。

### 当前对话根本没有 GitHub 访问能力

明确写：

`当前对话无法实际访问 GitHub，因此不能声称已读取仓库。`

然后才可以按：

- 当前对话中最新明确长期规则；
- Suen 当天最新明确指令；
- 当天总控交接；

继续执行。

商业方向无法确认时仍默认纯内容。

---

## 七、禁止行为

禁止：

- 只复述文件名，然后声称已读取；
- 用记忆里的规则冒充刚刚读取的 GitHub；
- 没有拿到 SHA 却编造 SHA；
- 读取失败后继续输出“最终版”；
- 只读总控提示词，不读栏目自身真源；
- 用总控对栏目规则的概括覆盖栏目文件原文；
- 因为“赶时间”跳过规则读取；
- 一边生成完整成稿，一边才发现规则冲突再大面积返工；
- 只读取 `Suen统一文笔总则.md`，却跳过 `文笔成稿验收协议.md` 的最终 QA；
- 只完成规则读取，却跳过 `专用对话执行验收协议.md` 的执行与交付自检。

---

## 八、执行目标

这套协议不是要求每次把仓库全文复制给 Suen。

目标只有三个：

1. **确保工具真的被调用；**
2. **确保当前成稿使用的是当前规则，不是旧记忆；**
3. **在生成前发现冲突，而不是成稿后由 Suen 人工发现。**

规则读取属于生产前置步骤。未完成读取验收时，正式交付尚未开始。

读取完成后，正式成稿还必须继续执行：

- `00-系统总控/专用对话执行验收协议.md`；
- `00-系统总控/文笔成稿验收协议.md`。

读取正确但任务执行、文笔或交付没有真正符合规则，仍然不算合格交付。
