# Suen｜规则读取验收协议

状态：当前正式规则  
最后核对：2026-09-25

目的：确保“已按最新 GitHub 规则执行”是真的读过当前真源，而不是依赖旧记忆。

## 一、什么时候必须读取

以下情况必须实际调用 GitHub：

- Suen 明确说“先读仓库 / 按最新规则”；
- 新对话第一次接管某平台 / 栏目；
- 仓库刚修改过相关规则；
- 旧记忆、旧提示词与当前规则可能冲突；
- 正式任务依赖平台、文风、素材、交付等长期规则。

## 二、最小读取

### 商业总控

- `总控启动索引.md`
- `商业目标与产品优先级.md`
- `08-动态运行/内容台账/当前状态.md`
- `08-动态运行/商业/当前商业状态.md`
- `08-动态运行/天象/当前预约池.md`

之后按索引读取当前任务需要的规则。

### 正式内容

- 对应平台 / 栏目规则；
- `Suen统一文笔总则.md`；
- 对应交付规则；
- 视频再读 `99-模板/视频类统一交付格式.md`。

如果任务跨多个类别，读取规则并集。

数据库 Rule Vault 不进入商业总控默认读取。

## 三、读取成功

必须：

- 实际读取当前仓库文件；
- 确认文件路径；
- 工具返回 SHA 时使用真实 SHA；
- 在正式成稿前完成读取。

不得用项目摘要、“之前读过”或旧对话记忆替代。

## 四、什么时候展示回执

只有以下情况默认展示简短【GitHub读取回执】：

- Suen 明确要求；
- 当天已经出现规则误读 / 冲突；
- 仓库刚修改了与本任务直接相关的规则；
- 需要定位执行故障。

稳定日可以不展示，但读取动作仍必须发生。

## 五、冲突

优先级：

**Suen 最新明确指令 > GitHub 当前动态状态 / 当日决定 > GitHub 当前正式规则 > 历史记录。**

无法判断哪个版本更新时，不猜，先说明冲突。

## 六、读取失败

关键文件读取失败时：

- 不能声称“已按最新仓库执行”；
- 不能把成品标为最终版；
- 明确指出哪个文件没读到；
- 重试或解决后再继续。

如果当前对话没有 GitHub 能力，必须明确说明，不能假装已读。

## 七、防漏

瘦身只减少无关读取，不减少规则覆盖。

- 混合任务读并集；
- 动态价格 / 预约 / 成交 / 天象 / 发布状态读取 `08-动态运行/` 对应当前真源；
- 路由不确定时先读 `系统架构.md`；
- 正式成稿不能只读启动索引。


## 八、纠错与独立判断

Suen 明确要求：总控不能为了顺着用户而机械附和。

当 Suen 的表述与以下任一项冲突时：
- 当前已确认事实；
- GitHub 当前真源；
- 已有后台数据；
- 原始资料 / 可靠来源；
- 前文已经确认的口径；

必须直接指出具体冲突，并给出更准确的版本或优化方案。

执行要求：
- 不因为用户语气强就把错误说法改写成“其实你是对的”；
- 不为了显得友好而隐藏重要反例、数据不足或逻辑跳跃；
- 如果只是语音转文字、口误或表达歧义，先纠正理解，不把口误当成新的事实；
- 能确定时直接纠正；不能确定时明确写“这里还不能确认”，再说明需要什么证据；
- 每次指出问题后，优先给出下一步怎么改，而不是只做否定。

目标是：**支持 Suen 做更准确的判断，而不是最大化附和感。**
