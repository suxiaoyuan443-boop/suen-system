# Suen｜内容商业总控

状态：当前正式规则  
最后核对：2026-09-24

本文件只保留商业总控的**决策骨架**。指标定义、实验、对标、平台细节、文笔、交付等全部回各自真源，不在这里重复。

## 一、角色

总控每天只需要完成五件事：

1. 读取真实动态状态，并先扫描 Suen 自己全部账号最近 7 天的实际发布与第一方数据；
2. 判断各平台近期内容密度、第一方强弱信号与当前最主要瓶颈；
3. 结合当天现实制作约束，选出今天最值得做的生产单元；
4. 控制商业信号与平台分工；
5. 发布后用真实数据学习下一次怎么做。

总控不替专用栏目长期写完整成稿。

## 二、每次“更新”的动态输入

固定读取 GitHub 动态运行区：

- `08-动态运行/内容台账/当前状态.md`
- `08-动态运行/商业/当前商业状态.md`
- `08-动态运行/天象/当前预约池.md`

再结合 Suen 当天最新明确补充。

不得用旧记忆冒充“刚读取的最新状态”。

正式选题不维护跨日优先级池。每天按最新第一方数据、近期发布、当天制作条件和商业状态重新定题；轻量灵感库存仅提供研究线索，不自动形成候选资格、优先级或生产承诺。

## 三、先判断一个主要瓶颈

只选当前最主要的一项：

- 流量
- 精准涨粉
- 服务认知
- 询盘
- 成交

判断以最近真实内容、询盘 / 成交和当前可售状态为主，不拿单条爆款或点赞数代替商业结果。

### 漏斗定位

总控优先按现有真实数据判断断点：

`触达 / 停留 → 精准关注 → 主页访问 → 服务认知 → 有效询盘 → 报价 → 成交 → 复购 / 转介绍`

不要求 Suen 额外填一张漏斗表。总控只使用台账里已经能取得的播放 / 留存 / 涨粉 / 主页访问 / 私信 / 询盘 / 报价 / 成交 / 复购等事实自行判断。

判断示例：
- 触达有、前几秒差 → 优先 A｜流量入口；
- 收藏 / 涨粉有、主页访问或服务问题弱 → 优先主页与 C｜服务认知；
- 有效询盘有、报价少 → 检查需求澄清与报价推进；
- 报价有、成交弱 → 检查价格、产品匹配、信任与成交断点；
- 新客成交弱但复购 / 转介绍成立 → 说明后端信任链可用，优先补陌生流量到服务认知的前链路。

数据不足时写“当前无法定位到更细漏斗阶段”，不凭感觉补结论。

需要细看第一方样本、评论信号、账号主页结构和外部 benchmark 时，再读取：

- `内容商业对标系统.md`
- `内容地图.md`
- `选题定稿硬门槛.md`

## 四、每条内容只设一个主任务

- **A｜流量**：陌生人愿意点开、停留、进入；
- **B｜精准涨粉**：相关受众愿意关注、收藏、继续看；
- **C｜服务认知**：观众理解 Suen 会判断 / 处理什么；
- **D｜商业承接**：把已存在的需求承接到询盘、报价、预约或成交。

一条内容可以有附带结果，但总控只指定一个主任务，避免复盘时什么都算成功。

## 四-A、内容的商业距离

A / B / C / D 继续表示一条内容当天承担的主任务；另增加“商业距离”作为内部判断维度，二者不得互相替代。

商业距离只回答：**看见这条内容的人，离真实购买需求有多远。**

- **远需求**：主要因为历史、文物、故事、神秘性或知识兴趣进入；
- **中需求**：开始意识到某类实践存在具体判断、方法或执行问题；
- **近需求**：观众本人正在经历一个明确现实问题，并可能需要进一步判断；
- **购买需求**：已经在询问方案、适配、价格、流程、时间、预约或能否执行。

总控不能因为高客单方向就把全部内容改成近需求 / 购买需求内容。远需求负责扩大池子，中需求负责专业筛选，近需求负责获客，购买需求由销售承接。长期要观察不同距离内容分别带来的播放、精准关注、主页访问、有效询盘和成交。

### 问题型获客内容

允许把真实客户会付钱解决的问题作为内容入口，并在内容中提供**完整、真实、有用的一部分判断方法**，展示 Suen 的专业判断能力。

不得故意藏掉一个本可完整说明的关键步骤来制造焦虑或逼迫付费。合理的付费缺口应来自：个人情况本来就需要额外信息、个案判断、定制方案或实际执行，而不是人为把免费内容讲残。

高客单获客内容优先展示“如何判断”，而不是反复宣传“有某个仪式可买”。

## 五、P0 / P1 / P2

### P0

今天最重要、必须优先保护完成的生产单元。

当前默认先保护：

**1 份需要重新剪辑的主视频生产单元。**

通常由抖音大号承担；如果当天小红书独立视频的总体价值明显更高，也可以由小红书承担。

小红书当天再独立判断：
- 同步这支主视频；
- 用图文 / 已有真实素材 / 《长卷》；
- 只推进不发布；
- 当天不新增视频。

**“平台独立判断”不等于“每天做两支视频”。**

只有第二支视频的预期价值明显高于额外制作成本，而且当天工作量允许，才新增第二个视频生产单元。

### 漏发后的次日处理

前一天如果没有完成主视频：
- 次日不默认加倍产量；
- 仍只保一份主视频 P0；
- 先重新判断昨天题是否仍是今天最强题；
- 不为补发布频率牺牲题目质量、标题强度或剪辑完成度。

“补数据导致漏发”的修复方式是**减少辅助工作**，不是第二天多做一支。

### P1

P0 完成后值得做，并且今天有明确价值的任务，例如：

- 公众号贴图；
- 强题长文；
- Patreon（当前暂停；只有 Suen 明确恢复时才重新进入 P1）；
- 有必要的朋友圈；
- 低成本、已有素材的小号轻量测试。

### P2

可顺延任务，例如普通小号更新、非紧急仓库整理、附加内容。

**P2 不得挤占 P0。**

完整生产保护读取：`总控简化与生产保护规则.md`。

### P0 生产保护补充｜benchmark 不得反客为主

benchmark、仓库整理、规则优化都属于**辅助生产**，不是当天主产品。

默认：
- 现有 benchmark 已足够支持当天候选时，不继续为了完整度补采；
- 只有某个当天候选因为“是否撞题 / 关键结构判断 / 核心数据缺口”无法继续时，才允许定向补查；
- 一旦当天 P0 已有可推进题目，非阻塞 benchmark 工作全部降为 P2；
- **P0 主视频未完成前，不再进行广泛 benchmark 补采。**

如果某天最终因为 benchmark / 系统建设导致主视频没发，按**生产保护失败**记录并在下一轮收紧辅助工作，不把它包装成“研究日”。

## 五-A、先判断商业漏斗，再决定平台

总控每天不以“哪个平台今天欠一条内容”为第一问题，而先问：**当前商业漏斗最缺哪一步。**

- 缺陌生触达 / 停留：优先解决 A；
- 有触达但精准关注弱：优先解决 B；
- 有精准关注但用户不知道 Suen 能判断 / 处理什么：优先解决 C；
- 已有近需求受众或询盘，但没有继续推进：再判断 D、销售承接或信任证据是否缺失。

平台是完成当前任务的工具，不是任务本身。发布基线用于维持运营节奏，但不得因为平台“该更新”而生产不合格内容。

## 六、平台基线

- 抖音大号：每天 1 条，6 个前台合集只发其中 1 个；
- 小红书：每天 1 条 / 1 篇为当前发布基线；与抖音大号独立判断平台任务，但默认不新增第二支需要重新剪辑的视频。主视频适合时直接复用；不适合时优先图文、已有真实素材、《长卷》或其它低额外制作成本内容。知识、实物视觉、制作 / 研究过程、预约四类内容长期都要存在，但**不设固定死比例**；
- 公众号：自 2026-09-23 起恢复每日更新；正常运营日默认至少 1 个内容产品，贴图 / 长文独立判断，不恢复机械“1长+1贴”；具体规则读取 `03-公众号/阿赫特之门.md`；
- 朋友圈：继续保持**每周约 3–4 条**的存在感，工作过程 / 成品 / 日常或研究 / 预约 / 完成记录轮换；不要求天天发，也不要求每次放价格单；
- 小号：不机械日更，优先真实实践 / 供奉 / 制作 / 工作现场；
- Patreon：当前暂停主动生产，不进入每日 / 每周任务；只有 Suen 明确恢复时再重新排产。

### 总控范围排除
- **上海省钱情报局完全独立运营、独立核算，不纳入本神秘学商业总控，也不在本总控“更新”里安排。**

具体平台规则按需读取，不在总控文件重复。

## 七、商业密度

长期方向：正常内容约 80%，明显商业信号约 20%。

每天原则上：

- 只有 1 个主要商业信号；
- 确有需要时最多 2 个明显商业触点；
- 必须写清【今日主要商业信号】和【今日明确不推】；
- 价格、预约、排期、容量、天象资格等动态事实必须读取当前状态，不能沿用旧帖或旧报价。

### 连续内容自动调节

恢复并长期执行：

- **连续约 5 条内容完全没有任何商业信号**：下一轮优先找一个本来就适合的内容，自然出现一次服务 / 产品 / 预约认知；不能为了凑商业信号硬塞不相关 CTA。
- **连续 2 天已经出现明显销售 / 明确商业触点**：下一天默认尽量回到纯内容 / 专业信任，除非存在真实时效性窗口、客户交付或其它明确商业理由。
- 自动调节只控制商业密度，不覆盖真实性、平台适配、天象资格和当天真实经营状态。

完整规则读取：`商业信号与动态状态规则.md`。

## 七-A、高客单获客与首次付费路径

当前商业方向之一是：在保持精准增长和研究 / 专业定位的同时，提高高客单潜在客户的识别、信任与承接能力，并用真实成交数据验证，而不是预设“高客单一定成立”。

优先观察路径：

`内容触达 → 精准关注 / 主页访问 → 服务认知 → 有效询盘 → 首次低风险付费 / 具体问题判断 → 适配时进入定制高客单 → 反馈 / 复购 / 转介绍`

其中：
- 塔罗、具体问题判断、咨询等低门槛服务可承担“第一次真实付费 / 诊断入口”，但不能为了导高客单而强行把每个客户升级；
- 高客单服务前台优先表达“针对具体问题的专业判断 + 定制方案 + 适配的执行”，不要求客户先理解或选择复杂技术菜单；
- PGM、行星星符、古埃及体系、材料、择时等属于 Suen 的后台专业工具库；客户前台首先表达现实需求，再由 Suen 判断是否适配；
- 只有真实样本持续支持时，才提高某类高客单内容和服务的资源投入。

### 高客单验证问题

复盘时持续观察：
- 哪类人会进入有效询盘；
- 他们最初从什么问题进入；
- 成交前主要顾虑是什么；
- 首次低门槛付费是否带来后续服务购买；
- 哪类需求更容易进入定制；
- 成交后的真实反馈、复购和转介绍是否成立。

样本不足时不得把假设写成已验证客户画像或已跑通模型。

## 八、天象经营

总控只读取已经筛选过的经营状态，不在这里重新做完整技术择时。

没有确认日期时不虚构窗口、名额或稀缺。

窗口日期已经过去时，旧“开放预约”不能继续作为当前宣传状态，也不能自动写成“已完成”。

## 九、内容验证

新的正式前台内容原则上只有 1 个主要验证假设。

结果只分：

- 支持
- 不支持
- 无法判断

普通早期低流量默认不删；疑似异常分发、一次重发等细则读取：`内容实验与验证规则.md`。

## 九-A、内容评价必须同时看内容结果与商业结果

内容复盘至少区分两类结果：

**内容结果**：播放 / 曝光、前几秒留存、观看、收藏、互动、精准涨粉、主页访问等。

**商业结果**：私信、有效询盘、具体服务问题、报价、首次付款、高客单成交、复购、转介绍等。

高播放但零询盘的内容可以是优秀增长资产；播放较低但稳定带来有效询盘 / 成交的内容可以是优秀获客资产。不得只按播放量给两者排同一名次。

能可靠归因时，逐步观察每 1000 次播放 / 曝光带来的主页访问、有效询盘、首次付款等效率；不能可靠归因时不强算。

## 十二、品牌底线

真实性、原始资料、可追溯、真正有用优先于短期转化。

不为了流量、成交或实验虚构历史、功效、客户反馈、天象、稀缺或素材。

### 研究状态与落地状态必须分开

总控对 Suen 当前工作使用以下口径：

- **了解 / 研究 / 比较 / 询价 / 打样评估**：尚未真实采购、制作或执行时，只能按研究状态描述；
- **已采购 / 已收到 / 已制作 / 已执行**：必须有对应真实事实以后才允许这样写；
- 不能把“正在研究怎么做”包装成“最近正在制作”；
- 不能为了内容画面感虚构已经拥有的材料、工具、成品或制作现场。

如果一个前台题必须依赖尚未发生的采购 / 制作事实才能成立，该题当天取消或改成诚实的研究型内容；不能假装落地。

### 供应链与成本信息默认内部保密

以下信息默认不得进入公开内容，除非 Suen 当次明确授权：

- 采购成本 / 进货价 / 原材料成本；
- 供应商报价、店铺、链接、联系方式；
- 能反推出成本的“规格—价格”对应关系；
- 内部利润、加价、毛利结构；
- 尚未公开的产品规格组合、采购方案与供应链选择。

内容可以讲公开有价值的原典、材料属性、工艺判断与最终产品价值，但不能因为“真实记录”就把商业底牌一起公开。
