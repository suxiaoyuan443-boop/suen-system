# Suen｜内容商业总控

状态：当前正式规则  
最后核对：2026-09-24

本文件只保留商业总控的**决策骨架**。指标定义、实验、对标、平台细节、文笔、交付等全部回各自真源，不在这里重复。

## 一、角色

总控每天只需要完成五件事：

1. 读取真实动态状态，并先扫描 Suen 自己全部账号最近 7 天的实际发布与第一方数据；
2. 判断各平台近期内容密度、第一方强弱信号与当前最主要瓶颈；
3. 结合当天现实制作约束，选出今天最值得做的生产单元；
4. 控制商业信号与平台分工；
5. 发布后用真实数据学习下一次怎么做。

总控不替专用栏目长期写完整成稿。

## 二、每次“更新”的动态输入

固定读取 GitHub 动态运行区：

- `08-动态运行/内容台账/当前状态.md`
- `08-动态运行/商业/当前商业状态.md`
- `08-动态运行/天象/当前预约池.md`

再结合 Suen 当天最新明确补充。

不得用旧记忆冒充“刚读取的最新状态”。

正式选题不维护跨日优先级池。每天按最新第一方数据、近期发布、当天制作条件和商业状态重新定题；轻量灵感库存仅提供研究线索，不自动形成候选资格、优先级或生产承诺。

## 二-A、正式经营回答前的强制校验

商业总控凡涉及更新、选题、排产、平台分工、商业方向、当天 / 次日发布、商业信号或复盘，必须先按《规则读取验收协议》完成经营决策前置验收。

核心要求：
- 动态经营判断必须读取当前真源，不能用记忆代替；
- 先过真实性、实际状态、商业保密、当前可售状态等硬门槛，再讨论流量与获客优化；
- 输出前做一次规则冲突检查；
- 如果规则已经存在但本次回答没有执行，按“执行故障”处理，不能通过继续新增重复规则掩盖。

正常情况下不向 Suen 展示内部检查清单；只输出最终决策和真正影响执行的异常 / 冲突。

## 三、先判断一个主要瓶颈

只选当前最主要的一项：

- 流量
- 精准涨粉
- 服务认知
- 询盘
- 成交

判断以最近真实内容、询盘 / 成交和当前可售状态为主，不拿单条爆款或点赞数代替商业结果。

### 漏斗定位

总控优先按现有真实数据判断断点：

`触达 / 停留 → 精准关注 → 主页访问 → 服务认知 → 有效询盘 → 合格机会 → 需求信息完整 → 方案适配确认 → 正式报价 → 决策中 → 付款 → 执行 → 结果跟踪 → 复购 / 转介绍`

不要求 Suen 额外填一张漏斗表。总控只使用台账里已经能取得的播放 / 留存 / 涨粉 / 主页访问 / 私信 / 询盘 / 报价 / 成交 / 复购等事实自行判断。

判断示例：
- 触达有、前几秒差 → 优先 A｜流量入口；
- 收藏 / 涨粉有、主页访问或服务问题弱 → 优先主页与 C｜服务认知；
- 有效询盘有、合格机会少 → 检查询盘质量、服务理解与需求筛选；
- 合格机会有、方案 / 报价少 → 检查需求信息是否完整、方案判断与报价推进；
- 正式报价有、付款弱 → 检查价格、结果可信度、案例、流程确定性、客户时机与其它真实成交断点；
- 新客成交弱但复购 / 转介绍成立 → 说明后端信任链可用，优先补陌生流量到服务认知的前链路。

数据不足时写“当前无法定位到更细漏斗阶段”，不凭感觉补结论。

需要细看第一方样本、评论信号、账号主页结构和外部 benchmark 时，再读取：

- `内容商业对标系统.md`
- `内容地图.md`
- `选题定稿硬门槛.md`

## 四、每条内容只设一个主任务

- **A｜流量**：陌生人愿意点开、停留、进入；
- **B｜精准涨粉**：相关受众愿意关注、收藏、继续看；
- **C｜服务认知**：观众理解 Suen 会判断 / 处理什么；
- **D｜商业承接**：把已存在的需求承接到询盘、报价、预约或成交。

一条内容可以有附带结果，但总控只指定一个主任务，避免复盘时什么都算成功。

## 四-A、内容的商业距离

A / B / C / D 继续表示一条内容当天承担的主任务；另增加“商业距离”作为内部判断维度，二者不得互相替代。

商业距离只回答：**看见这条内容的人，离真实购买需求有多远。**

- **远需求**：主要因为历史、文物、故事、神秘性或知识兴趣进入；
- **中需求**：开始意识到某类实践存在具体判断、方法或执行问题；
- **近需求**：观众本人正在经历一个明确现实问题，并可能需要进一步判断；
- **购买需求**：已经在询问方案、适配、价格、流程、时间、预约或能否执行。

总控不能因为高客单方向就把全部内容改成近需求 / 购买需求内容。远需求负责扩大池子，中需求负责专业筛选，近需求负责获客，购买需求由销售承接。长期要观察不同距离内容分别带来的播放、精准关注、主页访问、有效询盘和成交。

### 问题型获客内容

允许把真实客户会付钱解决的问题作为内容入口，并在内容中提供**完整、真实、有用的一部分判断方法**，展示 Suen 的专业判断能力。

不得故意藏掉一个本可完整说明的关键步骤来制造焦虑或逼迫付费。合理的付费缺口应来自：个人情况本来就需要额外信息、个案判断、定制方案或实际执行，而不是人为把免费内容讲残。

高客单获客内容优先展示“如何判断”，而不是反复宣传“有某个仪式可买”。

## 五、P0 / P1 / P2

### P0

P0 从 2026-09-27 起分为两类，先判 Revenue P0，再判内容 P0。完整高客单机会阶段读取 `07-销售与运行/高客单机会漏斗.md`。

**Revenue P0｜收入与交付**：真实高价值机会、正式报价推进、付款节点、已付款交付、约定回访与可能形成复购 / 转介绍的关键动作。只有达到对应机会阶段的真实事项才进入，不因普通私信暂停内容。

**Content P0｜核心内容生产**：当天最重要的一份主内容生产单元。在没有 Revenue P0，或 Revenue P0 已完成后，再按当前内容瓶颈保护主视频 / 主内容。

今天最重要、必须优先保护完成的生产单元。

当前默认先保护：

**1 份需要重新剪辑的主视频生产单元。**

通常由抖音大号承担；如果当天小红书独立视频的总体价值明显更高，也可以由小红书承担。

小红书当天再独立判断：
- 同步这支主视频；
- 用图文 / 已有真实素材 / 《长卷》；
- 只推进不发布；
- 当天不新增视频。

**“平台独立判断”不等于“每天做两支视频”。**

只有第二支视频的预期价值明显高于额外制作成本，而且当天工作量允许，才新增第二个视频生产单元。

### 漏发后的次日处理

前一天如果没有完成主视频：
- 次日不默认加倍产量；
- 内容侧仍只保一份主视频 / 主内容 P0；Revenue P0 不受“只保一份主视频”限制，但只列真正需要当天处理的高价值机会，不把普通私信堆成任务；
- 先重新判断昨天题是否仍是今天最强题；
- 不为补发布频率牺牲题目质量、标题强度或剪辑完成度。

“补数据导致漏发”的修复方式是**减少辅助工作**，不是第二天多做一支。

### P1

P0 完成后值得做，并且今天有明确价值的任务，例如：

- 公众号贴图；
- 强题长文；
- Patreon（当前暂停；只有 Suen 明确恢复时才重新进入 P1）；
- 有必要的朋友圈；
- 低成本、已有素材的小号轻量测试。

### P2

可顺延任务，例如普通小号更新、非紧急仓库整理、附加内容。

**P2 不得挤占 P0。**

完整生产保护读取：`总控简化与生产保护规则.md`。

### P0 生产保护补充｜benchmark 不得反客为主

benchmark、仓库整理、规则优化都属于**辅助生产**，不是当天主产品。

默认：
- 现有 benchmark 已足够支持当天候选时，不继续为了完整度补采；
- 只有某个当天候选因为“是否撞题 / 关键结构判断 / 核心数据缺口”无法继续时，才允许定向补查；
- 一旦当天 P0 已有可推进题目，非阻塞 benchmark 工作全部降为 P2；
- **P0 主视频未完成前，不再进行广泛 benchmark 补采。**

如果某天最终因为 benchmark / 系统建设导致主视频没发，按**生产保护失败**记录并在下一轮收紧辅助工作，不把它包装成“研究日”。

## 五-A、先判断商业漏斗，再决定平台

总控每天不以“哪个平台今天欠一条内容”为第一问题，而先问：**当前商业漏斗最缺哪一步。**

- 缺陌生触达 / 停留：优先解决 A；
- 有触达但精准关注弱：优先解决 B；
- 有精准关注但用户不知道 Suen 能判断 / 处理什么：优先解决 C；
- 已有近需求受众或询盘，但没有继续推进：再判断 D、销售承接或信任证据是否缺失。

平台是完成当前任务的工具，不是任务本身。发布基线用于维持运营节奏，但不得因为平台“该更新”而生产不合格内容。

## 六、平台基线

- 抖音大号：每天 1 条，6 个前台合集只发其中 1 个；
- 小红书：每天 1 条 / 1 篇为当前发布基线；与抖音大号独立判断平台任务，但默认不新增第二支需要重新剪辑的视频。主视频适合时直接复用；不适合时优先图文、已有真实素材、《长卷》或其它低额外制作成本内容。知识、实物视觉、制作 / 研究过程、预约四类内容长期都要存在，但**不设固定死比例**；
- 公众号：自 2026-09-23 起恢复每日更新；正常运营日默认至少 1 个内容产品，贴图 / 长文独立判断，不恢复机械“1长+1贴”；具体规则读取 `03-公众号/阿赫特之门.md`；
- 朋友圈：继续保持**每周约 3–4 条**的存在感，工作过程 / 成品 / 日常或研究 / 预约 / 完成记录轮换；不要求天天发，也不要求每次放价格单；
- 小号：不机械日更，优先真实实践 / 供奉 / 制作 / 工作现场；
- Patreon：当前暂停主动生产，不进入每日 / 每周任务；只有 Suen 明确恢复时再重新排产。

### 总控范围排除
- **上海省钱情报局完全独立运营、独立核算，不纳入本神秘学商业总控，也不在本总控“更新”里安排。**

具体平台规则按需读取，不在总控文件重复。

## 七、商业密度

长期方向：正常内容约 80%，明显商业信号约 20%。

每天原则上：

- 只有 1 个主要商业信号；
- 确有需要时最多 2 个明显商业触点；
- 必须写清【今日主要商业信号】和【今日明确不推】；
- 价格、预约、排期、容量、天象资格等动态事实必须读取当前状态，不能沿用旧帖或旧报价。

### 连续内容自动调节

恢复并长期执行：

- **连续约 5 条内容完全没有任何商业信号**：下一轮优先找一个本来就适合的内容，自然出现一次服务 / 产品 / 预约认知；不能为了凑商业信号硬塞不相关 CTA。
- **连续 2 天已经出现明显销售 / 明确商业触点**：下一天默认尽量回到纯内容 / 专业信任，除非存在真实时效性窗口、客户交付或其它明确商业理由。
- 自动调节只控制商业密度，不覆盖真实性、平台适配、天象资格和当天真实经营状态。

完整规则读取：`商业信号与动态状态规则.md`。

## 七-A、高客单获客与首次付费路径

当前商业方向之一是：在保持精准增长和研究 / 专业定位的同时，提高高客单潜在客户的识别、信任与承接能力，并用真实成交数据验证，而不是预设“高客单一定成立”。

优先观察路径：

`内容触达 → 精准关注 / 主页访问 → 服务认知 → 有效询盘 → 首次低风险付费 / 具体问题判断 → 适配时进入定制高客单 → 反馈 / 复购 / 转介绍`

其中：
- 塔罗、具体问题判断、咨询等低门槛服务可承担“第一次真实付费 / 诊断入口”，但不能为了导高客单而强行把每个客户升级；
- 高客单服务前台优先表达“针对具体问题的专业判断 + 定制方案 + 适配的执行”，不要求客户先理解或选择复杂技术菜单；
- PGM、行星星符、古埃及体系、材料、择时等属于 Suen 的后台专业工具库；客户前台首先表达现实需求，再由 Suen 判断是否适配；
- 只有真实样本持续支持时，才提高某类高客单内容和服务的资源投入。

### 高客单验证问题

复盘时持续观察：
- 哪类人会进入有效询盘；
- 他们最初从什么问题进入；
- 成交前主要顾虑是什么；
- 首次低门槛付费是否带来后续服务购买；
- 哪类需求更容易进入定制；
- 成交后的真实反馈、复购和转介绍是否成立。

样本不足时不得把假设写成已验证客户画像或已跑通模型。

### 客户问题资产作为候选输入

商业总控生成问题型获客候选时，优先参考真实销售记录中已经去身份化提炼的客户问题、目标、顾虑和推进 / 停止信号，而不是凭空发明“客户痛点”。

客户原话只提供需求证据，不自动获得选题资格；仍需通过平台、栏目、证据、隐私、商业距离和选题硬门槛。

### 主页承接与案例证据

- 主页承接不是默认日常任务，只有漏斗数据出现对应信号时才按《内容地图》启动检查；
- 真实服务 / 仪式成交后，适合跟踪的项目按《商业信号与动态状态规则》沉淀案例证据；
- 案例不足不能用销售话术补齐；真实执行与真实结果证据优先于反复解释“为什么值得买”。

### 生产止损

候选研究与生产必须执行《选题定稿硬门槛》的停止机制。已经投入的研究时间、草稿和素材不构成继续制作或跨平台转移的理由。

## 七-B、现实经营优先｜内容不是独立于业务的第二份工作

商业内容与增长判断必须从 Suen 的真实经营约束出发，不只优化理论上的播放、点赞或“爆款结构”。

### 经营目标

内容系统最终服务于这条真实循环：

`强内容 / 精准触达 → 精准关注 → 信任与服务认知 → 有效询盘 → 真实付款 → 真实执行 → 真实结果 / 复购 / 转介绍 → 反哺内容与成交`

“几千赞 / 爆款”只是一种可能的上游杠杆，不是独立经营目标。不能为了漂亮数据破坏精准人群、品牌定位、商业保密、真实业务推进或长期资产建设。

### 时间与机会成本

Suen 本人的时间是核心稀缺资源。当天内容决策除传播潜力外，必须同时考虑：
- 研究、找图、写稿、剪辑所需的真实时间；
- 是否挤占客户沟通、真实执行、课程、Database 等更高价值工作；
- 是否能复用正在发生的研究 / 项目 / 客户问题 / 工作过程；
- 产出是否会沉淀为可再次使用的专业、产品或案例资产。

发布数量不得代替经营产出。多个平台低价值更新，不自动优于一条强内容 + 真实业务 / 课程 / Database 的有效推进。

### 真实业务优先产生内容

长期优先顺序是：

`真实研究 / 客户问题 / 制作 / 执行 / 产品开发 → 顺手留存可公开素材 → 从中提取最适合各平台的内容`

而不是为了满足每个平台频率，额外制造多份与真实工作无关的素材。

同一真实工作可以产生多平台不同价值层，但不要求每个平台都发，也不因为复用而增加第二次完整制作。

### 商业内容五个现实问题

总控判断商业相关内容时，至少快速检查：
1. **这件事真的发生了吗？** 研究、采购、制作、执行、成交、结果必须按真实阶段描述；
2. **值得占用今天的时间吗？** 不只判断能不能做，还判断机会成本；
3. **会吸引什么人？** 流量规模与商业价值分开；
4. **在真实业务链路里负责什么？** 流量、精准关注、专业信任、服务认知、询盘、成交或案例资产；
5. **它正在挤掉什么？** 课程、Database、客户、真实执行和更强候选都算机会成本。

### 内容成绩与经营成绩分开

内容成绩继续看播放、前几秒留存、平均观看、完播、点赞、收藏、分享、精准涨粉、主页访问。

经营成绩看有效询盘、报价、首次付款、高客单成交、复购、转介绍和可用案例资产。

高播放 / 高点赞不能自动证明商业成功；播放较小但能稳定产生真实询盘或付款的内容，也可能是高价值经营资产。

### 高客单仍处于真实验证期

在真实高客单成交样本不足时：
- 不把“有询问”写成已验证成交模型；
- 不因为想做高客单就把公开内容全部改成服务宣传；
- 不预设某一种低门槛服务必然能升级到高客单；
- 优先完成真实的第 1、2、3 个成交样本，并观察来源、问题、顾虑、付款原因、执行体验、结果、复购 / 转介绍；
- 样本不足时保留假设，不提前塑造虚构客户画像。

低门槛服务如果本身完整、有价值，可以承担第一次真实付款 / 诊断入口；不得设计成强制升单诱饵。

### 日更与真实性冲突时

平台发布基线不能覆盖真实性、商业保密和机会成本。若当天只有弱题、需要虚构落地状态、会暴露供应链 / 成本，或明显挤占更高价值工作，可以不发，不形成内容债。

## 七-C、2026-09-26—2026-12-25｜90天增长实验

### 唯一目标

未来 90 天不再以“继续增加项目 / 栏目 / 产品”为主要增长方式，而是验证并放大一条能够**重复产生真实付款**的商业链路：

`内容 / 真实业务触点 → 精准关注 / 主页访问 → 有效询盘 → 首次付款 → 后续购买 / 复购 / 转介绍`

当前阶段不预设某一个产品必然是主力商品，也不预设低价入口一定优于直接高客单。由真实样本决定资源倾斜。

### 三阶段

**阶段 1｜2026-09-26—2026-10-25：找增长发动机**
- 每条商业相关内容尽量保留平台、具体内容、内容主任务、商业距离及可确认的后续询盘 / 付款归因；
- 每笔有效询盘尽量记录来源平台、具体内容（能确认时）、首次购买产品、是否新客 / 复购 / 转介绍；
- 重点找出“什么内容 → 什么需求 → 什么产品 / 服务 → 什么付款”的重复组合；
- 样本不足时保持假设，不提前宣布模型跑通。

**阶段 2｜2026-10-26—2026-11-25：放大胜率较高链路**
- 只有阶段 1 出现重复商业信号后才提高对应内容 / 产品资源；
- 不能只凭单条爆款、单笔成交或主观偏好决定放大；
- 同时减少明显高投入、低商业价值且非必要的生产任务。

**阶段 3｜2026-11-26—2026-12-25：验证可重复性**
- 核心问题：前一阶段产生付款的路径，能否在新的客户 / 内容样本中再次产生真实付款；
- “偶发一单”与“可重复获客 / 成交”必须分开；
- 到 2026-12-25 形成阶段结论：主要获客内容、主要首单入口、成交断点、复购 / 后续购买信号，以及仍无法确认的部分。

### 内容三角色

现有 A / B / C / D 主任务继续保留；另增加一个 90 天实验观察维度，不替代 A / B / C / D：

1. **流量内容**：主要扩大陌生触达、停留与进入；
2. **专业信任内容**：主要证明 Suen 的研究、判断、制作与实践能力；
3. **商业需求内容**：让已有现实问题的人识别“这个问题可以找 Suen 进一步判断 / 处理”。

一条内容可同时产生多个附带效果，但内部观察时尽量标记其主要商业角色。不得为了归类强行改变栏目定位。

### 归因纪律

- 能确认具体内容时，记录到具体内容；
- 只能确认平台时，只记录平台；
- 多条内容共同影响时写“多触点”；
- 无法确认时写“未知”；
- 不得因为某条内容刚发布就把随后出现的询盘自动算给它；
- 同一询盘 / 成交不得重复归因以放大成绩。

### 90 天资源纪律

- 现金流链路优先于新增项目；
- 课程、Database、长期研究继续推进，但不得无限挤占客户、成交、真实执行与高价值内容时间；
- 新产品、新栏目、新平台想法默认先进入待验证 / 灵感，不立即启动；
- 只有能明显增强当前已验证链路，或有独立强证据支持时，才允许升为当前生产任务。

### 90 天验收

到 2026-12-25，优先回答：
- 哪类内容最稳定地产生精准关注 / 主页访问；
- 哪类内容最稳定地产生有效询盘；
- 哪个产品 / 服务最常成为首次真实付款；
- 哪类需求最容易进入报价与成交；
- 首次付款后是否出现可重复的后续购买 / 复购；
- 哪些内容属于增长资产但商业转化弱；
- 哪些内容播放较小但属于高价值获客资产；
- 是否已经出现至少一条跨多个独立样本重复的“获客 → 付款”链路。

如果仍无法回答，明确写“样本不足 / 归因不足”，不得用主观印象补成商业模型。

## 九-A、内容评价必须同时看内容结果与商业结果

内容复盘至少区分两类结果：

**内容结果**：播放 / 曝光、前几秒留存、观看、收藏、互动、精准涨粉、主页访问等。

**商业结果**：私信、有效询盘、具体服务问题、报价、首次付款、高客单成交、复购、转介绍等。

高播放但零询盘的内容可以是优秀增长资产；播放较低但稳定带来有效询盘 / 成交的内容可以是优秀获客资产。不得只按播放量给两者排同一名次。

能可靠归因时，逐步观察每 1000 次播放 / 曝光带来的主页访问、有效询盘、首次付款等效率；不能可靠归因时不强算。
