# Suen｜Slack选题池管理规则

状态：当前正式规则  
生效：2026-09-20

本文件只解决一个问题：**候选题如何进入、停留、降级、冷却和离开选题池，且不被商业总控提前推进到正式生产。**

## 一、动态真源

当前选题池保存于 Slack：

- `#选题池`
- Channel ID：`C0C2Y0BES13`

GitHub 只保存维护机制，不保存每天具体候选题。

## 二、选题池与正式定题必须分开

`#选题池` 只负责候选阶段。

以下动作都**不等于正式定题**：

- 找到可靠资料；
- 找到真实图片；
- 标题已经优化；
- 初步判断很适合流量；
- 被标成高优先；
- 比其它候选更强。

只有 Suen 明确进入“更新 / 今天发什么 / 定题 / 正式更新”等定题场景后，商业总控才允许调用 `选题定稿硬门槛.md`，从池内选择候选进入正式定题。

**在“继续做选题池 / 优化选题池”阶段，禁止自动执行硬门槛、P0、生产交接或脚本制作。**

## 三、候选状态

选题池只使用以下状态：

- `新候选`：刚进入池，尚未做基础可行性检查；
- `高优先候选`：入口、栏目归属和基础证据明显较好，值得优先保留；
- `待核查`：方向可用，但核心事实、对象、图片或原文仍需补；
- `冷却`：题本身可用，但近期观看体验 / 主题重复，不适合马上使用；
- `已淘汰`：证据、入口、栏目或商业价值明显不足；
- `已转定题`：只有进入正式定题场景后才允许出现，表示已离开候选池流程。

不得在普通选题池维护阶段写：

- 已通过硬门槛；
- 正式定题；
- P0；
- 进入生产；
- 交给专用对话。

## 四、每个候选至少保留的字段

每个候选默认记录：

- 题目；
- 【栏目】文物 / 异录 / 辨伪 / 残页 / 隐理 / 牌记；
- 状态；
- 主要入口：观众为什么会点开；
- 观看体验：奇怪的东西 / 奇怪的问题 / 现实里的神秘学；
- 现实依据：为什么适合 Suen 当前真实账号数据、商业瓶颈、主页结构或近期内容节奏；
- 对标参考：具体参考哪个对标账号的哪一种入口 / 结构 / 视觉 / 商业连接；
- 证据风险：当前最需要警惕的事实或解释问题；
- 重复 / 冷却提示（如有）；
- 一句话保留理由；
- 资产复用价值（可选）：一次性流量 / 可沉淀公众号 / Patreon / 数据库 / 课程相关资料。

不要求在候选阶段完成正式脚本级研究。

### 现实依据硬要求

候选不能只因为“题很好看”进入池。

每轮新增 / 优化候选前，必须先读取当前仍有效的：
- `#内容历史台账`：近期真实表现、最近 7 天观看体验与重复；
- `#商业决策总控`：当前主要瓶颈、主页 / 服务承接、产品与商业状态；
- Suen 当天最新明确要求。

候选里的“现实依据”至少回答一个：
- 当前为什么需要这种入口 / 观看体验；
- 它补了主页什么缺口；
- 它为什么避开近期重复；
- 它与当前 A / B / C / D 哪一类经营问题有关；
- 它为什么值得占用 Suen 的制作时间。

### 对标参考硬要求

每一个候选必须写“对标参考”。

规则：
- 优先使用与该候选最相关的 1—2 个长期 benchmark；
- 当天有可靠 7—30 天近期样本时，优先写近期样本观察；
- 同一天已刷新过同一对标样本，可以复用，不为每个候选重复搜索；
- 只能迁移入口、第一屏、问题结构、证据组织、系列化或商业连接方法；
- 不复制对方题目、文案、人格；
- 流量账号不能当历史 / 原典证据源；
- 如果近期样本拿不到，明确写“近期样本未可靠取得”，然后只使用长期方法，不编造近期趋势。

## 五、池子结构

抖音大号候选池原则上保持：

- 3—5 个真正可推进的高质量候选；
- 尽量覆盖至少 2—3 种不同观看体验；
- 高优先候选不要全部依赖同一种视觉（例如连续都是馆藏静态图 / 原页扫描）；
- 不为了栏目轮播机械凑齐 6 个栏目；
- 同类文物 / 古埃及 / 所罗门 / 塔罗连续过密时，优先补不同体验，不靠换标题假装新题。

小红书、小号的独立候选只有在确实需要时记录，不把所有平台灵感都塞进大号池。

## 六、选题池维护动作

商业总控在“优化选题池”阶段只允许：

1. 读取 Suen 当前真实状态与本轮相关 benchmark；
2. 补新候选；
3. 优化标题入口；
4. 判断栏目；
5. 做基础证据可行性检查；
6. 检查最近重复与冷却；
7. 为每个候选写现实依据 + 对标参考；
8. 升 / 降候选优先级；
9. 淘汰弱题；
10. 保持池子不过度膨胀。

如果已经有足够强候选，不为了“显得有工作”继续无限扩池。

## 七、进入正式定题的触发

只有以下情况之一成立，才从 `#选题池` 进入正式定题：

- Suen 明确说“更新”并需要决定今天发什么；
- Suen 明确说“定题 / 选今天的 / 正式更新”；
- Suen 明确指定某个候选要进入下一阶段。

进入后再读取：

- `内容地图.md`
- `内容商业对标系统.md`
- `选题定稿硬门槛.md`
- 对应栏目规则

通过硬门槛以后，才进入生产保护。

## 八、与其它 Slack 频道的分工

- `#选题池`：未来可能发什么；
- `#内容历史台账`：已经真实发布了什么、数据怎样；
- `#商业决策总控`：当前瓶颈、P0/P1/P2、商业信号、询盘与成交决策；
- `#天象检索与预约`：已筛选的天象经营状态。

候选题不要再长期堆进 `#商业决策总控`。

## 九、核心原则

**选题池负责“存选择”，总控负责“做决定”，专用对话负责“做成品”。**

三层不能提前串线。
