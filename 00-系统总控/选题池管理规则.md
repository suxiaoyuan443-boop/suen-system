# Suen｜GitHub选题池管理规则

状态：当前正式规则  
生效：2026-09-20

本文件只解决一个问题：**候选题如何进入、停留、降级、冷却和离开选题池，且不被商业总控提前推进到正式生产。**

## 一、动态真源

当前平台候选池动态真源：

- 抖音大号：`08-动态运行/选题池/当前选题池.md`
- 小红书：`08-动态运行/选题池/小红书当前选题池.md`
- 朋友圈：`08-动态运行/选题池/朋友圈当前候选池.md`（只在需要个人感想 / 私域内容时使用）

本文件保存维护机制；具体候选与当前状态写入对应平台动态文件。

## 二、选题池与正式定题必须分开

各平台当前候选池都只负责候选阶段；抖音大号的2—5个高优先上限只约束大号池。

以下动作都**不等于正式定题**：

- 找到可靠资料；
- 找到真实图片；
- 标题已经优化；
- 初步判断很适合流量；
- 被标成高优先；
- 比其它候选更强。

只有 Suen 明确进入“更新 / 今天发什么 / 定题 / 正式更新”等定题场景后，商业总控才允许调用 `选题定稿硬门槛.md`，从池内选择候选进入正式定题。

**在“继续做选题池 / 优化选题池”阶段，禁止自动执行硬门槛、P0、生产交接或脚本制作。**

## 三、候选状态

选题池只使用以下状态：

- `新候选`：刚进入池，尚未做基础可行性检查；
- `高优先候选`：入口、栏目归属和基础证据明显较好，值得优先保留；
- `待核查`：方向可用，但核心事实、对象、图片或原文仍需补；
- `冷却`：题本身可用，但近期观看体验 / 主题重复，不适合马上使用；
- `已淘汰`：证据、入口、栏目或商业价值明显不足；
- `已转定题`：只有进入正式定题场景后才允许出现，表示已离开候选池流程。

不得在普通选题池维护阶段写：

- 已通过硬门槛；
- 正式定题；
- P0；
- 进入生产；
- 交给专用对话。

## 四、每个候选至少保留的字段

每个候选默认记录：

- 题目；
- 【栏目】文物 / 异录 / 辨伪 / 残页 / 隐理 / 牌记；
- 状态；
- 主要入口：观众为什么会点开；
- 观看体验：奇怪的东西 / 奇怪的问题 / 现实里的神秘学；
- 现实依据：为什么适合 Suen 当前真实账号数据、商业瓶颈、主页结构或近期内容节奏；
- 对标参考：具体参考哪个对标账号的哪一种入口 / 结构 / 视觉 / 商业连接；
- 对标撞题检查：确认没有与现有 benchmark 的同一人物 / 文物 / 文本 / 事件 / recipe / 具体争议撞内容；
- 证据风险：当前最需要警惕的事实或解释问题；
- 重复 / 冷却提示（如有）；
- 一句话保留理由；
- 资产复用价值（可选）：一次性流量 / 可沉淀公众号 / Patreon / 数据库 / 课程相关资料。

不要求在候选阶段完成正式脚本级研究。

### 题目范围与证据范围必须匹配

候选进入高优先前必须做一次 **scope match**：

- 标题说“很多传统 / 有些星符 / 护符一般为什么这样”，证据就不能只来自一个作者、一本书、一个具体 recipe；
- 如果当前证据只支持 Agrippa、PGM 某一段、某一类 Horus cippi，就把题目范围缩到该传统 / 作者 / 对象，或改路由；
- **禁止用宽标题包装窄证据**，再用“原典很多”制造机制题的错觉；
- 对《隐理》尤其严格：如果去掉当前唯一核心作者 / 文本以后，机制答案失去支撑，该题不能以宽泛《隐理》身份升高优先。

### 六栏目候选完整性｜不只《隐理》

所有候选在升为“高优先候选”前，都要按对应栏目的**成片主角**验证一次：

- 文物：对象不能只是配图；
- 异录：人物 / 事件 / 时间线不能只是例子；
- 辨伪：必须真的能稳定判对错；
- 残页：具体原文必须是主要价值；
- 隐理：机制必须脱离单一案例仍成立；
- 牌记：判断必须由这副具体牌局产生。

候选阶段一旦发现“题目像A栏目、做出来大概率像B栏目”，先改路由再谈优先级。
不得因为某栏目近期空缺、某题商业价值高、素材现成或当天制作方便而降低栏目资格。

### 现实依据硬要求

候选不能只因为“题很好看”进入池。

每轮新增 / 优化候选前，必须先读取当前仍有效的：
- `08-动态运行/内容台账/当前状态.md`：近期真实表现、最近 7 天观看体验与重复；
- `08-动态运行/商业/当前商业状态.md`：当前主要瓶颈、主页 / 服务承接、产品与商业状态；
- Suen 当天最新明确要求。

候选里的“现实依据”至少回答一个：
- 当前为什么需要这种入口 / 观看体验；
- 它补了主页什么缺口；
- 它为什么避开近期重复；
- 它与当前 A / B / C / D 哪一类经营问题有关；
- 它为什么值得占用 Suen 的制作时间。

### 对标撞题硬要求

候选进入池以前，必须先用当前 **全部14个对标账号** 已取得的 benchmark 年度库 / 题目流做一次内容对象去重，不能只查核心5。

判断单位不是标题文字，而是**核心内容对象**：
- 同一人物 + 同一事件 / 行为；
- 同一件文物 / 同一批核心对象；
- 同一本书 / 手稿 / 原文段落；
- 同一历史事件；
- 同一个具体仪式 recipe / 操作；
- 同一个实践争议 / 判断问题。

命中以上任一项，默认不进入 Suen 候选池；换成 Suen 自己的对象。  
共享“炼金术 / 占星 / 古埃及 / 护符”等大类不算撞题，只要具体对象与答案中心不同。

不得用以下方式假装避开重复：
- 换中文标题；
- 换问句；
- 换栏目；
- 换第一屏；
- 把同一对标题拆成上下集。

只有用户明确要求做同题比较 / 回应 / 研究史时才允许例外。

数据不完整的账号只能写“现有库未发现同题”，不得写成“确定没有做过”；完整度不足时保留不确定性。

### 对标参考硬要求

每一个候选必须写“对标参考”。

规则：
- 优先使用与该候选最相关的 1—2 个核心 benchmark；
- 默认先读取该账号近 365 天全量基线，再看最近 90 天 / 最近 3—5 条是否出现新变化；
- 不再要求每次必须取得 7—30 天样本；低频更新账号只要年度数据完整，就仍然是有效 benchmark；
- 同一天已刷新过同一对标样本，可以复用，不为每个候选重复搜索；
- 只能迁移入口、第一屏、问题结构、证据组织、系列化或商业连接方法；
- 不复制对方题目、文案、人格；
- 流量账号不能当历史 / 原典证据源；
- 如果近一年全量数据有缺口，明确写“年度数据缺口：缺什么”；使用已取得的全部年度样本，不退化成只看最近几条，也不编造近期趋势。

## 五、池子结构

抖音大号候选池原则上保持：

- 2—5 个真正可推进的高质量候选；
- 尽量覆盖至少 2—3 种不同观看体验；
- 高优先候选不要全部依赖同一种视觉（例如连续都是馆藏静态图 / 原页扫描）；
- 不为了栏目轮播机械凑齐 6 个栏目；
- 只有 2 个真正强候选时可以保持 2 个，不为了满足池子数量制造第三个弱题；
- 同类文物 / 古埃及 / 所罗门 / 塔罗连续过密时，优先补不同体验，不靠换标题假装新题；
- 同一国家 / 时代 / 魔法传统如果在活跃池中过度集中，也要提示“主题集中”，优先寻找证据同样强但文化与视觉不同的候选；不设机械地域配额。

小红书、小号的独立候选只有在确实需要时记录，不把所有平台灵感都塞进大号池。

## 六、选题池维护动作

商业总控在“优化选题池”阶段，**开始生成任何候选以前**必须完成一次规则验收：

- 实际读取当前 `栏目选题边界与路由.md`；
- 实际读取本轮可能涉及的对应栏目规则，例如候选可能属于《隐理》，必须先读最新 `隐理.md`；
- 实际读取当前 `内容商业对标系统.md`；
- 实际读取 `08-动态运行/内容台账/当前状态.md`、`08-动态运行/选题池/当前选题池.md`、`08-动态运行/商业/当前商业状态.md`；
- 仓库当前正式规则与记忆 / 旧聊天 / 旧总结冲突时，以仓库为准。

**禁止先生成题，再事后用栏目规则给它找位置。必须先读规则，再生成 / 路由候选。**

完成验收后，只允许：

1. 读取 Suen 当前真实状态与本轮相关 benchmark；
2. 先做 benchmark 内容对象撞题检查；
3. 补新候选；
4. 优化标题入口；
5. 判断栏目；
   - 先按 `栏目选题边界与路由.md` 判断价值中心；
   - 候选准备进入某栏目以前，再用该栏目的当前专属规则做一次入选条件复核；
   - 任一硬条件不满足，改路由或淘汰，不为了补栏目保留；
6. 做基础证据可行性检查；
   - 特别检查《隐理》：如果问题依赖某个具体传统 / 具体器物 / 具体习俗才能成立，即使标题是“为什么”，也不得归《隐理》；先按价值中心路由到文物 / 残页 / 异录等。
7. 检查最近重复与冷却；
8. 为每个候选写现实依据 + 对标参考 + 对标撞题检查；
9. 升 / 降候选优先级；
10. 淘汰弱题；
11. 保持池子不过度膨胀。

如果已经有足够强候选，不为了“显得有工作”继续无限扩池。

### 当天没有合格候选时

当天制作条件（例如不想出镜、不做《文物》、时间不足）只能用于**淘汰和排序**，不能降低栏目资格。

如果剩下候选没有任何一个真正通过栏目 / 证据 / 成片形态：
- 允许当天大号不发；
- 允许改做小红书图文、公众号、课程、数据库或其它更合适任务；
- 不得为了“今天必须有一支大号视频”把次优或路由不稳的候选强行抬成P0。



## 七、进入正式定题的触发

只有以下情况之一成立，才从 `08-动态运行/选题池/当前选题池.md` 进入正式定题：

- Suen 明确说“更新”并需要决定今天发什么；
- Suen 明确说“定题 / 选今天的 / 正式更新”；
- Suen 明确指定某个候选要进入下一阶段。

进入后再读取：

- `内容地图.md`
- `内容商业对标系统.md`
- `选题定稿硬门槛.md`
- 对应栏目规则

通过硬门槛以后，才进入生产保护。

## 八、与其它动态文件的分工

- `08-动态运行/选题池/当前选题池.md`：抖音大号未来可能发什么；
- `08-动态运行/选题池/小红书当前选题池.md`：小红书未来可能发什么（含独立视频 / 实践 / 《长卷》候选）；
- `08-动态运行/内容台账/当前状态.md`：已经真实发布了什么、数据怎样；
- `08-动态运行/商业/当前商业状态.md`：当前瓶颈、P0/P1/P2、商业信号、询盘与成交决策；
- `08-动态运行/天象/当前预约池.md`：已筛选的天象经营状态。

候选题只保存在当前选题池，不长期堆进商业当前状态。

## 九、核心原则

**选题池负责“存选择”，总控负责“做决定”，专用对话负责“做成品”。**

三层不能提前串线。

### 平台候选池分离

从 2026-09-25 起：
- 抖音大号与小红书分别维护当前候选池；
- 六个视频栏目共享事实 / 栏目标准，不共享每日定题；
- “同题双平台”只代表生产可复用，不代表候选状态自动同步；
- 抖音大号的2—5个活跃高优先上限只约束大号池；
- 小红书另有《长卷》，必须独立判断是否值得用长文形式。

## 十、选题池不是全平台唯一选题来源

选题池负责“存选择”，不是“限制选择”。

- 当前主选题池主要服务抖音大号；
- 总控在正式“更新 / 今天发什么”场景中，可以直接从池内取高质量候选，也可以根据最新数据、平台空窗、重复结构、当天商业状态主动生成并核查新题；
- 公众号、小红书、小号、Patreon 等平台不需要为了使用该池而强行拿走抖音大号候选；
- 当其它平台需要新题时，应读取该平台当前规则并独立判断；
- 新题如果未来也适合进入大号候选池，可以在核查后再写入，不要求“先入池才能被选中”。

选题池是加速器，不是闸门。
