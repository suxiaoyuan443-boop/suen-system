# Suen｜统一文笔与成稿执行总则

状态：当前正式跨平台规则  
最后核对：2026-10-07

本文件同时负责：**共同文笔底线 + 成稿 QA + 专用对话完整执行要求**。

平台 / 栏目规则更具体时，以更具体规则补充执行。

## 一、成品应该是什么感觉

像一个真的看过资料、知道对象怎么使用的人，把事情自然讲清楚。

专业感来自：

- 具体对象、动作、材料、位置；
- 原始资料、文物、手稿、文本；
- 明确用途、判断条件、版本差异；
- 能追到来源的证据。

不靠术语密度、营销口吻、故作神秘或空泛总结制造专业感。

## 二、文笔硬规则

避免：

- 换任何题都能套的 AI 开头；
- 连续“不是 / 并不 / 不能 / 不等于”；
- “本质上 / 说到底 / 真正重要的是 / 这告诉我们”等空泛总结；
- 一句话一段的故意碎句；
- 强行升华；
- 同一个结论换几种说法重复；
- 用“空间结构 / 建立边界 / 底层逻辑”等抽象词替代本来能直接说清的动作；
- 用现代常识补历史文本没有说明的原因。

具体能写成“谁站哪里、什么写在哪里、先做什么、后做什么”，就优先写具体版本。

“你有没有发现”不是机械禁词；只有后面立刻接真实、具体、与当天主题直接相关的场景时才成立。

### 反“修辞模板”补充｜2026-10-07

Suen 明确不接受以下高频 AI 修辞作为默认写法：

- “不是 A，而是 B”“并不是……而是……”这类为了制造力度而写的对照句，尤其不能连续出现；
- 连续用否定句推进正文，例如“不是……也不是……更不是……”；
- “这个故事最有意思的地方是 / 并不是……”“真正有意思的是……”；
- “如果事情只停在这里……”“事情到这里还没有结束……”；
- “更关键的是 / 真正关键的是 / 性质就完全不一样了”等替观众标注重点的转折模板；
- 把作者自己的修改过程、审核过程或内部提醒写进口播，例如“这里不需要再强调”“这个词我们不用”等元话语。

处理原则：
- 能直接把事实、动作和前后关系说出来，就不要先否定一个版本再推出另一个版本；
- 转折由事件本身产生，不靠模板句宣布“这里有转折”；
- 强调由具体细节承担，不靠“真正、关键、有意思”等评价词；
- 正式口播里不得泄露编辑备注、内部 QA、写作说明或自我纠错痕迹。

### 句式与节奏反 AI 补充｜2026-09-25

除了禁用固定词，还要检查**句子的排列方式**。Suen 对“整齐得像文案”的同构排比非常敏感。

默认避免：
- 连续三句或更多使用同一个句法骨架；
- “看到A会……看到B会……看到C会……”这类换名词即可复用的并列句；
- “材料会变、工艺会变、做法会变”这类为了节奏而凑出来的三连排比；
- 连续使用“我会……我会……我会……”或“有的人……有的人……有的人……”制造所谓真人感；
- 先列三件事，再用一句抽象结论收束的标准化短文结构；
- 为了让文字“有力量”故意压成对仗、金句、广告语。

可以自然并列，但每一项必须真的有信息必要，而且句式不需要刻意整齐。

交付前多做一项检查：
> **如果只替换人名、项目名或名词，这几句话还能原样套到别的题上吗？**

如果可以，优先改成当前对象真正发生过的动作、判断、细节或犹豫。真人感来自思路本身，不来自模拟口头禅、故意打乱语序或人为加碎句。

### 反“整理稿”补充｜2026-09-27

Suen 对“资料都对，但像 AI 整理出来的讲义”同样敏感。正式口播还要避免：

- 每一段都按“资料 → 解释 → 所以结论”完整收束；
- 每换一个来源就重新总结一次同一个中心意思；
- 为了显得清楚，把自然讲话改成“定义 A、解释 B、总结 C”的标准说明书；
- 先把答案抽象成一个概念，再让后面的材料只负责重复证明这个概念；
- 用“我最近在查 / 最近研究到”作为万能真人感开头。

优先做法：
- 让具体对象、动作或原页先推进；
- 一份材料只负责增加它真正新增的那一层；
- 前面说清的结论后面直接沿用，不换词复述；
- 最后只在真正需要时收一次，不要求每段都自带结论。

如果某栏目已有 Suen 明确认可的历史成稿，且当前环境可以可靠读取，正式写新稿前**必须读取至少 1 条**作为语感 / 节奏参照；需要时可读第 2 条。当前正式规则仍然是边界真源，旧稿只用于对齐真实表达习惯，不覆盖事实、平台或栏目新规则。

如果明知存在认可成稿、但当前环境无法可靠取得：
- 不得声称“已按历史语感对齐”；
- 先按当前正式文笔与栏目规则完成其它研究 / QA；
- 只有当语感差异会直接影响成稿合格性时，才把“认可样稿不可访问”作为真实阻塞说明，不能自行用一篇旧的 AI 稿或未确认稿代替。

## 二-B、反AI不能只靠禁句｜生成结构硬规则｜2026-10-07

本轮跨专用对话复盘确认：现有规则已经禁止大量AI高频句式，但成稿仍会稳定出现AI感。原因是**表层措辞被限制，底层组织方式没有被强制改变**。

典型失败不是单个词，而是：
- 先替材料总结一个抽象答案；
- 再拆成第一层 / 第二层 / 第三层；
- 每段按“事实 → 解释 → 小结”完整收束；
- 最后再用一句总括把全文重新说一遍。

即使完全不用“不是A而是B / 真正关键 / 本质上”，这种结构仍然是AI整理稿。

### 1. 研究笔记和正式口播必须是两种结构

研究阶段可以有：
- 分层机制；
- 时间线；
- 证据表；
- 对照项；
- QA清单。

**正式口播不得直接按这些研究标签展开。**

正式口播优先沿着：
- 眼前具体对象；
- 一个实际动作；
- 原页下一句；
- 人物下一步行为；
- 一个新出现的细节
自然往前走。

研究结构负责保证正确，不能直接变成观众听到的结构。

### 2. 正式口播先写成连续讲话，再切视觉段

禁止一开始就按HTML beat / 图片块写正文。

内部顺序：
1. 先写一份连续、无标题、无编号、无“第一层 / 第二层 / 第三层”的完整口播；
2. 正常语速通读并做真人文笔QA；
3. 通过以后，才按实际换图位置切成若干口播块；
4. 切块时不得为每块补一个独立总结句。

原因：先按素材块写，极易生成“每段一个观点、每段自己收尾”的AI模块化文本。

### 3. 默认减少解释型路标词

以下词不机械绝对禁止，但连续出现或承担段落骨架时默认重写：
- 第一层 / 第二层 / 第三层；
- 这说明；
- 这意味着；
- 可以看出；
- 所以我们可以理解；
- 从这里就能看出来；
- 值得注意的是；
- 换句话说；
- 简单来说；
- 也就是说；
- 因此真正……

能直接继续说下一个事实、动作、原句，就不要插解释路标。

### 4. 段落默认不要“收口”

真人讲话不需要每40—80字完成一次小论文。

除非确实到了一个自然结论点，否则段落结尾优先停在：
- 下一个动作之前；
- 一个具体细节；
- 一句原文；
- 一个画面；
- 一个尚未解释完、自然把人带到下一句的信息。

不要每段都用“所以 / 这说明 / 也就是说”封口。

### 5. 没有真实认可样稿时，不得声称“已对齐Suen语感”

当前仓库若没有可实际读取、且明确由 Suen 认可的完整口播样本：
- 不得把助手自己写过但未被明确认可的稿子当作样本；
- 不得因为标题或单句被认可，就推定整篇语感已被认可；
- 不得用“已按Suen旧稿对齐”作为QA结论。

在真正认可样稿入库前，默认使用**低修辞具体口语模式**：
- 少解释路标；
- 少总结；
- 少抽象名词；
- 具体对象和动作连续推进；
- 不模拟口头禅来制造真人感。

以后只要 Suen 明确确认某一版“文笔可以 / 这版对 / 可以发”，再把该完整成稿作为对应栏目的正向语感样本归档。未明确确认的稿子不入样本库。

### 6. 最终反AI验收不是查禁词，而是查骨架

交付前把来源卡、图片、标题全部拿掉，只读口播，问：

> **这段话是在顺着事情往前讲，还是在替资料做整理？**

如果还能明显看见“定义 → 分层 → 解释 → 总结”的骨架，即使一句禁词都没有，也判定为AI文风，内部重写。

## 二点五｜标题反 AI 硬规则

标题是成稿的一部分，同样执行“像真人会说的话”。

### 优先
- 直接说这条最有意思的事实 / 问题；
- 像 Suen 自己真的会问、会说的一句话；
- 能短就短，不为了“钩子感”补第二层反转；
- 普通词优先，不用运营词替代正常中文；
- 问句只有真的自然时才用，不把所有题都改成“为什么 / 真的能吗 / 到底怎么回事”。

### 强吸引仍然是硬要求

“反 AI”**不等于标题变平、变弱、变成资料目录。**

标题和开头仍然要尽可能强地抓住人，但吸引力优先来自内容本身：

- 一个真的奇怪的东西；
- 一个普通人马上能懂的冲突；
- 一个反常动作；
- 一个具体数字 / 时间 / 物件；
- 一句原文本身就很怪的话；
- 一个“为什么会这样”的真实问题。

优先做法：
1. 先找到这条内容里**最值得点开的那个事实**；
2. 把它放到标题或开头最前面；
3. 用普通中文直接说；
4. 删掉第二层运营话术和人为反转；
5. 如果事实本身不够强，不靠模板补成“强钩子”，回头换题或换入口。

例如 Suen 已经验证过的自然强标题：
- 《这个17世纪瓶子里为什么装着人尿和铁钉？》
- 《死后你的心脏会告发你？》
- 《你的名字也会被杀死？》
- 《古埃及墓里这扇门到底给谁走？》

它们强，不是因为套了营销句式，而是因为**对象和问题本身就足够怪，而且一句话马上听懂。**

### 开头同样执行

开头前2—5秒仍需强吸引，但不要写成广告脚本。

优先：
- 直接把最怪的对象 / 动作 / 冲突说出来；
- 先给具体事实，再解释背景；
- 尽量让观众在第一句话就知道“这条到底怪在哪里”。

避免：
- “你绝对想不到……”
- “很多人都不知道……”
- “今天带你了解……”
- “接下来这个可能颠覆你的认知……”
- 为了留人故意藏答案很久。

### 禁止高频 AI 标题模板
默认避免：
- “先别急着……”
- “一个A，一个B，真的能……吗？”
- “这个数字 / 这个答案我不会随口说”
- “你以为……其实……”
- “看似……其实……”
- “同样都是X，为什么……”
- “真正的问题不是……”
- “这件事比你想的更复杂”
- 为了制造冲突硬塞“真的 / 居然 / 竟然 / 怎么可能”

这些句式不是绝对永远不能出现；只有 Suen 当下自然会这样说、且内容确实需要时才可用。不能把它们当标题生成公式。

### Suen 当前标题基线

优先参考已经实际使用过、语气自然的标题，例如：
- 《第二木星星符到底写了什么？》
- 《古埃及墓里这扇门到底给谁走？》
- 《这个17世纪瓶子里为什么装着人尿和铁钉？》
- 《供品都给神了，为什么古希腊人最后还能把肉吃掉？》
- 《你的名字也会被杀死？》

共同点：
- 一条标题只放一个主要怪点 / 问题；
- 词很普通，像真人会问；
- 不叠两层“反差 + 反转 + 判断”；
- 不为了显得会做短视频而加多余态度词；
- 题目本身够怪时，标题就停在那里，不再二次加工。

候选阶段只需要把**题眼**说清楚，不要求提前产出最终发布标题。  
正式标题优先在口播 / 正文已经成型以后再写，并回看上述历史基线。

### 标题 QA
正式交付前单独问：
> **这句话如果不加书名号，像不像 Suen 会直接发给朋友 / 写在自己账号上的一句话？**

如果像“短视频运营课示例标题”，即使点击逻辑成立也要重写。

内部命题、运营目的、Hook 标签不得直接转换成发布标题。

## 三、研究型内容

文物、残页、辨伪、异录、隐理、长卷、公众号研究内容默认减少作者第一人称。

区分：

- 原始材料实际写了什么；
- 学者如何解释；
- 后世如何发展；
- 现代实践如何选择。

推测不能写成事实。

资料越硬，导航越简单：出现原页、希腊文、拉丁文、埃及语、魔法字符时，必须告诉观众具体看哪里、什么意思、为什么重要。

中文平台观众端默认中文表达；原始语言作为证据时保留原文，并同步给中文定位 / 解释。

## 四、完整执行

任务已经明确且没有真实阻塞时，专用对话默认自己完成：

1. 读取当前规则；
2. 确认核心答案有证据；
3. 完成必要研究；
4. 成稿；
5. 找素材 / 核查链接；
6. 文笔与交付 QA；
7. 自己修正明显问题；
8. 一次性交付完整成品。

不要做到一半停下来等 Suen 说“继续”。

不要把本可自行完成的搜图、原文定位、素材匹配、裁切建议、重复删除、排版修复转回给 Suen。

只有核心事实无法成立、缺少只有 Suen 才能提供的必要信息、或需要 Suen 做真实取舍时才提问。

## 五、长稿前内部门槛

长文、隐理、原典研究等，在完整写稿前先内部确认：

- 核心答案一句话能否说清；
- 主要证据分别支持什么；
- 哪些只是推测；
- 标题有没有承诺超过证据；
- 栏目路由是否正确。

证据不足时收窄题目或换题，不先写完整长稿再整篇返工。

## 六、交付前 QA

必须自己检查：

- 每段是否增加新信息；
- 是否存在同义复述；
- 是否有无证据拔高；
- 是否连续否定；
- 是否把具体动作写成抽象概念；
- 是否自然可说 / 可读；
- 是否符合栏目自己的语气；
- 是否把运营优化写成营销号文风；
- 素材是否真实、正确、可用；
- 交付格式是否完整；
- 是否无故留下半成品。

视频口播在脑内按正常语速完整读一遍；说不顺就改。

## 七、真实性

不得为了流量、神秘感、商业或补素材：

- 虚构历史、文物用途、原始文本；
- 把学者推测写成事实；
- 把现代重构反写成古代传统；
- 用 AI 图冒充真实历史资料；
- 虚构体验、客户反馈或功效。

## 八、用户指出“不对”时

先检查：规则有没有读对、执行有没有漏、证据是否支撑、文笔 QA 是否失败、交付格式是否漏。

不要先重新发明栏目理论、时长限制、多日准备期或更多临时提示词。

## 八-A、用户反馈进入长期规则的分流

Suen 对成稿的修改意见必须先判断属于哪一层，避免“所有反馈都永久化”与“换对话后全部丢失”同时发生。

### 1. 一次性任务反馈
只影响当前稿件 / 当前题，例如：
- 今天这张图不用；
- 这一篇删掉某个案例；
- 当前标题再短一点。

这类不写成长期规则。

### 2. 栏目长期反馈
明确适用于某一栏目 / 内容产品，例如：
- 《长卷》正文不要写成缩小版论文；
- 《异录》必须保持说书式故事推进；
- 《牌记》必须围绕具体牌局判断。

应修改对应栏目唯一真源，不复制到多个文件。

### 3. 跨平台长期反馈
明确是 Suen 对普遍文笔 / 成稿方式的长期要求，例如：
- 系统性 AI 组织方式；
- 同义复述；
- 抽象总结；
- 成稿交付前必须自己 QA。

应修改本文件或真正负责该主题的系统真源。

### 重复错误升级
同类错误第二次再次出现时，必须先检查：
1. 现有 GitHub 是否已经有明确规则；
2. 如果已有，定性为**执行故障**，修执行链，不新增重复规则；
3. 如果确实没有，而且 Suen 的反馈明显是长期要求，再修改唯一真源；
4. 不把一次性的当前稿件意见误写成永久规则。

目标是让反馈形成闭环，同时保持仓库单一真源和规则可维护性。

## 九、正式成稿最小读取

正式内容任务至少读取：

1. 对应平台 / 栏目当前规则；
2. 本文件；
3. 对应交付规则；
4. 视频再读 `99-模板/视频类统一交付格式.md`。

正常情况下不再额外加载旧的两个验收协议全文。


## 十、统一文笔不等于统一栏目口吻

统一总则只负责共同底线，**不能把不同栏目写成同一种声音**。

正式成稿必须同时执行：

1. 统一文笔底线；
2. 当前栏目自己的文风 / 叙事 / 开头 / 结构规则；
3. 当天总控变量。

当“统一总则”和“栏目具体表达方式”同时适用时：

- **栏目更具体的语气、叙事和结构要求优先**；
- 统一总则继续约束真实性、AI腔、重复、抽象空话、证据边界和完整执行；
- 不能为了统一文笔，把《异录》写成《残页》，把《辨伪》写成《隐理》，或把《牌记》写成研究论文。

六个大号栏目必须保留各自明显差异：

- **文物**：带着观众看真实对象，指哪里就讲哪里；
- **异录**：说书式真实故事，人物、事件、转折和画面感优先；
- **辨伪**：判断题，明确、轻松、朋友聊天感；
- **残页**：最高严谨度，从原页、具体行、词义和版本进入；
- **隐理**：解释实践机制，答案早出现，具体动作优先；
- **牌记**：像真实看牌过程，允许少量经验型第一人称，重点是为什么这样判。

“服务认知”是当天任务标签，不是独立文风或独立栏目。需要展示现实判断时，先服从实际承载它的栏目 / 平台：具体牌局回《牌记》，可证实的实践机制回《隐理》，纯个人判断 / 服务原则优先放小号、朋友圈或适合的小红书内容。

验收时如果一篇稿子只满足“没有 AI 味”，但失去了当前栏目的声音，仍然视为不合格。


## 十一、真人口语参照

从 2026-09-20 起，视频口播、朋友圈、抖音小号及其它需要“像 Suen 本人说话”的内容，优先参考 Suen 当天自我介绍视频中的自然表达方式。

核心特征：

- 像人顺着想法直接说，不像提前写好的说明书；
- 允许自然停顿、转折、稍微绕一下再说清楚；
- 不为了“信息完整”把每一句都写成标准答案；
- 少用“第一、第二、第三”“我主要分成两部分”“所以这个账号会……”这类提纲式表达；
- 不强行把每段都收束成一句结论；
- 可以保留“其实、反正、我平时、我会、对我来说”这类真实口语，只要不过度重复；
- 专业感继续来自真实资料、具体经历、明确判断，不靠正式腔；
- 如果成稿读起来像品牌介绍、课程简介、AI整理稿，即使信息都对，也要继续改到像真人会说的话。

正式研究型长文仍按对应栏目规则执行，不机械套用口语化。

## 视频口播可说性硬规则｜2026-09-26

所有视频口播首先按“人实际要说出口”来写，不按资料卡、论文摘要或馆藏记录的写法直接搬进嘴里。

### 英文 / 外文
- 有自然中文名称时，口播优先说中文。
- 英文馆名、术语、拉丁文、希腊文、埃及语转写、英文类别名如果读起来会卡，不要求口播逐字念。
- 原词对证据重要时：**口播先说中文意思，原词放字幕 / 图片 / 来源里。**
- 馆藏页上的英文标题、考古地点代码、墓号、英文材料名不因为“资料完整”就强塞进口播。
- 不自行发明中文译名；没有稳定译名时，用普通中文解释它是什么，原词留在画面。

### 数字
- 馆藏号、登录号、长串编号默认留在图注 / 来源，不要求口播念。
- 年代优先说成自然中文，如“新王国时期”“大约三千多年前”“公元前十六世纪左右”；只有具体年份直接影响结论时才精确念。
- 尺寸只在“大小本身值得看”时进入口播，且一次只保留真正有用的数字。
- 一句话里不要连续塞“馆藏号 + 年代范围 + 尺寸 + 墓号”等多组数字。
- 数字书面上可以完整保留，口播允许改成更自然的近似范围，只要不改变事实结论。

### 实际讲话验收
正式交付前必须把口播按正常语速完整读一遍，并额外检查：
- 哪个英文词真实拍摄时容易卡；
- 哪串数字需要低头确认才能念；
- 哪句话像在念馆藏说明或论文摘要；
- 哪些信息观众看字幕就够了，不需要嘴里再念一遍。

出现上述情况，优先改口播，把精确信息留给画面、图注和来源。

**判断标准：如果 Suen 拿起手机直接录，这句话需要先练两遍才能顺下来，就还不是最终口播。**
