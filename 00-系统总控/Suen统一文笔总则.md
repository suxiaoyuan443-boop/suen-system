# Suen｜统一文笔与成稿执行总则

状态：当前正式跨平台规则  
最后核对：2026-10-13

本文件同时负责：**共同文笔底线 + 成稿 QA + 专用对话完整执行要求**。

平台 / 栏目规则更具体时，以更具体规则补充执行。

## 零、生成与QA分离｜2026-10-07

本文件很长，**不得把整份规则当成第一稿生成模板。**

正式口播生产分两阶段：

### A｜生成第一稿
只用：
- 当前栏目规则；
- 当天事实范围；
- `00-系统总控/Suen口播写作内核.md`；
- `00-系统总控/Suen认可文笔样本库.md` 中当前可用的正向样本。

第一稿必须先写成连续自然口播，不按QA条目、不按HTML块、不按“第一层/第二层/第三层”组织。

### B｜写完以后再QA
第一稿完成后，才使用本文件其余规则检查：
- AI结构；
- 同义复述；
- 抽象总结；
- 术语密度；
- 可说性；
- 证据边界。

QA发现整稿级问题时，保留已核事实，重新选择信息与组织正文；只有句段局部有问题时，修复对应位置并保留其它合格内容。删禁词、换同义词不构成结构修复。

目的：防止“规则越多，稿子越像合规说明书”。

## 一、成品应该是什么感觉

像一个真的看过资料、知道对象怎么使用的人，把事情自然讲清楚。

专业感来自：

- 具体对象、动作、材料、位置；
- 原始资料、文物、手稿、文本；
- 明确用途、判断条件、版本差异；
- 能追到来源的证据。

不靠术语密度、营销口吻、故作神秘或空泛总结制造专业感。

## 二、文笔硬规则

默认优先相对完整、逻辑清楚的长句。一句话可以同时包含事实、补充、解释和因果，句子长短根据内容自然变化；不要为了口语感、节奏或配图，把一个完整意思拆成连续碎句。

段落围绕一个对象、问题或理解关系自然展开，通常在同一段中交织资料和必要解释，再进入下一段。连续口播指思路连贯，允许自然分段；不要求全文只有一段，也不连续一句话一段。

具体细节之后，继续讲清与用途、操作、使用对象或环境的关系，以及判断依据。删掉空话和重复时，保留读者理解所需的解释。

避免：

- 换任何题都能套的 AI 开头；
- 连续“不是 / 并不 / 不能 / 不等于”；
- “本质上 / 说到底 / 真正重要的是 / 这告诉我们”等空泛总结；
- 一句话一段的故意碎句；
- 强行升华；
- 同一个结论换几种说法重复；
- 用“空间结构 / 建立边界 / 底层逻辑”等抽象词替代本来能直接说清的动作；
- 用现代常识补历史文本没有说明的原因。

具体能写成“谁站哪里、什么写在哪里、先做什么、后做什么”，就优先写具体版本。

“你有没有发现”不是机械禁词；只有后面立刻接真实、具体、与当天主题直接相关的场景时才成立。

### 反“修辞模板”补充｜2026-10-07

Suen 明确不接受以下高频 AI 修辞作为默认写法：

- “不是 A，而是 B”“并不是……而是……”这类为了制造力度而写的对照句，尤其不能连续出现；
- 连续用否定句推进正文，例如“不是……也不是……更不是……”；
- “这个故事最有意思的地方是 / 并不是……”“真正有意思的是……”；
- “如果事情只停在这里……”“事情到这里还没有结束……”；
- “更关键的是 / 真正关键的是 / 性质就完全不一样了”等替观众标注重点的转折模板；
- 把作者自己的修改过程、审核过程或内部提醒写进口播，例如“这里不需要再强调”“这个词我们不用”等元话语。

处理原则：
- 直接把事实、动作和前后关系说出来，辨析只在确有必要时使用；不要把“删生硬桥接句”扩大成删除全部解释、过渡或判断；
- 衔接讲清前后的指代、因果、条件或事件变化，保留自然连接词；不靠模板句宣布“这里有转折”；
- 强调由具体细节承担，不靠“真正、关键、有意思”等评价词；
- 正式口播里不得泄露编辑备注、内部 QA、写作说明或自我纠错痕迹。

### 句式与节奏反 AI 补充｜2026-09-25

除了禁用固定词，还要检查**句子的排列方式**。Suen 对“整齐得像文案”的同构排比非常敏感。

默认避免：
- 连续三句或更多使用同一个句法骨架；
- “看到A会……看到B会……看到C会……”这类换名词即可复用的并列句；
- “材料会变、工艺会变、做法会变”这类为了节奏而凑出来的三连排比；
- 连续使用“我会……我会……我会……”或“有的人……有的人……有的人……”制造所谓真人感；
- 先列三件事，再用一句抽象结论收束的标准化短文结构；
- 为了让文字“有力量”故意压成对仗、金句、广告语。

可以自然并列，但每一项必须真的有信息必要，而且句式不需要刻意整齐。

交付前多做一项检查：
> **如果只替换人名、项目名或名词，这几句话还能原样套到别的题上吗？**

如果可以，优先改成当前对象真正发生过的动作、判断、细节或犹豫。真人感来自思路本身，不来自模拟口头禅、故意打乱语序或人为加碎句。

### 反“整理稿”补充｜2026-09-27；执行修订2026-10-12

Suen 对“资料都对，但像 AI 整理出来的讲义”同样敏感。正式口播还要避免：

- 每一段都按“资料 → 解释 → 所以结论”完整收束；
- 每换一个来源就重新总结一次同一个中心意思；
- 为了显得清楚，把自然讲话改成“定义 A、解释 B、总结 C”的标准说明书；
- 先把答案抽象成一个概念，再让后面的材料只负责重复证明这个概念；
- 用“我最近在查 / 最近研究到”作为万能真人感开头。

优先做法：
- 让具体对象、动作或原页先推进；
- 一份材料只负责增加它真正新增的那一层；
- 前面说清的结论后面直接沿用，不换词复述；
- 最后只在真正需要时收一次，不要求每段都自带结论。

段末不要用抽象话重新评价刚讲过的步骤、材料或叙述结构。Suen于2026-10-12明确退回《神庙求梦》中的两句：“睡下去，是前面这些准备之后才进行的一步。”“这里的材料、身体的位置和动作顺序，已经连成了一个完整的求问过程。”前文已经讲清先净化、献祭、祈祷，再躺下等待梦中启示，这两句没有增加具体知识，应删除，不能只把“完整过程”换成“完整仪式”“彼此联系”继续复述。

自然过渡从下一项必要信息开始：接下一个动作、换到有明确联系的地点或人物、引入下一段原文，或回答读者尚未弄清的问题。上一段已完整讲清时可以直接结束，下一段自然继续，不要求每个段末另写过渡句。例如奥罗波斯的羊皮与入睡步骤讲完后，若下一段要介绍埃皮达鲁斯的睡眠区，直接从那个地点和供人睡觉的建筑讲起即可。

这是已有“抽象总结 / 同义复述”禁忌的执行修正。具体因果、证据差异、用途解释及有新增信息的归纳继续保留；不机械禁用“步骤”“过程”等正常词，不靠压短完整句子或减少研究深度解决问题。

如果某栏目已有 Suen 明确认可的历史成稿，且当前环境可以可靠读取，正式写新稿前**必须读取至少 1 条**作为语感 / 节奏参照；需要时可读第 2 条。认可状态与样本正文统一读取 `00-系统总控/Suen认可文笔样本库.md`，不得自行认定某旧稿为认可样本。当前正式规则仍然是边界真源，旧稿只用于对齐真实表达习惯，不覆盖事实、平台或栏目新规则。

如果明知存在认可成稿、但当前环境无法可靠取得：
- 不得声称“已按历史语感对齐”；
- 先按当前正式文笔与栏目规则完成其它研究 / QA；
- 只有当语感差异会直接影响成稿合格性时，才把“认可样稿不可访问”作为真实阻塞说明，不能自行用一篇旧的 AI 稿或未确认稿代替。

## 二-B、结构与解释审核｜2026-10-07

研究笔记可以按来源、时间线、配方、机制、对照项分类。正式口播需要根据对象和读者当前的理解重新选择材料与顺序；具体事实、必要背景和解释交织推进。

定义、比较、归纳有正常用途。审核要判断它们是否解决了当前问题，是否让后文只剩同一结论的重复证明，不能仅因为出现定义或比较就判整稿失败。

### 1. 句子与段落

按第二节的完整句子、自然段落要求检查。重点定位：完整意思被拆成碎句、连续相同句法、资料与解释机械交替，以及同一事实反复出现。

### 2. 材料之间的关系

检查上一段让读者知道了什么，下一段增加了什么，两个材料通过哪个具体问题联系。没有关系时重新组织材料；不只删除路标词，也不靠加入“然后 / 更关键的是”制造连接。

### 3. 问题是否得到回答

正文提出“为什么”，后文必须给出能支持原因的证据与解释。另一份资料记载相同做法，可以证明平行关系，不能自动解释这种做法为何被选择。

说明证据支持的范围，区分操作记载、古人信仰、学者解释和当前未知。不能以资料罗列、相似性或术语定义冒充原因。

#### 标题承诺与回答核对｜2026-10-13

标题、封面及开头提出的主问题，和正文自身提出的问题一起验收。区分“是什么 / 做了什么”“怎么做”“为什么这样做”和“最后结果如何”，不能用回答其中一项冒充回答另一项。

成稿后在内部审核记录写明：**观众据标题会问什么 → 正文的具体答案 → 答案所在段落 → 支持答案的资料与推理范围**。标题问“为什么”，正文须讲清有关人物 / 使用者的观念、目的、条件及证据能支持的原因；只复述动作、引用请求或说明名词，即使资料准确，仍未兑现标题。答案应在自然叙述中建立；需要结尾回应时落到本题的具体解释，不强制每篇加总结或重复全文。

证据边界用于限定判断。影响核心答案的争议必须说清；姓名、署名、文书性质、未保存的后续等说明若与主问题无直接关系，放进来源 / 研究说明，避免正文连续用“可能 / 不知道 / 无法确认”拖走主线。不能隐藏会推翻核心判断的缺口，也不能把“不确定”当成结尾答案。

如果资料只能回答发生了什么、无法支持标题承诺的原因，先缩小提问范围、补证或换题；不能为保留强标题补造动机。若Suen指出标题与正文不符，撤回旧成品通过状态，修正文或标题后重新核对，图片齐全、链接可用及内部事实检查不能替代这项验收。

### 4. 连续口播与视觉切块

正文先作为完整连续讲述形成，保留自然段落；审核后再按实际换图位置切块。每个图片块不另补一段独立结论。交付排版不反过来要求一句话一段。

### 5. 正向语感参照

认可状态与样稿正文统一读取 `Suen认可文笔样本库.md`。有明确认可样稿时按本文件的样稿读取要求执行；没有样稿时，仍按已经明确的完整句子、自然叙述和解释要求写，不能声称已复刻 Suen 语感。

### 6. 审核落到当前正文

交付前暂时去掉标题、图片和来源卡，检查正文自身是否让读者逐渐理解对象、用途、使用方式与判断依据。

具体操作统一执行第六节“交付前QA”。一句“已读规则 / 无禁词 / 感觉像真人”不能替代对当前句段与解释关系的检查。

## 二点五｜标题反 AI 硬规则

标题是成稿的一部分，同样执行“像真人会说的话”。

### 优先
- 直接说这条最有意思的事实 / 问题；
- 像 Suen 自己真的会问、会说的一句话；
- 能短就短，不为了“钩子感”补第二层反转；
- 普通词优先，不用运营词替代正常中文；
- 问句只有真的自然时才用，不把所有题都改成“为什么 / 真的能吗 / 到底怎么回事”。

### 强吸引仍然是硬要求

“反 AI”**不等于标题变平、变弱、变成资料目录。**

标题和开头仍然要尽可能强地抓住人，但吸引力优先来自内容本身：

- 一个真的奇怪的东西；
- 一个普通人马上能懂的冲突；
- 一个反常动作；
- 一个具体数字 / 时间 / 物件；
- 一句原文本身就很怪的话；
- 一个“为什么会这样”的真实问题。

优先做法：
1. 先找到这条内容里**最值得点开的那个事实**；
2. 把它放到标题或开头最前面；
3. 用普通中文直接说；
4. 删掉第二层运营话术和人为反转；
5. 如果事实本身不够强，不靠模板补成“强钩子”，回头换题或换入口。

例如 Suen 已经验证过的自然强标题：
- 《这个17世纪瓶子里为什么装着人尿和铁钉？》
- 《死后你的心脏会告发你？》
- 《你的名字也会被杀死？》
- 《古埃及墓里这扇门到底给谁走？》

它们强，不是因为套了营销句式，而是因为**对象和问题本身就足够怪，而且一句话马上听懂。**

### 开头同样执行

开头前2—5秒仍需强吸引，但不要写成广告脚本。

优先：
- 直接把最怪的对象 / 动作 / 冲突说出来；
- 先给具体事实，再解释背景；
- 尽量让观众在第一句话就知道“这条到底怪在哪里”。

避免：
- “你绝对想不到……”
- “很多人都不知道……”
- “今天带你了解……”
- “接下来这个可能颠覆你的认知……”
- 为了留人故意藏答案很久。

### 禁止高频 AI 标题模板
默认避免：
- “先别急着……”
- “一个A，一个B，真的能……吗？”
- “这个数字 / 这个答案我不会随口说”
- “你以为……其实……”
- “看似……其实……”
- “同样都是X，为什么……”
- “真正的问题不是……”
- “这件事比你想的更复杂”
- 为了制造冲突硬塞“真的 / 居然 / 竟然 / 怎么可能”

这些句式不是绝对永远不能出现；只有 Suen 当下自然会这样说、且内容确实需要时才可用。不能把它们当标题生成公式。

### Suen 当前标题基线

优先参考已经实际使用过、语气自然的标题，例如：
- 《第二木星星符到底写了什么？》
- 《古埃及墓里这扇门到底给谁走？》
- 《这个17世纪瓶子里为什么装着人尿和铁钉？》
- 《供品都给神了，为什么古希腊人最后还能把肉吃掉？》
- 《你的名字也会被杀死？》

共同点：
- 一条标题只放一个主要怪点 / 问题；
- 词很普通，像真人会问；
- 不叠两层“反差 + 反转 + 判断”；
- 不为了显得会做短视频而加多余态度词；
- 题目本身够怪时，标题就停在那里，不再二次加工。

候选阶段只需要把**题眼**说清楚，不要求提前产出最终发布标题。  
正式标题优先在口播 / 正文已经成型以后再写，并回看上述历史基线。

### 标题 QA
正式交付前单独问：
> **这句话如果不加书名号，像不像 Suen 会直接发给朋友 / 写在自己账号上的一句话？**

如果像“短视频运营课示例标题”，即使点击逻辑成立也要重写。

内部命题、运营目的、Hook 标签不得直接转换成发布标题。

## 三、研究型内容

文物、残页、辨伪、异录、隐理、长卷、公众号等文章型正文默认不使用作者第一人称，也不以“我们可以看到”等句式反复代替。原典引用中的说话人按文本实际身份保留；真实个人表达只有在 Suen 当次明确要求时使用。

区分：

- 原始材料实际写了什么；
- 学者如何解释；
- 后世如何发展；
- 现代实践如何选择。

推测不能写成事实。

资料越硬，导航越简单：出现原页、希腊文、拉丁文、埃及语、魔法字符时，必须告诉观众具体看哪里、什么意思、为什么重要。

中文平台观众端默认中文表达；原始语言作为证据时保留原文，并同步给中文定位 / 解释。

## 三-A、长文章的知识交付

文章从具体对象进入，带入历史 / 现实语境、资料细节和用途，再解释为什么重要。研究与叙述交织，不先半篇故事再半篇百科，也不以宏大开场和结尾升华代替知识。

每个新段落至少增加一项可复述的信息或必要解释：对象、原文、动作、功能、证据、版本、比较或争议。学者意见围绕具体争议引入，不连续堆文献综述。证据较强时可以直接判断，说明依据及未解决部分，无需“个人认为”。

按资料允许覆盖：

- 文物：身份 / 年代 / 地区 / 材料 / 尺寸 / 馆藏或出土，外观及文字图像位置，用途 / 使用者 / 具体放置或操作 / 环境，判断依据、同类差异和证据边界；
- 仪式：文本 / 传统与时代、目的、执行者和对象、时间 / 地点 / 材料处理、动作与念诵顺序、步骤作用、结束、缺失及现代复原；
- 原典 / 手稿：实际内容、关键段落 / 词语、可靠译释、材料 / 神名 / 动作、版本差异与后世理解；
- 神明：放回具体宗教世界，用文本、形象和礼仪说明人们面对什么，不只列神职；
- 塔罗：具体问题、牌位、牌面条件与判断关系，真实反馈和解读分开。

原文、古人信仰 / 当事人声称、学者解释、后世传统、现代实践 / 复原与当前未知分别表达。原典“声称有效”不能改成实际有效；现代复原不自动替古代操作补齐。

完稿后暂时去掉修辞，检查完全不了解主题的读者能否说清“是什么、谁用、为什么、怎么用、在哪里、有什么证据、原文具体说了什么、哪些确定 / 未知”。资料缺项明确保留，不能为清单完整补造事实。问题回答清楚即可结束，不以篇幅代表价值。

## 四、完整执行

任务已经明确且没有真实阻塞时，专用对话默认自己完成：

1. 读取当前规则；
2. 确认核心答案有证据；
3. 完成必要研究；
4. 成稿；
5. 找素材 / 核查链接；
6. 文笔与交付 QA；
7. 自己修正明显问题；
8. 一次性交付完整成品。

不要做到一半停下来等 Suen 说“继续”。

不要把本可自行完成的搜图、原文定位、素材匹配、裁切建议、重复删除、排版修复转回给 Suen。

只有核心事实无法成立、缺少只有 Suen 才能提供的必要信息、或需要 Suen 做真实取舍时才提问。

## 五、长稿前内部门槛

长文、隐理、原典研究等，在完整写稿前先内部确认：

- 核心答案一句话能否说清；
- 主要证据分别支持什么；
- 哪些只是推测；
- 标题有没有承诺超过证据；
- 栏目路由是否正确。

证据不足时收窄题目或换题，不先写完整长稿再整篇返工。

## 六、交付前 QA

审核必须落到当前正文的具体句段，内部完成以下检查，不默认向 Suen 展示整张检查表：

1. **句子**：找出完整意思被拆碎、句法连续重复或读起来生硬的位置，修复后检查前后是否仍连贯。
2. **段落**：确认每段增加的知识或解决的问题；同一事实、结论的重复直接合并或删除。逐段检查末句：删去后是否少了具体事实、必要因果、证据边界或尚未讲清的判断？如果没有，删除，不再自动补一条总结或过渡；需要衔接时让下一句进入实际新增内容。
3. **解释**：核对正文提出的问题是否由后文回答，证据是否支持这层原因，是否把相似资料当成原因。
4. **返工**：把 Suen 已指出的缺陷对应到新版具体位置；有整稿级问题时，比较信息选择、解释关系和叙述顺序是否改变。仅删词或压短句，不能判为已经修好。

自然连接词、必要定义和归纳不按禁词表机械删除；选择局部修复或整稿重写，依据缺陷所在层级。

内部检查通过、技术文件完成、Suen 明确认可文笔是不同状态。认可状态回样本库核对；规则或流程修改成功不能据此宣布文笔问题已解决。

同时核对：

- 原始资料、古人信仰、学者解释与现代实践的边界，避免无证据拔高；
- 作者第一人称、连续否定、抽象空话与当前栏目语气；
- 口播按正常语速是否顺畅，运营优化是否带入营销号文风；
- 素材是否真实、对应、可用，交付格式是否完整，是否留下本可自行完成的半成品。

视频口播在脑内按正常语速完整读一遍；说不顺就改。

## 七、真实性

不得为了流量、神秘感、商业或补素材：

- 虚构历史、文物用途、原始文本；
- 把学者推测写成事实；
- 把现代重构反写成古代传统；
- 用 AI 图冒充真实历史资料；
- 虚构体验、客户反馈或功效。

## 八、用户指出“不对”时

先检查：规则有没有读对、执行有没有漏、证据是否支撑、文笔 QA 是否失败、交付格式是否漏。

不要先重新发明栏目理论、时长限制、多日准备期或更多临时提示词。

## 八-A、用户反馈进入长期规则的分流

Suen 对成稿的修改意见必须先判断属于哪一层，避免“所有反馈都永久化”与“换对话后全部丢失”同时发生。

### 1. 一次性任务反馈
只影响当前稿件 / 当前题，例如：
- 今天这张图不用；
- 这一篇删掉某个案例；
- 当前标题再短一点。

这类不写成长期规则。

### 2. 栏目长期反馈
明确适用于某一栏目 / 内容产品，例如：
- 《长卷》正文不要写成缩小版论文；
- 《异录》必须保持说书式故事推进；
- 《牌记》必须围绕具体牌局判断。

应修改对应栏目唯一真源，不复制到多个文件。

### 3. 跨平台长期反馈
明确是 Suen 对普遍文笔 / 成稿方式的长期要求，例如：
- 系统性 AI 组织方式；
- 同义复述；
- 抽象总结；
- 成稿交付前必须自己 QA。

应修改本文件或真正负责该主题的系统真源。

### 重复错误升级
同类错误第二次再次出现时，必须先检查：
1. 现有 GitHub 是否已经有明确规则；
2. 如果已有，定性为**执行故障**，修执行链，不新增重复规则；
3. 如果确实没有，而且 Suen 的反馈明显是长期要求，再修改唯一真源；
4. 不把一次性的当前稿件意见误写成永久规则。

目标是让反馈形成闭环，同时保持仓库单一真源和规则可维护性。

## 九、正式成稿最小读取

统一执行 `00-系统总控/规则读取验收协议.md` 的“正式内容”入口，不在此重复清单。视频口播使用口播内核；研究长文章与数据库按自己的正文要求生成。样本库为空时不能声称已有认可语感基线。

Suen 最新提供的通用写作文风规范覆盖旧示例中的作者第一人称、碎句、持续反驳及信息不足写法。长文每段应增加具体知识；资料缺少的使用方式、年代、动作等应明确未知，不能为了填满最低问题清单而补造事实。

## 十、统一文笔不等于统一栏目口吻

统一总则只负责共同底线，**不能把不同栏目写成同一种声音**。

正式成稿必须同时执行：

1. 统一文笔底线；
2. 当前栏目自己的文风 / 叙事 / 开头 / 结构规则；
3. 当天总控变量。

当“统一总则”和“栏目具体表达方式”同时适用时：

- 栏目具体的语气、叙事和结构补充共同底线；旧栏目示例与 Suen 当前已确认的作者第一人称、完整句子或事实边界要求冲突时，执行最新共同要求；
- 统一总则继续约束真实性、AI腔、重复、抽象空话、证据边界和完整执行；
- 不能为了统一文笔，把《异录》写成《残页》，把《辨伪》写成《隐理》，或把《牌记》写成研究论文。

七个大号栏目必须保留各自明显差异：

- **文物**：带着观众看真实对象，指哪里就讲哪里；
- **异录**：说书式真实故事，人物、事件、转折和画面感优先；
- **辨伪**：判断题，明确、轻松、朋友聊天感；
- **残页**：最高严谨度，从原页、具体行、词义和版本进入；
- **隐理**：解释实践机制，答案早出现，具体动作优先；
- **古术**：讲清历史宗教/魔法实际做法、使用问题与环境，必要解释随动作和资料推进；
- **牌记**：围绕具体牌局说明为什么这样判断；文章型正文沿用默认不使用作者第一人称的要求，个人经验表达按 Suen 当次明确指令处理。

“服务认知”是当天任务标签，不是独立文风或独立栏目。需要展示现实判断时，先服从实际承载它的栏目 / 平台：具体牌局回《牌记》，可证实的实践机制回《隐理》，纯个人判断 / 服务原则优先放小号、朋友圈或适合的小红书内容。

验收时如果一篇稿子只满足“没有 AI 味”，但失去了当前栏目的声音，仍然视为不合格。


## 十一、真人口语参照

自我介绍、朋友圈和真实工作现场中可核实的自然表达，可以帮助理解口语节奏；只有实际取得的文字或视频才能声称已参考。文章型正文仍执行共同文笔底线，完整认可成稿的语感参照统一读取样本库。

核心特征：

- 像人顺着想法直接说，不像提前写好的说明书；
- 允许自然停顿、转折、稍微绕一下再说清楚；
- 不为了“信息完整”把每一句都写成标准答案；
- 少用“第一、第二、第三”“我主要分成两部分”“所以这个账号会……”这类提纲式表达；
- 不强行把每段都收束成一句结论；
- 自然连接词按具体语境保留，不主动塞入口头禅；作者第一人称只用于 Suen 当次明确要求的个人表达；
- 专业感继续来自真实资料、具体经历、明确判断，不靠正式腔；
- 如果成稿读起来像品牌介绍、课程简介、AI整理稿，即使信息都对，也要继续改到像真人会说的话。

正式研究型长文仍按对应栏目规则执行，不机械套用口语化。

## 视频口播可说性硬规则｜2026-09-26

所有视频口播首先按“人实际要说出口”来写，不按资料卡、论文摘要或馆藏记录的写法直接搬进嘴里。

### 英文 / 外文
- 有自然中文名称时，口播优先说中文。
- 英文馆名、术语、拉丁文、希腊文、埃及语转写、英文类别名如果读起来会卡，不要求口播逐字念。
- 原词对证据重要时：**口播先说中文意思，原词放字幕 / 图片 / 来源里。**
- 馆藏页上的英文标题、考古地点代码、墓号、英文材料名不因为“资料完整”就强塞进口播。
- 不自行发明中文译名；没有稳定译名时，用普通中文解释它是什么，原词留在画面。

### 数字
- 馆藏号、登录号、长串编号默认留在图注 / 来源，不要求口播念。
- 年代优先说成自然中文，如“新王国时期”“大约三千多年前”“公元前十六世纪左右”；只有具体年份直接影响结论时才精确念。
- 尺寸只在“大小本身值得看”时进入口播，且一次只保留真正有用的数字。
- 一句话里不要连续塞“馆藏号 + 年代范围 + 尺寸 + 墓号”等多组数字。
- 数字书面上可以完整保留，口播允许改成更自然的近似范围，只要不改变事实结论。

### 实际讲话验收
正式交付前必须把口播按正常语速完整读一遍，并额外检查：
- 哪个英文词真实拍摄时容易卡；
- 哪串数字需要低头确认才能念；
- 哪句话像在念馆藏说明或论文摘要；
- 哪些信息观众看字幕就够了，不需要嘴里再念一遍。

出现上述情况，优先改口播，把精确信息留给画面、图注和来源。

**判断标准：如果 Suen 拿起手机直接录，这句话需要先练两遍才能顺下来，就还不是最终口播。**
