# Suen｜选题定稿硬门槛

状态：当前正式规则  
最后核对：2026-09-24

本文件只解决一件事：**一个候选题什么时候可以升级为正式题。**

适用于抖音大号，以及当天承担主要流量 / 精准涨粉任务的小红书、公众号前台题。

未通过只能写：

`候选题｜待筛选`

## 一、定题顺序

### 1. 先读动态状态

读取 GitHub 当前动态真源（内容台账 / 选题池 / 商业状态 / 天象预约池），确认：

- 当前主要瓶颈；
- 最近实际发布内容；
- 当前商业 / 天象状态。

### 2. 先看自己的数据

读取 `内容商业对标系统.md`。

确认：

- 相关第一方结构现在是单样本 / 重复信号 / 稳定结构中的哪一档；
- 当前主页已经被什么内容体验占据；
- 最近 7 天有没有明显重复。

这里的“最近 7 天重复”必须按**整个 Suen 内容系统**检查，不只看准备发布的那个账号。至少同时扫：

- 抖音大号；
- 抖音小号；
- 小红书；
- 最近实际发布的公众号 / 朋友圈（如果主题高度相关）。

重复不只看标题，还要看：

- 同一个核心问题词；
- 同一个现实判断场景；
- 同一个 Hook；
- 同一个答案中心；
- 只是换账号 / 换栏目后继续讲同一件事。

例如：小号刚发过“我对不顺的看法”，大号短期内再用“最近一直不顺，要不要净化？”作为主入口，默认按相邻体验重复处理，除非这次明确是有价值的后续、商业承接或新证据补充。

**同一支成片按计划同步到小红书，不算重复选题。** 这是一个生产单元的跨平台分发，不是两个独立新题。

如果确实要重复同一主题，必须能说清新价值：新对象、新证据、新判断任务或明确商业承接，而不是只换措辞。

低样本账号如果某一栏目 / 体验已经占多数，至少筛出 **1 个其它内容体验的合格候选**进行比较；最终仍选主导类型可以，但要有真实理由。

### 2.5 成片形态预演｜先看“做出来会像什么”

在正式栏目路由和评分前，必须先做一次极短的**成片形态预演**，不能只看标题像不像某个栏目。

至少写清：
- 前5秒观众看到 / 听到什么；
- 中段主要靠什么推进；
- 证据是主角还是只是支撑；
- 观众看完最应该记住什么。

然后做反向删除测试：

- 如果删掉某一页 / 某一段原文以后，整条内容基本塌掉，且中段主要是定位、翻译、逐段解释 → 更接近《残页》；
- 如果删掉某一件具体文物以后，题目基本不成立 → 更接近《文物》；
- 如果删掉具体来源，问题依然成立，多个材料都只是用来证明一个可明确回答的“为什么” → 才像《隐理》；
- 如果去掉人物与时间线以后故事失去主要价值 → 《异录》。

**标题里写“为什么”不等于《隐理》。**
**证据里用了原文也不等于《残页》。**
最终看成片实际由什么推进。

如果预演结果显示“标题是机制题，但生产时必然会被单一原典章节牵着走”，必须在P0前改题、改栏目或换候选，不能等成片做完才发现路由错。

### 3. 栏目路由

读取：

`01-抖音大号/栏目选题边界与路由.md`

按题目的**价值中心**路由，不先定栏目再硬改题。

### 4. 外部对标

长期 benchmark 方法参与判断；当天第一次定新前台题时实际刷新最相关 2—3 个近期样本。

无法可靠取得就明确降级，不编造。

### 5. 100 分模型

正向评分：

- 陌生人理解速度：20
- 视觉奇异度：15
- 答案反差：15
- 证据强度：15
- Suen 差异化：10
- 精准受众价值：10
- 商业桥接：5
- 制作效率：10

制作效率看：

- 历史耗时；
- 素材是否现成；
- 是否能抖音 + 小红书复用；
- 返工风险；
- 是否能沉淀长期资产。

扣分 / 淘汰：

- 最近相邻题材 / 观看体验明显重复：-20（按整个内容系统检查；换账号 / 换栏目不自动消除重复）
- 需要大量背景解释：-10
- 标题专业但普通人不知道在讲什么：-20
- Hook 很猛但正文答案空：-20
- 与付费课程核心教学链高度重合：谨慎，必要时换角度或淘汰
- AI 伪史、AI 假文物、AI 假实景、核心事实无法核实：直接淘汰

分数使用：

- 80+：强前台 / 流量候选
- 70—79：结合当天瓶颈判断
- 60—69：更适合精准 / 窄题材
- <60：通常不占大号当天唯一主发布位

分数不能覆盖栏目资格、证据可答性、主页结构和当天真实瓶颈。

### 5.5 题目范围匹配

在证据检查前确认：

- 标题范围不能大于证据范围；
- “有些 / 通常 / 这类 / 为什么会”这类泛化表述必须有对应范围的材料支撑；
- 当前只有单一作者 / 单一文本时，优先缩到该作者 / 体系 / recipe，不允许为了入口更宽而扩大结论；
- 《隐理》若主要依赖一个具体文本，必须再次做栏目复核。

### 6. 证据与素材

正式定题前必须确认：

- 核心答案能被可靠资料正面支持；
- 标题没有承诺超过证据；
- 真实图片 / 原页 / 文物 / 历史画面可取得；
- 不依赖 AI 假史料；
- 制作复杂度与当天 P0 工作量匹配。

### 7. 商业边界

如果题目涉及产品 / 服务，读取当前商业信号规则和 `08-动态运行/商业/当前商业状态.md`。

内容先成立，再决定今天是否需要商业桥。

### 8. 发布前验证

新的正式前台内容原则上只写 **1 个主要验证假设**。

读取：

`内容实验与验证规则.md`

至少写：

```text
主要验证：
主任务：A / B / C / D
主要观察指标：
对照基线：最近最可比样本 / 无可靠可比样本
```

时效通知、已确认商业动作或稳定结构复用可以写：

`无新增实验｜执行稳定结构`

### 9. 可选｜定题后的塔罗流量盲测

只有题目已经通过前面 1—8 的数据、对标、栏目、证据、素材与商业硬门槛以后，才可以进入塔罗测试。

固定顺序：

**理性定题 → 锁定题目 / 平台 / 基线 → 抽牌 → 发布前锁定判断 → 发布 → 真实数据后验。**

完整协议读取：

`Tarot Judgment Rules/16-内容流量盲测与后验.md`

硬边界：
- 塔罗不参与前面的候选生成和证据筛选；
- 牌面不能把未通过硬门槛的题“救活”；
- 牌面不能覆盖事实、平台合规、版权、栏目资格或真实商业状态；
- 如有多个同样通过硬门槛的高质量候选，可把塔罗作为附加比较 / 盲测层，但必须保留原始内容数据判断；
- 发布以后必须按事前定义的统计窗口验收，不允许看结果再改“什么叫爆”。

## 二、最终通过条件

以下全部成立才进入正式生产：

- [ ] GitHub 当前动态真源已读取
- [ ] 当前瓶颈已判断
- [ ] 第一方历史信号已检查
- [ ] 当前主页 / 近 7 天跨账号、跨平台重复已检查
- [ ] 低样本账号需要时做过跨体验候选比较
- [ ] 成片形态预演已通过
- [ ] 栏目路由正确
- [ ] 长期 benchmark + 当日近期样本已完成或明确降级
- [ ] 100 分模型已检查
- [ ] 题目范围 ≤ 证据范围
- [ ] 核心答案证据成立
- [ ] 真实素材可取得
- [ ] 商业边界真实
- [ ] P0 工作量可完成
- [ ] 主要验证假设已写或明确无新增实验
- [ ] 如本轮启用了塔罗流量盲测，题目 / 平台 / 基线 / 统计窗口 / 判断已在发布前锁定

如果当天没有任何候选完整通过以上条件，结论就是：

`今天没有合格的大号P0`

允许改做其它平台 / 其它任务。**不得因为当天需要发布、已经投入时间、某栏目近期没发或某个候选商业上很顺，就降低硬门槛。**

通过后只需对 Suen 显示：

`选题状态：已通过硬门槛`

不默认展示完整评分表。

## 三、通过后进入生产保护

确定：

- 栏目 / 内容产品
- 题目
- 核心问题
- A / B / C / D
- 商业边界
- 主要验证

以后进入生产保护。

只有核心事实 / 证据、栏目路由、商业 / 天象 / 法律硬边界、Suen 新补充的真实账号结构或 Suen 最新指令发生变化时，才退回重新定题。

普通文笔、图片、链接、排版、素材匹配由专用对话自行修。
