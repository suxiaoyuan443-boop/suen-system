# Suen｜选题定稿硬门槛

状态：当前正式规则
最后核对：2026-09-18

本文件解决一个执行问题：**总控不得因为“已经想到一个看起来不错的题”就直接把它写成最终选题。**

从现在开始，所有抖音大号正式选题，以及承担当天主要流量 / 精准涨粉任务的小红书、公众号前台题，在被写成“最终选题 / 今日正式题目”以前，必须完成下面的硬门槛。

如果任何必检项没有完成，这个题只能写成：

> 候选题｜待筛选

不得：

- 写成“最终题目”；
- 生成正式专用对话执行提示词；
- 写入 Slack 当日执行表作为已定题目；
- 因为当天赶时间就跳过检查。

---

## 一、先确认栏目路由

先读取：

`01-抖音大号/栏目选题边界与路由.md`

确认题目的价值中心确实属于当天栏目。

禁止先决定栏目，再把题目硬改成该栏目形式。

例如《隐理》必须额外通过：

1. 去掉具体文物 / 人物 / 单条 recipe 后，问题仍然成立；
2. 标题里的“为什么”能够被现有证据真正回答成“因为 Y”；
3. 文物、原文和案例只负责证明答案，不代替答案。

---

## 二、先看 Suen 自己已经验证过什么

外部 benchmark 不能排在 Suen 自己的真实历史数据前面。

在查看外部对标以前，先读取当前可取得的第一方历史样本，包括：

- 抖音大号已发布内容及复盘数据；
- 抖音小号已经验证过的**内容类型 × 入口结构 × 内容形式**；
- 小红书已经验证过的题目结构与精准涨粉表现；
- 公众号贴图 / 长文已经出现的入口信号；
- 评论、主页访问、涨粉、收藏、分享、询盘等能够说明真实受众反应的数据。

优先回答：

- Suen 自己哪些**题目结构 / 观看体验 / 入口结构**已经被真实数据验证；
- 哪些只是互动好看，但没有涨粉 / 收藏 / 主页访问；
- 哪些能够吸引精准受众；
- 哪些形式在不同平台表现差异很大；
- 同一主题换成视频 / 图文后，平台反馈有没有明显变化；
- 当前候选题是在扩展一个已验证结构，还是只因为外部账号最近也在做类似内容。

### 第一方数据使用原则

- **Suen 自己的真实数据优先于外部账号经验。**
- 保存和复用的是题目结构、观看体验和入口逻辑，不机械复刻旧题。
- 小号表现好的题可以证明某种问题结构值得验证，但大号若采用同类方向，仍需重新经过大号栏目路由、证据与制作规则。
- 小号历史样本比较时，先尽量在**相近内容形式 / 相近统计窗口**内比较，再跨类型总结；图文划走率与视频完播 / 2 秒跳出率不得直接互比。
- 单条爆款不能自动成为永久公式；需要结合其它相近内容、发布时间、统计窗口和平台差异判断。
- 如果第一方历史数据不足，才更多依赖外部 benchmark 补视野，不反过来让外部对标覆盖真实自有数据。

## 三、对标检查｜长期五维 + 当日近期样本

读取：

`00-系统总控/内容商业对标系统.md`

对标分成两层，不能混为一件事。

### A｜五个长期 benchmark 方法都要参与判断

每个候选题都要经过以下五个长期方法维度：

1. **穹印之源｜中文入口**
   - 中文普通观众第一眼能不能懂题目；
   - 标题是不是具体问题，而不是论文式概念；
   - 硬核资料有没有被包装成一个有吸引力、但不夸大的入口。

2. **ESOTERICA / Justin Sledge｜证据与学术组织**
   - 有没有真正能支撑核心答案的原典、手稿、文物或可靠研究；
   - 历史事实、文本内容、学者解释和争议有没有混在一起；
   - 资料密度高时，普通观众能不能跟上。

3. **Angela’s Symposium / Angela Puca｜source-based 品牌**
   - 是否强化 Suen 的“真实资料 + 研究解释”识别；
   - 是否以来源为基础，而不是用现代 occult 常识代替历史证据；
   - 是否有长期精准受众价值。

4. **Foolish Fish｜商业连接**
   - 如果当天需要商业承接，连接是否自然；
   - 如果当天是纯内容，是否保持纯内容；
   - 题目本身是否先成立为内容，而不是广告包装。

5. **Let’s Talk Religion｜复杂问题的大众化解释**
   - 能不能从一个具体问题进入复杂历史 / 宗教 / 仪式背景；
   - 是否需要大量前置知识；
   - 专业术语是否真的被解释。

这五项是**长期方法检查**，不等于每天必须把五个账号的最新主页全部刷一遍。

### B｜每天第一次前台定题要刷新最相关的 2—3 个近期样本

每个 Asia/Shanghai 运营日第一次需要确定新的前台题目时：

- 根据当天 A / B / C / D 任务和瓶颈，选择最相关的 2—3 个对标账号；
- 实际查看近期可取得的创作样本，默认优先最近约 7—30 天；
- 同一运营日内已经刷新过、任务没有变化，可以复用，不重复搜索；
- 不机械平均检查五个账号的最新内容。

近期样本重点看：

- 最近的题目类型；
- 标题入口；
- 第一屏 / 开头；
- 内容结构；
- 原始资料 / 案例数量；
- 新系列 / 新形式；
- 商业信息位置和密度。

如果近期内容无法可靠取得：

- 标记 `近期样本未可靠取得`；
- 不得把长期印象冒充“刚看过最近内容”；
- 可以换查另一个相关对标；
- 如果整体近期样本不足，当天对“近期趋势”的判断降级，但不能编造。

**近期样本只用于提取方法，不直接复制题目。**

## 四、Suen 100 分模型

完成第一方历史检查和对标检查后，再按 `商业总控.md` 的 Suen 100 分模型评分。

必须检查：

- 陌生人理解速度；
- 视觉奇异度；
- 答案反差；
- 证据强度；
- Suen 差异化；
- 精准受众价值；
- 商业桥接；
- 制作效率；
- 最近 7 天相邻题材 / 观看体验重复扣分。

分数不能代替栏目资格和对标检查。

一个题即使 80+，如果栏目路由错误或核心“为什么”答不出来，也不能定稿。

---

## 五、先看这个账号现在已经是什么样子

选题不能只看“这一个题够不够好”，还必须看**当前账号主页已经存在什么内容**。

对抖音大号尤其执行：

- 定题前先确认当前账号已经实际发布了哪些前台栏目 / 内容类型；
- 看当前主页给陌生人的第一印象是否已经过度集中在某一个栏目、文化或观看体验；
- 如果账号仍处于早期、实际发布样本很少，优先查看**当前全部已发布内容**，不能只看最近 3—7 天；
- 如果现有少量内容几乎全部来自同一栏目，下一条再选同栏目时必须额外说明为什么继续重复仍然比引入第二种内容体验更值得；
- 当两个候选题质量、证据和流量潜力接近时，优先选择能够补全账号前台认知的那一个。

### 低样本账号必须做跨内容体验候选比较

如果账号仍处于低样本阶段，并且当前主页已经被某一种栏目 / 观看体验明显占据：

1. 不能只生成同一主导类型的候选题；
2. 最终定题前，至少实际筛出 **1 个来自其它栏目 / 其它观看体验的合格候选** 与主导类型候选比较；
3. 比较至少看：题目强度、证据、流量潜力、制作成本、当前瓶颈和对主页认知的影响；
4. 如果最终仍选择主导类型，要能说明它为什么明显强于跨类型候选；
5. 如果经过真实筛选后其它类型没有合格候选，可以保留同类型强题，但不能跳过比较过程。

这里的目的不是轮播，而是避免“先找到一个不错的同类题 → 再给继续重复找理由”的路径依赖。

这里检查的是**主页内容结构和观众对账号的整体认知**，不是要求七个栏目机械轮播。

允许连续发同一栏目，只要存在明确理由，例如：

- 该栏目当前正在产生明显更强的真实数据；
- 有强时效 / 商业 / 资料机会；
- 其它候选题证据或制作条件明显较弱；
- 连续内容虽然同栏目，但实际观看体验和品牌认知并不重复。

禁止为了“栏目平衡”发布弱题；也禁止完全不看账号已有内容，导致一个新账号连续被同一栏目定义。

如果 Slack 台账对当前账号早期历史记录不完整，而 Suen 当次明确补充了真实已发布内容，以 Suen 最新明确事实为准，并在后续台账中补齐需要长期参考的发布事实。

## 六、近 7 天重复与当天瓶颈

在完成账号整体结构检查后，再回看 `#内容历史台账` 最近 3—7 天：

- 是否连续看同一类资料页 / 文物 / 原文；
- 是否连续出现相似死亡、古埃及、咒语等体验；
- 当前真正瓶颈是流量、精准涨粉、服务认知、询盘还是成交；
- 候选题是否解决当天瓶颈，而不是只因为“这个题有意思”。

**账号整体结构检查**与**最近 7 天重复检查**是两件事：前者解决“主页现在像什么账号”，后者解决“最近观众是不是连续看同一种体验”。两项都必须做。

---

## 七、核心答案与素材可行性

在定题前先确认：

- 核心答案能够被可靠资料正面支持；
- 标题里的问题不会超出证据能回答的范围；
- 真实图片 / 原页 / 文物 / 历史画面可以取得；
- 不依赖 AI 假文物、假历史实景或无来源网图；
- 制作复杂度不会明显挤垮当天 P0 生产任务，除非该题有足够高价值且总控明确接受成本。

---

## 八、主要验证假设｜进入生产前必须完成

新的正式前台内容在最终定题后、进入生产保护前，原则上只写 **1 个主要验证假设**。

完整执行：`00-系统总控/内容实验与验证规则.md`。

至少确认：

- 假设在看到结果以前写好；
- 只验证一个主要变量或一个明确组合，不把标题、时长、栏目、画面、CTA 等全部拆成多个“实验”；
- 主要观察指标与当天 A / B / C / D 主任务一致；
- 有可靠可比样本时写对照基线，没有时明确写“无可靠可比样本”；
- 时效通知、已确认商业动作或纯稳定结构复用，可以写 `主要验证：无新增实验｜执行已验证稳定结构`，不强行制造实验。

主要验证假设用于发布后学习，不得为了实验增加制作负担，也不得反向推翻已经通过的强题。

## 九、最终定题与生产门槛

只有下面全部为“是”，才允许写“最终选题”并进入正式生产：

- [ ] 最新 Slack 三个核心频道已按工作流读取；
- [ ] 当前瓶颈已经判断；
- [ ] Suen 自己相关的历史有效内容 / 题目结构已检查；
- [ ] 当前账号已有内容 / 主页结构已经检查；
- [ ] 如果账号样本很少，已经查看当前全部已发布内容而不是只看近 7 天；
- [ ] 如果低样本账号被单一栏目 / 观看体验明显占据，已经实际做过至少 1 个跨内容体验合格候选比较，或明确记录其它类型没有合格候选；
- [ ] 栏目价值中心路由正确；
- [ ] 五个长期 benchmark 方法已参与判断；
- [ ] 当天最相关 2—3 个近期对标样本已刷新，或已明确记录近期样本无法可靠取得；
- [ ] Suen 100 分模型已检查；
- [ ] 最近 7 天内容体验重复度已检查；
- [ ] 核心答案能够被可靠资料正面支持；
- [ ] 商业密度与当天任务一致；
- [ ] 制作素材真实可取得；
- [ ] 该题与当天 P0 工作量匹配；
- [ ] 新的正式前台内容已经写好发布前主要验证假设，或明确记录“无新增实验｜执行已验证稳定结构”；
- [ ] 主要观察指标与 A / B / C / D 主任务一致，未用无关指标替代目标。

只要有一项未完成：

> **候选题不得升级为最终题，也不得进入生产保护。**

## 十、通过以后进入生产保护

一旦题目通过本硬门槛，并且已经确定：

- 栏目 / 内容产品；
- 题目；
- 核心问题；
- A / B / C / D 主任务；
- 商业边界；
- 主要验证假设 / 无新增实验说明；

则进入 `00-系统总控/总控简化与生产保护规则.md` 定义的**生产保护状态**。

之后总控不再因为非阻塞性的“再深一点 / 再换一种理论 / 再多做一个平台版本”随意推翻已经通过的题目。

只有事实、核心证据、栏目路由、商业 / 天象硬边界、**Suen 新补充的真实账号内容结构**或 Suen 最新明确指令发生真实变化时，才退回重新定题。

---

## 十一、Slack 与对话输出规则

内部完整检查可以很详细，但正常稳定日对 Suen 不需要展开全部过程。

默认只显示：

`选题状态：已通过硬门槛`

需要记录在 Slack 时可使用：

`选题硬门槛：已完成｜自有历史样本 + 账号结构 + 跨内容体验比较（低样本适用） + 栏目路由 + 五个长期对标方法 + 当日近期样本 + 100分模型 + 近7天重复度 + 证据可答性 + 发布前主要验证假设`

如果没有完成，只能写：

`候选题：待完成选题硬门槛，不进入执行`

只有 Suen 明确要求、某项未通过、当天发生规则冲突或执行故障需要定位时，才展开详细检查表。
