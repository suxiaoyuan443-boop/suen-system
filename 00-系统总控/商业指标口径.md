# Suen｜商业指标口径

状态：当前正式规则
最后核对：2026-09-25

本文件统一当前商业目标的统计口径，避免“有效询盘 / 成交 / 利润”在不同对话、不同平台或不同复盘中被重复计算。

具体目标数字仍读取 `商业目标与产品优先级.md`；本文件只规定这些数字**怎么算**。

---

## 一、有效询盘

有效询盘的资格继续服从 `07-销售与运行/客户商业记录规则.md`。

通常至少出现一项明确购买行为：

- 问具体服务 / 产品；
- 问价格；
- 问能否执行；
- 提供与购买决策直接相关的需求；
- 继续推进时间、方案、预约、付款等细节。

单纯点赞、表达兴趣、问免费资料、普通学术讨论、抽奖消息不自动算有效询盘。

### 去重

同一客户围绕**同一购买需求**的连续沟通，只计 1 个有效询盘，不因：

- 连续发多条消息；
- 同一天多次追问；
- 从评论转私信；
- 从小红书转微信；
- 同一需求跨平台继续沟通

重复累加。

如果无法确认两个记录是不是同一客户 / 同一需求，不为了冲 KPI 强行重复计数；先保留为待核对。

同一客户以后出现一个明显独立的新购买需求，可以作为新的商业机会单独记录，但是否进入当前“有效询盘数”累计必须基于真实独立需求，不把同一单拆成多单。

---

## 二、成交

成交必须有真实交易事实。

至少满足：

- 已发生实际付款或已确认交易成立；
- 产品 / 服务和金额能够真实对应；
- 不是“有购买意向 / 口头答应 / 已报价 / 等会付款”。

未付款不得记成交。

如果只支付定金、预付款或部分款项：

- 先按真实状态写 `已付定金 / 已付部分款`；
- 是否计入完整“成交数”，以该业务真实成交约定和 Suen 最新明确口径为准；
- 在没有明确口径时，不自行把部分付款当成完整成交 KPI。

同一订单的补款不重复增加成交笔数。

复购 / 追加购买如果确实形成新的独立订单，可以单独记录，同时标明客户关系。

---

## 三、报价

报价是漏斗阶段，不等于成交。

需要区分：

- 未报价；
- 已报价；
- 客户继续沟通；
- 已付定金 / 部分款；
- 已成交；
- 已取消 / 已退款（如实际发生）。

讨论“价格大概多少”但尚未给出实际报价，不擅自记成已正式报价。

---

## 四、成交金额 / 收入

成交金额记录真实交易金额，不拿报价金额代替实际成交金额。

如果发生：

- 折扣；
- 补款；
- 退款；
- 取消；
- 平台退款 / 售后调整

应按真实交易变化更新，不保留一个已经失真的原金额继续累计。

同一笔订单的多次付款，应避免把每次付款都当成新的成交额重复相加；最终以该订单实际净收款事实为准。

---

## 五、实际总回款与外部市场回款

为了同时看真实现金收入和市场验证，商业复盘允许并行保留两种回款口径：

### 实际总回款

统计周期内所有真实发生、未被退款冲销的实际收款都计入，包括熟人本人真实购买。

它回答的是：

**这个月实际收到了多少钱。**

### 外部市场商业回款

用于观察市场验证时，单独统计来自真实商业客户的回款，例如：

- 平台陌生流量；
- 老客户；
- 搜索；
- 师父 / 朋友等转介绍来的第三方客户；
- 其它能够确认属于真实市场购买关系的客户。

Suen 的私人熟人本人购买，例如朋友本人、伴侣本人直接购买，可以计入实际总回款，但**不用于证明陌生市场已经跑通、内容获客已经成立或某个价格已经被外部市场验证**。

“朋友转介绍来的另一位客户”和“朋友本人购买”必须区分；前者可以属于外部市场商业结果，后者只进入实际总回款。

来源无法可靠确认时，只记录实际收款事实，不为了填市场验证口径强行分类。

## 六、预计毛利与净利润必须分开

### 预计毛利

通常可理解为：

`实际成交收入 - 已知直接材料 / 执行成本`

只有直接成本足够明确时才记录。

### 净利润

净利润继续保留为经营质量指标，但**当前 Q4 / 12月硬目标不是“月净利润 ≥ ¥4000”**；该旧短周期 KPI 已取消。当前收入目标统一读取 `商业目标与产品优先级.md`，目前为 2026年12月当月实际收入 / 回款至少 ¥2000。

无论是否存在净利润目标，都不能把“预计毛利”直接当成“净利润”。

只有在相关成本覆盖足够完整时，才可以报告为净利润进度。可能影响净利润的项目包括但不限于：

- 材料成本；
- 包装 / 快递；
- 平台手续费；
- 支付手续费；
- 外包 / 制作成本；
- 广告 / 推广支出（如实际发生）；
- 退款 / 售后损失；
- 其它明确属于当前经营周期的必要成本。

如果这些数据不完整：

- 可以汇总 `已知成交额`；
- 可以汇总 `预计毛利 / 已知利润贡献`；
- **不得把它直接写成“当前净利润”。**

复盘时应明确：`净利润数据覆盖不完整`，直到真实成本足够支持计算。

## 七、来源与归因

询盘 / 成交需要尽量保留：

- 来源平台；
- 对应具体内容（能可靠确认时）；
- 产品 / 服务；
- 新客 / 复购 / 转介绍。

只能确认平台时，只归因到平台；不能确认具体内容时，不因为发布时间最近就强行归因。

同一商业结果不得同时算作两条内容各自“带来 1 个成交”。

如果一次成交确实受多条内容共同影响，可以在复盘里写“多触点”，但 KPI 仍只计真实的一次商业结果。

---

## 八、周期进度的报告方式

报告当前阶段进度时，优先使用：

- 有效询盘：已确认唯一询盘数；只有当前目标文件确实设置询盘目标时才显示“/目标”；
- 成交：已确认成交数；只有当前目标文件确实设置成交目标时才显示“/目标”；
- 当月实际收入 / 回款：当前目标文件设置收入目标时，与该目标对照；
- 已知成交额；
- 预计毛利 / 已知利润贡献；
- 净利润：只有数据覆盖足够完整时才给正式数值，不自动当成当前硬 KPI。

不得为了填满目标看板而估算缺失商业数据。

阶段目标过期后继续服从 `商业目标与产品优先级.md` 的到期规则，不自动续期。

## 九、获客内容与首次付费的新增观察口径

为了判断“精准内容 → 询盘 → 首次付费 → 高客单”是否真实成立，后续在数据能够可靠取得时增加以下观察，不把缺失数据补成估算值：

- 内容对应的主页访问；
- 有效询盘数；
- 首次真实付款人数 / 订单；
- 首次付款所购买的服务类型；
- 后续是否产生独立的更高客单服务购买；
- 复购与转介绍。

### 内容商业效率

能可靠归因时，可以计算例如：

- 每 1000 次播放 / 曝光产生的主页访问；
- 每 1000 次播放 / 曝光产生的有效询盘；
- 每 1000 次播放 / 曝光产生的首次付款。

这些指标用于区分“增长资产”和“获客资产”，不要求每条内容同时在两类指标上优秀。

无法确认某个询盘 / 成交来自哪条内容时，只归因到能够确认的平台或记为多触点 / 未知，不为了证明获客模型而强行归因。

### 首次付费 → 后续高客单

同一客户先购买塔罗、咨询、具体问题判断或其它低门槛服务，之后又形成独立高客单订单时：

- 两笔真实订单分别按实际交易记录；
- 客户层面额外标记为“首次付费后升级 / 后续购买”；
- 不把第二笔订单倒算成第一条内容直接带来的高客单成交，除非归因证据充分。

这项数据用于验证低门槛服务是否真的承担有效的信任 / 诊断入口，而不是预设它一定能提高高客单成交。
