# Suen｜总控简化与生产保护规则

状态：当前正式规则
最后核对：2026-10-07

本文件解决一个问题：商业总控需要足够严谨，但不能把内部检查、系统维护和提示词复杂度继续转嫁给 Suen，也不能因为优化系统而导致当天内容没有真正发布。

## 一、总控只负责五件事

每天“更新”以后，总控只负责：

1. 判断当天最主要瓶颈：流量 / 精准涨粉 / 服务认知 / 询盘 / 成交；
2. 决定当天任务优先级；
3. 完成选题定稿与商业边界；
4. 把最少必要变量交给专用对话；
5. 确保当天主要生产任务真正完成，不让非阻塞性系统维护打断生产。

总控不替专用栏目重新写长期规则，不替栏目发明新的内容理论，不把内部检查表全部展示给 Suen。

---

## 二、P0 / P1 / P2 生产优先级

当天任务按实际价值与工作量分三层。

### P0｜今天必须先完成

当天最重要的生产单元。

当前默认先保护：

**1 份需要重新剪辑的主视频生产单元。**

通常由抖音大号承担。小红书独立判断当天平台任务：
- 适合同题时复用同一支完整成片；
- 不适合时优先图文 / 已有真实素材 / 《长卷》；
- 只有独立第二支视频明显值得额外制作成本且当天工作量允许，才新增第二支视频。

平台独立判断，不等于默认双倍剪辑。

P0 未完成前，不因为“顺便优化系统”“再补一篇内容”“再做一个附件”等非阻塞性任务打断主生产。

### P1｜完成 P0 后值得做

有明确品牌、流量、搜索、商业或资产价值，而且当天工作量允许的任务。

例如：

- 公众号贴图；
- 有强题时的公众号长文；
- 当天确有必要的朋友圈商业 / 工作记录。

### P2｜有余力再做

没有当天硬价值、不影响主要经营目标、可以顺延的任务。

例如：

- 抖音小号普通更新；
- 非紧急系统整理；
- 不影响当天发布的仓库美化 / 文档整理。

P2 不得挤占 P0。

---

## 三、选题通过以后进入“生产保护状态”

当下面五项已经确定：

- 栏目 / 内容产品；
- 题目；
- 核心问题；
- A / B / C / D 主任务；
- 商业边界；

并且已经通过 `选题定稿硬门槛.md`，该任务进入**生产保护状态**。

进入生产保护状态后：

- 总控不再中途给栏目追加新的抽象理论；
- 不再临时改变栏目长期时长；
- 不再因为“也许更深”而要求整篇推翻重写；
- 不再把非必要的平台优化扩展成第二个完整制作任务；
- 专用对话按自己当前正式规则完成研究、成稿、素材、QA 与交付。

只有以下情况允许退出生产保护、退回重新定题：

1. 核心事实 / 原典证据明显不成立；
2. 核心问题无法被现有可靠证据真正回答；
3. 题目被发现路由到了错误栏目，且继续制作会导致整条内容价值中心错误；
4. 商业 / 天象 / 法律或平台硬边界出现真实阻塞；
5. Suen 明确改变当天任务。

普通文笔问题、图片匹配问题、排版问题、链接问题不属于重新定题理由，应由执行对话自行修好。


## 三-A、口播返工诊断与收敛机制｜2026-09-28

来源后验：2026-09-27《行星星符图都画好了，为什么还不能做？》在选题已经通过硬门槛后，专用对话至少产生6个口播版本，最终未发布。

Suen随后明确纠正：这次返工不能简化成“表达层小修被放大”。主要存在两个**整稿级缺陷**：

1. **机制理解错误 / 深度不足**：稿子只浅层解释标题，停在“文本要求择时 / 要看行星日、行星时、位置”等操作条件，没有真正回答《隐理》要求的“这个传统为什么认为这一步会起作用、天体状态为什么会进入图像制作机制”；
2. **系统性AI文风**：问题不是某几句话，而是整篇的句式、组织、重复、抽象总结和推进方式都不像Suen认可的真人口播。

因此正确规则不是“AI感只能局部修”，也不是“超过两版就禁止整稿重写”。

### 先判断缺陷层级

#### A｜整稿级缺陷

以下任一项成立，可以、而且通常应该整篇重写：
- 核心机制理解错；
- 只回答操作步骤，没有回答栏目真正的“为什么”；
- 结构从根上没有围绕正确价值中心推进；
- 标题承诺的深度明显高于正文；
- 整篇都呈现系统性AI文风，而不是局部措辞问题；
- 全文主要依赖同一种AI句式、连续总结、抽象概括、机械排比或重复换词；
- 整体语感与已确认合格的旧《隐理》明显不一致。

这类问题不能靠“修几句”假装解决。

#### B｜局部缺陷

例如：
- 单独一句不自然；
- 某一段重复；
- 个别术语难懂；
- 一处转折生硬；
- 结尾一句不明确；
- 某张图或某条来源错误。

如果全文机制、结构和整体语感已经成立，才采用局部修复，并锁定其它已经合格的段落。

### “太AI”必须先判断是局部还是系统性

Suen说“很AI / 整篇都很AI”时，不得自动理解成“只改几个词”。

必须检查：
- 是否整篇都在用相同句式；
- 是否段段都像“观点—解释—总结”模板；
- 是否大量使用抽象名词代替具体动作；
- 是否不断重复“所以 / 真正 / 本质上 / 也就是说”；
- 是否虽然事实正确，但整体不像真人自然讲话；
- 是否只换词，原来的AI组织方式仍然没变。

如果是系统性问题：
**整篇重写。**

### 多次重写后的处理

如果已经发生2次以上整稿重写，不是停止整稿重写，而是必须先做**根因诊断**：

- 机制理解是否仍然错；
- 是否没有读取/理解栏目“机制深挖硬规则”；
- 是否没有参考已确认合格的旧《隐理》语感；
- 是否每次只做同义改写，没有真正改变结构；
- 是否上一轮用户明确指出的问题在下一版又复发。

只要整稿级缺陷仍然存在，就继续整稿重写，直到合格。

但下一版必须针对根因改变，不能生成“同一套AI结构的第7个同义版本”。

### 专用对话的责任

正式把成稿交给Suen前，专用对话必须自行完成两道内部验收：

1. **机制验收**
   - 一句话能否回答“为什么”；
   - 是否已经从操作条件继续追到该传统自己的作用机制；
   - 是否把择时、行星时、位置等“操作表现”误当成机制答案；
   - 是否有证据支撑到当前解释深度。

2. **真人口播验收**
   - 读取1—2条Suen已经认可 / 已发布的旧《隐理》作为节奏参照；
   - 检查整篇是否存在系统性AI组织方式；
   - 正常语速朗读；
   - 整篇不像真人说话时，内部重写后再交付，不把明显不合格版本交给Suen做第一轮QA。

### 生产保护真正保护什么

生产保护不等于“限制必要重写”。

它保护的是：
- 不让非阻塞系统工作打断P0；
- 不让已经确认正确的事实和结构被无故反复推翻；
- 不让同一个已知问题在多个版本里反复出现；
- 让专用对话自己消化规则和QA，而不是把6版试错成本转给Suen。

如果机制和整篇文风确实不合格，**重写本身是正确动作**。

9/27的生产失败应理解为：
**首轮成稿质量门没有拦住整稿级缺陷 + 后续虽然最终收敛到正确机制与真人文风，但收敛发生得太晚，挤压了录制 / 剪辑 / HTML / 成片所需时间，最终吞掉发布窗口。**

## 三-B、正式生产首稿质量门｜2026-10-07

来源后验：2026-10-07 同一批正式生产中，出现：
- 《文物》首版HTML生成后才被 Suen 判定“文笔不符合要求”；
- 《隐理》首版HTML生成后才被 Suen 判定“还是有点AI / 不够深”；
- 《残页》正式生产至少三次需要 Suen 手动发送“从暂停的地方继续”；
- 《异录》多次出现“史实成立但不像完整奇妙小故事”的正式成品。

因此增加以下执行门，不新增用户操作负担。

### 1. 选题通过 ≠ 成品通过

状态必须分开：
- **选题通过**：允许进入正式研究 / 写作；
- **成品已生成｜待验收**：已有HTML / 素材，但不等于质量确认；
- **成品合格**：当前成品已经实际通过栏目、机制 / 故事、真人文笔和素材QA，且没有尚未处理的 Suen 明确负反馈。

只要 Suen 对当前版本明确说“文笔不符合 / 很AI / 机制浅 / 不像故事 / 无聊 / 栏目不对”，该版本立即失去“成品合格”资格，不能继续在台账或QA里保留“已通过”的表述。

### 2. HTML 是最后包装层，不是质量证明

正式生产内部顺序固定为：
1. 研究 / 核证；
2. 形成完整口播；
3. **先做栏目核心验收 + 真人文笔验收**；
4. 通过以后再做正式素材配对 / 下载 / Base64；
5. 最后生成HTML并做技术QA。

第3—5步仍由专用对话在同一次正式生产中自行完成，不要求 Suen 先审一版口播，也不恢复多轮确认流程。

禁止：
- 因为已经找到图片就提前生成HTML；
- 用“HTML已完成 / 图片已内嵌”掩盖正文仍像资料卡、论文摘要或AI整理稿；
- 已知要整稿重写时继续维护旧HTML结构。

### 3. 内部QA不得冒充用户验收

内部文笔检查按 `Suen统一文笔总则.md` 第六节执行，必须检查当前句段、段落新增信息、问题与答案的关系，以及已有负反馈在新版中的处理。检查内容默认留在后台，不增加 Suen 的逐句验收负担。

专用对话只有完成对应检查后才可以写“内部QA：通过 / 技术QA：通过”，不得把没有经过用户确认的主观质量项写成“用户已确认文笔通过 / 成品已验收”。规则文件已修改、禁词已删除、HTML已生成，分别只证明这些动作发生过，不能据此宣称文笔问题已解决。

尤其当同一题上一版已经被 Suen 明确否决时，新版在用户再次确认前，状态最多为：**返工版已生成｜待验收**。

### 4. 已有明确负反馈时，必须先吸收再重做

- “文笔不符合要求” → 先改变整篇组织方式，再写；
- “有点AI” → 检查是否为系统性AI结构，不做同义替换；
- “机制不够底层” → 重新研究机制链，不从原任务提示词继续扩写；
- “不像故事 / 无聊” → 先重新判断选题与故事胚子，不靠加转折词救稿。

### 5. 正式生产不得依赖 Suen 发送“继续”

没有真实外部阻塞时，研究、下载、成稿、素材、HTML、QA 应在一次正式生产中自行推进到完成。

以下不构成把流程交回 Suen 的理由：
- 普通网页下载失败；
- 某个工具调用需要换来源；
- 需要继续翻页 / 继续读文件；
- 需要换一个公版图源；
- HTML尚未生成完；
- Base64处理中途需要继续执行。

只有真正需要 Suen 提供新信息、授权、账号操作或做不可替代选择时，才允许停下询问。

### 6. 批量生产优先降低返工成本

一次性做多支视频时，先让每支正文通过自己的栏目核心门，再进行最重的素材包装。

目标不是“尽快产生5个HTML”，而是：**尽量让5个HTML第一次交到 Suen 手里时，已经是值得剪的版本。**

## 四、内部检查默认不全部展示

以下检查继续强制执行，但默认留在系统内部：

- 栏目路由；
- 五个对标方法；
- Suen 100 分模型；
- 最近 7 天重复度；
- 证据可答性；
- 商业状态有效性；
- 文笔 QA；
- 素材 QA。

正常稳定日，Suen 只需要看到：

`选题状态：已通过硬门槛`

只有以下情况才展开详细检查：

- Suen 明确要求；
- 某项未通过；
- 出现规则冲突；
- 仓库刚发生相关修改；
- 当天已经出现执行故障，需要定位原因。

GitHub SHA 回执同理：需要验证时显示，不把它变成每天挡在成品前面的固定长表。

## 五、专用对话交接最小化

总控交给专用对话时使用**任务单**，不替专用对话预写成稿。

### 首次接管

新专用对话第一次承担正式生产时，先按 `规则读取验收协议.md` 完成一次 GitHub 接管验收。接管完成前不写正式正文。

### 日常任务单只锁当天会改变成品的变量

正常只传：

```text
执行今天正式生产。
前台合集 / 内容产品：
题目 / 核心问题：
形式：
主任务：A / B / C / D
今日重点：
事实范围 / 不可扩大范围：
发布时间：
商业边界：纯内容 / 唯一允许的商业方向

按当前 GitHub 本栏目 / 平台规则及统一验收规则完整执行。
没有真实阻塞时自行完成研究、成稿、素材与 QA，一次性交付。
```

这些变量属于当天锁定项。专用对话不得自行：
- 把“有些案例”扩大成整个传统；
- 改栏目 / 内容产品；
- 改图文、视频、页数等已经明确的形式；
- 增删商业 CTA；
- 把主任务改成另一类任务；
- 把计划 / 研究写成已经发生。

如果证据迫使题目范围、栏目或核心结论发生实质变化，退回总控说明阻塞，不静默改题。

### 总控禁止越权预写

除非 Suen 当次明确要求，或该内容产品本身存在固定页面 / 镜头模板，总控任务单**不预设**：
- 第1页到第N页分别写什么；
- 每一段具体怎么说；
- 哪个来源必须放第几段；
- 固定开头句 / 结尾句；
- 可被专用对话直接扩写的完整答案骨架。

总控可以锁定已经核实的事实范围、必须核查的材料和不可越过的证据边界，但结构、证据顺序、正文表达由专用对话按栏目规则与实际资料自行完成。

如果小红书同步抖音同一成片，再加一句：

`小红书同步同一成片，并补标题 / 封面文字 / 配文。`

总控不要每天在提示词里重新复制：

- 文笔总则；
- 视频交付规则全文；
- 规则读取协议全文；
- 栏目长期规则；
- 文笔 QA 条目；
- 素材 QA 条目。

这些由专用对话实际读取 GitHub 当前真源。

## 五-A、《隐理》任务提示词防失真规则｜2026-09-28

来源后验：2026-09-27 总控给《隐理》的任务提示词过长、过度预写答案与结构，客观上把执行对话往“浅层复述标题 + 按资料顺序讲解”方向推，属于总控提示词设计问题。

以后总控给《隐理》下任务时：

### 1. 不在提示词里替专用对话预写“机制答案”

总控只锁：
- 正式题目；
- 主任务；
- 当前真实工作状态；
- 商业边界；
- 已通过的证据范围；
- 今天要验证什么。

不得把“时间本身就是制作条件的一部分”这类**仍然只是操作层 / 结论层**的话，当成已经完成的机制答案塞给执行对话。

必须要求执行对话先自行回答：

> 这个传统为什么认为这一步会起作用？
> 中间的因果链是什么？
> 哪一环有原典支持？

如果只能回答“因为文本要求这样做”，不得开始写完整稿。

### 2. 不预设“第一段Agrippa、第二段Picatrix”这类证据顺序

证据顺序由机制解释决定。

总控可以指定必须核哪些材料，但不能把来源顺序直接写成成片结构，否则容易变成：
作者A说什么 → 作者B也说什么 → 所以时间重要。

《隐理》必须先形成机制链，再把原典放到真正能证明对应环节的位置。

### 3. 新专用对话不复制整套长期规则

如果新对话能够读取GitHub：
- 启动提示词只要求实际读取当前真源；
- 再传当天变量；
- 不把数千字文笔规则、素材规则、商业规则重新复制进提示词。

原因：
超长任务词会让真正决定成稿质量的“机制问题”和“真人文笔”被大量次级要求淹没。

### 4. 正式写稿前增加“机制预演”

专用对话必须在内部先完成，不默认展示：

- 一句机制答案；
- 3—5步因果链；
- 每一步由哪类原典支持；
- 哪些只是操作表现，不是机制；
- 最深能讲到哪里，哪里证据不足必须停。

只有机制预演成立，才进入口播。

### 5. 不给可直接模仿的AI式示范句

总控如果要说明开头功能，只说明：
- 第一秒出现什么冲突；
- 多早给答案方向。

不再提供一整句高度整理过的“示范口播”，避免执行对话沿着总控句式继续扩写成同一套AI文风。

### 6. 一次任务只保留真正会改变今天成稿的变量

正常《隐理》生产提示词应尽量短：
- 题目；
- 主任务；
- 今日机制重点；
- 真实状态；
- 商业边界；
- 小红书是否同步。

其它长期规则回GitHub读取。

核心原则：
**总控负责把题定对，不替《隐理》把机制讲浅；专用对话负责真正研究机制并写成人话。**

## 六、生产保护：先完成当天内容，再修非阻塞性系统问题

进入当天内容生产以后，如果发现系统还有可以优化的地方，先判断它是否真正阻塞当前发布。

### 可以立即打断生产

只限：

- 事实 / 核心证据可能错误；
- 商业状态可能错误；
- 天象时间 / 宣传资格存在冲突；
- 当前规则直接导致成品无法正确交付；
- 用户明确要求先停止生产处理系统问题。

### 不应打断生产

例如：

- README 可以写得更漂亮；
- 模板可以再精简；
- 某条长期说明有轻微重复；
- 某个文件命名可以更统一；
- 不影响当前成品的仓库整理；
- 非必要的新自动化想法。

这些先记为后续系统维护项，等 P0 完成以后再处理。

核心原则：

**先修当前成品并完成发布任务，再处理不阻塞发布的长期系统优化。**

## 八、目标

总控的价值是：

- 帮 Suen 做决定；
- 把最重要的事情排到最前；
- 减少需要人工盯的地方；
- 避免系统优化吞掉生产时间；
- 让专用对话自己承担执行与 QA；
- 最终让当天内容真正完成并能发布。


### 跨日未发布资产判断｜2026-09-28

“昨天没发”不自动等于今天必须补，也不自动等于昨天稿子作废。

第二天判断时必须区分：

1. **稿件仍不合格**：需要继续研究 / 重写，不因昨天投入获得优先级；
2. **稿件已合格、只差成片**：剩余新增制作成本较低，这是今天真实的制作条件，可以在候选竞争中获得效率优势；
3. **成片已经完成、只差发布**：只要题目仍适合当天平台状态，优先级可高于重新生产一支新视频。

这里的优势来自“今天还需要做多少新增工作”，不是为了回收昨天的沉没成本。
