# Suen｜总控简化与生产保护规则

状态：当前正式规则
最后核对：2026-09-18

本文件解决一个问题：商业总控需要足够严谨，但不能把内部检查、系统维护和提示词复杂度继续转嫁给 Suen，也不能因为优化系统而导致当天内容没有真正发布。

## 一、总控只负责五件事

每天“更新”以后，总控只负责：

1. 判断当天最主要瓶颈：流量 / 精准涨粉 / 服务认知 / 询盘 / 成交；
2. 决定当天任务优先级；
3. 完成选题定稿与商业边界；
4. 把最少必要变量交给专用对话；
5. 确保当天主要生产任务真正完成，不让非阻塞性系统维护打断生产。

总控不替专用栏目重新写长期规则，不替栏目发明新的内容理论，不把内部检查表全部展示给 Suen。

---

## 二、P0 / P1 / P2 生产优先级

当天任务按实际价值与工作量分三层。

### P0｜今天必须先完成

当天最重要的生产单元。

当前通常优先：

**抖音大号 1 条 + 小红书同步同一支完整成片**

如果当天有更高优先级的真实商业 / 平台任务，可以由总控调整，但必须说明理由。

P0 未完成前，不因为“顺便优化系统”“再补一篇内容”“再做一个附件”等非阻塞性任务打断主生产。

### P1｜完成 P0 后值得做

有明确品牌、流量、搜索、商业或资产价值，而且当天工作量允许的任务。

例如：

- 公众号贴图；
- 有强题时的公众号长文；
- 当天确有必要的朋友圈商业 / 工作记录。

### P2｜有余力再做

没有当天硬价值、不影响主要经营目标、可以顺延的任务。

例如：

- 抖音小号普通更新；
- 非紧急系统整理；
- 不影响当天发布的仓库美化 / 文档整理。

P2 不得挤占 P0。

---

## 三、选题通过以后进入“生产保护状态”

当下面五项已经确定：

- 栏目 / 内容产品；
- 题目；
- 核心问题；
- A / B / C / D 主任务；
- 商业边界；

并且已经通过 `选题定稿硬门槛.md`，该任务进入**生产保护状态**。

进入生产保护状态后：

- 总控不再中途给栏目追加新的抽象理论；
- 不再临时改变栏目长期时长；
- 不再因为“也许更深”而要求整篇推翻重写；
- 不再把非必要的平台优化扩展成第二个完整制作任务；
- 专用对话按自己当前正式规则完成研究、成稿、素材、QA 与交付。

只有以下情况允许退出生产保护、退回重新定题：

1. 核心事实 / 原典证据明显不成立；
2. 核心问题无法被现有可靠证据真正回答；
3. 题目被发现路由到了错误栏目，且继续制作会导致整条内容价值中心错误；
4. 商业 / 天象 / 法律或平台硬边界出现真实阻塞；
5. Suen 明确改变当天任务。

普通文笔问题、图片匹配问题、排版问题、链接问题不属于重新定题理由，应由执行对话自行修好。

---

## 四、内部检查默认不全部展示

以下检查继续强制执行，但默认留在系统内部：

- 栏目路由；
- 五个对标方法；
- Suen 100 分模型；
- 最近 7 天重复度；
- 证据可答性；
- 商业状态有效性；
- 文笔 QA；
- 素材 QA。

正常稳定日，Suen 只需要看到：

`选题状态：已通过硬门槛`

只有以下情况才展开详细检查：

- Suen 明确要求；
- 某项未通过；
- 出现规则冲突；
- 仓库刚发生相关修改；
- 当天已经出现执行故障，需要定位原因。

GitHub SHA 回执同理：需要验证时显示，不把它变成每天挡在成品前面的固定长表。

---

## 五、专用对话交接最小化

总控交给专用对话时，默认只传当天变量：

```text
执行今天正式更新。
前台合集 / 内容产品：
题目：
主任务：A / B / C / D
今日重点：
商业边界：纯内容 / 唯一允许的商业方向

按当前 GitHub 本栏目 / 平台规则及统一验收规则完整执行。
没有真实阻塞时自行完成研究、成稿、素材与 QA，一次性交付。
```

如果小红书同步抖音同一成片，再加一句：

`小红书同步同一成片，并补标题 / 封面文字 / 配文。`

总控不要每天在提示词里重新复制：

- 文笔总则；
- 视频交付规则全文；
- 规则读取协议全文；
- 栏目长期规则；
- 文笔 QA 条目；
- 素材 QA 条目。

这些由专用对话实际读取 GitHub 当前真源。

---

## 六、生产保护：先完成当天内容，再修非阻塞性系统问题

进入当天内容生产以后，如果发现系统还有可以优化的地方，先判断它是否真正阻塞当前发布。

### 可以立即打断生产

只限：

- 事实 / 核心证据可能错误；
- 商业状态可能错误；
- 天象时间 / 宣传资格存在冲突；
- 当前规则直接导致成品无法正确交付；
- 用户明确要求先停止生产处理系统问题。

### 不应打断生产

例如：

- README 可以写得更漂亮；
- 模板可以再精简；
- 某条长期说明有轻微重复；
- 某个文件命名可以更统一；
- 不影响当前成品的仓库整理；
- 非必要的新自动化想法。

这些先记为后续系统维护项，等 P0 完成以后再处理。

核心原则：

**先修当前成品并完成发布任务，再处理不阻塞发布的长期系统优化。**

---

## 七、总控对 Suen 的默认可见输出

正常“更新”优先使用短版：

```text
【今日总控】
当前瓶颈：
选题状态：已通过硬门槛 / 候选待筛

【P0】
抖音大号｜栏目｜题目｜A/B/C/D
小红书｜同步同一成片 / 独立任务

【P1】
公众号贴图 / 长文 / 朋友圈中真正值得做的任务

【P2】
有余力再做；没有则省略

【商业信号】
无 / 承载平台 + 唯一方向

【今日明确不推】

【执行对话】
只给真正需要复制的超短执行令
```

不把内部评分表、五个对标逐项结论和完整数据分析默认堆给 Suen。

---

## 八、目标

总控的价值是：

- 帮 Suen 做决定；
- 把最重要的事情排到最前；
- 减少需要人工盯的地方；
- 避免系统优化吞掉生产时间；
- 让专用对话自己承担执行与 QA；
- 最终让当天内容真正完成并能发布。
