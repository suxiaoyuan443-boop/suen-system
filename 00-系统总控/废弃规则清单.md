# Suen System｜废弃规则清单与审计规则

状态：当前正式审计文件
首次建立：2026-09-17
最后核对：2026-09-17

## 这份文件解决什么问题

GitHub 里允许出现“旧规则曾经是什么”的历史说明，但**旧规则不能继续作为当前执行指令存在于正式规则文件里**。

因此仓库分成两类：

### A. 当前正式规则

真正指导以后生成、判断和执行的文件。

这些文件不得继续把已经废弃的规则写成当前要求。

### B. 历史/版本说明

例如：

- `CHANGELOG.md`
- `00-系统总控/迁移与冲突记录.md`
- `05-择时与仪式/历史规则说明.md`

这些文件可以引用旧规则，但必须明确写成“旧规则 / 已覆盖 / 历史 / 不再执行”。

只要旧规则只存在于 B 类历史说明里，就不算旧规则污染当前系统。

# 以后怎么审计

每次 Suen 明确说“这条旧规则不要了 / 改成……”时：

1. 更新当前正式文件；
2. 把旧规则登记到本文件；
3. 写明替代规则和正式真源；
4. 如果旧规则仍需保留历史，只能放在 CHANGELOG / 冲突记录 / 历史说明，并明确标注“已废弃”；
5. 再检查 README、模板、索引有没有引用旧版；
6. 最后更新 `最后核对` 日期。

## 判断原则

以后如果某条规则同时出现在“正式规则文件”和“历史说明”中：

- 正式文件写当前执行方式；
- 历史说明只能解释它过去是什么以及为何被覆盖；
- 如果两边都像在下当前指令，视为审计失败，必须修正。

## 当前审计结论

截至 2026-09-17，本清单列出的 **15 类已知旧规则** 均已经有明确替代规则，并已核对对应正式文件/目录。

这不等于数学意义上的“绝对不存在任何我们尚未回忆到的旧规则”。它表示：**目前已经识别出来的旧规则都有显式退役记录，不再需要靠记忆判断新旧。**
