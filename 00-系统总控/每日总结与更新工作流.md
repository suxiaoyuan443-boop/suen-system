# Suen｜每日总结与更新工作流

状态：当前正式规则
最后核对：2026-09-23

## 一、总流程

`总结 → 补齐事实台账 → 更新当前状态 → 判断瓶颈 → P0/P1/P2 → 专用对话执行 → 发布 → 后续复盘`

## 二、Suen 说“总结”

读取：
- `08-动态运行/内容台账/当前状态.md`
- 当前月份 `08-动态运行/内容台账/YYYY-MM.md`（存在时）
- `99-模板/内容复盘台账模板.md`

只补已发生事实，不定新题。未知数据不估算。

确认后：
1. 更新 `内容台账/当前状态.md`；
2. 已发布 / 已复盘事实写入当月内容台账；
3. 区分发布日期、复盘日期和仪式 / 星符执行日期。

计划发布、成品完成、准备发布都不等于已经发布。
询盘 / 成交只有可靠确认来源时才归因给具体内容。

## 三、Suen 说“更新”

读取：
1. `08-动态运行/内容台账/当前状态.md`
2. `08-动态运行/选题池/当前选题池.md`（抖音大号）
3. `08-动态运行/选题池/小红书当前选题池.md`（小红书，需要规划小红书时读取）
4. `08-动态运行/选题池/朋友圈当前选题池.md`（需要规划朋友圈专业内容时读取）
5. `08-动态运行/商业/当前商业状态.md`
6. `08-动态运行/天象/当前预约池.md`

然后：
0. **先做最近 7 天全平台发布扫盘**：至少同时检查抖音大号、小红书、抖音小号、公众号、朋友圈最近实际发布内容，以及课程 / 数据库近期是否被挤压。不能只盯当日主平台。需要看栏目、观看体验、题材、发布时间和实际结果，避免刚发过的栏目 / 体验在两三天内无理由重复。当前动态文件落后于用户新截图时，以用户刚提供的真实发布截图补齐后再规划；
1. 判断一个主要瓶颈；
2. 检查当前可售 / 可预约状态；
3. 检查当前候选、冷却、待核查；
4. 先检查现有选题池是否有可直接节省时间的合适候选；选题池只负责提供现成选择，不是唯一来源。池内不适合、数量不足、平台不同、需要不同观看体验或最新数据改变判断时，总控必须主动寻找并核查新题；
5. 决定 P0 / P1 / P2；
6. 需要新前台题才加载内容地图、对标和硬门槛；
7. 需要商业动作才加载商业信号规则；
8. 需要实验 / 重发才加载实验规则；
9. 生成短总控；
10. 把真实变化写回对应当前动态文件；
11. 只有真实发生的历史事实才追加到当月记录。

## 四、选题池

平台动态真源：
- 抖音大号：`08-动态运行/选题池/当前选题池.md`
- 小红书：`08-动态运行/选题池/小红书当前选题池.md`

两者共享栏目 / 事实规则，但独立判断候选，不把一个平台的候选状态自动同步给另一个平台。

- 抖音大号活跃候选原则上保持 2—5 个高质量候选；不足 2 个时再主动补池，不为数量凑弱题；
- 候选不等于正式定题；
- 发布 / 淘汰 / 冷却后及时更新；
- Git commit 保存旧版本，不在当前文件堆历史垃圾；
- “继续做选题池”不自动进入生产。

## 五、动态文件失败处理

读取失败：
- 不声称掌握最新状态；
- 不用记忆补成当前事实；
- 不新增依赖该状态的商业动作。

写入失败：
- 明确说明哪个状态没有成功持久化；
- 不声称已保存；
- 后续先补写再继续。

## 六、动态状态有效期

价格、预约、排期、容量、折扣、天象资格、今日主推等，使用前必须读取当前状态。
“今日决定”跨日自动失效，除非明确写为持续状态。

## 七、定题只在需要时加载重规则

只有要定新的前台题时，才加载：
- `内容地图.md`
- `内容商业对标系统.md`
- `选题定稿硬门槛.md`
- 对应平台 / 栏目规则

先看第一方真实数据，再看外部 benchmark。

## 八、生产保护

题目、主任务、商业边界确定后进入生产保护。

P0 未完成前：
- 非阻塞仓库整理不抢生产时间；
- 非阻塞 benchmark 补采不抢生产时间；
- 规则优化不抢生产时间；
- 只有直接卡住当天题目的事实核查 / 撞题检查 / 必要素材问题可以继续。

当前 benchmark 已经足够支持候选生成时，默认停止广泛补采。  
**先完成当天可发布内容，再做数据建设。**

如果某天因为 benchmark / 系统整理导致主视频最终未发布，复盘时明确记为生产保护失败，并在后续把同类辅助任务降级，不把它合理化为默认研究安排。

## 九、Patreon

Patreon 当前暂停主动生产与运营推进。

- 默认不进入每天“更新”任务；
- 不安排周更 / 日更；
- 不占用 Work 模式额度；
- 只有 Suen 明确说“恢复 Patreon”或出现必须处理的真实订阅 / 账户事项时才显示。

Work 模式额度当前优先用于 **Suen Akhet Database**。

## 十、复盘

取得合理数据窗口后，对照发布前确定的主任务 / 假设复盘，不事后改写实验目的。

## 课程催进度｜每日总结后

从 2026-09-20 起，Suen 每天完成“总结”后，总控在总结正文结束后追加一条轻量课程推进提醒。

目的：

- 课程当前约完成 40%，仍有约 60% 待完成，因此需要持续推进；
- 提醒不是新的长任务，也不要求每天高强度写课。

默认提醒方式：

推荐收尾语气保持自然，例如：
“今天总结到这里。课程别忘了再推进一点，哪怕只补一页讲稿或者写半小时也算。”


## 十一、主动优化与讨论判断

当 Suen 询问“还有什么可以讨论 / 优化”或类似问题时：

- 先基于当前真实状态判断是否存在新的、有实际价值的问题；
- 已经讨论清楚、没有新数据、没有新矛盾的事项，不为了延长对话再次包装成“可讨论点”；
- 不把已确定的执行项重新拿出来当新策略讨论；
- 有值得优化的内容时，直接指出最有价值的部分和原因；
- 如果当前没有新的高价值优化点，直接明确回复“目前没有额外值得讨论 / 优化的”，无需硬凑话题；
- 后续出现新数据、执行结果、平台变化、商业信号或规则冲突时，再主动提出真正需要讨论的问题。

## 十二、Suen说“更新”时的唯一正式交付格式

从 2026-09-21 起，本节是“更新”的唯一正式输出规则。旧的“默认输出”“提示词统一放末尾”等格式已删除，不再并行使用。

Suen 说“更新”时，总控必须一次性交付**当天完整运营安排**，不能只给主内容，也不能让 Suen 再追问公众号、朋友圈、课程、数据库或专用对话提示词。

### 一、先给今日总控

简短说明：

- 今天真正的主要瓶颈；
- 今天最重要的主任务；
- 哪些昨天 / 近期数据改变了今天判断；
- 哪些事情今天明确不需要继续折腾。

不为了显得完整重复已经讨论清楚、没有新数据的问题。

### 二、逐项给今天完整安排

至少逐项检查：

**上海省钱情报局不属于本总控，不在这里安排；它继续按自己的独立系统运行。**

- 抖音大号
- 小红书
- 抖音小号
- 公众号
- 朋友圈
- Patreon（当前暂停，正常不展开）
- 课程
- Suen Akhet Database
- 客户 / 订单 / 交付
- 天象 / 当前预约窗口
- 其它当天真实存在的行政、产品或商业事项

每项必须明确成以下之一：

- 今天更新 / 执行什么；
- 今天只推进、不发布；
- 今天观察；
- 今天不做，并说明原因。

凡是“今天发布”的内容，必须同时给出**明确发布时间**。
凡是“今天推进但不发布”的任务，必要时给出建议执行时段，帮助排完整日程。

发布时间不能省略，并按以下顺序判断：

1. **Suen 已明确的长期发布习惯 / 偏好**；
2. **该平台自己的第一方历史数据**：过往发布时间、粉丝活跃时段、内容表现、发布后首轮分发；
3. **最近可比样本**；
4. 只有前三项不足时，才使用当天运营错峰作为补充。

当前已确认的正式运行参数：

- **默认发布锚点：20:30（Asia/Shanghai）**；
- 只要某个平台还没有足够稳定的第一方历史数据证明其它时间长期更优，当天发布优先使用 20:30；
- 某个平台后续如果通过足够多的真实历史样本形成更可靠时段结论，可以为该平台单独覆盖 20:30；
- 抖音大号现有粉丝活跃数据：21–22点第二、22–23点第一、23–24点第三；当前仍优先 20:30，让首轮分发进入后续活跃段；
- 单条内容在20:30附近表现差，不能单独推翻发布时间锚点，必须先区分题材、Hook、留存、账号分发等其它变量；
- 不为了“多平台错峰”随意改成18:30、20:10、21:50等未经第一方数据支持的时间；确有管理冲突时才做小幅调整。

允许总控根据当天工作量安排更多真正有价值的任务；不需要把日程压缩到只剩两三件事，也不能为了显得忙而硬塞无意义工作。

### 三、提示词必须跟在对应任务下面

凡是某一项需要进入专用对话执行：

1. 先写该平台 / 事项今天要做什么；
2. 紧接着写“发给【对应专用对话】”；
3. 下一行直接放**独立代码块**，提供可直接复制发送的完整提示词；
4. 然后再进入下一个平台 / 事项。

禁止：

- 把所有专用对话提示词统一堆到整份更新最后；
- 用普通引用块代替代码块；
- 把多个专用对话提示词塞进同一个代码块；
- 只写“去某某对话执行”却不给可直接发送的提示词。

提示词只传当天变量，不重复粘贴整套长期规则。正常至少包含：

- 前台合集 / 内容产品；
- 题目；
- 主任务；
- 今日重点；
- **发布时间（凡当天要发布必须写）**；
- 商业边界；
- 要求专用对话按 GitHub 当前规则完整执行。

### 三点五、一份主视频生产原则

每天先确定**一份需要重新剪辑的主视频生产单元**。

- 抖音大号与小红书可以分别判断平台最需要什么，但总控不能因此默认安排两支新视频；
- 主视频同时适合两个平台时，直接双平台复用；
- 不适合小红书时，小红书优先图文、已有真实素材、《长卷》或其它不需要第二次剪辑的形式；
- 只有独立第二支视频的预期价值明显高于额外时间成本，而且当天工作量允许，才安排第二支；
- “每天1条 / 1篇”的小红书发布基线不等于“每天1支新剪视频”。

### 四、公众号必须单独判断

每次“更新”都实际读取：

`03-公众号/阿赫特之门.md`

公众号当前执行 **每日更新**。

当天正常应在以下三种发布状态里选一个：
- 只发贴图；
- 只发长文；
- 两者都发。

只有 Suen 当天明确暂停或出现真实客观阻塞时，才允许“两者都暂缓”，并必须写清阻塞原因。

不得恢复已经取消的“固定 1 篇长文 + 1 篇贴图”，也不得把某一天“只做贴图”或“只做长文”的临时安排写成长期固定规则。

总控不能因为现成选题池里没有合适题就让公众号停更；公众号需要独立按自身规则、最近发布内容与第一方数据主动寻找当天新题。

同时执行“高上限短视频题保护”：
- 对陌生人入口明显强、适合 A｜流量 / B｜精准涨粉、且能抖音大号 + 小红书复用的好题，优先留给抖音 / 小红书；
- 公众号不能为了完成日更先消耗这些题；
- 公众号优先选择资料价值高但短视频冷入口较窄的独立题，或同一研究对象中短视频没有使用的新价值层。

### 五、同日跨平台定题保护

某个题已经正式分配为某平台 / 栏目的当日 P0 或正式生产题后：

- 不得未经说明又把它分配给另一平台做第二个独立生产单元；
- 明确计划的同一成片同步发布除外；
- 如果同一研究对象要同时进入公众号、Patreon等不同产品，必须有清晰的新价值层；
- 没有新价值层时，另选题或让另一平台暂缓，不为了填满日程抢同一个题。

### 六、最后给执行顺序

所有平台 / 事项及其提示词都列完后，最后再给当天执行顺序：

- 先做什么；
- 后做什么；
- 哪些属于有余力再做；
- 哪些今天不用碰。

“更新”的目标不是给一个最小任务清单，而是让 Suen 一次看到**今天完整要做什么，以及每件事下一步直接怎么执行**。


### 七、选题池不是唯一来源

- 选题池的作用是提高定题效率，不是限制总控只能从池中选；
- 当前 `08-动态运行/选题池/当前选题池.md` 服务抖音大号；`08-动态运行/选题池/小红书当前选题池.md` 服务小红书。公众号、小号等仍按各自规则独立寻找内容；
- “更新”时如果某个平台需要内容而现有池中没有合适题，总控应按该平台当前规则、近期数据、内容空窗和重复情况主动寻找新题；
- 主动找的新题仍需完成必要的证据、重复、栏目 / 平台适配和素材可得性检查；
- 不为了使用选题池而把原本属于大号候选的题硬挪给其它平台。

### 八、历史内容复用前必须核对发布状态

在把旧稿、旧题或“记得以前做过”的内容安排为当天发布前，必须先核对：
- 当前月度内容台账；
- 相关平台当前状态；
- 必要时再查历史对话 / 文件。

已确认发布过的内容不得误写成“未发布库存”。
如果要二次利用，必须明确是重做、延伸、不同价值层或再编辑，而不是把历史已发布内容当新内容。


### 九、Work 模式执行优先级

当前固定：
1. 有 Work 模式额度时，优先推进 Suen Akhet Database；
2. 数据库可安排重写、结构整理、批量文件处理等适合 Work 的任务；
3. Patreon 当前暂停，不使用 Work；
4. 普通 Chat 能稳定完成的内容任务不主动挤占 Work 额度。
