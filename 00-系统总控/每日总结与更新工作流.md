# Suen｜每日总结与更新工作流

状态：当前正式规则
最后核对：2026-10-14

## 一、总流程

`总结 → 补齐事实与交付状态 → 检查客户履约 / Revenue P0 → 判断经营与内容断点 → 选择当天 P0 → 执行 → 记录发布 / 交付 → 复盘`

## 二、Suen 说“总结”

读取：
- `08-动态运行/内容台账/当前状态.md`
- 当前月份 `08-动态运行/内容台账/YYYY-MM.md`（存在时）
- `99-模板/内容复盘台账模板.md`

只补已发生事实，不定新题。未知数据不估算。

确认后：
1. 更新 `内容台账/当前状态.md`；
2. 已发布 / 已复盘事实写入当月内容台账；
3. 区分发布日期、复盘日期和仪式 / 星符执行日期。

计划发布、成品完成、准备发布都不等于已经发布。
询盘 / 成交只有可靠确认来源时才归因给具体内容。

读取：
1. `08-动态运行/内容台账/当前状态.md`
2. `08-动态运行/商业/当前商业状态.md`
3. `08-动态运行/天象/当前预约池.md`

`08-动态运行/灵感库存/当前灵感.md` 只在当天确实需要补充研究线索时按需读取，不属于“更新”的必读真源。

然后：
0-现金. **先判现金安全**：若 Suen 当次明确报告基本生活、必要照护或近期到期款项存在无法覆盖的缺口，依据 `商业目标与产品优先级.md` 的现金安全规则，先给出不依赖假设成交的现实处理优先级；同时保护已付款履约和真实客户动作。未核实实际可动用资金与待支付义务时，不给具体可花余额或虚构收入预测。现金安全阻塞不能仅靠安排更多视频、熬夜或开发新产品应对，也不自动改变今天真实内容的发布状态。
0-应急分流. **现金安全阻塞尚未解除时，停止默认内容排产分支**：完成现有已付款履约 / 已约定客户动作核对后，直接按第十二节「现金安全应急短版」输出。只有 Suen 当次明确要求正式内容生产、已有成品确实需要低成本发布，或现实经营需要特定内容承接时，才进入第1、3-A、3-B、4、5步相关的全平台扫盘、七栏目和热点候选；没有这种需要就不执行，不因此判定内容工作流失败，也不形成补更债。此分流不取消已发生发布 / 交付事实的记录，不强迫课程/数据库补进度，也不把现金压力当成永久状态。任何计划收入、正式报价和未执行订单预收款都不能不经现金/履约核对直接算成今天生活可用金额。
0. **先检查 Revenue P0**：读取当前商业状态与真实客户推进事实，确认是否存在待方案、待正式报价、当天明确决策、已付款关键交付、已约定回访等高价值动作。资格读取 `07-销售与运行/高客单机会漏斗.md`。存在 Revenue P0 时先排进当天最前；普通私信不升级为 Revenue P0。已付款订单交付状态不明时，先核对实际约定与进度，不能因缺记录就写“没有待交付”。
0-A. **经营建设断点**：没有 Revenue P0，但正式报价 / 付款条件、可用服务入口或成本核算直接卡住销售时，可安排一个经营建设 P0。写清阻塞、具体产出和验收条件，例如“完成待确认的报价与服务范围草案”；客户和平台条件未齐时不收款。普通整理、美化、补规则和闲聊不升级。内部准备完成只记建设结果，不能记合格机会、报价或成交。
0-B. 新经营方案、主推变化或新的平台交易动作，按 `现实环境与商业决策规则.md` 读取当前观察并核查相关最新资料，不把宏观数字当作客户预算。
0-C. 没有客户动作也没有经营阻塞时，再安排 Content P0；当天可产出不足时，允许只推进长期产品或必要研究，不用虚构发布任务。
1. **再做最近 7 天全平台发布扫盘**：至少同时检查抖音大号、小红书、抖音小号、公众号、朋友圈最近实际发布内容，以及课程 / 数据库近期是否被挤压。不能只盯当日主平台。需要看栏目、观看体验、题材、发布时间和实际结果，避免刚发过的栏目 / 体验在两三天内无理由重复。当前动态文件落后于用户新截图时，以用户刚提供的真实发布截图补齐后再规划。
2. 判断一个主要瓶颈。商业漏斗存在明显断点时，优先写清是询盘质量、合格机会、方案、报价、付款、执行还是复购 / 转介绍；否则再判断内容增长瓶颈。
3. 检查当前可售 / 可预约状态。
3-选题来源. **需要新候选时，先按主任务选择来源**：A/B/研究题在七栏目机会扫描前执行 `内容商业对标系统.md` 二-A，读全账号历史强样本＋最新数据与具体对标高表现题材；最近7天不能替代历史比较。C/D执行二-B，检查去身份化的真实咨询/报价/交付问题、已确认服务约定及可展示判断，相关对标只辅助表达。两者都优先使用已有证据，缺口阻塞时才定向补采。

3-服务认知. 当Suen明确要求促进获客，或真实漏斗显示服务理解/购买决定存在具体断点时，后台检查是否有与该断点对应的C候选，并与其它任务比较。写清目标对象、具体疑问、信任依据及业务关系；没有依据就标待核，不硬造客户，不把研究内容直接改名“获客视频”。先按平台/栏目定位决定形式；有真实工作可复用时优先低成本表达，不新增每日配额。已经进入生产保护的题不因这项常规检查而重开。
3-A. **再做七栏目机会扫描**：大号需要生成新候选时，后台依次检查《文物 / 异录 / 辨伪 / 残页 / 隐理 / 牌记 / 古术》当前是否存在真实可用原料，再进入候选生成。这里是机会扫描，不是栏目轮播，也不要求七栏各造一个题：
   - 文物：有没有一件具体真实对象本身值得看；
   - 异录：有没有人物 + 事件 + 时间线 + 转折；
   - 辨伪：有没有能在明确范围内稳定判对 / 错的问题；
   - 残页：有没有一页 / 一句 / 一段原文本身值得拆；
   - 隐理：有没有能被证据真正回答的实践机制问题；
   - 古术：有没有可讲清使用者、具体做法与环境的历史宗教/魔法实践，实际操作资料是否足够；
   - 牌记：有没有适合公开的具体真实牌局与判断过程。
   只有存在真实材料的栏目进入候选竞争。某栏目连续 10—14 天既没有进入候选、也没有发布时，只触发一次“是不是候选生成漏检”的检查，不自动获得发布优先级。
3-B. **实时热点扫描**：当日确实需要生成新的A/B/研究前台候选时，在七栏目机会扫描之后、正式候选定题之前，增加一次轻量公开热点扫描。C/D基于真实问题或已确定商业动作时，不为形式另加热点扫盘。默认看最近 24 小时—7 天；慢热议题可扩到 30 天。优先观察抖音、小红书、微博、近期新闻与搜索结果里和 Suen 内容边界真实相关的热点，例如：
   - 占星 / 行星逆行 / 重大天象；
   - 塔罗、神秘学、巫术、宗教史相关争议或大众误解；
   - 古埃及、考古、博物馆、手稿、文物的新发现 / 新展览 / 热门事件；
   - 与已有七栏目可以自然承接的影视、名人、文化事件。
   热点只提供**候选优先权和大众入口**，不直接变成正式题。必须进一步转成 Suen 自己能提供新判断 / 原始证据 / 纠偏 / 机制解释的具体问题。纯“今天很火所以讲一下”、泛运势、无证据跟风不进入正式候选。
   记录具体链接、发布日期、采集日和能确认的互动 / 问题，方法按 `内容商业对标系统.md` 热点层执行。用户观察或检索线索可以保留，但热度强度与页面未复核时写待核；不凭印象标“高互动 / 爆”。已有批次或当天P0可推进时不重扫，样本足以取舍就停止。

4. 按所选来源路径、近期内容结构、当天产能与主要瓶颈生成少量候选，依据回对标系统二-A或二-B。A先做陌生人入口/无聊筛选；B看精准问题与有依据的判断；C看是否减少一项具体服务理解疑问；D看当前商业动作及下一步是否真实可用。奇异度、反差与A类80分不强加给C/D，真实性、独立价值、素材与适用平台门共同执行。

5-A. 候选比较默认在后台完成。Suen 默认只看到最终 P0 / 明确待核查状态；只有 Suen 主动要求比较方案，或所有候选都存在真实阻塞时，才展开候选。不得把“这个行不行 / 那这个呢”的筛选工作连续转回给 Suen。

## 四、当天定题机制

正式选题只在当天发生，不维护跨日高优先候选池。

- 抖音大号、小红书、公众号、朋友圈按各自平台任务独立判断；
- 新候选按主任务选来源：A/B/研究题走对标系统二-A；C/D走二-B的真实问题与信任依据，再结合近7天发布、当日产能和商业状态；不将两条路径都改成爆款筛选；
- 大号先完成七栏目机会扫描；当天需要A/B/研究新候选时，再做一次实时热点扫描，把“当前大众正在讨论什么”作为额外候选来源；热点不形成独立栏目，也不能绕过七栏目路由；再只从有真实材料、证据与素材路径的候选中做决定；
- 每个平台只生成足够做决定的少量候选，不为了“库存充足”提前研究一批题；
- 轻量灵感库存只保存对象 / 问题 / 来源线索，不保存 P0、优先级、冷却、平台归属或“已通过”状态；
- 旧题如果今天仍值得做，按今天的状态重新参加判断；不会因为昨天研究过、写过一半或已经投入时间而获得优先权；
- 某题连续出现范围、栏目、证据或成片形态问题时，允许直接取消，不默认换栏目、换平台或改成长文继续救题。

## 四-A、明确事实触发即时写回

“总结”仍然负责系统化补齐台账，但**不再是动态真源唯一的写入触发词**。

当 Suen 在任何总控对话里明确确认下列事实时，应在当前任务完成后同步写回对应 GitHub 动态真源，不要求 Suen 再重复说一次“总结”：

- 已发布 / 已删除 / 已停止发布；
- 已成交 / 已付款 / 已退款；
- 已交付 / 已执行 / 已完成；
- 已到货 / 已采购 / 已开始制作；
- 已收到可用于经营判断的真实反馈或后台数据；
- 当前预约、产品可售状态或真实工作阶段发生变化。

写回原则：

1. 只写 Suen 已明确确认的事实；
2. 缺少标题、具体平台、金额、时间或数据字段时，记录已确认部分并把缺口标成“待补”，不自行推断；
3. “今天都发了”这类概括如果无法确定逐平台明细，不擅自补出未确认标题或平台；
4. 内容事实进入内容当前状态 / 当月台账；生产交付、质量反馈与实际发布分项记录。会影响接管的摘要变化同时核对 `08-动态运行/00-当前总览.md`，只同步必要摘要，不复制完整流水；商业事实进入商业当前状态 / 当月商业事实；真实项目阶段进入真实工作资产；天象状态进入预约池；
5. 销售私聊专用对话的“生成总结”触发规则不因此改变。

目标是让下一次总控真正从 GitHub 读到现实，而不是长期依赖旧聊天补丁。

## 五、动态文件失败处理

读取失败：
- 不声称掌握最新状态；
- 不用记忆补成当前事实；
- 不新增依赖该状态的商业动作。

写入失败：
- 明确说明哪个状态没有成功持久化；
- 不声称已保存；
- 后续先补写再继续。

## 六、动态状态有效期

价格、预约、排期、容量、折扣、天象资格、今日主推等，使用前必须读取当前状态。
“今日决定”跨日自动失效，除非明确写为持续状态。

只有要定新的前台题时，才加载：

## 八、生产保护

题目、主任务、商业边界确定后进入生产保护。

P0 未完成前：
- 非阻塞仓库整理不抢生产时间；
- 非阻塞 benchmark 补采不抢生产时间；
- 规则优化不抢生产时间；
- 只有直接卡住当天题目的事实核查 / 撞题检查 / 必要素材问题可以继续。

当前 benchmark 已经足够支持候选生成时，默认停止广泛补采。  
**先完成当天可发布内容，再做数据建设。**

如果某天因为 benchmark / 系统整理导致主视频最终未发布，复盘时明确记为生产保护失败，并在后续把同类辅助任务降级，不把它合理化为默认研究安排。

## 八-A、真实工作资产状态

新增动态真源：
- `08-动态运行/真实工作资产/当前状态.md`

它只记录真实项目当前处于研究、采购、制作 / 执行、完成、结果跟踪或案例可用中的哪一步。

使用规则：
- 每次“更新”不机械全文加载；只有当天需要从真实工作找低成本内容、判断项目是否已经落地、判断机会成本或发生状态变化时读取；
- Suen 明确说“已经买了 / 到货了 / 开始做了 / 做完了 / 有反馈了”等会改变事实阶段的信息时，应同步更新；
- 没有状态变化不要求每日维护；
- 它不是选题池，不能因为某项目已经记录就自动获得发布优先级；
- 动态资产状态必须服从真实性与商业保密规则。

## 八-B、每周时间—产出复盘｜不做精细工时表

每周复盘只判断时间大致花在哪里、换来了什么，不要求 Suen 每天开计时器。

如果当周有足够事实，按大致投入档位回看：
- 短视频研究 / 找图 / 写稿 / 剪辑；
- 公众号 / 其它平台内容；
- 客户沟通 / 报价 / 交付；
- 真实研究 / 制作 / 仪式执行；
- 《古埃及魔法实践》课程；
- Suen Akhet Database；
- 系统 / benchmark / 仓库维护。

可使用“很少 / 少量 / 中等 / 较多 / 主要时间”等粗档，不要求精确小时；Suen 主动提供真实耗时时可记录。

每周只回答三件事：
1. 哪一类工作消耗最多时间；
2. 产生了什么真实结果：内容增长、询盘 / 回款、执行资产、课程 / Database 进度等；
3. 下周是否需要减少某类低回报投入或保护某类长期资产时间。

典型需要调整的信号：
- 大量选题研究最终没有进入生产；
- benchmark / 系统维护再次挤掉 P0 或长期产品；
- 多平台发布很多，但客户 / 课程 / Database 长期停滞；
- 某类低成本真实工作内容持续产生有效增长 / 询盘，值得提高复用；
- 某类高成本内容长期没有对应的增长、品牌、搜索或商业资产价值。

不计算“播放 ÷ 小时”作为唯一 ROI，不为了复盘增加新的日报。
