# Suen｜每日总结与更新工作流

状态：当前正式规则
最后核对：2026-10-08

## 一、总流程

`总结 → 补齐事实与交付状态 → 检查客户履约 / Revenue P0 → 判断经营与内容断点 → 选择当天 P0 → 执行 → 记录发布 / 交付 → 复盘`

## 二、Suen 说“总结”

读取：
- `08-动态运行/内容台账/当前状态.md`
- 当前月份 `08-动态运行/内容台账/YYYY-MM.md`（存在时）
- `99-模板/内容复盘台账模板.md`

只补已发生事实，不定新题。未知数据不估算。

确认后：
1. 更新 `内容台账/当前状态.md`；
2. 已发布 / 已复盘事实写入当月内容台账；
3. 区分发布日期、复盘日期和仪式 / 星符执行日期。

计划发布、成品完成、准备发布都不等于已经发布。
询盘 / 成交只有可靠确认来源时才归因给具体内容。

## 三、Suen 说“更新”

读取：
1. `08-动态运行/内容台账/当前状态.md`
2. `08-动态运行/商业/当前商业状态.md`
3. `08-动态运行/天象/当前预约池.md`

`08-动态运行/灵感库存/当前灵感.md` 只在当天确实需要补充研究线索时按需读取，不属于“更新”的必读真源。

然后：
0. **先检查 Revenue P0**：读取当前商业状态与真实客户推进事实，确认是否存在待方案、待正式报价、当天明确决策、已付款关键交付、已约定回访等高价值动作。资格读取 `07-销售与运行/高客单机会漏斗.md`。存在 Revenue P0 时先排进当天最前；普通私信不升级为 Revenue P0。已付款订单交付状态不明时，先核对实际约定与进度，不能因缺记录就写“没有待交付”。
0-A. **经营建设断点**：没有 Revenue P0，但正式报价 / 付款条件、可用服务入口或成本核算直接卡住销售时，可安排一个经营建设 P0。写清阻塞、具体产出和验收条件，例如“完成待确认的报价与服务范围草案”；客户和平台条件未齐时不收款。普通整理、美化、补规则和闲聊不升级。内部准备完成只记建设结果，不能记合格机会、报价或成交。
0-B. 新经营方案、主推变化或新的平台交易动作，按 `现实环境与商业决策规则.md` 读取当前观察并核查相关最新资料，不把宏观数字当作客户预算。
0-C. 没有客户动作也没有经营阻塞时，再安排 Content P0；当天可产出不足时，允许只推进长期产品或必要研究，不用虚构发布任务。
1. **再做最近 7 天全平台发布扫盘**：至少同时检查抖音大号、小红书、抖音小号、公众号、朋友圈最近实际发布内容，以及课程 / 数据库近期是否被挤压。不能只盯当日主平台。需要看栏目、观看体验、题材、发布时间和实际结果，避免刚发过的栏目 / 体验在两三天内无理由重复。当前动态文件落后于用户新截图时，以用户刚提供的真实发布截图补齐后再规划。
2. 判断一个主要瓶颈。商业漏斗存在明显断点时，优先写清是询盘质量、合格机会、方案、报价、付款、执行还是复购 / 转介绍；否则再判断内容增长瓶颈。
3. 检查当前可售 / 可预约状态。
3-A. **先做六栏目机会扫描**：大号需要生成新候选时，后台依次检查《文物 / 异录 / 辨伪 / 残页 / 隐理 / 牌记》当前是否存在真实可用原料，再进入候选生成。这里是机会扫描，不是栏目轮播，也不要求六栏各造一个题：
   - 文物：有没有一件具体真实对象本身值得看；
   - 异录：有没有人物 + 事件 + 时间线 + 转折；
   - 辨伪：有没有能在明确范围内稳定判对 / 错的问题；
   - 残页：有没有一页 / 一句 / 一段原文本身值得拆；
   - 隐理：有没有能被证据真正回答的实践机制问题；
   - 牌记：有没有适合公开的具体真实牌局与判断过程。
   只有存在真实材料的栏目进入候选竞争。某栏目连续 10—14 天既没有进入候选、也没有发布时，只触发一次“是不是候选生成漏检”的检查，不自动获得发布优先级。
4. 根据最近 7 天内容结构、当天制作条件、六栏目机会扫描和当前瓶颈，现场生成少量当天候选。生成候选时先做一次轻量“陌生人入口”筛选：这个对象 / 问题能否让完全不了解 Suen 的人马上知道在讲什么，并自然产生具体问题、反常感、纠偏欲望或结果好奇；答案是否存在认知落差。入口不成立的题先与其它候选比较，不用重型研究、栏目或 benchmark 硬救。
5. 对已经通过入口初筛的候选做必要的栏目、证据范围、近期重复、素材可得性与平台适配检查；如需灵感，可读取轻量灵感库存，但不得继承其中任何优先级或“已投入成本”。
5-A. 候选比较默认在后台完成。Suen 默认只看到最终 P0 / 明确待核查状态；只有 Suen 主动要求比较方案，或所有候选都存在真实阻塞时，才展开候选。不得把“这个行不行 / 那这个呢”的筛选工作连续转回给 Suen。
6. 决定 Revenue P0 / Content P0 / P1 / P2。
7. 需要新前台题才加载内容地图、对标和硬门槛。
8. 需要商业动作才加载商业信号规则；涉及“今天推什么产品”时读取 `07-销售与运行/产品矩阵与主推优先级.md` 与 `产品价格架构与经济性.md`；涉及高客单时再读取机会漏斗 / Offer 规则。
9. 需要实验 / 重发才加载实验规则。
10. 生成短总控。
11. 把真实变化写回对应当前动态文件。
12. 只有真实发生的历史事实才追加到当月记录。

## 四、当天定题机制

正式选题只在当天发生，不维护跨日高优先候选池。

- 抖音大号、小红书、公众号、朋友圈按各自平台任务独立判断；
- 先看第一方数据和最近 7 天真实发布，再结合当天制作条件与商业状态；
- 大号先完成六栏目机会扫描，再只从有真实材料的栏目生成足够做决定的少量候选；不机械轮播，也不因为某几个栏目更容易出题就长期只在《文物 / 辨伪 / 隐理》中循环；
- 每个平台只生成足够做决定的少量候选，不为了“库存充足”提前研究一批题；
- 轻量灵感库存只保存对象 / 问题 / 来源线索，不保存 P0、优先级、冷却、平台归属或“已通过”状态；
- 旧题如果今天仍值得做，按今天的状态重新参加判断；不会因为昨天研究过、写过一半或已经投入时间而获得优先权；
- 某题连续出现范围、栏目、证据或成片形态问题时，允许直接取消，不默认换栏目、换平台或改成长文继续救题。

## 四-A、明确事实触发即时写回

“总结”仍然负责系统化补齐台账，但**不再是动态真源唯一的写入触发词**。

当 Suen 在任何总控对话里明确确认下列事实时，应在当前任务完成后同步写回对应 GitHub 动态真源，不要求 Suen 再重复说一次“总结”：

- 已发布 / 已删除 / 已停止发布；
- 已成交 / 已付款 / 已退款；
- 已交付 / 已执行 / 已完成；
- 已到货 / 已采购 / 已开始制作；
- 已收到可用于经营判断的真实反馈或后台数据；
- 当前预约、产品可售状态或真实工作阶段发生变化。

写回原则：

1. 只写 Suen 已明确确认的事实；
2. 缺少标题、具体平台、金额、时间或数据字段时，记录已确认部分并把缺口标成“待补”，不自行推断；
3. “今天都发了”这类概括如果无法确定逐平台明细，不擅自补出未确认标题或平台；
4. 内容事实进入内容当前状态 / 当月台账；商业事实进入商业当前状态 / 当月商业事实；真实项目阶段进入真实工作资产；天象状态进入预约池；
5. 销售私聊专用对话的“生成总结”触发规则不因此改变。

目标是让下一次总控真正从 GitHub 读到现实，而不是长期依赖旧聊天补丁。

## 八-B、每周时间—产出复盘｜不做精细工时表

每周复盘只判断时间大致花在哪里、换来了什么，不要求 Suen 每天开计时器。

如果当周有足够事实，按大致投入档位回看：
- 短视频研究 / 找图 / 写稿 / 剪辑；
- 公众号 / 其它平台内容；
- 客户沟通 / 报价 / 交付；
- 真实研究 / 制作 / 仪式执行；
- 《古埃及魔法实践》课程；
- Suen Akhet Database；
- 系统 / benchmark / 仓库维护。

可使用“很少 / 少量 / 中等 / 较多 / 主要时间”等粗档，不要求精确小时；Suen 主动提供真实耗时时可记录。

每周只回答三件事：
1. 哪一类工作消耗最多时间；
2. 产生了什么真实结果：内容增长、询盘 / 回款、执行资产、课程 / Database 进度等；
3. 下周是否需要减少某类低回报投入或保护某类长期资产时间。

典型需要调整的信号：
- 大量选题研究最终没有进入生产；
- benchmark / 系统维护再次挤掉 P0 或长期产品；
- 多平台发布很多，但客户 / 课程 / Database 长期停滞；
- 某类低成本真实工作内容持续产生有效增长 / 询盘，值得提高复用；
- 某类高成本内容长期没有对应的增长、品牌、搜索或商业资产价值。

不计算“播放 ÷ 小时”作为唯一 ROI，不为了复盘增加新的日报。

## 十一、主动优化与讨论判断

当 Suen 询问“还有什么可以讨论 / 优化”或类似问题时：

- 先基于当前真实状态判断是否存在新的、有实际价值的问题；
- 已经讨论清楚、没有新数据、没有新矛盾的事项，不为了延长对话再次包装成“可讨论点”；
- 不把已确定的执行项重新拿出来当新策略讨论；
- 有值得优化的内容时，直接指出最有价值的部分和原因；
- 如果当前没有新的高价值优化点，直接明确回复“目前没有额外值得讨论 / 优化的”，无需硬凑话题；
- 后续出现新数据、执行结果、平台变化、商业信号或规则冲突时，再主动提出真正需要讨论的问题。

## 十二、Suen 说“更新”时的唯一正式交付格式

本节是日常安排的唯一输出真源；`99-模板/每日总控模板.md` 与生产保护规则只引用本节。

### 1. 今日判断与 P0

先说明今天的主要瓶颈、改变判断的真实数据和先完成的动作：

- 有 Revenue P0：先给去身份化的客户阶段、约定动作、期限及完成条件；
- 无 Revenue P0 但有经营建设阻塞：给一个可检查产出，不虚构客户或收入；
- 其余情况：给 Content P0 或长期产品推进单元，主任务 A / B / C / D 与实际瓶颈对应。

后台检查客户交付、内容、商业、天象和长期产品，前台只展示今天需要执行、继续观察或发生变化的事项。可以用一行合并说明其它平台今日无独立生产，不逐项复制“今天不做”的空列表。

### 2. 一份主生产单元与平台安排

暂由小红书承担主要增长验证；当日强候选适合大号时可由大号生产并同步小红书。平台独立判断，优先复用已有成片 / 资料，额外生产必须值得其时间。

- 一天至多先保护一份新剪主视频；有明确价值和剩余产能时才安排第二份；
- 公众号按深度解释或资料整理价值安排长文 / 贴图 / 复用，不强制每天另找独立新题；
- 《长卷》只在问题需要完整上下文且资料足够时安排，不作为每日额外产出；
- 小号、朋友圈按真实表达和服务理解需要安排；
- Patreon 继续暂停；上海省钱情报局独立运行；
- 课程 / 数据库给具体推进单元、优先级与建议时段，默认不附专用提示词。有 Work 额度时数据库优先，实际产品范围回专用任务确定。

不因昨日漏发增加今天的视频债。跨日稿件重新核对发布状态、当前价值和用户验收；固定批次按已确认顺序推进，不自动另定题。

### 3. 发布时间与执行顺序

所有当天发布项写明确发布时间，Asia/Shanghai 默认锚点为 **20:30**。沿用 Suen 偏好；第一方稳定时段证据可覆盖，真实管理冲突可调整。单条低表现不推翻时段结论。

推进而不发布的任务按实际需要给建议时段。最后给简短执行顺序：客户履约 / 客户动作 → 经营或内容 P0 → 长期产品 → 余力任务；当天具体情况优先。

### 4. 专用对话任务词

需要专用前台内容生产时，任务下紧跟“发给【对应专用对话】”及独立代码块；不把提示词统放末尾。
