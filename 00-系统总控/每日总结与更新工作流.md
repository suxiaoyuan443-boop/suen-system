# Suen｜每日总结与更新工作流

状态：当前正式规则
最后核对：2026-09-18

本文件规定每天实际怎么运行“总结 → Suen填写台账 → 更新 → 商业总控 → 专用对话执行”。

周级商业复盘不塞进每日流程，单独读取：`每周商业复盘.md`。

---

## 一、每天中午：Suen 先说“总结”

“总结”阶段只处理已经发生的内容数据，不做当天新选题。

**这里的“总结”是商业总控 / 内容台账触发词，不触发销售私聊客户商业记录。销售私聊只有明确“生成总结”才生成客户记录。**

实际整理格式读取：

`99-模板/内容复盘台账模板.md`

### 固定步骤

1. ChatGPT 读取 Slack `#内容历史台账`，确认已经记录到哪里，避免重复或覆盖旧复盘；
2. 先确认每条内容是否**实际已经发布**，计划发布时间、已生成成品、准备今天发都不等于实际发布；
3. ChatGPT 根据当前台账和已知发布情况，告诉 Suen 今天需要补哪些平台、哪些字段；
4. 缺什么字段就明确列出来，不估算、不替 Suen 填后台数字；
5. **Suen 自己查看各平台后台，把数据填好后直接发送到 Slack `#内容历史台账`；**
6. ChatGPT 默认不代替 Suen 抄写或发送内容复盘数据到 `#内容历史台账`，除非 Suen 当次明确要求代发；
7. 抖音大号、抖音小号、小红书、公众号、朋友圈分别记录，不合并成一个“全平台”块；
8. 公众号贴图与长文必须分别记录。

因此日常“总结”阶段最省事的闭环是：

**ChatGPT 检查缺项 → Suen 直接在 Slack 填写并发送 → 填完后进入“更新”。**

如果只能确认“计划发布”，不能确认已经真正发出：

- 先标记“发布状态待确认”；
- 不把计划日期写成实际发布时间；
- 等 Suen 确认实际发布后再进入正式复盘块。

### 日期必须分三类

- **内容实际发布日期**：内容真正发出去的日期；
- **复盘日期**：这次统计数据的日期；
- **内容中提到的仪式 / 星符执行日期**：只是内容主题涉及的日期，不能代替发布日期。

例如：

一条朋友圈在 2026-09-15 发出，内容提醒 2026-09-17 木星第二星符，则台账必须写：

- 实际发布日期：2026-09-15
- 复盘日期：实际统计当天
- 涉及项目执行日期：2026-09-17（如需要记录）

不得因为内容讲 9 月 17 日就把这条朋友圈记成 9 月 17 日发布。

### 私信 / 询盘 / 成交归因

如果内容复盘块里要记录私信、有效询盘或成交，必须能可靠确认它由**当前这条内容**带来。

如果只能确认来自某个平台，不能确认具体哪条内容：

- 不塞进最近发布内容的复盘块；
- 在销售 / 商业记录里保留真实平台来源；
- 等以后有可靠归因再补具体内容。

**同一天发生不等于由同一天那条内容带来。**

有效询盘、成交、成交额、预计毛利与净利润累计统一执行：

`00-系统总控/商业指标口径.md`

不得把同一客户同一需求的连续沟通重复算成多个有效询盘，也不得把预计毛利直接写成净利润。

### 评论信号

除了评论数量，如果某条评论能帮助判断：

- 观众为什么喜欢；
- 哪里看不懂；
- 想看什么；
- 如何理解 Suen 定位；
- 有没有现实需求；
- 有没有服务认知；
- 有没有潜在商业需求；

则单列 `评论信号`。

普通无判断价值的夸赞、表情或闲聊不需要单独记录。

## 二、台账补齐后：Suen 再说“更新”

“更新”阶段必须重新读取最新 Slack，不用上一轮记忆代替实时读取。

固定读取：

1. `#内容历史台账`
2. `#商业决策总控`
3. `#天象检索与预约`

然后先诊断，再选题。

如果这是新对话 / 新会话第一次进入总控，或者 Suen 明确说 GitHub 规则更新过，还要先按 `系统架构.md` 的启动读取规则刷新 GitHub 当前正式配置。

### Slack 读取失败协议

如果某个核心频道读取失败：

1. 先根据 `07-销售与Slack/Slack架构.md` 的 **Channel ID** 重试 / 核对，不只靠频道名；
2. 仍无法读取时，明确告诉 Suen 哪一层动态数据没有读到；
3. **不得用旧记忆假装这是“刚读取的最新 Slack”。**

不同频道失败时，限制不同：

- `#内容历史台账` 读不到 → 不能声称完成了基于最新 3—7 天数据的确定性瓶颈诊断；如 Suen 要求立即继续，只能基于当前对话已有真实数据做**临时判断**，并明确数据覆盖不完整。
- `#商业决策总控` 读不到 → 不假设最新询盘、报价、成交、产品推进状态；默认不新增商业销售动作，除非 Suen 当天明确指定。
- `#天象检索与预约` 读不到 → 不新增星符 / 仪式窗口宣传，不猜是否开放预约、是否允许宣传、预约数或具体日期。

如果只是 Slack **写入失败**：

- 可以先把本应写入的标准记录完整显示给 Suen；
- 明确说“当前没有成功写入 Slack”；
- 不得声称已保存 / 已同步。

### 阶段数字先检查是否仍有效

在使用任何阶段性 KPI / 阅读基线前，先看规则日期：

- 当前 30 天商业目标是否仍在目标周期内；
- 公众号 14 天冷启动基线是否已到复核点；
- 以后新增的阶段测试是否已经过期。

如果已经超过周期、但没有新的正式版本：

- 旧数字只作为上一阶段参考；
- 不自动续期；
- 不擅自重新换算；
- 在当天判断里明确提示需要复核 / 重算。

### 商业数字必须先过统一口径

当“更新”需要引用当前周期有效询盘、成交、成交额或利润进度时，先执行：

`商业指标口径.md`

尤其检查：

- 跨平台同一客户同一需求是否重复计数；
- 报价是否被误当成交；
- 补款是否被重复算一笔成交；
- 预计毛利是否被误写成净利润；
- 归因是否只是因为“同一天发生”。

### 先判断当前主要瓶颈

结合最近 3—7 天真实表现，并参考更长周期历史基线，判断当前最主要问题属于：

- 流量
- 精准涨粉
- 服务认知
- 询盘
- 成交

同时看：

- 播放 / 阅读 / 曝光
- 点赞、收藏、评论、分享
- 涨粉、主页访问
- 私信、有效询盘、成交
- 评论信号
- 内容题型
- 最近内容体验是否过度重复
- 用户实际工作量

不拿一次爆款当正常基线。

## 三、再决定当天平台任务

当天每条正式内容尽量指定一个主要 A / B / C / D 任务：

- **A｜流量**
- **B｜精准涨粉**
- **C｜服务认知**
- **D｜商业承接**

完整定义见 `商业总控.md`。

不要让一条内容同时承担四个任务。专业信任可以作为附带效果或在理由里说明，不另外制造第五套任务体系。

### 抖音大号

当前发布基线：**每天 1 条，只发 7 个前台合集中的 1 个栏目。**

总控每天需要决定：

- 使用哪个前台合集
- 题目
- 承担任务（A / B / C / D + 中文名称）
- 为什么今天选它

7 个前台合集：文物、异录、辨伪、残页、隐理、世问、牌记。

不机械轮播。

如果今天决定大号停更，属于对当前基线的例外，必须写清真实理由，例如平台状态、内容质量、工作量或 Suen 当天明确指令；不能默认把“发不发”当成随意选择。

### 小红书

当前发布基线：**每天 1 篇 / 1 条内容。**

总控每天需要决定：

- 是否直接同步抖音同一支完整成片
- 是否需要独立《长卷》或其它内容
- 如果不按日常基线发布，为什么今天例外停更

通常优先同步当天抖音同一成片。

如果同步抖音视频：

**只算一个制作任务。**

不另外生成“小红书视频制作”对话任务；直接在当天对应的抖音栏目专用对话里，一次生成：

- 抖音完整成片
- 小红书标题
- 小红书封面文字
- 小红书配文

不重新剪第二支视频。

《长卷》不机械日更。

### 公众号

贴图与长文必须分开判断：

- 【贴图】今天是否值得承担推荐 / 陌生流量测试
- 【长文】今天是否有足够强的深度题材，是否值得投入长文工作量

公众号已经不再服从旧的机械“每天 1 长文 + 1 贴图”逻辑。

如果贴图与长文同一天都发，最多只有其中一篇可以出现轻商业信息，而且必须服从当天唯一主要商业信号；不能两篇都卖。

### 朋友圈

只有真实工作记录、客户反馈、产品过程、已确认窗口或明确商业承接需要时才安排。

不为了日更硬发，不重复提醒同一个预约窗口。

### 抖音小号

不强制日更。

### 独立项目

上海省钱情报局等独立项目不进入本流程的神秘学内容调度、有效询盘、成交或商业信号统计。

不得把星符、仪式、塔罗、数据库、课程等本项目内容塞进上海省钱情报局任务。

## 四、选题必须经过四层筛选

每次“更新”确定前台选题时，不只凭感觉。

必须结合：

1. **近期真实数据**：什么结构在当前账号上真的有效；
2. **对标账号方法**：入口、证据、解释、品牌、商业连接；
3. **Suen 100 分选题模型**；
4. **内容体验重复度**：即使栏目名不同，也要判断观众最近是不是连续在“看资料 / 看古书 / 看文献”。

高层对标规则见 `内容商业对标系统.md`；额外的“神秘感入口硬检查”见 `商业总控.md`。

其中 100 分模型的“相邻题材明显重复 -20”默认重点检查最近 **7 天**，并同时判断栏目不同但观看体验是否仍高度相似。

---

## 五、统一商业密度

长期约：

- 正常内容 80%
- 明显商业信号 20%

一天最好只有 1 个主要商业信号，最多 2 个。

最终必须写清：

- 【今日唯一 / 主要商业信号】
- 【今日明确不推】

如果当天是纯内容，不擅自加入接单、报价、预约、购买或私信 CTA。

---

## 六、天象经营状态怎么用

`#天象检索与预约` 中的：

- 已确认
- 开放预约
- 是否允许商业宣传

可以作为总控判断商业信号的依据。

但具体执行时分属于技术真源。

星符与多数仪式的预约 / 宣传边界读取 `05-天象经营/Slack天象预约池规则.md`。

### 硬规则

如果不同记录中的具体执行时刻存在冲突：

- 总控不得自行选择其中一个时间公开使用；
- 不得擅自宣传具体几点几分；
- 精确时分必须以对应择时专用对话 / 专用择时系统的最新可靠复核结果为准。

在尚未完成技术复核时，可以写：

> “9 月 17 日木星窗口已开放预约”

但不要擅自公开冲突中的具体分钟。

## 七、当天总控结论写入 Slack

完成诊断与任务分配以后，把一份简短的“今日更新总表”写入 `#商业决策总控`。

这里记录：

- 当前瓶颈
- 判断依据
- 各平台今天做什么 / 不做什么
- 每个执行内容的主任务 A / B / C / D
- 如果大号 / 小红书偏离当前日更基线，写明原因
- 今日主要商业信号
- 今日明确不推
- 必要的商业推进事项

不把日常播放、点赞明细重复复制进商业总控。

固定格式见 `99-模板/每日总控模板.md`。

---

## 八、最后只给真正需要执行的专用对话提示词

总控结论之后，只生成当天实际需要执行的平台 / 栏目提示词。

提示词结构读取：

`99-模板/专用对话执行提示词模板.md`

共同文笔底线读取：

`Suen统一文笔总则.md`

执行稳定性同时读取：

`专用对话执行验收协议.md`

总控只传递当天任务、瓶颈、题目、A / B / C / D 主任务、商业边界和运营上要优化的变量；专用对话继续执行自己的长期栏目规则。

例如：

- 大号今天发《文物》
- 小红书同步同一成片
- 公众号只发贴图
- 朋友圈不发
- 小号不发

则只需要：

1. 《文物》专用对话提示词（同时包含小红书标题 / 封面 / 配文要求）；
2. 公众号贴图专用执行提示词。

不要为“不发”的平台制造提示词，也不要把同一支视频拆成两份制作工作。

专用对话目标明确且没有真实阻塞时，应自行完成研究、成稿、文笔 QA、素材 QA 和最终交付，不应做到一半停下来等 Suen 再说“继续”。

---

## 九、最终输出原则

先给当天总控结论，保持简洁。

不要写成长篇运营报告。

除非 Suen 追问分析过程，否则最终交付优先回答：

- 今天卡在哪里
- 今天发什么
- 为什么
- 今天卖不卖
- 哪些平台需要执行
- 复制什么提示词过去
