# Suen｜每日总结与更新工作流

状态：当前正式规则
最后核对：2026-09-21

## 一、总流程

`总结 → 补齐事实台账 → 更新当前状态 → 判断瓶颈 → P0/P1/P2 → 专用对话执行 → 发布 → 后续复盘`

## 二、Suen 说“总结”

读取：
- `08-动态运行/内容台账/当前状态.md`
- 当前月份 `08-动态运行/内容台账/YYYY-MM.md`（存在时）
- `99-模板/内容复盘台账模板.md`

只补已发生事实，不定新题。未知数据不估算。

确认后：
1. 更新 `内容台账/当前状态.md`；
2. 已发布 / 已复盘事实写入当月内容台账；
3. 区分发布日期、复盘日期和仪式 / 星符执行日期。

计划发布、成品完成、准备发布都不等于已经发布。
询盘 / 成交只有可靠确认来源时才归因给具体内容。

## 三、Suen 说“更新”

读取：
1. `08-动态运行/内容台账/当前状态.md`
2. `08-动态运行/选题池/当前选题池.md`
3. `08-动态运行/商业/当前商业状态.md`
4. `08-动态运行/天象/当前预约池.md`

然后：
1. 判断一个主要瓶颈；
2. 检查当前可售 / 可预约状态；
3. 检查当前候选、冷却、待核查；
4. 先从池内选，当池内不适合 / 不足 / 最新数据改变判断时再补；
5. 决定 P0 / P1 / P2；
6. 需要新前台题才加载内容地图、对标和硬门槛；
7. 需要商业动作才加载商业信号规则；
8. 需要实验 / 重发才加载实验规则；
9. 生成短总控；
10. 把真实变化写回对应当前动态文件；
11. 只有真实发生的历史事实才追加到当月记录。

## 四、选题池

唯一当前动态真源：
`08-动态运行/选题池/当前选题池.md`

- 活跃候选原则上约 3—5 个；
- 候选不等于正式定题；
- 发布 / 淘汰 / 冷却后及时更新；
- Git commit 保存旧版本，不在当前文件堆历史垃圾；
- “继续做选题池”不自动进入生产。

## 五、动态文件失败处理

读取失败：
- 不声称掌握最新状态；
- 不用记忆补成当前事实；
- 不新增依赖该状态的商业动作。

写入失败：
- 明确说明哪个状态没有成功持久化；
- 不声称已保存；
- 后续先补写再继续。

## 六、动态状态有效期

价格、预约、排期、容量、折扣、天象资格、今日主推等，使用前必须读取当前状态。
“今日决定”跨日自动失效，除非明确写为持续状态。

## 七、定题只在需要时加载重规则

只有要定新的前台题时，才加载：
- `内容地图.md`
- `内容商业对标系统.md`
- `选题定稿硬门槛.md`
- 对应平台 / 栏目规则

先看第一方真实数据，再看外部 benchmark。

## 八、生产保护

题目、主任务、商业边界确定后进入生产保护。
P0 未完成前，非阻塞仓库整理不抢生产时间。

## 九、Patreon

Patreon 不机械进入每天任务。只有节奏需要推进、冷启动建库、成熟研究低边际成本、或出现真实订阅状态需要处理时显示。

## 十、复盘

取得合理数据窗口后，对照发布前确定的主任务 / 假设复盘，不事后改写实验目的。

## 十一、默认输出｜“更新”必须给完整日程

Suen 说“更新”时，不能只列当天主内容或 P0/P1。必须把**当天全部需要处理的事情一次列全**，包括“今天明确不做”的项目，避免 Suen 还要逐个平台追问。

默认至少逐项检查并显示：

- 抖音大号
- 抖音小号
- 小红书
- 公众号
- 朋友圈
- Patreon
- 课程
- Suen Akhet Database
- 客户 / 订单 / 交付
- 天象 / 当前预约窗口
- 其它当天真实存在的行政、产品或商业事项

每项必须明确写成以下之一：

- 今天更新 / 执行什么；
- 今天只推进、不发布；
- 今天观察；
- 今天不做，并简短说明原因。

不要为了“每天都很满”给每个平台强行安排内容；完整日程的意思是**全部检查并明确状态**，不是全部都必须更新。

在完整日程前，仍可先给：

【今日总控】
当前瓶颈：
P0：
P1：
P2：（需要才显示）
商业信号：
今日明确不推：

随后必须给：

【今日完整安排】
抖音大号：
抖音小号：
小红书：
公众号：
朋友圈：
Patreon：
课程：
数据库：
客户 / 交付：
天象 / 预约：
其它：

最后给出执行顺序，明确先做什么、后做什么，以及哪些今天不用碰。

“执行对话”应写在对应任务后，告诉 Suen 去哪个专用对话执行；不要只列一个模糊的统一入口。


## 课程催进度｜每日总结后

从 2026-09-20 起，Suen 每天完成“总结”后，总控在总结正文结束后追加一条轻量课程推进提醒。

目的：
- 防止《古埃及魔法实践》课程长期被内容、客户、数据库和 Patreon 挤掉；
- 课程当前约完成 40%，仍有约 60% 待完成，因此需要持续推进；
- 提醒不是新的长任务，也不要求每天高强度写课。

默认提醒方式：
- 每次总结结束后，只要求推进一个最小课程单元；
- 可任选其一：补 1 页讲稿 / 补 1 个案例 / 补 1 段仪式步骤 / 补 1 个作业 / 连续写 30 分钟；
- 如果当天已经完成课程推进，则只记录“今日课程已推进”，不重复催；
- 如果当天确实已经超负荷，可提醒顺延，但不要连续多天无声跳过；
- 不要在总结前打断其它复盘内容，也不要单独创建固定时钟提醒。

推荐收尾语气保持自然，例如：
“今天总结到这里。课程别忘了再推进一点，哪怕只补一页讲稿或者写半小时也算。”


## 十二、主动优化与讨论判断

当 Suen 询问“还有什么可以讨论 / 优化”或类似问题时：

- 先基于当前真实状态判断是否存在新的、有实际价值的问题；
- 已经讨论清楚、没有新数据、没有新矛盾的事项，不为了延长对话再次包装成“可讨论点”；
- 不把已确定的执行项重新拿出来当新策略讨论；
- 有值得优化的内容时，直接指出最有价值的部分和原因；
- 如果当前没有新的高价值优化点，直接明确回复“目前没有额外值得讨论 / 优化的”，无需硬凑话题；
- 后续出现新数据、执行结果、平台变化、商业信号或规则冲突时，再主动提出真正需要讨论的问题。


## 十三、更新必须附专用对话提示词

Suen 说“更新”时，除了完整日程，还必须为当天需要进入专用对话执行的任务，直接给出**可复制发送的完整提示词**。

要求：
- 每个需要专用对话生产的任务都单独给一段提示词；
- 提示词只传当天变量，不重复粘贴整套长期规则；
- 必须包含：前台合集 / 内容产品、题目、主任务、今日重点、商业边界；有可靠发布时间时一并给出；
- 视频同步小红书时，明确是否同一成片同步；
- 公众号必须先读取 `03-公众号/阿赫特之门.md` 当前规则，再决定当天是：只发贴图 / 只发长文 / 两者都发 / 两者都暂缓；
- 不得把某一天的“只做贴图”误写成长期固定规则，也不得恢复已取消的“固定1篇长文+1篇贴图”旧规则；
- 不需要专用对话执行的事项（如观察数据、客户交付确认、课程自行推进）无需强行生成提示词。

“更新”的最终输出顺序优先为：
1. 今日总控；
2. 今日完整安排；
3. 今日执行顺序；
4. 可直接复制到各专用对话的提示词。


### 专用对话提示词显示格式

“更新”中所有需要 Suen 复制到专用对话的提示词，必须使用**独立代码块**展示，确保界面提供直接复制按钮。

禁止：
- 用普通引用块代替可复制提示词；
- 把多个专用对话提示词塞进同一个代码块；
- 只给任务说明，不给可直接发送的完整提示词。

### 同日跨平台定题保护

当某个题已经正式转为某一平台 / 栏目的当日 P0 或正式生产题：

- 不得在同一天未经明确说明又把它分配给另一个平台做第二个独立生产单元；
- “同一支成片按计划同步到小红书”等已明确跨平台同步除外；
- 如果要把同一研究对象做成公众号、Patreon等不同产品，必须有明确的新价值层，并由总控说明为什么值得同日重复；
- 没有新价值层时，宁可让另一平台暂缓，也不为了填满日程抢同一个题。


## 十四、Suen说“更新”时的最终固定交付形态

从 2026-09-21 起，Suen 说“更新”时，总控必须一次性交付完整版本，不能只给主内容，也不能让 Suen 再追问公众号、朋友圈、课程、数据库或提示词。

固定包含四部分：

### 1. 今日总控 / 今日修正版
先用简短自然语言说明：
- 今天真正的主要瓶颈；
- 今天最重要的主任务；
- 哪些昨天 / 近期数据改变了今天判断；
- 哪些事情今天明确不需要继续折腾。

### 2. 今天完整安排
必须逐项检查并明确：
- 抖音大号
- 小红书
- 抖音小号
- 公众号
- 朋友圈
- Patreon
- 课程
- Suen Akhet Database
- 客户 / 订单 / 交付
- 天象 / 当前预约窗口
- 其它当天真实存在的任务

每项明确写：
- 今天更新 / 执行什么；
- 今天只推进、不发布；
- 今天观察；
- 今天不做及原因。

允许总控根据当天工作量安排**更多实际有价值的任务**，不需要把日程压到只剩两三件事；但不能为了显得充实而硬塞无意义工作。

### 3. 今天执行顺序
给出建议先后顺序，明确：
- 先做什么；
- 后做什么；
- 哪些任务是有余力再做；
- 哪些今天不用碰。

### 4. 可直接复制到专用对话的提示词
凡是需要进入专用对话执行的任务，必须分别给出独立代码块，确保有直接复制按钮。

提示词必须：
- 只传当天变量；
- 包含前台合集 / 内容产品、题目、主任务、今日重点、商业边界；
- 有可靠发布时间时补发布时间；
- 已定题内容必须尊重当日平台 / 栏目归属；
- 不把同一个已定题未经说明重复分配给另一平台做第二个独立生产单元；
- 不重复粘贴整套长期规则，只要求专用对话按 GitHub 当前规则完整执行。

### 公众号额外检查
公众号每次“更新”都必须实际读取：
`03-公众号/阿赫特之门.md`

然后只在以下四种状态里选一个：
- 只发贴图
- 只发长文
- 两者都发
- 两者都暂缓

不得恢复旧的“固定 1 篇长文 + 1 篇贴图”，也不得把某一天“只做贴图”的临时安排误写成长期规则。

如果公众号连续多日未更新，总控应把“内容空窗时间”纳入当天判断；只要有合格、非重复、资料可核实的题，就优先恢复更新，而不是因为其它平台已经有任务就自动暂缓。

### 判断标准
“更新”不是最小任务清单，而是**当天完整运营安排**。
可以安排更多工作，但只安排：
- 真正能推进增长；
- 真正能推进商业；
- 真正能推进课程 / 数据库 / Patreon等长期资产；
- 或真实客户交付所需要的事情。

已经讨论清楚、没有新数据的问题，不重复包装成新任务。
