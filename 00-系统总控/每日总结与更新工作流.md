# Suen｜每日总结与更新工作流

状态：当前正式规则  
最后核对：2026-09-19

本文件只保留日常运行流程。平台细节、商业指标、实验和文笔不在这里重复。

## 一、总流程

`总结 → 补齐事实台账 → 更新 → 读取动态状态 → 判断瓶颈 → P0/P1/P2 → 专用对话执行 → 发布 → 后续复盘`

## 二、Suen 说“总结”

目标：补齐已经发生的事实，不定新题。

步骤：

1. 读取 Slack `#内容历史台账`；
2. 确认哪些内容真的已经发布；
3. 告诉 Suen 当前缺哪些必要数据；
4. 未知数据不估算；
5. 补齐后按 `内容复盘台账模板.md` 记录。

必须区分：

- 内容实际发布日期；
- 本次复盘日期；
- 内容涉及的仪式 / 星符执行日期。

计划发布、成品完成、准备发布都不等于“已经发布”。

询盘 / 成交只有能可靠确认来源时才归因给具体内容。

## 三、Suen 说“更新”

先重新读取 Slack：

1. `#内容历史台账`
2. `#商业决策总控`
3. `#天象检索与预约`

然后：

1. 判断当前一个主要瓶颈；
2. 检查当前可售 / 可预约状态；
3. 决定 P0 / P1 / P2；
4. 如需新前台题，再读取内容地图、对标和硬门槛；
5. 如需商业动作，再读取商业信号规则；
6. 如需实验 / 重发判断，再读取内容实验规则；
7. 写当天短总控；
8. 只给真正需要执行的专用对话短交接。

## 四、Slack 读取失败

### 台账读不到

不能声称已经完成最新内容表现诊断。

### 商业决策总控读不到

不能假设最新询盘、报价、成交和当天商业决定；不新增销售动作。

### 天象频道读不到

不新增星符 / 仪式日期宣传，不猜窗口状态。

如果用户要求继续，只能明确按当前可确认信息做临时判断。

## 五、动态状态有效期

以下信息使用前必须确认今天仍有效：

- 价格
- 可售 / 可预约状态
- 排期 / 容量
- 折扣 / 套餐
- 天象宣传资格
- 今日主推 / 今日纯内容 / 今日明确不推

昨天的“今日决定”跨日自动失效。

带明确测试周期的规则到期后也不能自动续期。

## 六、定题只在需要时加载重规则

如果今天只是执行已定任务，不机械读取对标、100 分模型和所有栏目规则。

只有要定新的前台题时，才加载：

- `内容地图.md`
- `内容商业对标系统.md`
- `选题定稿硬门槛.md`
- 对应平台 / 栏目当前规则

先看 Suen 自己的真实第一方信号，再看外部 benchmark。

## 七、生产保护

题目、主任务、商业边界确定后进入生产保护。

普通文笔、配图、链接、排版、素材匹配等问题由执行对话自行解决，不因此重新推翻选题。

P0 未完成前，不用 README 美化、仓库整理等非阻塞维护抢时间。

## 八、Patreon

Patreon 不机械进入每天任务。

以下情况才在“更新”里显示：

- 本月约 4 篇内部节奏明显需要推进；
- 当前处于冷启动建库；
- 已有成熟研究 / 实践记录，今天完成边际成本低；
- 出现真实订阅、取消或付费来源需要处理。

## 九、复盘

发布后取得合理数据窗口，再回看发布前已经确定的主任务 / 假设。

不要看完结果后倒推“这条本来就是在验证什么”。

详细结果判定读取：`内容实验与验证规则.md`。
