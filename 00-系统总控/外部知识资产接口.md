状态：当前正式规则

商业运营区默认不复制独立项目完整内部规则。**数据库写作规则是 Suen 明确设置的隔离 Rule Vault 例外**：规则存在 GitHub，但不进入商业总控默认上下文。

课程是否设置正式作业、评分、练习或提交机制，不由本运营仓库定案；需要时回到课程专用真源读取最新决定。

## Suen Akhet 数据库

数据库采用“规则与内容分离”：

- **长期写作 / 验收规则真源**：`Suenakhet Database Rules/Suenakhet数据库写作完整要求.md`；
- **数据库内容本体**：Obsidian；
- Obsidian 不再维护第二份完整写作规则，避免双真源；
- 商业总控日常不读取数据库完整规则，只有数据库专用对话 / Work 执行写作时读取。

GitHub 商业运营层只需要知道当前产品状态：

- 内容载体：Obsidian；
- 对外方向：Obsidian Publish；
- 需要正式首页；
- 支持数据库单独购买；
- 支持课程 + 数据库打包；
- **购买模式尚未最终定案：一次性买断与订阅制都在评估中，不得擅自写成已经确定的订阅制；**
- 价格、访问周期、续费方式、更新承诺尚未最终定案；
- v1 须先由 Suen 确认有限发布范围，全时代扩展为长期方向；范围内证据和导航保持专用标准，先清理再重写，不靠空壳条目制造完成。

日后数据库写作规范发生变化，直接更新隔离目录中的规则真源；只有它改变产品售卖方式、交付状态或商业总控决策时，才额外同步本文件的经营层状态。
