# 迁移与冲突记录

状态：正式系统规则
最后核对：2026-09-17

## 版本优先级

发生冲突时按以下顺序判断：

1. Suen 最新明确指令
2. 当前正在运行的自动化配置
3. 最新 Slack 正式记录 / 频道结构
4. 最新专用对话长期规则
5. 当前正式母稿、规范文件
6. 旧自动化、旧 PDF、旧 GitHub 文件与历史对话

高优先级明确覆盖低优先级时，不把两个版本拼接成折中版。

## 2026-09-17 本次迁移已确认的覆盖关系

### 抖音大号栏目

旧的 5 类 / 6 栏目结构被后续规则覆盖。当前前台共 7 个合集：文物、异录、辨伪、残页、隐理、世问、牌记。`口述` 只保留为内部母类，不再作为前台合集名。

### 公众号发布频率

旧规则“收到更新固定生成 1 篇 7000+ 长文 + 1 篇贴图”已经被后续总控规则覆盖。

当前为：贴图与长文独立判断。长文实际生成时默认仍保持 7000 字以上的深度，但不机械日更；总控可以只安排贴图、只安排长文或暂缓。

### Slack 架构

2026-09-16 起正式拆分：

- `#内容历史台账`：只记内容发布与复盘事实
- `#商业决策总控`：瓶颈、任务、商业信号、询盘、报价、成交、产品推进
- `#天象检索与预约`：已筛选天象的经营状态，不存完整技术推导

9 月 16 日之前旧频道中的混合记录只作为历史，不再定义当前结构。

### 自动化

## 不迁入 GitHub 的数据

- 客户姓名、联系方式、付款资料
- 私聊完整原文
- 密码、API Key、Token、恢复码
- 每日动态播放/点赞等运营数据
- 会持续变化的天象预约人数与执行状态
- 大体积 PDF、图片、视频和 HTML 成品

这些继续留在 Slack、Library / Drive 或对应业务系统。
