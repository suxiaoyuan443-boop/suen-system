## 当前商业主线

下面的顺序与当前短期承接优先级一致；它描述“先承接什么”，不代表每天都要销售。

### 1. 塔罗 / 咨询

较轻的首次付费入口与日常现金流。

### 2. 定制仪式

核心高利润服务。依赖真实需求、执行能力与适合的时间窗口。

多数需要择时的仪式服从 `05-天象经营/天象预约池规则.md`；没有确认日期时，不为了成交虚构具体窗口或“最佳日期”。

### 3. 星符 / 特定古典魔法项目

预约型高价值项目，依赖经过确认的合适天象。

具体窗口、预约与宣传边界统一服从 `05-天象经营/天象预约池规则.md`，不能把星符当成 365 天随时执行的普通现货。

### 4. 蜂蜜罐 / 魔碗 / 护符等实物

承担视觉获客、内容素材与辅助收入。

### 5. 原典核查 / 专题研究

专业小众服务。材料成本低，以资料检索、原典定位、研究能力与可追溯结果作为价值。

### 6. 课程 + Suen Akhet 数据库

当前已经从“纯长期设想”进入**正式产品化阶段**：

- 《古埃及魔法实践》课程仍在继续完善；
- 数据库以 Obsidian 为内容载体；
- 对外方向为 Obsidian Publish；
- 需要正式数据库首页；
- **数据库必须作为可独立购买的正式产品存在，不作为课程附赠品降级处理；**
- 同时支持课程 + 数据库组合购买，但组合的作用是提高客单价与转化，不是替代数据库单卖；
- 数据库售卖模式仍需继续比较“一次性买断 / 订阅制 / 买断+更新期 / 其他组合方式”。

当前阶段优先完成：

1. 课程内容补全；
2. 数据库结构与首页；
3. 课程和数据库内容边界；
4. 数据库独立产品结构与售卖模式；
5. 课程 + 数据库组合购买机制；
6. 之后再定价格、访问周期、续费规则和正式发售节奏。

## 产品角色 ≠ 今日可售状态

上面的“商业角色”是长期产品定位，不代表今天自动可以公开销售。

如果当天要把某个产品 / 服务设成商业信号，商业总控还必须从 Suen 最新明确指令或 GitHub `08-动态运行/商业/当前商业状态.md` 确认至少这些动态事实：

- 当前是否真实可售 / 可预约；
- 实际价格是否已确认；
- 当前交付方式；
- 是否存在容量 / 排期限制；
- 是否依赖天象窗口；
- 是否允许当天公开宣传；
- 如果状态刚发生变化，是否已有最新记录覆盖旧状态。

不知道就标记“不确定 / 待确认”，不得从旧内容、旧报价或历史聊天自动推断今天仍然有效。

## 使用方式

商业总控不机械按上述顺序天天销售。

每天根据：

- 真实流量；
- 当前瓶颈；
- 咨询内容；
- 成交断点；
- 当天可售时间窗口；
- 产品是否已经准备好；
- 用户实际工作量

决定唯一主要商业信号。

一个产品“长期价值高”不等于“今天必须推”。


### 目标客户商业质量观察

当前不建立“年龄 / 城市 / 职业 / 刚毕业女生”等固定人口统计画像。商业判断优先观察真实购买行为：

- 可支配支付能力与实际成交金额；
- 现实需求强度；
- 对 Suen 的信任程度与购买方式；
- 是否重视专业判断、定制、原典依据、材料、择时和执行质量，而不只比较最低价格；
- 是否能够理解神秘学服务不做百分百现实结果保证；
- 是否存在复购或转介绍可能。

长期希望逐步吸引有稳定可支配收入、存在明确现实需求、愿意为专业服务支付数百元至千元以上的人。低价产品仍可承担首次成交、现金流和老客加购，但不把“只能几十元至一两百元消费、主要依赖最低价格决定”的人群设为品牌唯一核心商业人群。

这一层只作为目标客户的商业质量观察，不新增复杂评分，也不把当前少量样本写成已经验证完成的客户画像。

如果后续出现新的明确商业策略，Suen 最新明确指令覆盖本文件中的旧优先级。


### 当前短期商业入口顺序（2026-09-20）

Suen 已确认当前短期商业承接不做“大而全服务菜单”，而是保持清晰入口：

- 第一入口：塔罗 / 判断类咨询；
- 核心高利润：定制仪式；
- 预约型高价值：星符与特定古典魔法项目；
- 辅助收入：蜂蜜罐、魔碗、护符等实物；
- 专业小众服务：原典核查 / 专题研究；
- 中期数字资产：课程 + Suen Akhet Database；
- 订阅资产：Patreon。

对外服务说明页的目标是让陌生人知道“现在可以找 Suen 做什么”，而不是陈列全部商品。课程、数据库在正式可售前不进入当前服务页主区；价格、天象窗口和预约状态仍以当下真实状态为准。

### 检查原则

- **600 / 800 / 1000 是最低检查线，不是增长上限，也不是达到后就可以降低更新强度的“完成线”。**
- 小红书阶段目标是持续争取最大化增长：能继续涨就继续涨，能做出高潜力题就继续做高潜力题，不能因为提前达到某个月检查线就主动降频、保守选题或停止测试爆款结构。
- 月度检查点只用于判断“有没有明显掉队”，不用于限制上行空间；如果当月实际增长远超检查线，下一阶段继续沿用有效结构，而不是把节奏压回最低标准。
- 小红书是阶段主要公开增长账号；如果资源冲突，现阶段优先保护小红书的稳定更新、高质量选题和高潜力内容测试。
- 抖音小号低于100粉时只看总粉丝、单条涨粉和基础互动；过100粉后再开始读取完整粉丝画像。
- 抖音大号不因为短期低分发占用过多精力，不用“救大号”牺牲小红书、课程或数据库。
- 课程如果某月底明显掉队，总控需要提高次月课程推进频率，并继续执行每日总结后的轻量催进度。
- 数据库 10 月最重要的是“标准稳定”，不是条目数量；如果 10 月底模板仍在频繁推翻，11 月批量重写会被直接阻塞。
- Patreon 当前暂停，不纳入周产出与月度检查；恢复必须由 Suen 明确触发。
- 收入增长优先来自真实咨询、仪式、星符、实物、复购与转介绍，不用单条爆款替代经营结果。

## 每周执行框架｜2026 Q4

生效：2026-09-20

本框架用于把 Q4 目标落到每周执行，不是机械排班，也不要求每天平均分配。

### 内容前台

每周优先保证：

- 至少 1 个“小红书 / 抖音大号高上限候选位”：目标是冲更高分发与涨粉上限；
- 其余主内容优先承担稳定精准涨粉、收藏、专业识别，不要求每条都爆；
- 抖音小号至少保留真实实践 / 供奉 / 制作 / 工作现场的人格内容，不把小号做成第二个知识号；
- 朋友圈按真实业务状态发布，不机械日更；
- 有真实订单 / 实践时，优先复用真实素材，不为了内容改变实际仪式。

### 长期资产

每周最低推进：

- 课程：至少 2 个明显推进块；
- 数据库：至少 1 个深度推进块，当前优先母版 / 重写标准；
- Patreon：当前暂停，不安排周最低推进。
