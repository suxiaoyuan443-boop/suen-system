# Suen｜系统架构

状态：当前正式架构
最后核对：2026-10-08

## 一、时间基准

内容运营、动态台账、“今天 / 昨天 / 明天”默认使用 Asia/Shanghai（UTC+8）。

## 二、GitHub 双层结构

### 规则层
保存长期规则：商业总控、栏目、平台、指标、实验、对标、销售、模板。

### Revenue Engine

高客单销售的当前操作层位于 `07-销售与运行/`：
- `高客单机会漏斗.md`
- `高客单Offer与报价规则.md`
- `销售私聊规则.md`
- `客户商业记录规则.md`

每日总控按 `每日总结与更新工作流.md` 先核对履约 / Revenue P0、可售阻塞与经营建设，再安排内容或长期产品。机会漏斗只记真实客户阶段，内部建设不计成交；重要策略读取 `现实环境与商业决策规则.md`。

### 动态层
`08-动态运行/` 保存当前经营状态与月度事实：

- `00-当前总览.md`
- `内容台账/当前状态.md`
- `灵感库存/当前灵感.md`（可选辅助，不是定题真源）
- `商业/当前商业状态.md`
- `商业/现实环境观察.md`（按策略 / 渠道决策需要读取）
- `天象/当前预约池.md`

## 三、隔离 Rule Vault

独立知识项目的长期方法规则不进入商业总控常规上下文：

- `Suenakhet Database Rules/`：数据库写作 / 验收规则；
- `Tarot Judgment Rules/`：塔罗案例训练、规则提取、Suen 采用层与运行时解牌协议。

Rule Vault 不保存大型知识资产本体。数据库正文继续在 Obsidian；塔罗原始课程 / 视频 / 完整转录继续留在外部私有资料源。

商业总控默认不读取 Rule Vault，只有对应任务按需进入。

## 四、历史层

- 月度文件保存已经发生的事实；
- Git commit 保存每次修改；
- `08-动态运行/历史/` 保存迁移来源与旧系统归档；
- 历史不能覆盖当前状态。

## 五、真源优先级

**Suen 当前明确指令 > GitHub 当前正式规则 + GitHub 当前动态文件 > 月度历史 / Git commit / 旧对话 / 记忆。**

规则负责“应该怎么做”，当前动态负责“现在是什么”。

## 六、正常读取原则

普通任务先读：
1. 启动索引；
2. 商业目标；
3. 当前总览；
4. 当前任务需要的动态文件；
5. 当前任务需要的正式规则。

不默认加载迁移档案或全部历史。

## 七、动态事实路由

- 已发布 / 数据 → 内容台账
- 临时研究线索 / 灵感 → 轻量灵感库存；正式选题在当天现场判断，不保存跨日候选状态
- 询盘 / 合格机会 / 方案 / 正式报价 / 付款 / 执行 / 复购 / 转介绍 / 当前商业瓶颈 → 商业
- 已筛选天象经营状态 → 天象预约池
