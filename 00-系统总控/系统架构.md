# Suen System｜系统架构

状态：当前正式结构
最后核对：2026-09-17

## 1. GitHub｜长期规则真源

负责：

- 长期稳定规则
- 平台/栏目规范
- 商业总控与内容对标系统
- 择时筛选标准
- 模板
- 课程与数据库规则
- 重要版本历史

原则：同一主题只维护一个当前正式规则；发生重大变化时更新对应文件，并在根目录 `CHANGELOG.md` 留记录。

GitHub 不保存：客户隐私、密码、Token、API Key、付款资料、完整私聊、当前账号不存在的自动化配置、品牌视觉母版，以及不属于本仓库范围的独立项目规则。

## 2. Slack｜正在发生的经营与执行

当前核心频道分工：

- `#内容历史台账`：实际已发布内容与复盘事实
- `#商业决策总控`：瓶颈、任务、商业信号、询盘、报价、成交与产品推进
- `#天象检索与预约`：已经筛选过的天象经营状态

Slack 日常流水不需要全部复制到 GitHub。只有形成长期制度后才迁移规则。

## 3. Drive / Library｜大文件与正式内容资产

负责：

- PDF / DOCX / PPTX
- 图片 / 视频
- HTML 成品
- 课程母本
- 研究资料
- 品牌/视觉母版
- 原始素材

GitHub 保存这些资产所依赖的长期内容规则与研究规则，不替代大文件仓库。

## 4. ChatGPT｜执行与跨系统协调

ChatGPT 负责：

- 读取 GitHub 当前正式规则
- 读取 Slack 最新经营状态
- 读取 Library / Drive 正式母稿与资料
- 进行研究、分析、内容生成与版本更新
- 在用户授权范围内跨系统写回

处理长期任务前优先读 GitHub；处理“今天发生什么”再读 Slack；处理具体母稿/课程/资料内容时读 Library / Drive。

## 5. 版本冲突

发生冲突时读取 `迁移与冲突记录.md`。默认遵循：

用户最新明确指令 → 最新 Slack 正式记录 → 最新专用对话规则 → 当前正式母稿/规范 → 历史文件。

完成正式迁移后，GitHub 文件成为该主题的长期规则真源；后续新指令仍可覆盖并更新它。
