# Suen System｜系统架构

状态：当前正式结构
最后核对：2026-09-17

## 1. GitHub｜运营配置层

这个仓库的职责不是保存所有知识，而是让 **Slack + ChatGPT 的日常运营更稳定、更省事**。

负责：

- 商业总控规则；
- 平台 / 栏目长期执行规则；
- Slack 频道分工与数据结构；
- 客户商业记录流程；
- 天象经营状态接口；
- 常用模板；
- 版本变更与废弃规则审计。

不负责：

- 完整课程规则；
- 数据库完整写入规范；
- 完整技术择时；
- 研究资料正文；
- 视觉资产与大文件。

## 2. Slack｜当天经营状态

当前核心频道：

- `#内容历史台账`：实际已发布内容与复盘事实；
- `#商业决策总控`：瓶颈、任务、商业信号、询盘、报价、成交与产品推进；
- `#天象检索与预约`：已经筛选过的天象经营状态。

Slack 保存动态状态；GitHub 保存 Slack 怎么工作。

## 3. 外部知识资产层

### 课程

完整课程母本、逐页讲稿、案例规范等留在课程专用对话与 Library / Drive。

### Suen Akhet 数据库

完整数据库写入规范、仪式模板、Obsidian 页面结构等留在数据库专用系统 / Obsidian。

### 完整择时

所罗门星符、Ars Paulina、水晶显灵、PGM/PDM 等技术推导留在专用择时系统。

### 研究资料

PDF、论文、手稿、文物图、专题研究手册等留在 Library / Drive。

GitHub 只通过 `外部知识资产接口.md` 记录运营层真正需要知道的状态。

## 4. ChatGPT｜协调执行层

处理任务时按问题类型选择真源：

- 问“今天发什么 / 推什么 / 卡在哪里” → Slack + GitHub；
- 问“栏目应该怎么写” → GitHub；
- 问“课程内部怎么教” → 课程专用系统 / Library；
- 问“数据库条目怎么写” → 数据库专用系统 / Obsidian；
- 问“这个时间能不能做” → 专用择时系统；
- 问具体原典 / 文物 / 研究材料 → Library / Drive / 外部研究来源。

## 5. 版本冲突

运营规则冲突时默认：

Suen 最新明确指令 → 最新 Slack 正式记录 → GitHub 当前正式运营规则 → 历史记录。

知识资产内部规则不由本仓库裁决，回到对应专用真源处理。

## 6. 核心边界

**Slack = 今天发生什么**  
**GitHub = Slack / ChatGPT 怎么工作**  
**Obsidian / Library / Drive = 知识资产本身是什么**  
**专用择时系统 = 技术判断怎么做**
