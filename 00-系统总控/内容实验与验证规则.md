# Suen｜内容实验与验证规则

状态：当前正式规则
最后核对：2026-10-12

本文件解决一个问题：**发布内容以后，系统到底学到了什么。**

目标不是把每条内容做成复杂 A/B Test，也不是为了数据而牺牲正常创作，而是让总控在长期积累中能够区分：

- 哪些只是一次偶然高表现；
- 哪些入口 / 内容体验值得继续验证；
- 哪些已经形成重复信号；
- 哪些最终可以进入稳定结构。

完整信号强度仍读取 `内容商业对标系统.md`；制作成本读取 `生产投入产出规则.md`。

---

## 一、每条正式前台内容只设 1 个主要验证假设

原则上，新的 P0 前台内容在正式定题后、进入生产前，由总控内部写 1 个：

`主要验证假设`

P1 轻量测试如果是为了验证某个第一方结构，也必须有明确假设。

假设只用于说明：**这条内容最值得观察什么。**

不能同时把标题、时长、画面、栏目、题材、商业 CTA 等所有变化都写成“本次验证变量”。

如果一条内容同时改变很多因素，最后只能判断“这个组合表现如何”，不能假装知道其中某一个因素单独造成了结果。

### 可以不设新增实验的情况

以下情况可以写：

`主要验证：无新增实验｜执行已验证稳定结构`

例如：

- 明确的时效性通知；
- 已确认的商业承接动作；
- 必须发布的项目记录；
- 当前只是稳定复用已验证结构，没有值得单独测试的新变量。

不能为了形式强行发明实验。

---

## 二、假设必须在看到结果以前写

禁止：

- 内容数据出来以后，再倒推“其实这条是在验证 XX”；
- 数据好就把所有变化都解释成成功原因；
- 数据差就临时换一个目标指标宣布“其实成功了”。

主要验证假设必须在发布前确定。

正常保存在当月 `08-动态运行/商业/YYYY-MM.md`，必要时同步当前商业状态；不把每天具体实验写进长期规则文件。

---

## 三、最小记录格式

总控内部只需要记录：

```text
主要验证：
主任务：A / B / C / D
主要观察指标：
对照基线：最近最可比样本 / 无可靠可比样本
```

### 假设怎么写

优先使用：

> 如果这次采用【一个明确入口 / 内容体验 / 形式变化】，是否更有利于【一个与主任务对应的结果】。

例如：

- 反直觉问题入口，是否比纯对象介绍更有利于陌生人继续看；
- 人物故事型内容，是否能在保持证据强度的同时补全主页体验并提高留存；
- 第一人称结果入口，是否更适合小号的人格关注；
- 原文核查型内容，是否更容易带来收藏与精准关注；
- 低成本现场内容，是否能以更低制作负担维持有效互动。

假设写结构，不写虚假预测数字。

---

## 四、A / B / C / D 各自看什么结果

假设必须服从当天主任务，不能拿无关指标宣布成功。

### A｜流量

优先观察：

- 陌生曝光 / 播放；
- 2 秒跳出；
- 前几秒留存；
- 平均观看；
- 完播；
- 能反映“愿不愿意继续看”的平台真实指标。

播放高但留存极差，不自动等于入口结构已经验证成功。

### B｜精准涨粉

优先观察：

- 新增关注；
- 主页访问；
- 收藏；
- 深度兴趣 / 圈内识别评论；
- 同类内容后续关注意愿。

点赞高不自动等于 B 成功。

### C｜服务认知

优先观察：

- 是否出现对 Suen 能做什么 / 怎么判断 / 工作边界的正确理解；
- 相关评论与私信；
- 主页访问；
- 服务问题的自然追问。

没有 CTA 也可以完成 C。

### D｜商业承接

优先观察：

- 有效询盘；
- 报价推进；
- 成交；
- 能可靠归因到当前触点的商业结果。

点赞、播放不能替代 D 的结果指标。

---

## 四-A、获客证据与内容归因｜按实际阶段认定

`获客型`描述选题意图，不是已发生结果。复盘分清：
- **获客潜力/服务认知假设**：目标对象、疑问、证据与业务关系在定题时成立，尚未产生观众反馈。
- **服务理解回应**：实际评论/私信能看出观众理解某项适配、判断、流程或交付；点赞/收藏/主页访问只作辅助，不单独证明理解，更不计客户。
- **实际获客**：出现符合《高客单机会漏斗》定义的有效询盘，涉及真实购买需求；泛知识、同行交流、夸赞和新增好友不自动计入。
- **付款及后续结果**：报价、接受报价、付款、执行、现实反馈、复购/转介绍各按真实状态记录。询盘不当付款，普通订单不当高客单验证。

来源可靠时，A/B/C/D内容都可以记录辅助商业结果，不能因此把原来的主任务/假设事后改成D。1条有效询盘只记单样本，不推出稳定获客率或高客单公式。无相关数据时写“获客结果未知/尚未取得证据”，不反推一定无客户。

有需要且自然取得信息时，由总控从已有记录保留：最初认识Suen的渠道、促成信任或决定的内容（如客户有说明）、本次发起咨询的触点，以及推进阶段。客户自述标明自述，多个触点共同影响时保留多触点，不按最后发布的视频自动归因，不把一个客户多次沟通重复计成多人。不要求Suen每单填长表，也不为归因打断正常咨询或追问无关隐私。

当前可售服务的有效询盘与未上线课程/Database的兴趣、候补或研究需求分开。商业事实回当月商业记录/当前状态；发布及内容后验回内容台账。缺首次来源、信任触点或金额时允许未知，不由平台印象补猜。

## 五、对照基线怎么选

优先找**最近最可比的历史样本**，例如：

- 同平台；
- 同内容形式；
- 相近视频时长 / 图文形式；
- 相近账号阶段；
- 相近 A / B / C / D 主任务。

没有可靠可比样本时直接写：

`对照基线：无可靠可比样本`

然后把这次作为新基线，不为了得出结论硬找一个不相干的旧内容比较。

## 六、早期分发异常与一次重发规则

默认原则：**正式内容发布后不要因为普通的早期低流量反复删除 / 重发。**

但 Suen 已有真实历史样本：个别内容首轮分发低到明显脱离账号正常量级，删除后重新发布才恢复正常分发。因此不能把“永远不删”写成绝对规则。

执行时区分：

### 1. 正常偏低

例如仍在持续获得播放 / 浏览，只是低于平时。

处理：

- 保持在线继续跑；
- 早期只记“数据窗口太早 / 暂无法判断”；
- 不因为比预期差就删除。

### 2. 疑似异常分发

只有同时接近以下情况时，才允许考虑**一次**重发：

- 发布后约 60—90 分钟仍低到明显脱离该账号近期正常分发量级；
- 增长几乎停住，而不是单纯“表现一般”；
- 没有证据表明低流量来自明显内容错误、违规、上传故障等其它原因。

处理：

- 可以删除并重发 **1 次**；
- 重发后原则上保留在线跑完整样本，不继续连续删除试运气；
- 如果同时换账号、换时段、换标题等多个变量，后续只能把它当“组合样本”，不能声称是“重发本身”救了流量；
- 原始版本和重发版本的发布轨迹都进入台账，前一版若过早删除，不拿来判定完整时段胜负。

### 3. 必须删除

事实错误、合规 / 版权风险、严重剪辑或上传错误等真实问题，可以直接删除并记录原因。

同一成片跨大号 / 小号测试时，如果中途删除，也只算分发尝试，不重复计算制作成本。

这条规则的目标是同时避免两种误判：

- 把正常低流量误当平台异常，反复删帖；
- 把极端异常分发硬留在线上，失去一次合理重发机会。

无论哪种情况，都不保证重发后一定获得更高分发。

## 六-A、发布后数据回收｜轻量固定窗口

数据回收的目标是减少临时截图、临时解释和重复向 Suen 要数据，不建立新的日常填表负担。

### 默认窗口

对 P0、明确实验样本和明显突破近期基线的内容，优先保留三个窗口：
- **早期窗口**：发布后约 1—3 小时；主要用于判断分发是否正常，不急着判内容成败；
- **24 小时窗口**：作为单条内容第一次正式复盘的优先窗口；
- **阶段窗口**：进入最近 7 天 / 月度复盘时读取当时累计值，用于判断是否形成重复信号或长尾。

平台后台不提供某项就记 N/A，不要求 Suen 为了补齐字段额外手工计算。

### 最小回收字段

抖音大号 A 类视频优先回收：
- 播放；
- 点赞 / 评论 / 收藏 / 分享；
- 2 秒跳出；
- 5 秒完播 / 前几秒留存；
- 平均观看；
- 完播；
- 新增关注；
- 能可靠取得时再记主页访问 / 询盘。

小红书按平台实际后台优先回收：
- 曝光 / 观看；
- 封面点击；
- 平均观看 / 完播；
- 点赞 / 收藏 / 评论 / 分享；
- 新增关注；
- 主页访问；
- 能可靠归因的询盘。

其它平台只保留与该条主任务直接相关的最小字段，不强行复制抖音指标。

### 数据输入方式

优先顺序：
1. Suen 直接提供后台截图时，由总控自行读取并写入；
2. 已有动态台账存在数据时直接复用，不重复追问；
3. 缺失且会实质影响判断时才询问；
4. 不影响当前决策的缺失字段允许空着。

同一内容不同时间截图必须保留时间窗口，不能把早期值与累计值混成同一组。

## 七、结果只分 3 类

在取得合理数据窗口以后，总控把结果写成：

### 1. 支持

当前样本与主要假设方向一致，且对应主任务指标确实出现正向证据。

只能升级为：

**单样本支持**

不能因为一条内容就升级成稳定公式。

### 2. 不支持

当前样本没有出现假设预期方向，或明显出现相反结果。

不等于这个结构永久无效；需要结合题材、时长、账号阶段等判断是否值得再测。

### 3. 无法判断

常见原因：

- 样本量太小；
- 同时改了太多变量；
- 数据窗口太早；
- 平台分发明显异常；
- 缺关键后台指标；
- 有活动 / 抽奖 / 外部流量等干扰；
- 对照样本根本不可比。

`无法判断` 是允许的正式结论，不为了让实验“有结果”硬判成功或失败。

---

## 八、什么时候从单样本升级

信号升级继续执行 `内容商业对标系统.md`：

- 第一次得到支持 → `单样本信号`；
- 多个相对可比样本在同一目标指标上重复支持 → `重复信号`；
- 多个时期 / 多个平台在相同目标指标上持续支持 → 才考虑 `稳定结构`。

跨平台迁移时，平台 A 的支持只给平台 B 提供假设，不直接算平台 B 已验证。

---

## 九、复盘时不要做伪因果

单条内容结果只能说明“这个组合在这次环境下表现如何”。

尤其不要写：

- 因为用了某一句标题，所以一定爆；
- 因为换了栏目，所以一定涨粉；
- 因为视频变短，所以数据一定提高；
- 因为某个对标账号也这样做，所以这个结构已被证明。

如果一次同时改了多个重要变量，应该保存为组合样本，下一次再拆其中一个变量验证。

---

## 十、制作成本也进入验证

当存在真实制作耗时档位时，结果判断可以额外记录：

- 这个假设是否得到支持；
- 为得到这个结果用了什么制作成本；
- 是否值得按同样成本再测试一次。

这不是把内容价值简化成“播放 ÷ 小时”。

高成本内容可能承担品牌、搜索、课程资产、长期信任；低成本内容可能承担频率、互动和人格存在感。

总控最终判断的是：**这个结构是否值得继续投入相同级别的时间。**

---

## 十一、对 Suen 不增加额外填表工作

这套实验记录由总控负责。

Suen 不需要每天另外填写实验表。

Suen 只继续提供原本就需要的真实信息：

- 实际发布；
- 平台后台数据；
- 能确认的询盘 / 成交来源；
- 方便时补一个制作耗时档位。

总控自行完成：

- 发布前写主要验证假设；
- 复盘时回看假设；
- 判断支持 / 不支持 / 无法判断；
- 决定是否升级信号强度。

---

## 十二、动态运行区只保留短记录

当月商业运行记录最多增加：

```text
主要验证：一句话
主要观察：1 个主指标，必要时 1 个辅助指标
```

取得数据以后，追加：

```text
验证结果：支持 / 不支持 / 无法判断
依据：一句话
信号状态：单样本 / 重复信号 / 稳定结构 / 不升级
```

不把完整实验报告写进当前动态文件。

---

## 十三、生产保护边界

主要验证假设是为了**发布后学东西**，不是为了让生产更复杂。

确定假设以后：

- 不因为想“实验得更干净”要求 Suen 重拍大量素材；
- 不为了测试变量牺牲事实准确性和自然表达；
- 不在生产中途不断追加第二、第三个实验变量；
- 不允许实验记录重新把 P0 变成系统维护任务。

仍然执行：

**先把当天该发的内容做好，再用真实结果学习。**


---

## 十四、塔罗流量盲测与内容实验分开

Suen 如果在题目通过内容硬门槛以后额外做“会不会爆”的塔罗测试：

- 内容系统的**主要验证假设**仍按本文件独立保存；
- 塔罗的牌位、牌面、直接判断、置信度与验收条件另存于 `Tarot Judgment Rules/16-内容流量盲测与后验.md`；
- 两者都必须在结果出来以前锁定；
- 发布后用同一份真实平台数据分别验收：
  - 内容实验回答“这个结构是否值得继续测试”；
  - 塔罗后验回答“事前流量判断是否命中”；
- 不允许数据差时把内容实验目标改成塔罗命中，也不允许塔罗没中时通过事后换统计窗口救回；
- 只有多个独立样本以后，才讨论是否存在 Suen 账号内可重复的牌面—流量关系。

这两套记录可以使用同一条内容，但**不能互相替代**。
