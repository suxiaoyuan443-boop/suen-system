# Slack｜内容历史台账规则

状态：当前正式规则
最后核对：2026-09-18

## 对应频道

Slack `#内容历史台账`

## 职责

只记录各平台**实际已经发布**的内容及其复盘事实数据，为商业总控提供输入。

2026-09-16 以前的频道历史包含旧商业总控混合记录；2026-09-16 起只新增内容表现数据。

## 运营时区

内容发布日期、复盘日期和发布后时长默认按：

**Asia/Shanghai（UTC+8）**

计算。

除非 Suen 当次明确指定其它时区，不因为设备、VPN、系统估算位置变化而自动改用日本时间、UTC 或其它时区。

## 可以记录

- 平台
- 栏目/合集
- **抖音小号主内容类型**：用于后台分析观看体验，不是前台栏目；类型定义读取 `01B-抖音小号/小号规则.md`
- **抖音小号内容形式**：视频 / 图文；视频能取得时记录时长，图文能取得时记录图片数
- **抖音小号入口结构（可选）**：用于分析第一眼 / 第一问怎么进入，例如反直觉问题、第一人称观点 / 结果、祈愿参与、视觉对象展示、现场过程、客订 / 反馈结果
- **小红书后台历史内容角色（可选）**：研究知识 / 实践与祭坛 / 教程方法 / 个人观点经验 / 祈愿参与 / 器物与客订；定义读取 `02-小红书/README.md`
- **小红书内容形式（可选）**：视频 / 图文 / 长文（长卷）
- **小红书入口结构（可选）**：视觉异常 / 奇怪对象、反直觉机制问题、原文 / 来源到底写了什么、现实判断 / 大众默认判断、实操教程、第一人称经验 / 结果、祈愿参与、器物 / 客订展示
- **主题标签（可选）**：例如古埃及、Bastet、Solomon、Hoodoo、阿拉姆魔碗、天使、塔罗等；与主内容类型分开
- **制作耗时档位（可选）**：用于投入产出判断；统一口径读取 `生产投入产出规则.md`
- 实际标题
- 实际发布时间
- 复盘日期
- 统计阶段，例如发布后约 17—18 小时、41—42 小时
- 播放/浏览/曝光
- 点赞、评论、收藏、分享
- 新增粉丝、主页访问
- 封面点击率 / 进入率（平台可见时）
- 2 秒跳出率、5 秒完播率、平均播放时长、完播率等平台可见指标
- 由该条内容直接带来的私信、有效询盘、问价、成交等事实结果
- **询盘 / 成交对应内容**：能够确认来源时，记录具体是哪一条内容带来的，不只写平台名
- 已确认的外部真实反馈
- **评论信号**：能帮助判断观众为什么喜欢、哪里看不懂、想看什么、如何理解 Suen 定位、有没有现实需求/服务认知/潜在商业需求的评论

## 制作耗时 / 生产单元规则

制作耗时只用于判断：**什么内容值得 Suen 花时间做。**

统一档位：

- 30分钟以内
- 30—60分钟
- 1—2小时
- 2—4小时
- 4小时以上
- 不知道 / 未记录

使用边界：

- 不要求精确到分钟；
- 只记录 Suen 知道或能大概判断的真实耗时，系统不得自行估算；
- 通常只在一条内容第一次进入台账时记录一次，后续 41—42 小时或更晚复盘不重复询问；
- 历史旧内容不要求大规模补录，不记得就不追溯；
- 抖音大号与小红书同步同一支完整成片时，视为同一个主要生产单元，主制作耗时只记一次；
- 小红书只改标题、封面文字和短配文时，不再重复计算一份完整制作耗时；
- 如果另外独立做《长卷》、图文、重新研究或明显重剪，才作为新的生产投入；
- 制作耗时的完整定义与投入产出判断读取 `生产投入产出规则.md`。

## 抖音小号后台标签规则

小号不建立大号式固定前台栏目，但为了以后比较不同观看体验，已发布内容优先记录一个 `内容类型`。

当前主类型统一读取 `01B-抖音小号/小号规则.md`，包括：

- 观点经验
- 机制解释
- 实践现场
- 神明供奉
- 器物制作
- 祈愿互动
- 商业证明

同时根据数据可取得情况记录：

- `内容形式`：视频 / 图文；
- `入口结构`：可选，用于分析开头和第一眼；
- `主题标签`：文化、神明、传统、器物、目标等主题信息。

使用规则：

- 一条内容只选 1 个主内容类型；
- 类型判断看观众实际在看什么体验，不按文化 / 神明 / 产品名分类；
- 入口结构与内容类型分开，同一类型可以使用不同入口；
- 文化、神明、传统、器物等另写 `主题标签`；
- 仅凭标题无法可靠判断的历史内容标“待确认”，不强行归类；
- 视频和图文的数据指标不同，比较表现时先在相近形式 / 相近统计窗口内比较；
- 视频的完播率 / 2 秒跳出率与图文的划走率 / 文案展开率不得直接当成同一个指标横比；
- 这些标签只用于后台复盘，不要求前台展示，也不要求机械轮播。

## 小红书后台分析标签规则

小红书当前前台仍使用 `7 个视频合集 + 独立长卷`，但为了连续学习账号历史，不把所有历史和新内容只压成前台合集。

需要分析时可记录：

- `历史内容角色`：研究知识 / 实践与祭坛 / 教程方法 / 个人观点经验 / 祈愿参与 / 器物与客订；
- `内容形式`：视频 / 图文 / 长文（长卷）；
- `入口结构`：视觉异常 / 奇怪对象、反直觉机制问题、原文 / 来源到底写了什么、现实判断 / 大众默认判断、实操教程、第一人称经验 / 结果、祈愿参与、器物 / 客订展示；
- `主题标签`：文化、神明、传统、器物、产品等具体主题。

使用边界：

- 这些字段是后台分析维度，不替代前台 `合集`；
- 不要求每条同步视频都人工补齐所有标签，标题与成片足够判断时由总控 / 复盘自行归类；
- 判断不稳时写“待确认”或直接省略，不为填表增加 Suen 工作；
- 视频、图文、长卷先在相近形式与相近统计窗口内比较，再总结跨形式规律；
- 浏览高、收藏高、涨粉高、询盘强分别看，不用单一指标代表“小红书表现好”；
- 当前完整定义读取 `02-小红书/README.md`。

## 不在这里记录

- 当日选题决策
- 商业策略与平台任务分配
- 客户完整聊天原文
- 天象技术推导或窗口安排
- 尚未发生的预测数据
- **仅“计划发布”但尚未确认真正发出的内容**

这些分别进入 `#商业决策总控`、销售记录系统或 `#天象检索与预约`。

## 发布时间分析规则

- 新内容只要后台可见，优先记录精确到分钟的实际发布时间；
- 时间统一换算为 Asia/Shanghai；
- 旧内容不要求大规模补录，已有可靠截图时可以补；
- 发布时间进入分析时，必须与内容类型 / 形式 / 统计窗口一起比较；
- 单条爆款不能直接证明某个小时最好；
- 当前各平台时段基线与挑战点统一读取 `平台发布时间与时段实验规则.md`。

## 实际发布硬规则

`计划发布时间`、`预计今天发`、`已经生成成品`、`已经准备好` 都不等于“实际已发布”。

只有有可靠依据确认内容已经真正发出，才进入正式发布台账并填写实际发布时间。

如果只能确认计划、不能确认已发布：

- 不把计划日期写成实际发布时间；
- 不为了补齐当天台账而猜测发布状态；
- 可以在总结时标记“发布状态待确认”，待 Suen 补充后再写入正式发布记录。

## 日期规则

必须严格区分三类日期：

1. **内容实际发布日期**：内容真正发出去的日期；
2. **复盘日期**：这次统计数据的日期；
3. **内容中提到的仪式 / 星符执行日期**：只是内容主题涉及的项目日期，不能代替发布日期。

三类日期默认都先按 Asia/Shanghai 判断内容运营日历日；其中仪式 / 天象的技术时间仍以对应专用择时系统为准。

例如 2026-09-16 复盘 2026-09-15 发布的内容，应明确写：

- 复盘日期：2026-09-16
- 发布时间：2026-09-15
- 统计阶段：发布后约 17—18 小时

如果这条内容讲的是 2026-09-17 木星第二星符，9 月 17 日仍然只是“涉及项目执行日期”。台账发布时间必须保持 9 月 15 日，不能因为主题讲 9 月 17 日就改成 9 月 17 日发布。

隔日再次复盘同一内容时，不改原发布时间，只增加新的复盘时间点。

## 询盘 / 成交归因

如果能够从私信入口、客户原话、店铺来源、评论跳转或其它可靠信息确认某次询盘来自具体内容，台账应尽量写清：

- 询盘来源平台；
- 对应具体内容 / 题目；
- 是否有效询盘；
- 是否继续报价 / 成交。

如果只能确认来自某个平台，不能确认具体内容，就只写到平台层，不擅自归因给最近一条内容。

**“当天发过这条内容”不等于“当天询盘就是这条带来的”。**

## 评论信号

不是每条评论都要单独记录。

只有评论能帮助以后判断以下问题时，才增加 `评论信号`：

- 观众为什么喜欢；
- 哪里看不懂；
- 想看什么；
- 如何理解 Suen 的定位；
- 有没有现实需求；
- 有没有服务认知；
- 有没有潜在商业需求；
- 是否暴露出稳定的长期兴趣人群；
- 是否出现圈内 / 实践者 / 从业者 / 深度爱好者识别信号。

### 常见评论信号类型

- **选题需求信号**：主动要求“多说一些更神秘的真实事物”等，说明观众希望继续看某类题材。
- **理解门槛信号**：“没看懂这页原文 / 不知道看哪里”，说明资料本身可以保留，但导航和带看要更简单。
- **品牌认知信号**：认可“认真资料、不是乱讲 / 不做伪史”，说明“神秘内容 + 真实证据 + 认真解释”的差异正在被观众识别。
- **长期兴趣受众信号**：观众明确表达自己长期喜欢历史、宗教、死亡观念、魔法、仪式、文物、原典等，说明这类内容可能吸引长期精准受众，而不只是单条猎奇流量。
- **圈内 / 实践者识别信号**：如果公开账号信息能明确看出对方本身在做神秘学、仪式、蜡烛、塔罗等相关内容，并对星符、原典、古典魔法内容产生正向反馈，可以记录为圈内 / 实践者识别。
- **商业需求信号**：明确问价格、能不能处理、服务内容等；但是否构成有效询盘仍按销售规则判断。

### 两个边界

1. **圈内 / 实践者识别 ≠ 潜在客户。** 这首先说明内容正在被专业圈 / 深度爱好者识别，主要用于判断精准涨粉和专业定位。
2. **普通夸赞 ≠ 评论信号。** 只有当“喜欢 / 支持”等评论结合账号身份、具体内容偏好或明确判断价值时，才需要单独记录；否则只计入评论数量。

## 平台拆分

抖音大号与抖音小号必须独立记录，不能合并成一个“抖音”块。没有发布的平台明确写“未发布”。

抖音大号记录前台栏目；抖音小号记录后台 `内容类型`，并在有价值时补 `内容形式 / 入口结构 / 主题标签`，两者不是同一套分类系统。

小红书记录前台合集；在有分析价值时再补 `历史内容角色 / 内容形式 / 入口结构 / 主题标签`，这些后台维度不替代前台合集，也不要求 Suen 手工逐条维护。

公众号贴图与长文也要分开记录和判断，不能把贴图的推荐表现当成长文已经获得自然分发。

## 真实性

只记实际发生的数据。未知字段留空或写“不知道/未找到”，不为了表格完整而估算或补写。

每日“总结 → 补齐 → 写入台账”的完整流程见 `每日总结与更新工作流.md`。

实际整理时使用 `99-模板/内容复盘台账模板.md`，按平台删减无意义字段，不要求为了模板完整保留一排空项。
