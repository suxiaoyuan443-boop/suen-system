# GitHub｜内容历史台账规则

状态：当前正式规则  
最后核对：2026-10-10

当前动态文件：`08-动态运行/内容台账/当前状态.md`

月度事实文件：`08-动态运行/内容台账/YYYY-MM.md`

职责：记录真实发布与复盘事实；为追溯当前质量状态，也可分项记录已发生的制作交付、用户反馈与验收。生产记录不得计入发布样本，为商业总控提供可区分的一手事实。

## 一、时间

运营默认时区：**Asia/Shanghai（UTC+8）**。

必须区分：

1. 内容实际发布日期；
2. 本次复盘日期；
3. 内容涉及的仪式 / 星符执行日期。

第三项不能替代发布时间。

## 二、什么才能进台账

只有确认已经真实发布的内容才能作为正式发布记录。已交付HTML / 素材包、用户质量反馈与验收结果属于生产事实，另标记录类型、发生日、补录日和版本范围；不据这些事实新增发布、涨粉、询盘或收入。明确事实的即时写回触发统一执行 `每日总结与更新工作流.md` 四-A，不以用户再次说“总结”为前提。

以下都不等于已发布：

- 计划发布时间；
- 成品已经生成；
- 已排稿 / 准备发布。

不确定时写：

`发布状态：待确认`

不猜发布时间。

## 三、平台必须拆开

- 抖音大号与小号独立记录；
- 公众号贴图与长文独立记录；
- Patreon 公开帖与付费帖区分；
- 已明确未发布的平台可标“未发布”；没有该平台发布信息时写“待确认”，不能将缺记录视为未发布。

抖音大号记录前台栏目。

抖音小号、小红书的后台内容类型 / 角色 / 入口结构等定义回各自平台规则；只有有分析价值时记录，不要求 Suen 手工补齐所有标签。

## 四、记录字段

按平台实际能取得的数据选择：

- 平台、栏目 / 合集、题目；
- 实际发布时间、复盘日期、发布后时长；
- 播放 / 浏览 / 曝光；
- 点赞、评论、收藏、分享；
- 新增粉丝、主页访问；
- 平台特有留存 / 点击 / 完播等指标；
- 制作耗时档位（已知时）；
- 评论信号；
- 具体问题 / 服务兴趣信号（真实出现时）；
- 能可靠归因的私信、有效询盘、成交。

未知字段省略或写“不知道 / 未找到”，不得估算。

## 五、制作耗时

统一档位：

- 30分钟以内
- 30—60分钟
- 1—2小时
- 2—4小时
- 4小时以上
- 不知道 / 未记录

规则：

- 只记 Suen 知道的真实粗档位；
- 通常首次复盘记录一次；
- 历史旧内容不追问补录；
- 抖音大号 + 小红书同一支成片视为一个主要生产单元，只记一次主制作耗时；
- 独立长卷、图文、明显重剪 / 重新研究才算新的生产投入。

完整投入产出口径读取 `生产投入产出规则.md`。

## 六、询盘 / 成交归因

只有能从入口、客户原话、店铺来源、评论跳转等可靠确认时，才把询盘 / 成交归到具体内容。

只能确认平台、不能确认具体内容时，只记平台来源。

**同一天发生 ≠ 由当天最近一条内容带来。**

## 七、评论信号

只记录会影响以后判断的评论，例如：

- 想继续看什么；
- 哪里看不懂；
- 对真实资料 / 品牌定位的识别；
- 长期兴趣受众 / 圈内实践者识别；
- 现实服务需求 / 问价。

普通夸赞只计评论数。

圈内识别 ≠ 潜在客户。

“具体问题 / 服务兴趣信号”只在真实出现时记录，例如：
- “这种情况你会怎么判断？”
- “这个能不能做？”
- “你接不接这种需求？”
- 询问价格 / 时间 / 执行条件。

它可以帮助定位“精准兴趣 → 服务认知 → 有效询盘”之间的断点，但不能自动算有效询盘。

## 八、比较边界

- 视频与图文先在相近形式 / 统计窗口内比较；
- 视频完播率不能和图文划走率直接横比；
- 单条爆款不能证明某个发布时间或结构永久最好；
- 公众号未满约24小时，不得把当前阅读写成“24h阅读”。

## 九、边界

这里不记录：

- 当日选题决策；
- 商业调度；
- 客户完整聊天；
- 天象技术推导；
- 尚未发生的数据。

实际复制格式读取：

`99-模板/内容复盘台账模板.md`
