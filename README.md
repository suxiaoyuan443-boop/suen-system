# Suen System

Suen 的 **Slack / ChatGPT 商业运营配置仓库**，同时允许保存少量与运营系统**严格隔离的长期规则备份区**。

**当前状态：2026-09-19 已稳定为“商业运营配置 + 隔离规则库”的双区结构。商业总控默认只读取运营区；数据库等独立规则只有在对应专用任务中才读取。**

如果使用 **Codex / ChatGPT / 其它仓库执行器** 修改本仓库，先读根目录：

`AGENTS.md`

它只负责告诉执行器“先读什么、什么不能擅自改、修改后怎么做一致性检查”，不替代下面的正式业务规则。

## 这个仓库负责什么

只保存会直接影响日常运营的长期配置：

- 商业总控怎么判断瓶颈与分配任务；
- 总控 P0 / P1 / P2 优先级、生产保护与短交接；
- 商业信号、商业密度、跨平台重复销售与动态状态有效期；
- 每天“总结 → 台账 → 更新 → 商业总控 → 专用对话”的执行流程；
- 每周商业复盘怎么做；
- 有效询盘、成交、利润等商业指标怎么算；
- 内容制作耗时、同一生产单元与投入产出怎么判断；
- 正式前台内容如何设置主要验证假设、复盘结果并升级第一方信号；
- 各平台 / 栏目长期执行规则；
- Suen 跨平台共同文笔底线；
- 规则读取、执行验收和成稿 QA；
- 视频“口播 ↔ 直接图片”的统一交付格式；
- Slack 各频道怎么分工；
- 客户商业记录怎么写；
- 天象筛选结果如何进入 Slack 经营层；
- 常用模板；
- 新旧规则版本与废弃记录。

## 这个仓库不负责什么

以下内容有自己的专用真源，不在这里复制完整规则：

- 《古埃及魔法实践》完整课程规则、逐页讲稿、案例标准；
- Suen Akhet 数据库正文、神明页、仪式页、文物页和 Obsidian 实际内容；
- 所罗门星符、Ars Paulina、水晶显灵、PGM/PDM 等完整技术择时；
- 研究资料正文、PDF、手稿、文物图、课程母本；
- 品牌视觉规范；
- 不属于本仓库范围的独立项目，如上海省钱情报局；
- 独立项目自己的自动化提示词、任务状态与通知配置；
- 单条内容专属的一次性素材包工作流 / GitHub Action；
- 未经 Suen 确认存在的自动化，不在仓库里擅自虚构；
- 客户隐私、密码、API Key、Token、付款资料；
- 每日临时数据和完整聊天原文。

**“不纳入本仓库”不代表该项目或自动化不存在。**例如上海省钱情报局属于独立商业项目，其真实自动化状态应在对应任务 / 专用系统中读取，而不是由本仓库代替保存。

这些内容分别留在 **专用对话 / Obsidian / Library / Drive / 专用择时系统 / 对应自动化系统**。

### 例外：隔离规则库

为了避免长对话结束后丢失工作方法，本仓库允许保存**独立项目的长期写作 / 执行规则**，但必须放在根目录的隔离命名空间中，并满足：

- 不进入商业总控默认启动读取集；
- 不参与内容平台日常调度；
- 不与 Slack 当日经营状态混用；
- 不保存数据库正文、客户数据、PDF / 图片等知识资产本体；
- 对应项目只保留一份规则真源，避免 GitHub 与 Obsidian 同时维护两套。

当前隔离规则库：

- `Suenakhet Database Rules/`：数据库写作与验收规则真源；数据库正文仍在 Obsidian。

## 最简单的理解

- **Slack**：今天发生了什么
- **GitHub 运营区**：Slack / ChatGPT 商业系统应该怎么工作
- **GitHub 隔离规则库**：独立项目长期工作规则，按需读取，不进入总控默认上下文
- **Obsidian / Library / Drive**：知识资产本身是什么
- **专用择时系统**：完整技术判断怎么做
- **独立项目 / 自动化系统**：保存各自项目的真实任务状态

## 怎么判断有没有旧规则污染

同时看：

1. `00-系统总控/废弃规则清单.md`
2. `00-系统总控/迁移与冲突记录.md`
3. `CHANGELOG.md`
4. 当前正式规则文件

历史说明可以提旧规则，但必须明确标注为“旧规则 / 已覆盖 / 不再执行”。

# 外部知识资产

课程、完整择时等项目在 `00-系统总控/外部知识资产接口.md` 只记录**经营层需要知道的状态和读取位置**。

数据库是当前明确例外：**数据库内容本体在 Obsidian，数据库长期写作规则真源保存在本仓库隔离目录 `Suenakhet Database Rules/`。**商业总控默认不读取这套规则。

# 版本原则

1. GitHub 运营区维护商业运营配置；独立项目规则只有在明确隔离的 Rule Vault 目录中才允许保存。
2. 同一运营主题只保留一个当前正式规则文件。
3. 新规则覆盖旧规则时，同时更新正式文件、废弃规则清单与 CHANGELOG。
4. 动态数据留在 Slack，不进入 GitHub。
5. 知识资产内部规则发生变化，如果不影响运营和售卖，不需要同步到这个仓库。
6. 没有最终定案的商业参数标注“暂定 / 待定”，不擅自作决定。
7. 视频、成稿、专用对话的执行规则优先引用统一协议，不在多个栏目重复维护互相冲突的副本。
