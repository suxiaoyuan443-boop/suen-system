# Suen System

Suen 的 **Slack / ChatGPT 商业运营配置仓库**。

**当前状态：2026-09-17 已恢复到最初定位——帮助 Slack 和日常运营更省事，不再承担课程、数据库、完整技术择时等知识资产的完整真源。**

## 这个仓库负责什么

只保存会直接影响日常运营的长期配置：

- 商业总控怎么判断瓶颈与分配任务；
- 每天“总结 → 台账 → 更新 → 商业总控 → 专用对话”的执行流程；
- 各平台 / 栏目长期执行规则；
- Suen 跨平台共同文笔底线；
- Slack 各频道怎么分工；
- 客户商业记录怎么写；
- 天象筛选结果如何进入 Slack 经营层；
- 常用模板；
- 新旧规则版本与废弃记录。

## 这个仓库不负责什么

以下内容有自己的专用真源，不在这里复制完整规则：

- 《古埃及魔法实践》完整课程规则、逐页讲稿、案例标准；
- Suen Akhet 数据库完整写入规范、神明页、仪式页、Obsidian 结构；
- 所罗门星符、Ars Paulina、水晶显灵、PGM/PDM 等完整技术择时；
- 研究资料正文、PDF、手稿、文物图、课程母本；
- 品牌视觉规范；
- 不属于本仓库范围的独立项目，如上海省钱情报局；
- 当前不存在的定时自动化规则；
- 客户隐私、密码、API Key、Token、付款资料；
- 每日临时数据和完整聊天原文。

这些内容分别留在 **专用对话 / Obsidian / Library / Drive / 专用择时系统**。

## 最简单的理解

- **Slack**：今天发生了什么
- **GitHub**：Slack / ChatGPT 应该怎么工作
- **Obsidian / Library / Drive**：知识资产本身是什么
- **专用择时系统**：完整技术判断怎么做

## 怎么判断有没有旧规则污染

同时看：

1. `00-系统总控/废弃规则清单.md`
2. `00-系统总控/迁移与冲突记录.md`
3. `CHANGELOG.md`
4. 当前正式规则文件

历史说明可以提旧规则，但必须明确标注为“旧规则 / 已覆盖 / 不再执行”。

# 外部知识资产

课程、数据库、完整择时等项目只在 `00-系统总控/外部知识资产接口.md` 记录**经营层需要知道的状态和读取位置**，不复制完整内部规则。

# 版本原则

1. GitHub 只维护运营配置，不复制独立知识项目的完整规则。
2. 同一运营主题只保留一个当前正式规则文件。
3. 新规则覆盖旧规则时，同时更新正式文件、废弃规则清单与 CHANGELOG。
4. 动态数据留在 Slack，不进入 GitHub。
5. 知识资产内部规则发生变化，如果不影响运营和售卖，不需要同步到这个仓库。
6. 没有最终定案的商业参数标注“暂定 / 待定”，不擅自作决定。
