# Suen System

Suen 的长期规则、内容商业系统、平台栏目、择时规范、研究方法、课程与数据库规则总仓库。

**当前状态：2026-09-17 第二轮完整性校正已完成，进入持续维护。**

## 这个仓库负责什么

- 保存长期稳定规则的**当前正式版本**；
- 保存重要规则调整的版本记录；
- 为 ChatGPT / Slack 提供统一规则真源；
- 避免同一规则散落在不同对话、Slack 消息和旧文件中。

## 怎么判断有没有旧规则污染

不要只看某个文件“像不像最新版”，而是同时看：

1. `00-系统总控/废弃规则清单.md`：明确登记哪些旧规则已经退役、由什么新规则替代、正式真源在哪；
2. `00-系统总控/迁移与冲突记录.md`：记录新旧版本发生过哪些覆盖；
3. `CHANGELOG.md`：记录每次长期规则变更；
4. 当前正式文件本身。

**历史文件可以提到旧规则，但必须明确写成“旧规则 / 已覆盖 / 历史 / 不再执行”。**

如果一条旧规则仍在正式规则文件里像当前指令一样出现，就视为审计失败，需要修正。

2026-09-17 已建立第一版废弃规则登记表，对 15 类已知旧规则完成审计。

## 不放什么

- 客户姓名、联系方式、付款信息、完整聊天原文等隐私数据；
- 密码、API Key、Token、恢复码等密钥；
- 每日临时聊天记录；
- 每日播放/点赞/预约人数等动态经营数据；
- 当前账号并不存在的定时自动化配置；
- 品牌视觉母版与视觉规范；
- 上海省钱情报局等不属于本仓库当前范围的独立项目；
- 大体积 PDF、图片、视频、HTML 成品。

## 系统分工

- **GitHub**：长期规则、平台栏目、总控逻辑、模板、择时规范、课程/数据库规则、版本记录；
- **Slack**：当日执行、内容复盘、商业状态、询盘/成交、天象经营状态；
- **Drive / Library**：课程母本、研究资料、PDF、图片、视频、HTML、视觉母版与原始素材；
- **ChatGPT**：读取规则、分析、研究、跨系统整理与更新。

详细结构见 `00-系统总控/系统架构.md`。

# 版本原则

1. 同一主题只保留一个当前正式规则文件；模板与索引可以引用它，但不另造第二套规则。
2. 新规则明确覆盖旧规则时，更新正式文件并记录到 `CHANGELOG.md`。
3. 从 Slack、专用对话或 Library 迁移内容时，先判断新旧版本和适用范围。
4. 动态数据留在业务系统；GitHub 只保留长期规则。
5. GitHub 文件成为长期规则真源后，Suen 后续新的明确指令仍然可以覆盖并更新它。
6. 没有最终定案的商业参数明确标注“暂定 / 待定”，不为了系统完整擅自作决定。
7. 每次废弃长期规则时，同时更新 `废弃规则清单.md`，避免旧版本重新进入正式文件。
