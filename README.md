# Suen System

Suen 的长期运营规则仓库，采用两区结构：

- **运营区**：商业总控、平台、动态运行、销售、Patreon、天象经营、模板。
- **隔离 Rule Vault**：独立项目的长期工作规则。当前包括 `Suenakhet Database Rules/` 与 `Tarot Judgment Rules/`。

数据库正文仍在 Obsidian；塔罗原始课程、完整视频与大段转录仍保存在外部私有资料源。Rule Vault 只保存长期方法、验收规则、数据结构与可复用工作流。

## 当前商业运行顺序

当前路线为研究品牌、少数现有服务现金流验证、一个有限知识产品和受保护数据库研究。总控先核对现金安全、已付款履约与Revenue P0；无紧急动作时按证据缺口选择一份经营验证、知识产品、内容或研究主单元，不默认每天新视频。目标回 `00-系统总控/商业目标与产品优先级.md`，日常格式回 `00-系统总控/每日总结与更新工作流.md`，知识单元回 `07-销售与运行/有限知识产品验证规则v1.md`。

经营方案同时读取 `00-系统总控/现实环境与商业决策规则.md` 与 `08-动态运行/商业/现实环境观察.md`；重要策略依最新可取得资料、实际客户、平台许可和完整经济性判断。

高客单销售不再只看“有效询盘 → 报价 → 成交”，而按机会阶段记录：有效询盘 → 合格机会 → 信息完整 → 方案适配 → 正式报价 → 决策 → 付款 → 执行 → 结果跟踪 → 复购 / 转介绍。

详细规则读取：
- `07-销售与运行/高客单机会漏斗.md`
- `07-销售与运行/高客单Offer与报价规则.md`

## 版本原则

1. 同一主题只保留一个正式真源；其它文件只引用，不复制完整规则。
2. 动态数据写入 GitHub `08-动态运行/`，与长期规则分目录保存。
3. 新规则覆盖旧规则时，更新唯一真源与 `CHANGELOG.md`；旧文件如果已无运行价值，直接删除。历史追溯使用 Git commit / CHANGELOG，不在工作树继续维护“废弃规则副本”。
4. 未确认的价格、KPI、天象、自动化、售卖方式不得自行定案。
5. 客户隐私、支付信息、密码、Token 不进入仓库。
6. 商业总控默认不得读取隔离 Rule Vault；数据库任务才读取 `Suenakhet Database Rules/`，塔罗解牌 / 训练 / 《牌记》案例判断任务才按需读取 `Tarot Judgment Rules/`。
7. 原始课程视频、完整课程字幕、版权资料、客户可识别信息、Token 与网盘凭证不得进入本仓库。
8. 新对话接管以“读对相关规则”为标准，不以“读完整个仓库”为标准。

仓库维护入口：`AGENTS.md`。
