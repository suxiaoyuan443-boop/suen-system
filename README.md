# Suen System

Suen 的长期运营规则仓库，采用两区结构：

- **运营区**：商业总控、平台、Slack、销售、Patreon、天象经营、模板。
- **隔离 Rule Vault**：独立项目的长期工作规则。当前包括 `Suenakhet Database Rules/`。

数据库正文仍在 Obsidian；Rule Vault 只保存数据库写作 / 验收规则。

## 新商业总控从哪里开始

不要全文读取仓库。

固定先读：

1. `00-系统总控/总控启动索引.md`
2. `00-系统总控/商业目标与产品优先级.md`
3. Slack 三个动态频道

再由启动索引按任务加载需要的规则。

## 真源分工

- **Slack**：今天发生了什么、当前动态状态。
- **GitHub 运营区**：商业系统、平台和 ChatGPT 应该怎么工作。
- **GitHub Rule Vault**：独立项目长期工作规则，按需读取。
- **Obsidian / Library / Drive**：内容资产、研究资料、数据库正文。
- **专用择时系统**：完整技术判断。
- **独立自动化系统**：各自任务状态。

## 版本原则

1. 同一主题只保留一个正式真源；其它文件只引用，不复制完整规则。
2. 动态数据放 Slack，不写进 GitHub 长期规则。
3. 新规则覆盖旧规则时，更新真源与 `CHANGELOG.md`；旧规则可能污染执行时再更新废弃记录。
4. 未确认的价格、KPI、天象、自动化、售卖方式不得自行定案。
5. 客户隐私、支付信息、密码、Token 不进入仓库。
6. 商业总控默认不得读取数据库 Rule Vault；数据库任务才读取。
7. 新对话接管以“读对相关规则”为标准，不以“读完整个仓库”为标准。

仓库维护入口：`AGENTS.md`。
