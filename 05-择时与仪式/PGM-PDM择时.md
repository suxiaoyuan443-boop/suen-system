# PGM / PDM｜原典先行择时

状态：当前正式规则
最后核对：2026-09-17
默认外部天象地点：上海（Asia/Shanghai）

## 适用范围

用于 PGM、PDM 以及同一希腊—埃及语境中的具体 magical recipe。

## 第一原则：先找具体 recipe

不得先看现代星盘再替文本“配一个好日子”。顺序必须是：

1. 确认具体 PGM / PDM 编号；
2. 确认行号或可定位段落；
3. 确认所依据的校勘版 / 原文 / 工作译文；
4. 提取原文实际写出的时间要求；
5. 再换算到现代日期与当地钟表时间；
6. 最后才决定是否额外叠加 Suen 天象质量筛选。

没有具体编号和行号时，不把“PGM 里写过”当作完成引用。

## 原典时间要求需要提取什么

逐项检查具体 recipe 是否规定：

- 阴历日 / 月中第几日
- 月相
- 月亮所在黄道位置
- 日出、日落、夜间、白昼等一天中的时段
- 行星日
- 行星时
- 太阳状态
- 特定星辰或天文条件
- 与节庆、月份、季节有关的要求
- 其他明确的天文或时间限定

原文没有要求行星日 / 行星时，就不能因为后世行星魔法常用而自动补成原典要求。

## 两套评级必须分开

### PGM 原典适配度

使用：`D / B / A / S`

衡量现代候选日期对具体 recipe 明文时间条件的贴合程度。

### Suen 附加天象质量

使用：`不检查 / B / A / S / SS`

这是额外筛选，不属于 PGM / PDM 原文。未检查时必须明确写“未检查”，不能让读者误以为原典本身要求这些条件。

## 原典与附加规则冲突时

具体 recipe 的明文时间要求优先定义“原典适配”。

如果用户同时要求 Suen 严格天象质量，则在满足原典条件的候选中继续用更严格标准筛选。两者要分别写结果，不把现代附加规则伪装成古代原文。

## Suen Moon Hard Filter

只有在本次明确启用“附加天象质量”时才应用：

1. 月亮与太阳：应用 <15° 或分离 <12° → 淘汰
2. 月亮 VOC → 淘汰
3. 月亮在天蝎或摩羯 → 淘汰
4. Via Combusta → 淘汰
5. 月亮与火星/土星合、刑、冲 → 淘汰
6. 月亮与本 recipe 的目标行星刑、冲 → 淘汰
7. 月亮下一应用相位为凶相 → 淘汰

Bonatti 等更深入的月亮条件可以作为深度复核，但不自动冒充原典条件。

## 标准输出

每次至少给出：

- recipe 编号与行号
- 所用文本/版本
- 原文时间要求摘要
- 对应现代日期换算
- PGM 原典适配度：D/B/A/S
- Suen 附加天象质量：不检查/B/A/S/SS
- 如果淘汰，明确是“原典不符”还是“附加质量未通过”
- 不确定处与版本问题

这样可以避免把“历史忠实度”和“现代附加择时质量”混成一个分数。
