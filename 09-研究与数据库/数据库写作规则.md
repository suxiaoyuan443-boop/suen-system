# Suen Akhet｜数据库写作规则

状态：当前正式规则
最后核对：2026-09-17

## 当前载体与产品方向

数据库当前以 **Obsidian** 为主要整理载体，并计划使用 **Obsidian Publish** 作为正式对外访问方式。

当前产品方向：

- 需要一个正式的数据库首页 / 导航首页；
- 数据库支持 **单独购买**；
- 同时提供 **课程 + 数据库打包**；
- 访问模式 **暂定订阅制**；
- 具体价格、订阅周期、续费价格和权益仍待后续定案。

详细产品结构见 `数据库产品结构.md`。

## 数据库的核心任务

数据库不是“神秘学营销百科”，也不是神明关键词卡片。

每个页面都要真正解决一个查询问题：

- 这个对象是什么；
- 来自什么历史环境；
- 现存证据是什么；
- 古人实际怎么使用 / 怎么理解；
- 现代实践可以做到什么程度；
- 哪些部分是复原，哪些是现代新增；
- 读者接下来去哪里核查原始资料。

读完一页以后，不能只留下“某神掌管爱情 / 某仪式用来保护”这种空结论。

## 总体文笔

### 1. 正文默认不出现作者第一人称

不用：

- 我认为
- 我查到
- 我觉得
- 我们可以看到
- 今天来讲

优先采用对象本身作为句子主体，例如：

- “现存材料中可以看到……”
- “这件文物的铭文写明……”
- “在该版本中，这一段位于……”

### 2. 禁止明显 AI 开头

避免：

- 你有没有想过
- 很多人不知道
- 你绝对想不到
- 在神秘学的世界里
- 自古以来
- 今天让我们一起探索

直接进入具体对象、文本、问题或历史事实。

### 3. 禁止连续反驳模板

尤其避免整段连续使用：

- 不能
- 并不
- 不等于
- 不是……而是……

需要纠正误解时，先把正确内容自然讲清楚；只有真的需要对比时再使用反驳句。

### 4. 不一句一段

数据库不是短视频字幕。

以完整自然段承载一个完整信息单元。每一段至少推进一个新的事实、材料、动作、版本问题或解释。

### 5. 不写看完等于没看的长文

禁止用大量背景、形容词和泛泛历史把页面撑长。

长页面必须持续增加：

- 新原文
- 新文物
- 新案例
- 新动作
- 新材料
- 新版本信息
- 新比较
- 新解释

如果一个段落删掉以后不影响读者理解，它大概率没有必要存在。

### 6. 专业感来自具体性

优先写：

- 对象名称
- 年代
- 地点
- 馆藏号 / 手稿号 / 纸草号
- 行号 / folio
- 材料
- 动作
- 原文
- 译文
- 版本
- 学术解释

不靠术语数量制造“学术感”。

### 7. 术语第一次出现必须解释

不能假定普通读者知道 Egyptological、Greek、Latin 或 ritual-magic 术语。

第一次出现时说明：

- 原文 / 原词
- 转写
- 基本含义
- 在当前语境里为什么重要

---

## 证据层级

页面必须主动区分：

1. **可直接确认的历史事实**
2. **原始文本 / 文物所表达的古代观念**
3. **学术解释**
4. **学界存在争议的解释**
5. **后世接受与改写**
6. **现代实践 / 现代重构**

这六层不能揉成一个确定句。

如果证据只支持“可能 / 局部 / 某一时期”，就不能扩写成“古埃及人一直都这样做”。

# 神明页固定结构

每位神明页面优先包含以下部分。

## 1. 名称

- 中文名
- 原文名
- 常见拉丁转写
- 希腊化 / 后世名称（如有）
- 名称含义与版本差异

## 2. 历史

- 最早可见材料
- 主要活跃时期
- 地域变化
- 崇拜中心
- 神格在不同时期的变化

## 3. 图像与形态

- 人形 / 动物形 / 复合形
- 冠饰
- 持物
- 典型姿态
- 不同时期或地区的变化

图像特征只能写有证据的内容，不能把现代艺术常见造型当成古代固定标准。

## 4. 神话与关系

- 主要神话
- 家族关系
- 与其他神明的组合
- 地方神学差异

不要为了整理成“统一神谱”抹掉不同地区、时期互相矛盾的版本。

## 5. 功能与称号

不是简单列“爱情 / 战争 / 财富”。

需要说明：

- 哪些称号对应什么功能
- 哪个时期 / 地区出现
- 功能是神庙层面、国家层面、家庭层面还是私人魔法层面

## 6. 崇拜与供奉

优先写真实材料：

- 神庙日课
- 节庆
- 供物清单
- 祷词
- 奉献物
- 家庭供奉证据

必须区分神庙制度与普通家庭可执行实践。

## 7. 相关原始资料

至少尽量列出：

- 文物
- 纸草
- 石碑
- 神庙铭文
- 咒文
- 护符
- 神谕
- 学术出版

给稳定编号和来源链接。

## 8. 相关仪式

只收录能追到实际文本 / 文物 / 学术来源的内容。

每个仪式给出入口，不只写“可用于保护 / 爱情 / 财富”。

## 9. 现代实践

明确分成：历史材料 / 可复原部分 / 现代适应 / 现代新增。

## 10. 常见误读

只纠正确实常见且有证据能说明的问题，不为了“辟谣感”硬造错误观点。

# 仪式页固定结构

## 1. 基本信息

- 名称
- 来源
- 编号 / 行号 / folio
- 年代
- 语言
- 所属文本传统
- 目的

## 2. 使用情境

尽量回答：

- 谁使用
- 为谁使用
- 在什么环境使用
- 什么问题触发这个仪式

无法确认就明确写“不确定”。

## 3. 原文与译文

优先顺序：

- 原文 / transliteration
- working translation
- 中文译文
- 逐段讲读

不要只给中文二手转述。

## 4. 材料

每种材料都要说明：

- 原文怎么写
- 现代对应是什么
- 是否存在版本争议
- 在仪式里承担什么作用

## 5. 动作

把动作按原文顺序还原：

- 准备
- 制作
- 触碰 / 涂抹 / 书写 / 佩戴 / 放置等
- 诵读
- 埋藏 / 焚烧 / 沉水 / 保存等收束动作（如果原文有）

## 6. 时间与空间

有原文要求时写：

- 日期
- 月相
- 时段
- 行星要求
- 方位
- 房间 / 神庙 / 户外环境

原文没有要求，就不能自动补现代择时规则。

## 7. 因果机制

讲清材料、动作、名字、图像、话语之间怎样构成仪式逻辑。

不能只写“增强能量”“提升频率”这类无法落到历史资料的现代空话。

## 8. 现代执行

明确告诉读者今天实际操作时：

- 哪些可以原样复原
- 哪些材料需要替代
- 哪些步骤因安全 / 法律 / 环境需要调整
- 哪些是现代新增

---

# 原文 / 文献页固定结构

至少包括：

- 文献 / 手稿 / 纸草 / 文物名称
- 稳定编号
- 年代
- 馆藏
- 语言
- 编辑 / 校勘版本
- 原文或转写
- working translation
- 中文译文
- 逐行 / 逐段讲解
- 关键词
- 版本问题
- 与其他版本的比较
- 实际用途 / 历史语境
- 可打开的来源链接

数据库不能只存“翻译结果”，要让读者能追回原对象。

---

# 现代实践页面

数据库允许写得非常具体。

可以包括：

- 准备
- 时间
- 地点
- 神像 / 祭坛摆放
- 工具
- 材料
- 供物
- 颜色（有来源或明确说明为现代选择时）
- 动作顺序
- 诵读
- 收束
- 频率
- 注意事项

但每一个步骤都必须能回答：

**这是历史原文、历史复原、现代适应，还是现代新增？**

页面不能让读者分不清。

---

## 来源要求

优先级：

1. 原始对象 / 原始文本
2. 权威馆藏或数据库
3. 学术项目
4. critical edition / 校勘版
5. 同行评议论文
6. 可靠学术出版物
7. 二手资料只用于发现线索

关键历史断言不能只依赖博客、Pinterest、营销网站或无来源社交媒体内容。

## “没有找到”的表达

没有找到支持材料时，不直接写“绝对不存在”。

优先写：

> 在当前可查的主要资料与研究范围内，尚未找到支持这一说法的材料。

并尽量记录核查过的数据库、关键词、编号或出版物。
