# Suen Akhet｜数据库首页结构

状态：当前正式信息架构
最后核对：2026-09-17
适用载体：Obsidian / Obsidian Publish

## 首页的任务

首页不是品牌介绍页，也不是欢迎词占半屏的 landing page。

购买者打开数据库以后，首页首先要解决 4 个问题：

1. **这里有什么？**
2. **我现在应该从哪里开始？**
3. **我想查一个具体神明 / 仪式 / 文本时怎么走？**
4. **哪些内容是古代原始材料，哪些是现代实践？**

首页要让零基础用户不需要先理解整个 Obsidian 文件结构，也能马上进入内容。

---

# 第一屏

第一屏尽量短。

建议包含：

## Suen Akhet 数据库

一句定位：

**古埃及神明、原典、文物、仪式与现代实践的可追溯研究数据库。**

下面直接给主要入口，不写长篇品牌宣言。

### 快速入口

- 从神明开始
- 从想解决的问题开始
- 从原典 / 文物开始
- 从历史时间线开始
- 从现代实践开始
- 第一次使用数据库

---

# 1｜第一次使用数据库

给第一次进入的人一个非常短的说明页。

必须解释：

- 数据库和课程有什么区别；
- 条目里的“历史材料 / 复原 / 现代适应 / 现代新增”是什么意思；
- 怎么看来源；
- 怎么从一页继续跳到相关神明、文本和仪式；
- 如何判断一个页面是否已经完整、仍在持续补充或存在学术争议。

不要让新用户先看几十条使用守则才进入内容。

---

# 2｜按神明查

神明是最重要的一级入口之一。

## 神明索引建议提供多种进入方式

### A. 按名称

A–Z / 中文拼音或统一字母索引。

### B. 按主要历史地域 / 崇拜中心

例如：

- Heliopolis
- Memphis
- Thebes
- Bubastis
- Abydos
- Elephantine

只在确有资料时建立分类，不为了目录完整强行给每位神明贴单一地域标签。

### C. 按实践主题

例如：

- 保护
- 治疗
- 家庭与生育
- 王权与荣耀
- 死亡与来世
- 战争与危险
- 爱情与吸引
- 繁荣与供给
- 占卜与神谕

这里是导航，不代表“某神只掌管一个领域”。

### D. 当前重点神明

可以把已经内容最完整、最适合新用户阅读的条目放在首页，例如：

- Bastet
- Sekhmet
- Horus

重点神明不是“最强神明排行”。

---

# 3｜按目的 / 实践问题查

这是给“我知道自己想做什么，但不知道该查哪位神或哪份文本”的用户。

建议入口：

- 保护
- 供奉
- 繁荣 / 财富
- 爱情
- 成功 / 荣耀
- 治疗
- 占卜 / 神谕
- 对敌 / 防御性处理
- 诅咒与攻击性材料（历史研究入口）
- 家庭供奉
- 神像 / 临在

每个目的页不要直接给一个现代 recipe。

目的页应该先列：

1. 相关历史材料；
2. 相关神明；
3. 相关文物；
4. 相关原典；
5. 可以复原的仪式；
6. 现代实践页。

---

# 4｜按原典 / 文物查

适合研究型用户和课程学员。

建议分为：

## 原典 / 文献

- Pyramid Texts
- Coffin Texts
- Book of the Dead 等葬祭文本（按数据库实际覆盖建立）
- 神庙日课
- 医疗 / 魔法纸草
- 神谕与敕令
- PGM
- PDM
- 其他逐步收入的文本

## 文物类型

- 护符
- 石碑
- Horus stelae
- 雕像 / 神像
- 陶片 / ostraca
- 折叠护符
- 仪式器物
- 祭祀 / 奉献物

每个索引都应能跳回具体条目，而不是只做分类页。

---

# 5｜按历史时间线查

首页提供一条清楚的古埃及历史入口。

目的不是做完整埃及史教科书，而是帮助用户理解：

- 一个神明最早什么时候出现；
- 某个 ritual / spell 属于什么时期；
- 法老时期材料和 PGM/PDM 为什么不能混为同一层；
- 某个做法是古王国、新王国、晚期还是希腊—罗马时期材料。

时间线上的每个时期都可以跳到：

- 重点神明；
- 代表文本；
- 代表文物；
- 代表实践。

---

# 6｜现代实践

单独建立入口，避免用户把历史资料页里的内容直接理解成现代操作教程。

建议分：

- 家庭供奉
- 祭坛 / 神像
- 日常供物
- 祈祷
- 现代仪式复原
- 材料替代
- 空间与安全
- 原典动作如何适应现代环境

所有现代实践页继续遵守四层标记：

1. 历史材料
2. 可复原部分
3. 现代适应
4. 现代新增

---

# 7｜资料鉴别 / 研究工具

这是数据库区别于普通“神明百科”的核心之一。

首页应能直接进入：

- 怎么查文物编号
- 怎么查纸草 / 手稿
- 怎么判断一张图片是真是假
- 怎么找原始出处
- 怎么看论文 / DOI / ISBN
- 怎么判断“古埃及传统”是不是现代拼合
- PGM/PDM 与法老时期材料怎么区分
- 常用数据库 / 馆藏 / 学术项目

完整研究方法读取 `资料鉴别与研究规则.md`。

---

# 8｜课程配套入口

对购买课程 + 数据库打包的用户，首页可以提供：

- 第 1 课相关数据库页面
- 第 2 课相关数据库页面
- ……
- 第 10 课相关数据库页面

课程入口只做索引，不把课程 PPT 全部复制到数据库。

同一条资料可以被课程索引引用，但数据库条目本身应能独立阅读。

---

# 9｜最近更新

订阅制数据库需要让用户看得到“数据库在持续增长”。

首页保留最近更新区域，例如：

- 新增条目
- 大幅扩写
- 新增原文
- 新增文物图
- 修正旧译文
- 更新来源

但不要为了显得更新频繁，把标点修改也写成一次重大更新。

建议另设完整 `更新记录` 页面。

---

# 10｜页面状态标记

为了避免用户把半成品当最终结论，可以给条目使用简单状态：

- `完整条目`
- `持续补充`
- `资料整理中`
- `存在重要争议`

状态用于透明度，不做百分比进度条。

---

## 首页不应该出现什么

- 大段“欢迎来到神秘世界”的品牌文案；
- 复杂的会员销售页替代内容导航；
- 大量装饰图片压过入口；
- “最强神明 / 最灵仪式 / 必做仪式”排行；
- 让新用户先读完整数据库规则才能开始查资料；
- 把课程、数据库和咨询服务混成一个菜单。

## 最终标准

一个第一次进入的购买者，应在 **30 秒内**知道：

- 数据库能查什么；
- 自己从哪里进去；
- 怎么区分历史资料和现代实践；
- 怎么继续追来源。
